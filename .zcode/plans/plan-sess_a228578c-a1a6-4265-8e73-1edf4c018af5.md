# ChatFlow 五联修：个推链路 / 通话页消失 / 视频封面 / MIUI相册 / 视频缓存

## 已实证的根因（探索确认）

| # | 问题 | 根因 |
|---|---|---|
| 1 | **个推后台无提醒** | ① CID 竞态：initialize→ensureRegistered 时 CID 未到，无重试；② EventChannel replay bug：回放代码在 lambda 内部，CID 已存在但无新事件时 Dart 永远收不到；③ 老用户升级后无隐私同意记录→永远不初始化；④ 无 resume/网络恢复重检查；⑤ bridge 把临时错误全放 rejected（Synapse 可能删 pusher）；⑥ 限频不分会吞来电；⑦ event_id_only 时 type 可能缺失→来电误判为消息 |
| 2 | **接听后页面消失** | `connected` 时 `incomingCallActive=false`，而 CallPage 只在 `incomingCallActive==true` 时挂载——被叫接通即卸载通话页 |
| 3 | **视频无封面** | SDK `sendFileEvent` 先构建含 thumbnail_file 的 info，再 spread extraContent——`{'info':{'duration':...}}` **覆盖整个 info**（丢 thumbnail_file/mimetype/size） |
| 4 | **MIUI 相册无视频** | `pagerFor(album.entity)` 不传 RequestType——"本地视频"用 entity=null 退化为 common（混合列表） |
| 5 | **视频重复加载** | `VideoViewerPage.loadBytes` 直接 `loadAttachment`（无缓存）→每次全量下载+写临时文件+不删除 |

## 实施（测试先行，每项先写失败测试）

### A. 个推链路（最高优先级）
1. **Kotlin EventChannel 修复**（MainActivity）：onListen 立即回放当前 CID（移出 lambda）+ 去重（不重复发）。
2. **GetuiPushTokenProvider**：initialize 失败可重试（去掉 `_initialized` 一旦置 true）；token() 加短暂等待（轮询 ≤8s）；tokenUpdates 正常。
3. **MatrixPusherService**：可恢复状态机——ensureRegistered 失败后有限指数退避（4 次：10s/30s/2m/10m），watchTokenRefresh 内触发重注册；`isRegistered` 改为持久化到 SharedPreferences（跨重启）；新增 `checkAndReRegister()`（查服务端 GET /pushers 比对）。
4. **AppHome**：resume/网络恢复时重新调用 ensureRegistered；隐私同意缺失的老用户（已登录状态）补写同意（升级迁移：只要已有登录会话即视为曾同意）。
5. **推送诊断页**（扩展既有 notification_diagnostics_page）：隐私同意/SDK 初始化/CID 存在性/bridge URL/pusher 注册状态/最近成功失败时间与类别/通知权限/电池优化（脱敏：CID 只显示存在/不存在）。
6. **服务端 bridge**：
   - `rejected` 语义修复：区分永久（个推业务码 20001-2 CID 无效类）vs 临时（网络/5xx/超时/鉴权失败）——临时错误不进 rejected，返回 `{}`（Synapse 会重试）。
   - 限频修复：`call` 类型跳过普通限频（用独立更长间隔 500ms 只做同通话去重）；`message` 保持 1.5s。
   - `type` 缺失时的来电识别：bridge 侧通过 `counts.unread` + `event_id` 存在性辅助，若 Synapse 不传 type 则统一 message（不伪造来电识别）——但**来电场景改由客户端 m.call.* 同步触发原生全屏通知**（更可靠），bridge 推送仅做"你有一条新消息"兜底。
7. **服务端验证**：SSH 确认 bridge 容器 env 与 .env 一致、nginx 路由、Synapse pusher 配置。

### B. 通话页消失
1. 先写失败测试：mount AppHome overlay，ringing→connecting→connected 后 CallPage 仍在。
2. 修复 `_callChanged`：`connected` 不再清 `incomingCallActive`；引入独立的 `callEnded` 判断——只有 `ended/failed/permissionDenied` 才清（页面卸载）。
3. 状态分离：`incomingCallActive`（系统来电通知+接听 UI 是否显示）与通话页面是否挂载（由 phase != idle/ended 决定）。

### C. 视频封面
1. 先写失败测试：`sendEncryptedMedia` 的 extraContent 不覆盖 SDK info 子键。
2. 修复 `matrix_e2ee_client.sendEncryptedMedia`：extraContent 含 `info` 时做**深合并**（SDK info 为底，extraContent.info 仅补充 duration 等新增键）。
3. `_videoPosterBytes` 多时间点抽帧（[200, 500, 1000, 2000]ms）+ 近黑帧检测（亮度采样均值 < 16 跳过）。
4. 抽帧全失败时使用明确的视频占位图（灰色 videocam 图标——已有），不显示黑色卡片。

### D. MIUI 相册
1. `pagerFor` 增加 `type` 透传：`DeviceGalleryPager(album: entity, type: album.isVideoOnly ? RequestType.video : RequestType.common)`。
2. 先写失败测试：videos album → pager 拿到的列表全为 AssetType.video。

### E. 视频缓存
1. `VideoViewerPage` 改用 `loadMediaWithCache` 包装 `loadAttachment`（磁盘缓存首次解密产物）。
2. 缓存键：`video-<eventId>-sha256(eventId+roomId+accountId前8)`，文件名哈希。
3. 并发请求合并（MediaMemoryCache in-flight dedupe 已有）。
4. 临时文件不再泄漏：直接播放缓存文件（`VideoPlayerController.file(cacheFile)`），不再另建 temp。
5. 先写测试：首次下载/第二次命中/新对象命中/模拟重启命中/并发合并。
