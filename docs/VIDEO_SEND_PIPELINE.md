# 视频发送管线（2026-09-10）

适用：apps/mobile_flutter Android/iOS。验证见 docs/verification/2026-09-10-chat-reliability-2084-video.md。

## 统一策略

相册、系统相机录像、文件入口视频共用 transcodeForChat。原图开关只影响图片。
相机完成后立即处理并发送，不再增加确认压缩/确认发送步骤。全部编码在设备执行，
输出继续通过 Matrix sendEncryptedMedia 端到端加密，不上传明文到业务服务器。

| 参数 | 普通 | 激进 |
| --- | --- | --- |
| 最长边 | 640px | 320px |
| H.264 视频码率 | 1,200,000bps | 160,000–400,000bps，按时长预算 |
| 帧率上限 | 24fps | 12fps |
| AAC 单声道 | 64,000bps / 44,100Hz | 32,000bps / 22,050Hz |

普通结果实际≤20MiB即采用；超限或编码失败自动再跑激进配置。激进结果仍超限或失败
则明确拒绝，没有原件上传绕过。普通/激进均以实际文件长度为准，再读取最多20MiB。
时长已知且原片超限时，以最低可接受视频+音频码率估算明显不可满足的视频并提示裁剪；
时长缺失继续尝试编码。估算不是编码器输出大小保证。

原生实现来自仓内 video_compress 3.1.4：Android Transcoder 明确设置各参数；iOS
AVAssetReader/Writer 转码。公开插件原先 Android 的480p/LowQuality分支忽略帧率，
iOS预设导出不提供音视频码率接口，因此不能只修改Dart参数宣称双端生效。

## 文件所有权和重试

- 转码串行化，避免共享插件被相册预览与发送同时调用。
- 编码器创建失败/取消文件后立即回收；Dart删除未采纳的压缩文件。
- 相册预览与发送各自拥有产物，结束/失败/离开后回收，不删除相册原件。
- 相机预处理先生成验证通过的内存payload及封面，清理APP录像原片与压缩文件后，
  再创建timeline消息。网络重试闭包只引用bytes，不引用已删除路径。
- 编码失败在创建相机timeline消息之前明确提示；网络失败保留可重试消息。
- 系统相机可自行取消。开始自动发送后未提供上传取消按钮，SDK行为未扩展。

## 进度与内存边界

相机压缩显示插件真实百分比；准备完成后显示“发送中”，消息气泡由原有timeline
发送状态管理。不宣称当前页面轮询了SDK加密/上传细分进度。
SDK仍使用完整缓冲区进行Matrix加密和上传，因此保留单视频最多20MiB的内存payload；
失败消息在当前timeline中持有该payload以支持重试。未新增分块上传或明文缓存。

## 发布前原生验证

当前Windows自动化覆盖策略、参数通道、边界、清理、网络重试及选择页。
Android/iOS原生编译和实机编码尚未在本子任务执行。发布前分别使用真实H.264/HEVC、
横竖屏、有声/无声、短片、长片、超大视频验证输出尺寸/码率/fps/AAC、最终长度、
播放/口型同步、后台中断、失败清理及相机/相册一致性。iPhone 15、iOS 26.6 是用户
原始环境描述，不能由Dart测试替代该设备验收。
