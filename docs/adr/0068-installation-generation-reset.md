# ADR-0068：安装世代与孤立密钥清理

2026-09-11；产品授权：用户 2026-09-11 明确要求修复 iPhone 卸载重装登录失败（L07），
并选定"安装标记 + 首次启动清理"方向与"清除全部遗留、对齐 Android"的清理范围。
领域评审：**通过（Astra，2026-09-11，实际 diff、启动调用链与 154/94/4 项测试证据复核）**；Quality/Security 评审：**通过**（见 `docs/verification/artifacts/2026-09-11/integrate-deploy-mi6/0068-installation-generation-reset-quality-security-review.md`）。
关联：ADR-0062（移动端单设备会话）、ADR-0063（切换账号保留本地聊天存储）。

## 背景

iOS 的钥匙串项不随应用卸载删除，而应用沙盒（含 SQLCipher 加密库文件）会删除。
Android 上 `flutter_secure_storage` 落在应用数据内，卸载即清。因此 iOS 卸载重装后
会出现一个 Android 不存在的状态：**全部密钥材料仍在，而它们所保护的加密库已不存在**。

该状态下，`MatrixClientFactory.continuityMetadata` 读到仍存在的本地绑定、却看到
重新打开的加密库没有任何身份，于是抛出 `StateError('Matrix continuity identity is
unavailable')`。该异常发生在登录流程的 `account_storage` 阶段，表现为
"聊天登录未完成，请重试（L07）"。同源的残留还包括注册设备键（永久复用卸载前的设备身份）、
旧业务会话（启动时被恢复，可能已被服务端标为 `SESSION_REPLACED`）、以及指向已不存在的
库的账号注册表与当前槽指针。

根本问题不是某个守卫写错了，而是应用**无法区分"同一安装的延续"与"全新安装但钥匙串有残留"**。

## 决定

1. **引入安装世代标记。** 在随卸载一起消失的存储（`SharedPreferences`：iOS 落
   NSUserDefaults，Android 落应用数据）中保存一个安装标记。
2. **标记缺失不等于全新安装。** 标记由本决定引入，存量安装升级时标记必然缺失而
   容器完好。因此标记缺失只表示"需要判断"，必须再取一项证据：
   **应用支持目录中是否仍存在 Matrix 加密库文件**（`liuhetong_matrix*.sqlite`，
   含迁移期的 `.sqlite.encrypted`）。容器随卸载消失、钥匙串不会，故该文件的存在
   等价于"上一次安装的密钥仍然有效"。
   - 文件存在 → 判定为**覆盖升级的延续**：**只写入标记，不删除任何密钥**。
   - 文件不存在 → 判定为**全新安装**：清除全部钥匙串遗留，然后写入标记。
3. **仅在判定为全新安装时清除。** 清除范围：所有账号槽的数据库密钥、绑定、恢复密钥、
   诊断盐、清库标记，账号注册表与当前槽指针，业务会话，注册设备键，以及 ADR-0063
   之前的无后缀遗留键。
4. **清除与判断必须发生在任何读取钥匙串遗留的动作之前**，即在构造业务 API 客户端、
   Matrix 客户端工厂与打开加密库之前。
5. **不确定时不清除、不写标记，也不启动业务或 Matrix。** 标记**读取失败**或**容器探测失败**时，
   两者都不做；`InstallationStartupGate` 显示“启动检查未完成，请重试”，仅在用户重试且
   `reconcile()` 成功后构造 `BusinessApiClient`、`MatrixClientFactory` 并打开加密库。
6. **清除未完成不写标记。** 逐键尽力删除并记录首个错误；清除失败则保持标记缺失，
   同时保留注册表与活动槽等枚举入口。启动门禁阻止建库；用户重试时才能安全地再次枚举
   全部遗留键，避免残留被永久化。
7. **注册表损坏不阻断清除。** 它只在"已判定为全新安装"之后影响候选后缀的枚举方式，
   改为从原始注册表字符串提取候选后缀。

## 明确不影响的部分

- **不修改** `continuityMetadata` 的既有兼容路径。它在 SDK 完全没有 session、user 或
  device 而本地仍有 binding 时只清除该失效 binding 并采用空库；本 ADR 不改变这条
  既有 L07 兼容行为，也不把它扩大为安装世代清理。真实 user/device/fingerprint 不匹配
  仍失败关闭。本 ADR 的“不清理”承诺指 `InstallationReconciler` 在证据不确定时不清理
  安装世代密钥、注册表或业务会话。
- **不修改** ADR-0063 约束的账号切换路径。该 ADR 要求"清库只删除当前槽及其密钥，
  不影响其他账号"，约束的是同一安装内的切换；本决定处理的是全新安装，
  此时每个槽的加密库文件都已随沙盒消失，没有任何槽还有可读数据。
- **不修改** E2EE 算法、密钥恢复流程、服务端契约或单设备会话策略。

## 后果

- **覆盖升级不丢数据、不改变行为。** 升级到含本决定的版本时标记缺失，但容器里的
  加密库文件仍在，判定为延续，只播种标记。这是本决定必须守住的第一条：缺少证据
  判断时，"标记缺失即全新安装"会让存量安装的加密库失去密钥——库文件还在磁盘上
  却永久不可解密，且在 ADR-0063 之前的空槽布局下 `create()` 会拿新密钥重开同一
  文件，异常抛在 `runApp` 之前，启动即失败。
- **判据依赖库文件名。** 探测按 `liuhetong_matrix*.sqlite` 匹配。若将来更改
  `MatrixClientFactory.databaseFileName` 而不更新探测，探测将永远看不到产物，
  覆盖升级会被误判为全新安装。两者必须一起修改。
- iOS 卸载重装后，用户必须重新登录，本地聊天记录不可恢复——这与卸载本身已经
  造成的损失一致（沙盒已删除），本决定只是让应用的判断与事实相符，
  而不是造成新的数据丢失。
- 重装后会创建新的 Matrix 设备身份。Olm/Megolm 状态随加密库消失，无法保留；
  服务端单设备策略本就会删除其他设备。
- 注册设备键被重置，重装后的登录在服务端表现为新设备，与 Android 卸载重装一致。
- 遗留的注册表与当前槽指针被清除，新安装从无槽状态开始。
