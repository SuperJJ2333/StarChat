# ADR-0061：仅过期储备快照的有界重采样

追加状态：2026-09-10 用户明确授权后已部署生产 API/Worker，见 docs/verification/2026-09-10-reserve-resampling-production.md。主机时间同步问题未在本 ADR 中修复。

日期：2026-09-10。状态：用户已批准修订方案 A 并要求执行；实现、领域与质量安全评审、隔离集成及全仓库门禁已完成，本次尚未生产部署。证据见 docs/verification/2026-09-10-bounded-reserve-resampling.md。本 ADR 补充 ADR-0013、ADR-0043，不修改金额、储备公式或证据有效期。

## 原因与边界

调查中的慢扫描使旧固化头超过 180 秒，而下一张快照尚未提交。新证据恢复后，既有事故仍需人工恢复。不能通过放宽新鲜度或自动解除暂停解决这一问题。只修复后台采样，保留同步管理 HTTP 的原有 200ms 单次重采样；预算 0 恢复该行为。

## 决策

1. 保持 ReserveCut 及其账本摘要协议不变。只读适配器在同一个 SQLite 事务中返回 cut 和独立的 age_expired_only 分类。仅 run OK、error 为空、stable_balance=1、SOURCE_MATCHED、时间不在未来且确已过期时分类为真。摘要无效、来源错误、对账差异、未核实、扫描 ERROR 均不能进入延长等待。
2. 后台预算最多 60 秒，约每秒重读；使用单调时钟、不续期的截止时间、按剩余预算限制 SQLite 读取。另以原 cut 的 fresh_until+预算约束已过期时间，重启不能让同一过期快照无限重新等待。只有 observation_id 严格增加且所有健康/年龄校验通过的新快照才可结束等待；新故障立即阻断，超时沿用 MANUAL_SOURCE_UNHEALTHY。
3. 等待前在短预算锁事务中调用 invalidate_wallet_reserve 并写 WAITING 心跳，提交后才等待。持有独立 whole-scan advisory lock，其他扫描获得 MONITOR_SCAN_BUSY；不持有资金事务或预算锁休眠。失效后的版本在外部读取前重新采集，仍检查并发变化，不能在发布前覆盖预期版本。
4. 失效储备阻止新出款执行、兑换、增发和储备依赖的入账。人工流动性策略既有报价/申请只是用户资金冻结，不授予外部签名资格；已有出款核验仍依赖其独立的新鲜链上证据。本改动不取消订单或阻断既有承诺的观察，不声称所有财务写入全部冻结。
5. 新快照仍走双读、发现/覆盖、账本完整性、暂停/限制、版本和提交时新鲜度检查；保留既有暂停，绝不调用事故复核/激活接口。源等待仅改变故障确认延迟，最终接受证据仍受获取120秒/固化头180秒的最早截止约束。
6. 只为后台 manual_tron 提供单任务监控协调器，最多一个独立线程执行扫描。两个后台调用点共享同一协调器；辅助调度不消费结果，维护任务一次性消费已完成结果，不能重复使用成功结果重试入账。告警/Outbox 和其他维护任务继续执行。退出时停止接受新扫描并等待在途扫描退出后关闭依赖。
7. 记录等待启动、恢复、故障、超时及等待时长/采样次数/前后 observation_id；只增加数值白名单，不记录地址、余额、凭据或原始错误。利用既有扫描耗时及固化头年龄日志排查慢源，不改变供应商额度或180秒策略。

## 验证与发布约束

测试覆盖：真实 SQLite 年龄单因分类、恶化状态立即拒绝、只读与读取预算；死区后恢复无事故、等待超时、同ID不续期、时钟变化、非法摘要、双读变化、提交过期、暂停不解除、资金准入失效与版本竞争、锁繁忙；调度单任务/一次消费/异常/退出及默认零预算兼容。先领域后质量安全评审，完成全仓库门禁与隔离集成证据。此次代码修复不执行生产事故结案、资金恢复或真实签名操作。
