# ADR-0080 移动凭证刷新中断恢复

日期：2026-09-21；状态：用户已明确批准“批准，按方案实施”；领域设计评审、质量安全设计评审均通过。不得把本文件当作已发布行为。

## 问题和约束

生产已确认用户19:57:55的退登录原因是 TOKEN_REUSE，19:58:19同设备重新登录。尚不能证明当时是响应丢失、持久化失败还是其他重复请求。当前协议先提交服务端轮换，再返回客户端持久化，无法安全处理提交成功但结果未知的窗口。ADR-0009仅有进程内 single-flight，明确要求旧凭证重用撤销；本决策对“同一次操作的重试”作窄化例外，必须明确批准。

## 方案比较

1. **采用：客户端持久化刷新操作凭据，服务端返回同一操作的既有结果。** 跨断网、进程退出恢复，无需用户操作；新增兼容协议和数据库字段，有额外持有完整请求的重试风险。
2. 仅修改提示、增加内存互斥：不足以覆盖服务端已提交但客户端未保存的窗口。
3. 允许所有旧令牌短期重用：无法区分正常恢复与泄露令牌的重放，不采用。

## 决策草案

### 客户端事务

- 在既有安全存储单条版本化会话记录中增加可选 pending_refresh_operation；值为 CSPRNG 生成的32随机字节，base64url无padding编码43字符。与当前刷新令牌绑定，同一操作始终使用同一值，不进普通偏好、日志、分析或错误文本。
- 在发起网络请求**之前**持久化操作值。写失败不发请求、不清会话。响应成功后把新令牌对及移除pending一次写回；只有写回成功才向调用方完成刷新。写回失败保留旧凭证和pending，之后重复同一操作，不能生成新操作值。
- 安全存储write抛错也可能已写入：无论预写或结果写回抛错，都必须在同一串行队列内重读并比较完整记录。已写成新结果则采用新结果；仍是同一旧记录/pending才允许重试；读失败暂停恢复；读到另一个账号/epoch或不同操作时丢弃迟到结果。禁止凭内存旧值覆盖持久化新会话。这里“保留旧凭证”仅指读回确认旧记录仍在的情况。
- timeout、连接中断、502/503/504、无效响应、临时安全存储不可用进入可重试状态。保持已登录的本地会话与聊天库；远程授权请求仍必须由服务端验权，禁止将缓存状态当作授权。不得自动密码登录。
- 同一客户端进程继续 single-flight；后台/回前台/启动入口共用实例。明确登录、登出、账号切换与刷新写入使用同一串行队列及session epoch，迟到结果不能复活旧账号。启动读取失败保留原记录，不初始化空会话覆盖它。
- 有限重试：单轮至多一次额外请求，之后退避（5/15/30/60秒，最多60秒）；后台停止定时重试，回前台/联网可触发一次，不按每个失败业务请求无限重试。不循环弹窗。

### 服务端兼容协议

- 独立移动刷新请求模型增加可选 operation_id，不复用管理员刷新或logout请求模型。不携带该字段的旧客户端沿用旧规则；部署新客户端前先部署兼容服务端。
- RefreshToken 增加可空 operation_hash、result_key_version；旧数据保持空。首次合法刷新在现有用户锁/事务内记录操作hash与replacement关联，原令牌仅消费一次。
- 新刷新令牌使用 HMAC-SHA256 确定性派生：key为高熵原刷新令牌的UTF-8字节，message为固定域标识`chatflow/mobile-refresh/result/v1`、分隔字节0与解码后32字节operation_id；输出32字节base64url无padding。固定算法版本1，不依赖JWT签名密钥，避免签名密钥更新破坏既有结果恢复。数据库仍只存令牌hash和操作hash，不存可直接兑换的明文凭据。重试必须与replacement记录的hash恒时验证一致，绝不因算法版本错误重新创建结果。
- **先检查账号、设备、族、管理域隔离和到期，再判断重复操作。** 已登出/替换/封禁/密码重置的会话不能通过重试恢复，不覆盖原撤销原因。
- 到期定义：首次消费按父令牌expires_at校验；已消费且operation匹配的恢复按replacement.expires_at校验，不再受已经完成消费的父令牌到期影响。这样在父令牌到期前成功消费但丢响应，仍能恢复有效子令牌。恢复不延长子令牌到期；边界测试覆盖父过期子有效、子刚好到期、族已撤销。
- 对已消费父令牌，仅当operation hash匹配、replacement存在且未消费且未过期、族/设备/账号仍有效，返回同一刷新令牌及当前有效access token。不创建新replacement，不延长replacement的原到期时间，最多保留原60天刷新有效期内的结果恢复能力。
- operation缺失或不匹配的重放继续拒绝并按原规则撤销族。已匹配但结果被后续轮换的操作返回明确 REFRESH_RESULT_SUPERSEDED，不撤销后来正常会话；客户端先重读安全存储，只有当前记录仍是该不可恢复旧操作时进入需重新认证状态。
- 恢复能力本质是“父令牌+随机操作凭据”的组合：只泄露旧令牌无法领取已创建结果；完整原请求被窃取仍可恢复未推进的结果，这是可接受性需批准的剩余风险。TLS、无敏感日志和限流保持。
- 移动access仍15分钟、刷新滑动60天，管理员48小时绝对期限、RBAC/TOTP/资金授权均不改。

### 错误原因与提示

- 仅确有新会话替换旧会话时返回 SESSION_REPLACED。默认提示“账号已重新登录，当前会话已结束，请重新登录”，不未经证据声称其他设备。
- Matrix授权/绑定对未知/失效会话使用真实认证错误；禁止把任意校验失败都标成 SESSION_REPLACED。
- 重用保护提示“登录凭证校验异常，请重新登录”；过期提示“登录已过期，请重新登录”；主动撤销提示“当前登录已失效，请重新登录”；封禁走既有账户受限流程。
- 网络及临时存储异常不退出账号、不显示被顶号提示。仅需要用户操作时展示简短具体原因，不显示L04/L07等内部编号。
- 不把已撤销的历史会话重新激活。修复保护将来的刷新流程，不恢复过去已结束的认证。

### 无负担诊断

- 复用现有异步有界诊断通道，增加 allowlist阶段码：pending_write_failed、request_uncertain、result_write_failed、retry_recovered、terminal_invalidated、result_superseded；状态码、耗时、App build、前后台状态、重试次数。
- 禁止operation_id、凭证/hash、账号、真实设备号、原始异常、请求/响应正文和聊天数据。刷新链路不等待上报；去重、容量上限、限频和既有退避均保留。诊断上传401不反向触发会话失效。
- 新包安装前无法取得旧客户端缺失的阶段证据，不夸大诊断覆盖。

## 验收与发布

必须红绿证明：服务端消费后丢响应、返回后安全存储写失败、进程重建恢复、并发401/回前台、预写失败无网络、登出/换号与迟到响应、非匹配重放仍撤销、匹配重试不能越过封禁/登出/替换/到期、重复恢复不延长有效期、replacement推进不误撤销、管理员隔离、Matrix错误分类、日志泄密检查。

扩展迁移只加可空列；服务端先行，客户端后行。旧客户端无法从新增操作恢复机制获益。新客户端在旧服务端回滚时不能删除pending并盲目重放；显示临时不可恢复服务状态并保留数据。正式回滚需保持兼容刷新端点，已发出的候选客户端不能使用不支持该字段的旧API。不删除新增列或令牌记录。

已核对当前旧API的StrictModel为extra=forbid：含operation_id请求返回422且不会进入rotate。必须以实际旧模型契约测试证明“不消费旧令牌”；新客户端对此保留pending，不去掉字段降级。不支持此strict约束的历史镜像不列为允许回滚目标，不能假设任意旧服务都会忽略字段而安全。

实现前通过领域设计审查和质量安全设计审查；实现后再做对应代码评审、专项/全量门禁和Android/iOS后台/断网/重启验证。未验证真机场景单独列缺口；不得声称永不退出（明确撤销和真实过期仍需登录）。
