# 管理台入口合并、客服改密与钱包只读授权 ADR

- 日期：2026-09-28。
- 状态：**待用户批准**。用户已确认[书面设计](../superpowers/specs/2026-09-28-admin-entry-merge-design.md)的总体方案；本 ADR 的受保护认证、权限和钱包边界仍须审阅批准后实施。
- 范围：管理后台登录与客服首次开通、客服修改共用登录密码、管理员钱包只读入口、管理员用户目录，以及相应后台视觉与加载状态。

## 背景与目标

目前后台有管理员、客服和独立“首次开通”三种页面入口。客服首次开通已有绑定邮箱/手机的验证码服务，但用户希望第一次正确登录时直接进入验证方式选择。管理员钱包页面现在要求 60 分钟 wallet grant 才读取资料，用户希望进入“USDT提现与支付”时免输入操作密码，同时保留实际操作的授权门槛。现有注册用户统计列表刻意不返回完整联系方式或余额，新“用户管理”需要单独的高权限读取边界。

本决策只调整上述入口和读取范围；不改变账本事实、用户钱包私钥控制、客服订单结算、钱包写入状态机或审批规则。后台登录仍以业务 API 的用户、角色及管理会话为权威，官方客服身份不由 Matrix 昵称或用户自行填写的后缀决定。

## 决策

### 1. 合并登录页面与客服首次开通

保留同一登录页内的“管理员 / 客服”切换，取消单独“首次开通”入口。管理员继续走图形验证码登录；已开通客服日常登录继续只使用既有账号密码，不增加图形或联系方式验证码。只有客服登录在密码和角色校验后明确返回 `STAFF_ACTIVATION_REQUIRED`，页面才弹出“首次开通验证方式”，提供邮箱、手机两个选项及现有开通挑战所需的图形验证码。图形验证码失败时刷新挑战；其他 401/403、网络或验证码失败均不推测为待开通。

开通复用现有 staff activation 挑战、五分钟验证码、尝试/发送限频、单次消费、审计和 Outbox。目标必须由服务端选取账号当前已验证的绑定联系方式，对页面仅返回脱敏目标；该流程不创建账号、授予角色或钱包权限。当前 STAFF_ROLES 的 SUPPORT_AGENT、FINANCE_SUPPORT、SUPPORT_SUPERVISOR 均可经客服入口完成开通与普通登录；现有仅主管角色被 staff login 拒绝的差异应在受保护认证测试中修正，混合超级管理员账号仍只走管理员入口。确认成功后重新验证客服登录，失败则要求用户明确重试。临时密码只在当前页面内存保留至确认或退出；取消、超时、模式切换、页面销毁或成功后立即清除，不进入浏览器持久存储、URL、日志、审计或错误文案。联系方式、验证时间或客服角色改变后，按既有身份摘要重新开通；相同身份的后续登录不重复开通。

### 2. 只有客服可在后台修改共用登录密码

客服账号菜单新增“修改密码”，修改的是与畅聊 App 共用的业务登录密码，不创建第二套后台密码。新身份接口要求有效且当前的管理会话、同一会话绑定的 HttpOnly Cookie、同源和 CSRF 校验、限频、当前密码及 12–256 位新密码。服务端在用户行锁内复核 ACTIVE、管理 session/family、已开通客服角色和当前密码；客服角色的授权与撤销也先锁同一 User 行，再变更角色，以序列化撤权与改密。撤权先提交时，改密须拒绝。SUPER_ADMIN（包括兼具客服角色的账号）、普通用户、App Bearer、过期/被替换会话均拒绝。页面显示条件仅用于体验，服务端权限检查是最终边界。

当前工作树的 `PasswordRecoveryService.reset()` 已有哈希更新、refresh family 撤销和 24 小时提现冷却，但尚无供已登录客服直接调用的公开事务接口，也没有改密完成的审计/Outbox。实施时须在身份模块提取可复用的公开改密应用操作，并在同一事务中更新 Argon2 哈希、撤销全部业务及管理 refresh family、失效旧恢复证明、建立 24 小时提现冷却，补齐审计和事务 Outbox。改密后前端清除当前密码输入和内存会话，回到登录页；不会自动重试原业务操作。审计、Outbox 和日志不得包含明文密码、完整联系方式或恢复证明。当前 Worker 的身份邮件 handler 不消费改密完成事件；改密完成采用独立的 `identity.account_credentials` topic 和 `identity.password.reset` 事件，发布前同步注册及测试对应消费者，不能与请求邮件的事件混同。集成前须核对主工作区后续账号安全实现并选定唯一的公开事务和事件契约。

### 3. 钱包负责人读操作免 wallet grant，写操作继续受保护

仅配置的官方钱包负责人在 ACTIVE 管理员身份、当前管理会话、设备和 family 有效且无提现安全保护期时，可进入“USDT提现与支付”并调用经审查的只读钱包接口，无须先取得 60 分钟 wallet grant。上线前须确认生产 `wallet_access_grant_enabled=true`；关闭该开关时既有旧策略保持不变。服务端 context 只向实际 owner 提供钱包菜单能力，非负责人、客服、App 会话、撤销会话和正在受提现 SecurityHold 保护的账号仍不可读取该专用资料。只读钱包响应 `Cache-Control: no-store`；只读授权不得以页面显示状态代替服务端校验。会改变财务/业务状态、创建可提交预检凭据或触发付款的请求仍需要原授权；正常只读查询追加的访问审计继续保留。

钱包业务写入继续要求现有 wallet grant，以及各自既有 RBAC、操作密码/TOTP 策略、幂等键、原因、审计、Outbox、链上证据、审批和事务提交前复核。只读豁免仅适用逐项列明的现有 GET/HEAD；未来新增钱包路由默认继续要求 grant。POST 型业务 preview、事故状态修改、出款和 owner transfer 均属写入边界；共用 `context()` 的修复路由必须拆开 GET 的只读授权与 POST preview 的 grant 回调，避免事务内预检凭据写入被豁免；直接 `/wallet/manual/payouts` 出款命令的原授权不变。取得、撤销 grant 的验证接口本身，以及固定操作密码的初次设置/修改，继续分别按既有独立会话和凭据规则执行；它们不是这次新增的 grant 豁免，也不能以前置 grant 阻断初次设置。页面可先显示只读数据；钱包业务写入时明确执行“验证以操作”，包括链上详情内的嵌套修复/核对入口。取得原有 60 分钟 grant 后仍由用户重新核对并主动提交，绝不自动重放。grant 到期且 owner 会话已确认有效时仅重新锁住业务写入；网络或权限状态不明、退出、账号切换、会话替换或 owner 变更则清除旧页面资料。管理员首次设置或修改固定操作密码仍按 [ADR-0014](0014-admin-wallet-operation-password.md) 要求核验登录密码、近期登录及适用的旧操作密码。

**替代范围：** 本 ADR 仅替代 [ADR-0064](0064-wallet-access-grant.md) 中“钱包读接口也必须持有 60 分钟 grant”、“验证前不加载敏感钱包数据”及“grant 过期后必须隐藏已渲染只读资料”的读取要求。ADR-0064 的 48 小时后台会话、60 分钟固定 grant、owner/设备/session/family 绑定、写入授权及提交前复核、无自动重放和其余失效规则继续适用。[ADR-0014](0014-admin-wallet-operation-password.md) 的独立固定操作密码、初设/修改凭据和资金命令门槛不变。

### 4. 管理员专属用户目录

新增 `POST /api/v1/admin/users/search` 只读查询，JSON 请求体包含搜索词、每页条数和游标，使完整邮箱或手机号搜索词不出现在 URL 访问日志。接口强制真实管理会话、同源检查及 `SYSTEM_ADMIN`；`AUDIT_VIEW`、`FINANCE_REVIEW`、客服角色和普通 App Bearer 均不能访问。查询审计记录 actor、结果和搜索词摘要，不保存原始联系方式。响应 `Cache-Control: no-store`，不得把密码哈希、完整钱包地址或 Matrix 标识混入结果。

结果涵盖所有账号状态，默认每页 50、最多 100；稳定游标与筛选条件绑定。支持按畅聊号、昵称、邮箱和手机号搜索，返回当前畅聊号、完整已绑定邮箱/手机号及验证状态、账号状态、精确两位小数的点钻余额字符串和当前官方客服头衔。余额由账本模块公开的批量只读接口按本页用户 ID 聚合 CAIBI 分录，未有分录显示 `0.00`；不按用户逐次查询、不用浮点或客户端估算。官方头衔须同时核对当前客服角色与客服资料，不使用用户可编辑的个人后缀或 Matrix 昵称；撤权后不再展示客服头衔。

侧边栏“用户管理”只向管理员显示，进入页面后才请求专用接口；`/admin/context` 不预取上述联系方式和余额。原 `analytics`、`security` 的脱敏响应和客服主管可见范围保持不变。页面采用文本节点显示个人信息，不写入浏览器持久存储或非必要遥测，并提供分页、搜索、刷新及明确的加载、空结果和失败状态。

### 5. 视觉与加载状态

登录页按已确认的“墨夜银锋”方向实现四行原文诗句、深墨与银锋层次和轻量本地动效；表单始终优先可读、可用。无需外部 three.js 资源即可加载认证页。窄屏、键盘操作、屏幕阅读器、焦点管理和减少动效偏好必须覆盖。管理台启动态居中显示品牌图标、动效与“正在加载管理台”状态；失败保留明确重试入口，不让装饰遮挡身份错误或操作反馈。

## 既有决策与边界

- [ADR-0081](0081-support-order-settlement-and-staff-activation.md) 的开通对象必须是现有官方客服、只向已验证绑定通道发码、联系方式或角色变化重新验证、客服订单结算及独立审批边界保留。
- [ADR-0083](0083-staff-console-session-access.md) 的客服日常免验证码、48 小时单设备管理会话、混合管理员只走管理员入口、客服订单无需钱包 grant 与客服不能进入管理员钱包专用功能保留；本次仅给官方钱包负责人开放只读入口。
- [ADR-0055](0055-admin-browser-login-captcha.md) 的管理员图形验证码、原子消费、限频和失败关闭保留；不让客服路径成为管理员验证码旁路。
- [ADR-0014](0014-admin-wallet-operation-password.md) 的钱包固定操作密码独立于登录密码。客服修改共用登录密码不会修改或清除钱包操作密码。
- 当前工作树的 [ADR-0085](0085-profile-visible-character-limits.md) 是昵称和个性签名可见字符限制，本次不改变。账号凭据双渠道改密决策文档在此工作树尚未出现；合并前须核对其确切编号与条款，保留全会话撤销、24 小时提现冷却、审计/Outbox 和 Matrix 密钥边界，不以本文覆盖更严格的既有要求。
- 账本余额只取业务 API 的 CAIBI 权威分录；USDT 与点钻分别保持既有精度。所有资金写入和钱包状态转换继续遵守根 `AGENTS.md` 的受保护变更门槛。

## 风险、回滚与验证门槛

主要风险是首次开通临时密码滞留、客服角色边界误判、改密后旧管理会话残留、恢复挑战或 OTP 与客服改密锁序相反造成死锁、钱包只读豁免误用于写接口、个人资料被较低权限角色读取，以及逐用户余额查询造成数据库负载。以精确错误码、短生命周期内存、服务端实时 RBAC/session 校验、所有受影响的改密与恢复确认流程统一先锁 User 再锁挑战/OTP 并重验、读写路由逐项清单、敏感字段专用响应模型、有限分页和批量账本查询控制这些风险。

实施前须完成本 ADR 审批，并先写失败测试。领域/规格审查先核对上述五项用户验收、旧 ADR 替代范围、账本余额口径和钱包只读/写入清单；其后独立质量/安全审查核对竞态、Cookie/CSRF、限频、数据泄露、缓存、日志、重放、资金不变量与回滚。测试至少覆盖首次及后续开通、身份变化、管理员验证码、客服改密后的 App/后台会话撤销及提现冷却、全角色拒绝、owner 无 grant 可读而钱包业务写入仍拒绝，grant 验证/撤销与操作密码设置沿用自身门槛、grant 到期与会话替换、目录跨页/查询/零余额/撤权及旧接口不泄露。OpenAPI、Worker 事件消费者、前端静态版本、运维说明和验收台账须与实现同步；完整门禁与真实生产证据分别记录。此工作树的 API/Worker 基线早于已经发布的钱包监控 T2 改动，生产候选须以实时镜像为基线保留该精确行为，不能整树覆盖。

生产发布先冻结当前 API、Worker、静态文件及数据库状态，做隔离恢复、候选与回退配置和 SHA 校验，按服务最小范围发布，公开验证健康、授权拒绝和资源加载，不在生产制造资金写入。可回退到保留已发布续期协议的冻结镜像/静态版本并恢复旧钱包读取门槛；已经完成的密码修改、会话撤销、审计和 Outbox 是持久安全事件，不通过回滚抹除。新目录若需停用，撤回专用入口及路由并保留审计；不执行破坏性迁移或删除已有 grant。
