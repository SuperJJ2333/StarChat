# ADR-0059：聊天红包与转账使用独立六位支付密码

状态：Accepted。用户于2026-09-09明确确认方案并要求直接实施及Redmi验证；仍须通过领域和质量安全复核。

决定：采用独立于登录密码、管理员操作密码及钱包TOTP的用户支付凭据。红包发送与聊天转账共用这一凭据，客户端通过六位密码框和三列数字键盘输入；服务端负责设置身份确认、哈希验证、失败锁定和绑定交易意图的短期单次授权。使用各业务公开应用接口协调授权消费及幂等事务，不改变账本公式或分配/转账状态机。

原因：仅客户端输入校验可被直接请求API绕过；复用登录/管理员凭据会混淆身份边界；各业务单独密码会造成重复设置和不一致。

约束：首次设置不直接付款；旧客户端不得绕过新增授权；正式强制启用前必须提供兼容客户端。恢复/回退不得通过关闭服务端支付验证来放行请求。错误尝试持久化且不因财务事务失败回滚。新数据仅做扩展迁移，保留现有安全限制。

完整流程、文件范围、验证和上线边界见 docs/superpowers/specs/2026-09-09-chat-payment-pin-design.md。2026-09-09领域与独立质量/安全代码复核均通过；测试、数据库演练和发布结果记录在本次验证报告中。

兼容期：已配置凭据的账号始终强制验证；`BUSINESS_PAYMENT_PIN_REQUIRE_ALL`默认false只允许尚未登记的旧客户端账号暂按既有规则使用。新客户端所有发送入口必须先设置。全账号切换须先交付兼容正式客户端；该开关不能关闭已登记账号的支付保护。
