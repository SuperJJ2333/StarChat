# 好友发现的精确联系方式与有限畅聊号匹配

状态：用户2026-09-27批准搜索规则及“完整输入末尾两位不同也可匹配”；实施依据。领域与质量/安全审查、具体生产发布仍独立记录。

## 决定

新版客户端通过认证 POST `/api/v1/users/search` 的 JSON `q` 查询三渠道，完整邮箱/手机号不进入 URL 请求行。旧 GET 留给旧客户端的畅聊号、完整邮箱兼容，不新增 GET 手机号发现；旧 POST `/contacts/search-phone` 保持四键公开投影并补统一关系排除。

邮箱采用既有 canonical normalized 完整等值；手机采用既有完整大陆号码规范化、ACTIVE、phone_findable、每账号10次/小时共享配额。所有查询沿用30次/分钟发现配额、排除自己和双向拉黑，不返回邮箱/手机号原值。

候选畅聊号长度 n ∈ [输入长度 m, m+2]，前 n−2 位与输入同长度前缀忽略大小写完全相同，其余输入0–2位可不同。当前完整号优先、最多20项；兼容既有注册号，6–20位仅属于改号规则。历史号归属不可用于公开发现或登录恢复。扫码另作完整号精确选择。

唯一身份和Matrix身份不变。0090只增加非唯一函数索引，筛候选后才聚合相关设备活动；实际PG16查询计划与同名异常索引拒绝验证作为门禁。扩展保留可回退旧API，不执行破坏性downgrade。

## 理由与兼容

原邮箱前缀扩大选择范围；手机的公开组合必须保留隐私、配额和关系限制。用户明确要求缩小结果并允许末尾两位不同。POST避免新版App把联系方式放入默认访问日志。请求体不记录，性能诊断只保留闭合类型/时长/结果，不保存搜索值。

手机号 GET 返回空列表，不能降级到旧无过滤手机号接口；POST未发布时客户端给出真实失败并保留输入，不伪造结果。新服务候选从当前生产镜像作清单内增量，保留其它任务的诊断接收端；本ADR不授权生产切换。
