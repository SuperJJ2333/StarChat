# ADR-0060：共享媒体 ID、内容寻址加密附件与千人群扩容

**状态：** 用户已批准本修订与实施；实施前领域及 Quality/Security 复核见执行记录。生产部署未授权。
**日期：** 2026-09-09
**实施计划：** [九任务实施计划](../superpowers/plans/2026-09-09-content-addressed-media-thousand-member.md)
**记录：** [执行证据](../verification/2026-09-09-media-dedup-implementation.md)

## 背景与已确认决策

用户明确确认“共享 media_id＋独立逻辑引用；按可信内容哈希复用经过校验的缓存”，随后要求开始执行。该确认替代前一版提案要求独立 media_id、热缓存必须验证当前附件信封的过度限制。用户已经接受确定性加密的可链接性与字典猜测风险，无需再次确认。千人群是容量目标，非已经通过的性能结论。

## 决策

1. **固定内容派生协议。** 最终处理后的字节 B，H=SHA-256(B) 的原始 32 字节。HKDF-SHA256：IKM=H，salt=UTF8("chatflow-media-v1")，info=UTF8("aes-256-ctr-v1")，L=48。key=OKM[0:32]；IV=OKM[32:40] 后接 8 个零字节（64 位 nonce、64 位初始零计数器，大端递增）。AES-256-CTR 加密，信封沿用 Matrix v2 key/iv/密文 SHA-256。协议版本字段 v=1。压缩、缩图与方向处理必须先完成；哈希标识最终字节而非视觉相似内容。重试复用生成结果，转发不重复压缩已经接收的附件。
2. **共享 media_id，独立上传者引用。** 密文摘要由服务端流式计算，全局摘要索引指向一个现有 media_id。每个 (media_id,user_id) 记录独立引用及创建/最近上传/删除时间，同一用户重复上传刷新引用而非推断房间消息数量。上传响应仍只有标准 mxc。用户媒体列表、统计与按用户删除按引用处理，不得按首个上传者删除其他用户的引用。引用逻辑删除后 blob 可保留用于重用；重新上传可激活引用。全局管理删除应显式区别于按用户删除，禁止无意删除共享文件。内容隔离作用于整个 blob，不能绕过隔离重传相同摘要。物理清理与新引用必须在同一摘要锁顺序串行：只有无有效引用且达到保留期才可回收。文件/数据库写失败不得发布不可读的 canonical ID。
3. **可信哈希为缓存内容权威。** 仅已成功解密的 Matrix 房间事件可提供 chatflow_media 扩展。主内容字段 content_sha256，缩略图字段 thumbnail_sha256，均为 64 位小写十六进制 SHA-256；未知版本或畸形已声明字段报损坏，缺少扩展走旧路径。命中内容缓存必须校验实际字节 SHA-256，长度 sidecar 不是充分证据。命中后不再下载/解密当前附件，也不要求其 key/iv 与缓存匹配。冷缓存仍经 SDK 密文哈希校验和附件解密，再验证明文哈希后缓存；错误信封可导致热路径成功、冷路径失败，这是内容哈希权威语义的已知结果，不作为泄密结论。内存、磁盘、视频直读和缩略图全部遵守同一哈希校验；保留原 room/event fallback、配额和清理能力。
4. **准确保密边界。** 明文哈希和附件密钥只在加密事件内传送，不进入上传参数、日志、业务 API 或推送。服务端处理的是密文，不能对 E2EE 附件做图片/视频压缩。观察者仍能猜测候选文件并重算密文确认内容、哈希与密钥，也能观察上传/下载身份和时序；不宣称绝对不可推断。SDK 原有密文摘要验证保持，新增明文摘要是额外内容校验。普通管理头像不是 E2EE 附件，不因去重自动变为密文。
5. **独立开关和扩容。** deterministicMediaEncryption 默认开，关闭恢复随机附件密钥；服务端 CHATFLOW_MEDIA_DEDUP 独立控制新去重。关闭开关不删除已产生的映射/引用，补丁镜像保持读取/生命周期兼容。Megolm 默认轮换不变。sync worker、独立 matrix-redis、replication、nginx 路由、邀请限流及关闭 presence 为本次授权的扩容实现。

## 生命周期实施约束

采用追加 schema；旧 media_id 原地保留，不扫描明文或移动旧文件。首次碰到未索引新上传时创建 canonical 行并登记引用；旧媒体逐步纳入与否必须显式记录，不声称存量立即去重。

锁顺序必须统一，数据库唯一摘要约束兜底；并发 loser 的临时文件清理不会删除 winner。跨进程争用必须由数据库协调，进程内锁不能单独作为正确性保障。blob 的全局隔离状态优先于引用激活。回收先锁定确认无引用，再从去重可选集合中移出，使重传不会获取已删除路径；任何失败留下可恢复状态而非假成功。

共享 media_id 的响应级 MIME/文件名使用 canonical 元数据；聊天展示应以加密事件的每事件元数据为准。上传者引用保存必要审计/配额信息，不记录明文摘要。引用代表上传者对媒体的持有，不伪称引用等于消息数，也不从 Matrix 加密消息猜测红删数量。

## 回退与兼容

旧事件无扩展，继续按随机信封解密。新事件保留标准 v2，旧客户端可以按信封读取但不执行新增明文哈希检查；需实测，不以结构相同替代互通证据。客户端关开关不能撤销旧文件的可链接性。

磁盘新内容缓存位于 chat-media/content/<hash>（播放可原地增加容器扩展），旧 room/event 缓存保持可读；LRU 同时覆盖两类。只有校验后才能提升旧缓存，损坏缓存按 miss 重拉，错误下载不得落盘。

服务器回退关闭新去重并保留补丁读/引用管理。禁止直接换回忽略引用模型的旧镜像做清理。Worker 回退先路由主进程并确认 /sync，再停 worker；主进程仍启用 Redis 时不能先停 Redis。

## 被否决方案

仅客户端去重不能满足跨用户服务器单副本；将明文哈希交服务器违反主动暴露边界；不登记引用直接复用 ID 无法安全按用户删除；只信路径/.len 无法发现同长度损坏；扩大 Megolm 轮换窗与服务器压缩密文均不采用。

## 审批与验证

本 ADR 的用户授权不代替实施前领域/质量安全复核与实现后测试。先规格、后质量安全评审。代码采用测试先行，覆盖派生独立向量、预处理、随机回退、缩略图、热缓存零下载、损坏拒绝、跨用户引用删除/重用、并发/隔离、关开关兼容。容量记录必须区分 200–500 VU 实测与未来 1000 成员 E2EE 验证，不能把 8/31 待切换实施包写成已验证 worker。生产部署、全量千人压测、联邦集群和先问后传协议仍不在本次范围。
