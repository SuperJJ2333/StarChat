# ADR：管理员专属提现、汇率预览与安全取消

状态：提议，待用户批准及 Domain、Quality/Security 设计评审。
日期：2026-09-30

## 背景

用户确认充值与提现一致展示、提现仅管理员操作、按充值口径调整汇率，并确认只有从未签名、从未广播才可撤销退款。历史客服提现授权需要收紧；链上暂无到账不构成退款证据。

## 决策

1. 后台提现专属鉴权要求有效 SUPER_ADMIN、配置中的官方钱包负责人和既有钱包资金鉴权。充值使用的财务客服鉴权保持原策略。限制覆盖路由、应用服务、领域入口和事务提交前验证。
2. 点钻本金除以最终点钻/USDT 汇率，Decimal ROUND_HALF_UP 到 6 位 USDT。快捷按钮相对有效基准汇率，不累乘。实际付款指令生成后禁止调价。
3. 未执行 REQUESTED 订单由管理员取消；已领取/未知但确认从未签名、从未广播按现有 VOIDED 预检、声明和独立证明处理。复用原子冻结/兑换冲回，不删除账本历史。
4. 已签名、已广播、存在候选哈希或不能确认广播时仅停止本单处理并进入复核，不退款。持续链上核验，合法到账仍可结算。
5. 未执行的旧客服领取由负责人明确接管并撤销租约；已执行旧单只能复核，不重付。自动监控不依赖客服权限。
6. 不新增全局暂停，不自动恢复历史暂停；不改变用户本人申请和既有未处理取消接口。保留旧客户端终态投影及现有审核要求。

## 替代方案与后果

- 只隐藏按钮：不能阻止旧客服会话调用接口，拒绝采用。
- 尚未监控到账即退款：延迟到账可导致重复付款，拒绝采用。
- 任意 SUPER_ADMIN 均可出款：超出当前官方负责人约束，本轮不扩大托管操作主体。
- 复用既有引擎并增加提现专属授权：范围较小、账本逻辑一致，但必须证明旧单接管、延迟链上到账和权限撤销并发安全。
