# ADR-0085：昵称与个性签名按可见字符限制

**状态：** 已批准（用户明确需求、领域与 Quality/Security 复审）
**日期：** 2026-09-24
**依据：** 用户本轮明确要求昵称最多 12、个性签名最多 20 个用户可见字符，组合 emoji 算 1，并要求输入和提交双重校验。

## 背景与受保护变更

现有 Flutter 编辑页无长度限制；资料 API、注册 API、Identity 服务和 `users` 列按 Unicode code point 限制昵称 64、签名 140。12 个家庭 emoji 可占 84 个 code point，20 个组合 emoji 可占约 200 个 code point，原列宽会拒绝满足用户可见字符规则的值。收紧资料/注册输入并更新 OpenAPI 是有意的兼容性变更，按根 `AGENTS.md` 的 breaking OpenAPI 规则需要本 ADR、领域及 Quality/Security 复审。

## 决策

1. 在 Flutter 用 Dart `characters`，在服务端用明确锁定版本的 Unicode extended grapheme cluster 分段库，按编辑完成并 trim 后的字素簇计数。昵称允许 1–12 个，签名允许 0–20 个。中文、拉丁文、数字、标点和单个 emoji 各计 1；ZWJ/肤色/旗帜等组合 emoji 依 Unicode 字素边界计 1。
2. Flutter 输入实时显示 `n/12`、`n/20`。超限输入被拒绝或截断至字素边界，显示可关闭的精确提示；客户端保存前再次校验**实际改动的字段**，只提交这些字段。服务端独立复验，超限返回字段明确的 422，不能因直接调用 API 而保存成功。
3. 所有可写入口共用同一服务端规则：个人资料 PATCH、`/auth/register` 的邮箱/手机号注册资格预检与实际注册。显式非空的超限昵称被拒绝；缺省、`null` 与显式空串 `""` 继续兼容现有 username 默认昵称，但默认值仅取前 12 个字素；纯空格昵称仍返回 422。资料 PATCH 的 `null`、空串和纯空格昵称都继续拒绝。预检、真正注册、幂等请求指纹使用一致的规范化结果。另一条 OTP 自动开户入口 `create_verified_phone_in_session` 的固定昵称为 `畅聊用户`+手机号末 4 位（8 字素），以测试守住上限。
4. 将 `users.nickname` 与 `users.signature` 以 `0088` 扩展为 PostgreSQL `TEXT`，升级不删除或改写任何既有值。历史上已保存的较长值继续读取和展示；只校验本次提交的字段，不能让无关资料更新被老值阻断。客户端只发送用户实际编辑过的字段；旧长昵称未编辑时不阻碍签名/头像更新，用户主动编辑超过新限制的字段时必须缩短才能保存。
5. 对 API 文本另保留宽松的 **512 code point** 原始输入资源上限，防止 25 MB 网关请求承载极长单字素。服务端随后严格校验 12/20 字素，因而 12 个家庭 emoji（84 code point）和 20 个复杂 emoji（约 200 code point）都能通过。OpenAPI 标准 `maxLength: 512` 标明其为原始码点安全边界，字段 description 与 `x-graphemeMaxLength: 12/20` 标明用户可见字素上限和 422。旧客户端显式提交超限值会收到明确错误，此行为变化由本次用户需求授权。公开畅聊号、金融身份、Matrix 用户 ID 均不因昵称截断或字段扩容而改变。
6. 跨版本重试只允许**旧版已提交完成**的资料/注册请求，以同一 actor 或注册作用域、同一 Idempotency-Key 和按旧规则计算的精确 payload hash 只读回放既有结果。检查在新长度校验前，但不能用旧规则发起新的写入；同 key 不同 payload 仍冲突，新 key 超限仍 422。新规则下的预检、实际注册和幂等指纹使用同一新规范化值。

## 兼容、发布与回退

- 先执行仅扩展列的迁移，再发布新 API；旧服务读取扩展列不会丢失现有资料。Flutter 更新可随后安装。
- 回退应用二进制时保留扩展后的列。若必须收缩列，迁移 downgrade 先检查是否存在超过旧 64/140 code point 的值；存在即明确失败并要求从备份恢复/人工处理，绝不截断。
- 如需回退到旧服务处理仍符合新字素但超过旧 code-point 长度的值，保留扩展列并阻止旧服务改写这些字段；先修复应用兼容性再考虑缩列。
- 不改登录鉴权、RBAC、TOTP、Matrix E2EE、账本或资金逻辑；日志不记录个人资料正文。生产前用隔离恢复的数据库演练迁移与回退，核对行数/摘要和其他模块无漂移。

## 验证与审查

- API 测试：12/20 个组合 emoji 接受，13/21 拒绝；注册预检与提交一致，显式超限拒绝、缺省/空串昵称按 12 字素派生、纯空格拒绝、OTP 固定昵称合规；新规则下有效请求的幂等重试稳定；旧版已完成请求同 actor/scope/key/hash 只读回放、不同 payload 冲突、新 key 超限拒绝，且不重复邀请消费/审计/Outbox；只提交签名/头像不受旧长昵称阻断。
- Flutter 测试：实时计数、粘贴截断、输入法组合、弹窗关闭后继续编辑、提交前复验及失败草稿保留。
- 迁移测试：旧数据保留；新大于旧列宽值可保存；危险 downgrade 拒绝；无超长值可回退。
- **领域复审：** `/root/delivery_audit` 于 2026-09-24 检查注册/资料/OTP 三条写入路径、生产旧列宽和既有幂等路径，提出空串、旧值、精确旧 COMPLETED 回放和 512 原始码点资源边界；上述条款已据此修订。
- **Quality/Security 复审：** `/root` 于 2026-09-24 核对了强制服务端校验、512 原始输入资源界、旧回放仅已完成且 actor/scope/key/hash 全匹配、新写不得绕过、迁移不截断、无敏感资料日志和不触碰 E2EE/资金。决定以本 ADR 实施，并在代码完成后复审查询/事务与迁移演练证据。
