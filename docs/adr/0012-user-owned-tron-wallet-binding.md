# ADR-0012：用户自有TRON钱包绑定、30天改绑与10USDT门槛

**日期：** 2026-09-07。
**状态：** 用户明确要求的架构修订，目标设计已记录；充值/提现资金路径已获用户明确确认，实施及生产启用未完成。

## 决策

后续第一版来源与签名策略已由用户修订为 [ADR-0013](0013-trongrid-single-source-manual-payout.md)：TronGrid 单源核验、imToken 人工签名提现。下文独立双源要求由该决策在明确范围内替代，其余归属、金额、审批和审计规则保留。

1. 移除平台生成用户充值地址、分层钱包/地址池和用户地址自动归集。绑定用户自己掌管并能证明控制权的TRON钱包；不收集私钥或助记词。
2. 一个用户一个有效钱包；同一地址不得跨用户复用。通过一次性消息签名挑战证明控制权，改绑保留不可变历史和订单绑定版本。
3. 采用滚动30×24小时：首次绑定不计改绑；首次成功改绑后，至少30天才能再次成功改绑。并发、幂等、解绑重绑均不能绕过。
4. 充值单条实际USDT转入至少10.000000；提现到账本金至少10.000000，费用单列加计。小额链上到账保留待处理记录，不销毁证据或记作收入。
5. 使用TronGrid监控流水。它是发现/查询源，不是签名器，也不自动满足现有独立双源最终性条件。
6. 已确认资金路径：绑定钱包主动转入官方统一钱包；提现仅转回订单锁定的绑定钱包。用户已确认该路径；完成代码与安全验收前不开放真实入账或付款。

## 与旧ADR的关系

替代ADR-0010的“必须为每用户分配平台专属地址”和自动归集结构；其拒绝“共用地址仅凭金额/时间/txid认领”的安全理由继续成立，新方案以事前控制权验证、独占绑定、充值意图及链上来源匹配处理归属。

官方钱包若实际持有用户充值资金，仍须独立受控签名、审批、储备和恢复；取消地址层级不取消这些要求。ADR-0010中复式账本、资产精度、USDT与点钻兑换不变量、幂等、未知订单恢复及资金关闭门禁保留。ADR-0011只读服务继续运行，不因此升级为自动入账服务。

详细方案见[用户自有钱包设计](../superpowers/specs/2026-09-07-user-owned-tron-wallet-design.md)。本次只修改文档，不修改生产服务或钱包金额配置。
