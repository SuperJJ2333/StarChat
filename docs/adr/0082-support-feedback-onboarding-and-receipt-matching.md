# ADR-0082：绑定钱包自动匹配与邀请码手机开通

- 日期：2026-09-23。
- 状态：用户已确认规则；实现及发布结论以本批验证记录为准。
- 承接 ADR-0081 和本批 support-feedback 计划，不改变账本公式、独立审批或资金凭证最终确认规则。

## 已确认的行为

1. 用户仅填写充值金额，从 APP 已绑定钱包向官方地址转账，无需填写交易凭证。已有观察器记录不可变到账事实，公开钱包接口验证付款区块时生效的地址归属；充值域仅关联唯一用户、金额、时间窗口对应的订单。金额不符、取消冲突、多订单歧义及迟到账保留核对，不猜测归属，也不自动发点钻。
2. 关联前后均重验订单；数据库资金锁、订单锁及凭证唯一约束保护多 worker 并发。网络最终确认在短事务外。关联审计和 Outbox 与订单投影一起提交。真正发币仍使用现有公开财务执行服务；凭证消费及平衡账本原子提交。
3. 已入账未登记由既有登记流程恢复，不重复消费付款凭证；链上服务暂不可用不阻塞已执行结果登记和到期处理。客服结算时按需更新确认凭证；超时不推断付款失败。
4. 后台本次加载获取缓存优先的汇率快照，展示估算、更新时间及过期状态；±1%/±5%始终基于本次显示基准，不累加。实际到账金额与最终人工结算率决定点钻数，独立审批及执行权限保留。用户端参考不是到账承诺。
5. 手机号验证码登录的新用户仍必须提供邀请码和同意条款。先验证短信，再通过既有注册服务原子消耗邀请码、创建账号及 Matrix 开通 Outbox。公开用户名采用不可逆派生，不暴露完整手机号，不生成可猜密码。已有封禁账号不被重建。
6. Matrix 开通等待使用短期随机、设备绑定、单次消费的登录续办票据；只存摘要。等待状态不伪装登录完成；成功后沿用双域会话写入和取消纪律。票据结果丢失时重新认证，不声称可任意重放。
7. 提现保留最低实际 10 USDT；不满足时复用 Toast 中文提示。只有明确金额拒绝才丢弃旧报价，未知网络结果保留原幂等键和金额，避免重复冻结。
8. 邮箱验证码使用专用邮件契约和模板；不得以钱包告警事件代替验证码，钱包告警的事件、严重级别约束保持。

## 验证与回退

本批无新增数据库结构。规格审查先于质量与安全复审；验证 OTP/邀请码/票据并发、双域登录、真实邮件适配器替身、到账归属/重复/并发/网络失败/执行后恢复。生产仅替换本批服务及静态资源，不修改资金或伪造会话。旧镜像和静态文件保留用于回退；已经形成的订单、审计和账本事实不回滚删除。
