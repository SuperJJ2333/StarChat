# ADR-0070：充值自动兑换点钻与已入账收据补兑换

日期：2026-09-13。业务决策已由本轮用户明确批准：CAIBI/USDT 双向 1:1，充值后自动转点钻，另为明确的两张已入账收据补兑换。实现领域与质量安全审查按任务计划记录，未通过不得发布。

沿用 ADR-0010 的固定比例、免手续费、两账本各自平衡和 0.01 兑换步长；沿用 ADR-0056 当前生产 manual_liquidity，保留暂停、账户限制、新鲜储备与真实出款边界。根 AGENTS 已更新兑换许可。此前“尚无兑换实现”的对话判断不完整：现有 production conversions_enabled=true，缺口是充值自动衔接。

1. 引入显式默认关闭的充值自动兑换开关；开启必须同时允许兑换。在三个现有收据入账路径（自动、普通修复、窗口外人工补录）中调用同一钱包公共应用方法，与充值信用写入同一事务；失败全回滚，不出现充值显示成功但点钻未发的半完成状态。
2. 复用 WalletConversion 和既有 convert_in_session，不改账本 schema。每张收据固定键 `deposit-receipt:<receipt_id>`，用户归属只能来自已 CREDITED 收据和相符的原 USDT 账本，不接受任意受益用户或金额。不可篡改或重新入账旧收据。
3. 按 ROUND_DOWN 截至两位小数兑换，残余六位小数继续留在用户 USDT 余额。USDT 减少与 CAIBI 增加精确等值；不能向上取整、透支、挪用 HOLD、额外赠送或对已兑换键重复发放。
4. 记录原收据、原充值账本、兑换编号及关联两资产账本的证据；操作者使用实际触发主体（worker/管理员），不能将管理员行为伪装为用户操作。每笔兑换保留审计和 Outbox。用户主动双向兑换保留现有接口和恢复规则。
5. 历史补兑换使用同一公共方法及专门受控运维入口，仅允许用户明确指定的两笔 txid/log_index=0；读取真实已入账用户/金额、兑换标识与可用余额后冻结执行清单。预检与执行分开；提交重新验证数据和资金门禁。两笔在一个事务中完成，可重复查询/重试原固定键，无重复余额。此次用户明确授权实际兑换，不自动扩展到其他历史充值。
6. 不新增 USDT P2P/红包，不调整汇率或提现手续费；不改已有提现的点钻来源/取消冲正，不减弱 E2EE、个推或其他任务改动。

实施前领域复核（Astra，2026-09-13）：采用 Terra C1 的命名空间与实际操作者意见。公共用户兑换服务必须拒绝保留前缀 `deposit-receipt:`，防止用户抢占自动兑换键。自动兑换失败回滚 CREDITED 状态及充值/兑换分录，但已经确认的链上收据事实必须保留 REVIEW/pending，供后续正常重试；原事务边界与嵌套 savepoint 需实测。历史两笔使用一个外层事务并非与每收据固定幂等矛盾：按固定顺序锁定并逐项调用同一方法，整体提交或整体回滚，重试逐个校验原键。每收据单独原子性仍成立。计划领域方向批准实施，质量安全验收后才准生产发布。

生产上线采用当前镜像最小覆盖并分别核对 API/worker。不因为旧工作区完整构建替换其他已发布代码。回退保留已执行兑换与账本，只关闭新自动衔接并回退代码；资金纠错必须关联冲正。
