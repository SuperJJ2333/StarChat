# ADR-0085：账号联系方式与双渠道验证码更换密码

日期：2026-09-26。状态：**已批准**，依据用户审阅 HTML demo 后明确回复“没有问题，请你正式实现”。批准范围为四项需求的正式实现和隔离验证；不含生产发布、真实短信/邮件发送或真实账号修改。

## 背景与替代关系

用户要求设置按账号/通用分组，账号安全支持手机与邮箱绑定更换、登录密码修改；登录提供忘记密码，使用**事先成功绑定且验证过**的邮箱或大陆手机号验证码。批准设计为 `docs/superpowers/specs/2026-09-26-account-ui-review-design.md`，批准 HTML SHA 为 `b0a20fba79dcd11845fa57aabb52696c6606553167f80719cee063abeffce45e`。

本 ADR 仅替代 ADR-0075 中“手机号不参与密码找回”的范围限制，保留其归一化、供应商校验、用途绑定、限频、单次消费等安全决策。旧邮箱找回链接与其 `/auth/password/forgot`、`/auth/password/reset` 协议继续兼容。

## 决策

1. **双渠道恢复**：仅 ACTIVE 账号当前绑定的 verified 邮箱/手机号可签发密码恢复 OTP。手机号按已有中国大陆标准归一化，邮箱按现有注册规范处理。未知、未绑定、未验证、冻结等请求使用相同受理反馈；不能注册账号、补写 verified 状态或泄露绑定关系。
2. **真正两步**：`code/request` 请求验证码，`code/verify` 消费正确验证码并在同一事务产生 5 分钟恢复证明，`code/reset` 单次消费证明后设置新密码。证明为高熵不透明随机值，库内仅存哈希，绑定 user、channel 与当时联系方式。可复用 `OtpChallenge` 存证明，无需扩展金融或身份表结构。
3. **验证边界**：验证码用途按邮件/手机密码恢复及邮箱换绑阶段隔离，沿用5分钟有效期、5次尝试、供应商故障不耗次数、单次原子消费、目标限频和IP限流。新的邮箱用途必须使用邮件通道，不调用 SMS 供应商；邮箱功能不依赖 SMS 开关。发送超时保留冷却，不自动重发或谎称未发送。
4. **绑定事实复查**：发码、验证、消费恢复证明各阶段检查当前用户及 verified 目标；目标换绑、账号停用或已消费后拒绝旧证明。已登录入口提交的验证码流程必须限制为当前账号，不能把当前会话误作其他账号的授权。
5. **邮箱绑定/换绑**：已绑定邮箱先验证旧邮箱；纯手机账号先验证既有且 verified 的手机；随后验证新邮箱，原渠道证明短时且单次使用，新邮箱唯一性与并发更新在事务中保证。邮箱完成前不作为找回渠道，旧邮箱不可用走客服帮助。复用现有手机换绑页和服务，不重新发明手机协议。
6. **改密后效果**：密码策略继续12–256位；保持既有全部业务 refresh family 撤销与24小时提现冷却。通过身份模块公开应用接口和同事务 Outbox/审计记录修改，不直接写其他模块表。旧链接 reset 行为与 Matrix 登录令牌编排不回退。
7. **E2EE**：仅恢复登录权。服务端不获得或重置用户聊天密钥/恢复密钥；客户端成功后通过既有账号生命周期撤销登录状态并保留本地历史，避免继续使用已失效会话。
8. **信息与运维边界**：不记录密码、验证码、证明令牌、完整联系方式。UI展示脱敏绑定状态；错误使用稳定代码和通用文案。依赖和生产开关不放宽，无真实验证码发送或生产数据操作。本轮不做破坏性迁移。
9. **匿名受理与投递**：新的匿名改密请求不等待外部邮件或短信供应商；OTP 与仅含挑战 ID 的投递 Outbox 原子落库，由 worker 再核对当前绑定和验证快照。未就绪或投递失败的挑战不可验证，迟到投递不得重新激活换绑后已失效的挑战；重放事件不得重复发送。匿名验证码错误、过期、未知目标与供应商校验故障使用同一公开失败响应，供应商故障不扣尝试数。
10. **可选鉴权的精确定义**：仅完全没有 Authorization 请求头时允许匿名流程；空值、非 Bearer、无效或过期令牌均为401。已登录流程固定发起时的身份，不重试为匿名。客户端迟到成功只撤销对应旧会话，不能清除期间登录的新会话。同登录 family 的可信 refresh 仍属于原会话；仅 API 的刷新持久化/确认读回可推进在途请求的会话谱系，手工写入或新登录不被认作可信刷新。出站 Bearer 保持固定，不因此重发验证码请求。
11. **验证的统一等待窗口**：新的匿名/已登录验证码验证端点使用同一5秒响应窗口，内部执行截止提前留出收尾时间；异步等待，不占用同步线程睡眠。仅新的恢复流程传入单调时钟 deadline，外部校验前后、扣尝试/消费、生成证明和事务提交前检查；PostgreSQL锁等待及语句使用剩余预算。超预算使用统一失败，不因取消等待而让迟到校验继续消费验证码或创建证明。拿锁及供应商返回后另用当前UTC复查验证码/证明有效期，不能沿用锁前时间。客户端8秒预算留出传输余量，旧认证协议不更改。

## 接口与兼容

- 新 `/auth/password/code/request`：`{channel: email|phone, target}` → 202 `{accepted: true, resend_after_seconds: 60}`。
- 新 `/auth/password/code/verify`：`{channel, target, code}` → `{reset_token, expires_in: 300}`。
- 新 `/auth/password/code/reset`：`{token, new_password}` → 204。
- 邮箱换绑：已登录 `/auth/email/rebind/old-request`、`old-confirm`、`new-request`、`confirm`，请求/响应沿用手机换绑风格；摘要由授权接口返回脱敏已验证绑定状态。
- OpenAPI 必须同步导出；Flutter/HTML 两条改密入口共用页面与公开 gateway。审阅控件和演示 OTP 不进入正式客户端。

## 验收与审查

领域审查先检查需求、用途/目标/当前用户绑定、单次消费和恢复效果；质量/安全审查随后检查并发、限频、枚举、日志、异步回调、生命周期与 E2EE。测试须涵盖邮箱与手机号、未绑定/未验证/非ACTIVE、错误/过期/重放、目标变更、用户越权、供应商失败、唯一性竞争、旧协议兼容、审计与Outbox和撤销/提现冷却。完成后记录真实命令、退出码和候选 SHA，不以 demo 通过代替真实服务与设备验证。
