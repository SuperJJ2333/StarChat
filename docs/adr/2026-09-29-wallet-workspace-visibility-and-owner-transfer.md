# 钱包工作台只读视图保持与所有者转出申报输入 ADR

- 日期：2026-09-29。
- 状态：**已获用户批准实施（2026-09-29）**。用户先批准[书面规格](../superpowers/specs/2026-09-29-wallet-workspace-polish-design.md)，要求去除所有者转出申报的日志序号输入、将原因码和用途说明合为单选，随后明确批准按本 ADR 与实施计划执行。领域和独立质量/安全审查仍按根 `AGENTS.md` 完成。
- 范围：官方钱包负责人管理台的只读页面生命周期、链上视图在当前管理会话内的保持、所有者转出申报的预检输入和后台用途选择。监视器 `PROTOCOL_PROBE_FAILED` 的故障治理另行处理。

## 背景

已发布的[管理台入口 ADR](2026-09-28-admin-entry-merge.md)允许有效官方钱包负责人管理会话读取逐项列明的只读钱包接口，无须先获取 60 分钟 wallet grant；资金、事故和 POST 预检仍须该 grant。当前前端在焦点/可见性回查时先锁定访问状态并销毁钱包内容，在切换后台菜单时也销毁链上面板，导致已授权的流水筛选、页码、滚动和详情消失，返回时重新取数。钱包顶端的通用“先验证”横幅又将只读浏览误写成进入页面的条件。

[ADR-0071](0071-manual-wallet-owner-transfer-declaration.md)要求以精确的 `(txid, log_index)` 匹配一笔已发生的所有者链上转出，以该键持久去重和对账。日志序号有不可删除的内部作用，但管理员不应在申报表单猜测它，尤其不能默认填 `0`。当前表单还让管理员分别填写原因码和用途说明，表达同一业务选择。

## 决策

### 1. 钱包只读页面与授权状态分开管理

删除只读页面顶部“当前可查看钱包资料。资金和事故操作需要先验证。”横幅及其按钮；具体资金、事故和预检操作被用户点击时，仍进入现有“验证以操作”流程。取得 grant 后原命令须由管理员再次主动提交，不自动重放。

浏览器重新获得焦点、标签页重新可见、跨标签页身份变动时，先阻止所有写操作并遮蔽已渲染敏感字段，保留非敏感页面框架、筛选位置与链上 DOM。链上详情、事故详情、修复及嵌套补录对话框实际挂在 `document.body`，须在这类主动回查开始时一并关闭；写入草稿清除，只读链上详情仅在内存保留已经取得的数据，同一会话 owner 核验成功后再恢复，不让旧异步响应重开弹窗。只有服务端再次确认同一管理会话及官方钱包负责人只读授权后，才解除遮蔽；回查成功本身不重新请求链上列表。已确认会话在页面持续可见时的现有 30 秒背景轮询不先遮蔽或关闭详情，避免定时闪隐；在途禁用写操作，返回失权、会话变化或网络未知时立即清除敏感内容。确认有效的 owner 会话仅发生 `ready -> verify`（写 grant 到期）时，锁住写操作，继续保留并显示只读数据。401、会话替换、账号或 owner 变化、权限撤销，以及网络或授权结果不明时，清除敏感 DOM 与链上快照并拒绝操作。回查并发须去重或以版本号丢弃过时成功结果，不允许旧响应在撤权后回填页面。

后台菜单切换时，仅在当前 `createAdminShell` 实例和同一后台管理会话身份下，保存一份**有界内存中的链上只读快照**：筛选草稿与已应用条件、offset、服务端 snapshot、最多一页 25 条列表及摘要、页面/表格滚动位置，以及最多一个已打开详情和其已取得的只读字段。快照在关闭详情模态及销毁面板之前取得；菜单离开时关闭模态和任何资金修复对话框，清除凭据与未提交写草稿。返回前由服务端重新核对当前管理会话及 owner 授权，等待时仅显示非敏感框架；成功后恢复链上现场并明确标示“本页缓存于”的时间，不自动调用链上列表接口。该时间不得冒充观察器最近成功扫描时间，用户可显式刷新。失权、未知、退出、页面刷新、会话或账号切换即丢弃快照。不得把新快照、密码/TOTP 或未提交写草稿放入 `localStorage`、`sessionStorage`、URL 或日志；已有 `operationJournal` 的在途请求元数据及幂等键保持原规则，返回后只查询原请求结果，不自动重新执行。

这只是展示生命周期的决定。服务端逐请求的 GET/HEAD 只读允许清单、`Cache-Control: no-store`、48 小时管理会话、60 分钟写 grant 与提交前授权复核不变。客户端缓存、隐藏状态和按钮可见性都不是授权凭据。未来新增钱包路由默认仍受 grant 保护，须另行审查才能进入只读清单。

### 2. 管理员选择用途，服务端精确定位链上事件

申报表单保留交易哈希和所有权声明，把“日志序号、原因码、用途说明”三个输入换成**一个必选、无默认值的用途单选**。首批业务用途为“钱包测试转出”→ `OWNER_TEST_DRAW`，固定说明“官方钱包持有人测试转出”；“对外付款”→ `OWNER_EXTERNAL_PAYMENT`，固定说明“官方钱包持有人对外付款”。不提供含义不清的“其他”。管理员选择决定提交的稳定原因码和说明，服务端仍分别保存、审计两字段；对直接使用现有 API 的调用者，原原因码格式与说明输入继续兼容。

`POST /wallet/manual/owner-transfers/preview` 的请求可省略 `log_index`，已有显式 `log_index` 的请求继续受理。参数形状校验后，预检须先完成官方负责人、当前 ADMIN 管理入口、wallet grant 及资金预算锁等既有门槛，才读取新鲜 TronGrid 证据；未授权调用不可借自动定位探测链上资料。仅当该交易中恰好存在**一笔**从配置的官方地址转出的 USDT Transfer 时，服务端自动解析其真实 `log_index`，随后沿用 ADR-0071 的 VERIFIED 覆盖事实、金额/地址一致、未被出款事件占用、未重复申报等检查。零笔或多笔时不得猜测、取首条或默认 `0`；返回明确的不可自动定位结果。

多笔事件时，管理员可在官方钱包链上流水按完整哈希查找，打开具体行详情，结合真实金额、目标地址与时间选择一笔；该受控行携带内部 `log_index` 到原预检接口，但申报表单没有可编辑的序号字段。链上只读观察记录尚未覆盖候选、候选无法安全区分或链上/覆盖证据冲突时，停止提交并提示核查，不通过仅凭金额或页面推断来选取事件。链上观察查询仍是只读辅助，最终选择必须由预检使用新鲜证据验证。

成功预检向管理员显示将申报的真实收款地址、精确六位 USDT 金额、缩略交易哈希及所选用途，等待明确的第二次确认。确认按钮复用当前 wallet grant 与写操作串行锁，双击只发一条执行请求。执行继续调用现有 `POST /wallet/manual/owner-transfers`，**必须**携带预检得出的精确 `log_index`；服务端在执行事务中重新取得证据并复核授权、覆盖、金额、地址、唯一性和状态。预检后相关事实发生冲突时拒绝，而不默默改选其他日志。既有 `(txid, log_index)` 唯一约束、`owner-transfer:<txid>:<log_index>` **账本**幂等键、平衡 USDT 分录、不可变申报、操作者/原因审计、Outbox、事故复核与资金恢复的独立步骤保持不变。预检本身不得生成申报、账本或可当作付款事实的记录。

申报执行前在现有 `operationJournal` 留一个按管理员账号隔离的待确认槽位，仅记录交易哈希、服务端预检给出的内部索引、用途原因码及随机 HTTP 幂等键；固定用途说明由原因码映射获得，密码、TOTP、地址、金额和写入草稿不落浏览器存储。原请求结果未知时阻止另一笔申报，先用 `GET /wallet/manual/owner-transfers/{txid}` 只认同一索引、原因码/固定说明与操作者全部匹配的记录；同一哈希的其他日志事件不算本次成功。未证实成功不得自动重发；如管理员明确重试，复用原请求参数和 HTTP 键，服务端仍以原精确链上键复核。该 HTTP 键与上述账本幂等键用途不同，不可混同。

执行接口和已有客户端请求体保持原必填 `log_index`；本次仅对预检新增可选字段，不删除、重命名或放宽执行键。更新 OpenAPI、管理台、[事故恢复手册](../runbooks/wallet-incident-recovery.md)和兼容测试。不需要数据库迁移，不修改出款订单状态机、监控覆盖匹配、用户负债或实际签名/出款能力。

## 取舍与既有 ADR 的关系

保留链上视图能免去菜单往返和焦点回查时的重复取数，但授权撤销与未知状态需要立即清除敏感内容；因此限定当前页面内存、单页上限、服务端返回前遮蔽、失权清除和旧响应隔离。链上缓存是上次读取的记录，绝不能展示为实时扫描或可用余额。显示哈希中段遮蔽仅是呈现方式，复制与精确检索仍用原始完整值，不能在提示文本或日志泄露完整地址和凭据。

本 ADR 细化[管理台入口 ADR](2026-09-28-admin-entry-merge.md)已经批准的 owner 只读豁免与“grant 到期仍可读、未知时清除”规则，不再扩大只读接口或角色。它继续以该 ADR 明确的替代范围覆盖 [ADR-0064](0064-wallet-access-grant.md) 对钱包读取必须持有 grant、grant 到期必须清除只读资料的旧要求；ADR-0064 其余 session、grant 和资金写规则继续生效。本 ADR 仅扩展 [ADR-0071](0071-manual-wallet-owner-transfer-declaration.md) 的**预检输入**与后台表单；ADR-0071 的精确链上键、账本和监控匹配、不可变审计、事故/恢复门槛不变。不会把所有者转出误记为人工出款订单；链上流水的“未关联出款订单”也不能据此判断所有者转出是否已经申报，更不会因链上流水已可查看而解除暂停。

## 验证、发布与回滚

实施须按[规格](../superpowers/specs/2026-09-29-wallet-workspace-polish-design.md)与获批实施计划先写失败测试，覆盖失焦回查成功/未知、全部脱离页面 DOM 的只读/写入对话框、grant 到期、菜单返回、筛选草稿与应用值、分页/滚动/详情、owner 或会话替换、并发旧响应、完整复制与失败反馈；单独覆盖预检唯一非零 `log_index`、零/多笔歧义与受控候选、授权先于证据读取、用途映射、旧显式索引请求兼容、预检无资金写、执行重验及幂等。专项门禁、OpenAPI、前端契约和现行完整相关门禁通过后，先做领域/规格审查，再做独立质量/安全审查，重点核对只读/写入清单、缓存残留、会话竞态、候选错选、金额精度、审计与回退。

发布前冻结生产 API、Worker、静态包、Compose 与 schema，核对当前版本和已发布的续期协议保护；以最小文件清单构建 API/静态候选，隔离验证兼容与回退，保留原 Worker 和钱包状态机。生产核验以真实静态资源哈希、API 结构化健康、未授权拒绝、会话撤权和无新错误为证据；HTML 200 或视觉稿不是功能上线证据，不在生产制造资金写入。若发生权限泄露、错误事件选择或协议异常，先撤回新静态包并切换已验证的兼容 API 回退镜像；保留既有申报、账本、审计和 Outbox，不做破坏性迁移或数据回写。旧显式索引请求在候选和回退中都可用，回退后界面恢复原提交方式；既有未结事故仍按事故恢复手册处理。
