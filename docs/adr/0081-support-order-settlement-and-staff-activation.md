# ADR-0081：客服异步订单、到账凭证与独立结算审批

- 日期：2026-09-23。
- 状态：按用户已批准的客服订单设计实施；发布须以本批验证记录为准。
- 设计：`../superpowers/specs/2026-09-23-support-order-workflow-design.md`。
- 用户最新确认：预估金额优先展示；实际充值点钻和提现 USDT 以客服结算为准。

## 决策

1. 沿用 RechargeRequest 和 ManualPayout，不创建第二套余额。充值申请、认领、参考汇率和用户提交凭证均不能使余额变化。预估率不自动成为结算率。
2. 新充值订单保存官方收款配置快照和两小时截止时间。真实链上成功、最终确认、合约、网络、收款地址、归属和实际金额由现有钱包凭证服务核实。第三方代付或归属不足保留待核对，不能仅按金额和时间匹配发币。
3. 凭证预留与旧自动入账、修复、人工到账案件互斥；在同一事务消费凭证、减少待归属 USDT 义务并写入平衡 CAIBI 账本。登记失败由既有 worker 恢复，登记本身不发币。PostgreSQL 和 ORM 不可变守卫共同保留旧凭证约束。
4. 新的订单专用财务申请只能从已锁定且已核实订单派生收款用户和正数金额，不接收任意用户或调账金额。客服确认最终结算率后仍提交 SUBMITTED 调整，须独立审批后执行。通用调账白名单和管理员权限不放宽；客服不能自批自执行。
5. 充值以持久租约、随机 token 摘要和行锁管理认领。资金执行前重验会话、客服角色、独立资金验证、认领和凭证。数据库全局资金锁先于订单/调整/凭证锁；外部链上查询在短事务之外。
6. 新提现策略支持客服租约；开始真实付款后保持唯一处理人，不因超时自动接管、解冻或重发。两小时后的不确定订单转核对，原链上证据确认规则继续适用。旧订单策略保持可追溯。
7. 后台首次开通只验证现有官方客服账号已绑定且已验证的邮箱或手机；不授予新角色，不创建另一个账号或钱包。客服使用管理会话和独立 `support-orders` 验证范围，不能凭此访问钱包所有者的修复功能。联系方式或角色改变须重新验证。
8. 通知采用 Outbox 加每客服持久收件箱；按提交后分配的客服局部序号分页，不以生产者时间戳作为丢弃旧事件的水位。重试允许重复传输，客户端按稳定事件 ID 去重。

## 迁移与恢复

0084–0087 从 0083 唯一 head 扩展；新增字段保留历史订单差异，新表不删除资金记录。发生故障时关闭新入口并保留数据，由前向修复或经验证的备份恢复处理；不得通过删表降级抹除订单、凭证、激活及审计历史。

## 验证要求

先规格符合性、后质量安全复审。至少验证独占认领、过期 token、跨进程并发、重复凭证和旧入口互斥、资金提交回滚、独立审批、重复执行、失效授权、两小时边界、通知乱序提交，以及新迁移实库演练。替身、隔离依赖和生产证据分开记录；本 ADR 不表示已上线或已验真机。
