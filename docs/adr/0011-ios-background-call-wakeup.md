# ADR 0011: iOS 真实来电唤醒与锁屏会话访问

状态：用户2026-09-08批准产品方案；本技术决策已完成独立领域审查及后续质量/安全审查。批准下述原生方案；插件原值写回方案被拒绝。实施代码仍需复核与真机验证。

需求：支持已经登录、设备重启后至少解锁过一次的iPad在锁屏时收到并接听加密Matrix来电。普通APNs与声明后台模式不足以保证进程唤醒和系统来电页。

决策一：独立网关只传room_id/call_id/媒体类型及到期时间。使用已有Matrix Bearer向固定Synapse whoami验证用户与设备；创建呼叫还需读取该加密房间实际双人成员。接收者设备资格经固定Synapse admin只读用户/设备接口确认，管理员凭据只在服务器挂载且不得出现在日志/响应。不得从任意密文通知推断VoIP，也不得将SDP、媒体、房间密钥或恢复密钥送到网关。不会修改现有业务登录、RBAC或资金接口。

决策二：只对iOS现有 `liuhetong.matrix_database_key.v1` 与 `liuhetong.business_session.v1` 使用Keychain `AfterFirstUnlockThisDeviceOnly`。这是对锁屏后本设备可访问时间的显式调整：锁屏期间App可继续访问会话与加密数据库，但重启后首次解锁前仍不可访问；内容不随设备备份迁移、不启用iCloud同步、不共享到扩展或服务器。恢复密钥、注册设备密钥和其他Keychain项目保持现有策略。

旧项目迁移：原生固定两项名称和既有service身份，SecItemCopyMatching精确读取非同步条目、不带accessibility过滤；仅errSecItemNotFound表示不存在，其他错误原样失败。成功读取后，SecItemUpdate仅更新accessibility；读回核验属性和值未变。禁止读失败当作不存在、生成新数据库密钥、删除条目再重建或清空数据库。属性更新失败必须暴露初始化失败。新安装只有确证不存在才SecItemAdd，重复项错误不得替换。现有SQLCipher算法、密钥内容、数据库格式和cipher_version强制校验不变。

禁止使用flutter_secure_storage9.2.4的读写回退路径迁移上述两项：实际依赖write在SecItemUpdate失败后会delete/add；read会在无value时再次查询synchronizable并可能掩盖锁屏错误。这两项直接走受限原生通道，其他条目仍使用原插件。

风险：与仅解锁可访问相比，首次解锁后锁屏时攻陷应用进程可访问更广的会话内容；这是后台加密通话需要的明确取舍，以本设备专用、最小两项及现有沙箱/Keychain保护约束。新版本必须先在解锁状态打开一次完成迁移。未首次解锁、用户注销、会话已撤销或网络失效时不得承诺接通。

接收方admin账户/设备查询仅证明当前投递资格，不能证明过去注册时的每一个访问令牌仍有效。来电唤醒是提示，媒体接通前仍由当前已认证的客户端和已解密Matrix会话校验，不能把设备存在描述成完整的接收方token撤销验证。

验证：Mock平台通道验证两项使用指定accessibility、迁移原值相同、恢复项策略不变、读写失败不清除数据；iPad实际升级后锁屏冷启动来电和数据库可读测试。网关鉴权/权限/多设备/限流/APNs载荷行为测试以及独立领域和质量安全审查。未通过审查不得部署网关或实施Keychain策略更改。
