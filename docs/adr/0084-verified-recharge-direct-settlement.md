# ADR-0084：已核验充值由认领客服直接下发点钻

日期：2026-09-23。状态：用户本次明确批准；领域/规格及质量安全独立审查由主任务完成。本授权包含本批生产部署，实施子任务不自行部署。

## 决策与授权范围

用户明确要求：已由系统核验到账的充值，持有处理权的客服可以直接下发点钻，无需独立管理员审批。本条覆盖 ADR-0077、ADR-0081、ADR-0083 中与该特定充值操作冲突的审批要求；普通财务调整、提现及管理员钱包审批/二次验证不变。

沿用 prepare-settlement / execute-settlement 两个公开 HTTP 命令。prepare 从被锁定订单、不可变到账回执和客服确认的结算率派生收款用户与金额，创建持久绑定并冻结金额，不入账。execute 调用财务公开 execute_support_recharge，仅接受有托管订单绑定、support-recharge 专用键及 RECHARGE_CREDIT 原因码的调整；不接收客户端收款人或发币金额。不生成虚假审批，不填写 reviewer 字段，不将 SUBMITTED 改成虚假 APPROVED。准备后的 SUBMITTED 仅表示待执行。

每次资金执行继续验证当前客服管理会话/角色/激活、五分钟认领 token、实际付款身份与最终确认的回执、订单未处理、有效期或人工核对授权。保持资金全局锁→订单→调整/凭证锁序；交易内调用公开账本服务、消费凭证、记录 EXECUTED、资金审计和 Outbox；提交前重验授权。USDT 六位、点钻两位与结算舍入不改变。

## 兼容与回退

既有 support-recharge 在途绑定可以直接执行；已有独立审批记录保留。普通调整绑定继续使用原审批 execute。所有入口共享 adjustment-execute:{adjustment_id} 服务端账本幂等键，凭证只能消费一次。已执行但登记失败的旧记录只恢复 CREDITED 登记，worker 仍能恢复；不能重建调整发第二次币。

prepare 与列表返回 settlement_approval_required、binding_final_rate、binding_final_caibi_amount。UI 继续已有绑定时必须展示被冻结的实际率/金额，不得让修改中的草稿冒充本次执行金额。本批不提供静默重算已绑定金额。

无新迁移，不改余额表结构或公式。回退时关闭新直发入口、保留所有资金记录；旧实现可能无法登记无 reviewer 的已执行命令，故回退必须保留本 ADR 的凭证登记兼容逻辑，不能盲目回滚整个服务文件。已入账纠错仍走关联冲正。

## 验证

新增独立用例覆盖无审批下发/无假审批、错误会话授权、错误认领、未核验、已拒绝、普通调整不可借道、提交时撤权全事务回滚、历史已执行恢复和两个独立数据库会话并发唯一入账。原普通调整审批与充值/钱包互斥回归继续运行。详细结果见 [专项记录](../verification/2026-09-23-direct-recharge-settlement.md)。
