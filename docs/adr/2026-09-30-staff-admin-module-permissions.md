# ADR：客服业务模块的独立权限

状态：用户授权范围已批准，领域/安全审查已完成，见本文补充及同日验收报告。授权来源：2026-09-30 用户明确开放五模块并要求直接执行。

客服、财务客服、客服主管拥有封禁管理、用户统计、广告管理、公告管理、点钻查询五个专用权限。不给予 system.admin、finance.review 或 audit.view 作为捷径。保留原有主管 audit.view 权限的兼容访问。

后台每个入口检查实时角色权限；新增客服访问须有已开通的 admin 会话（已有注册/邮箱/TOTP安全边界）。用户普通会话不能凭客服角色访问新增模块。管理员权限维持现有行为。

封禁与解除使用现有 AdminControlService 公共命令，保留幂等、审计、Outbox；查询返回有效封禁 ID。角色撤销仍只限管理员，逐角色调用既有接口。点钻查询不会授权任何写入，也不会开放管理员专属钱包。

列表采用现有游标或稳定排序与偏移分页，默认10，20/50可选。旧客户端合法页大小保持兼容。增加响应字段为可选/增量；不迁移账本和数据库，不改变资金公式。

回退：恢复本次冻结的前一 API 镜像与后台静态文件；前一镜像已包含管理员专属提现边界。无破坏性迁移。

领域审查补充：有效封禁查询返回 starts_at 作为本轮证据，解除在锁内比较该证据，重新封禁导致冲突。客服不得封禁自己或拥有任何管理角色的账号，管理员维持原权限。点钻发行凭证及详情亦采用专用只读权限，保留原 audit.view 兼容访问。

安全审查补充：上述管理账号保护也适用于解除封禁，且重放前检查目标。新开放给客服的命令收据按操作者隔离；既有管理员收据保留兼容。领域及安全设计审查意见已纳入，批准范围以用户直接执行授权为准。

单角色撤销：仅在撤销前现有开通验证仍有效、联系方式未变时，将验证摘要更新到减少后的角色集合；保留剩余角色的正常访问。不能为未开通账号创建验证，也不能在新增权限时沿用该机制。最后客服角色移除后即拒绝现有客服会话。
