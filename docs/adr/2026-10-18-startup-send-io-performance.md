# Startup/send I/O optimization safety decision

Status: User approved four bounded performance work items; domain and QUALITY/security implementation review pending. No rollout until reviews pass.

Context:2222 samples show full identity preflight2157/2521ms and SDK sendEvent1236/1516ms, event HTTP245.603ms in one sample. Attribution is incomplete; do not call the whole span encryption/network.

Decision:

1. Identity read continues to use a private temporary encrypted DB/WAL/SHM copy and read-only SQLCipher connection. Replace source prehash+copy with a single backpressured copy-and-hash stream. Retain copied-file full hash comparison and original full hash/type/existence recheck after identity inspection. This removes one of four full source-equivalent reads without accepting a changed final byte image. No inode/mtime-only shortcut, live DB open, cached authentication verdict or cipher/KDF reduction.
2. Telemetry consists only of closed enum stage and microseconds, bounded existing in-memory recorder. SDK optional observer failures cannot affect encryption/delivery. No message/room/account/device identifiers or secrets in diagnostics.
3. Durable startup head remains invalidated before every display-changing mutation is allowed to apply. A coordinator may reuse its already-invalid state until a head-write attempt starts; mark unknown before writing so partial writes/throws force invalidation again. Original capture permit/revision/owner and pending privacy fences remain authoritative. Optional rebuilding may coalesce; privacy invalidation and durable message/key writes may not.
4. Warm only existing outbound sessions after verified SDK identity, bounded8 prioritized rooms. Share one per-room load future with actual sends; after I/O, verify current loading epoch, identity/database and existing cached session before publication. Clear/dispose invalidates loading epoch. Do not create/share keys or advance Megolm during prewarm. All actual sends retain original rotation, membership, permission and durable session state checks.

Required evidence: red/green race and tamper tests, existing identity recovery and privacy regressions, separate domain then QUALITY/security review, signed Debug/device evidence and honest before/after timing scope. Failure falls back to existing canonical restoration/send path; optional preload failure never grants access.

Design review rulings (domain followed by independent QUALITY/security): direction conditionally accepted. Copy checks establish final byte equality, not absence of all ABA changes or an atomic multi-file snapshot; old SDK closure remains a prerequisite. Key load invalidation covers room-level clear/rotation even if cache is empty and new-session creation before its first await. A room-level loaded tombstone prevents re-reading an obsolete DB pickle during replacement; successful clear-all starts a new epoch. Late, invalid or duplicate native sessions are disposed, failures are retryable, old finally cannot delete a new flight. Head known-invalid is set only after durable success and reset before invoking any writer, including partial-write failure paths. Privacy-target fences remain independent and synchronous.
