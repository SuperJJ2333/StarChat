## 1. P0-1 朋友圈删除（仅作者可见入口）

- 事实：`deleteMoment` API 早已存在但无任何调用方；"仅作者可见"实现为
  **删除入口仅对作者展示**（`item.author.username` == 当前登录用户名，
  广告条目一律不显示）。
- 实现：`WeChatMomentTile` 新增 `onDelete`（动作行删除图标，仅作者传入）；
  `moments_page` 动作单 → 确认弹窗（不可恢复提示）→ **乐观删除**
  （`_deletedIds` 立即剔除）→ 失败回滚恢复条目 + 服务端错误文案 →
  成功同步内存 Feed 与磁盘缓存（防缓存首绘复活已删条目）。
- 测试（moments_flow_test 新增 4 用例）：作者可见/非作者不可见；
  确认取消不删除；乐观消失+缓存同步；失败回滚+错误文案。

## 3. P0-3 通话关键路径重构

| 要求 | 实现 | 证据 |
| --- | --- | --- |

| 来电不被服务器请求阻塞 | `IncomingCallGate`：**本地已同步成员优先**（`room.getParticipants`，零网络请求放行）；本地为空才回退服务器 /members（4s 超时，失败拒接——与旧语义一致，安全断言不削弱：加密房间+恰好双方+与信令声明一致） | `incoming_call_gate.dart` + 4 用例（本地零请求/回退/超时拒接/三方与冒名拒接） |
| 接听超时/失败/重试 | `accept()` 包 try/catch → failed；新增 `connecting` 相位 + **45s 连接超时**（此前 ICE 不通永远停在响铃）；`retryAfterFailure()`：会话存活→守卫再接听，已死→对同一用户回拨；CallPage failed 态「重试/关闭」按钮 | call_controller_test 6 新用例 |
| invite→UI→点击→ICE 耗时 | `CallDiagnostics`（backend+controller 共享时间线）：invite_received / incoming_ui_shown / answer_tapped / answer_sent / ice_connected / ended，`[chatflow/calldiag]` 逐段差值+结束 summary | 诊断用例（各阶段埋点与 summary） |
| candidate 类型/TURN/RTT/丢包/抖动 | `CallQualityMonitor`：连接后每 5s `getStats()`——选中 candidate-pair 的 local/remote candidateType（host/srflx/relay→TURN 判定）、currentRoundTripTime、jitter、packetsLost；结束汇总 `[chatflow/callquality] summary samples=N turn=used rttAvg=jitterMax=lost=` | call_quality_and_gate_test（解析/轮询/容错 6 用例） |

停来电铃）；来电铃声在点击接听时立即停止（此前响到 ICE 接通）。

## 5. P1-5 视频发送阶段化（详见 docs/VIDEO_SEND_PIPELINE.md）

- 阶段状态机 `video_send_stage.dart`：**转码(真实%)→加密→上传→发送事件**
  ——加密/上传取自 SDK 上传伪事件 `fileSendingStatusKey`（此前整体折叠
  成"发送中"），300ms 轮询驱动；上传无进度回调→如实显示不定进度。
- **去除 2 次冗余全量拷贝**：`sendEncryptedMedia` 正文与缩略图原实例
  透传（参数收窄 Uint8List，接口同步）；源码防回归断言（体内不得出现
  `Uint8List.fromList`）。
- 评估结论（如实）：Synapse 上传为单次完整 PUT，Matrix 无分块/追加
  协议；SDK 无流式/取消口子——流式分块加密上传当前不可行，取消边界=
  转码前与发送前；文档含可行渐进路径。
- 测试：`video_send_stage_test.dart`（阶段标签/busy 门控/状态映射/
  拷贝防回归）。

## 6. P1-6 TURN（详见 docs/TURN.md）——含两个生产缺陷修复

生产核查发现（**真实缺陷，非配置模板问题**）：
1. homeserver.yaml 的 turn_uris 是**过期内网地址** `turn:192.168.1.116:3478`
   （手机不可达）→ 生产 TURN 从未可用；
2. homeserver 的 turn_shared_secret（36 位 dev 残留）与 coturn 实际使用
   的 .env 密钥（64 位）**不一致** → TURN 认证必然失败。

已部署（SSH 备份 `*.bak-20260904T051529Z` / `*.bak-secret-fix`）：
- turn_uris → `turn:liuhetong888.com:3478 udp/tcp` +
  `turns:liuhetong888.com:5349?transport=tcp`；secret 与 .env 同步；
  synapse 重启 healthy，回归全 200（synapse/element/api）。
- coturn 启用 TLS：挂载 nginx 证书（SAN 含 liuhetong888.com），
  `--tls-listening-port=5349`，发布 5349 tcp+udp；ufw 放行 5349。
- **待人工**：托管商安全组放行 5349（服务器自连公网 IP 被拒，过滤在
  上游；放行后 turns 立即生效）。TCP-443 TURN 需 DNS+SNI 分流
  （443/tcp 被 nginx、443/udp 被 QUIC 占用），列为独立人工项。
- 仓库同步：compose 注释块 + homeserver 模板 `{{TURN_URI_TLS}}` +
  init_matrix 变量 + `.env.example` + docs/TURN.md（真机双机测试矩阵）。
