# 0.3.58 (61) 真机验收

此清单用于补足自动回归与模拟器不能覆盖的实际设备、网络和企业重签条件。测试使用专用账号及合成媒体，不采集真实聊天正文或密钥。

1. **升级与历史**：在现有安装中保留一条文字、一条语音、一段视频，再覆盖升级。核对旧会话与三种消息仍可读取；完全关闭、重新打开，再重启设备，重复核对。分别测试普通退出登录后同账号登录、会话过期后的同账号重新登录。更换账号时，确认不会显示上一账号的聊天内容。
2. **私聊唯一性**：同一联系人从联系人页和会话页连续进入，在网络延迟和短暂断网恢复后重复操作；应复用同一个私聊，不新建重复房间。
3. **语音与视频**：Android 与 iOS 双向发送专用测试语音和 H.264／HEVC 视频。播放自己的与对方的消息，离开会话再进入，关闭应用再打开，验证缓存后的播放；语音切换扬声器／听筒并验证暂停、继续。
4. **朋友圈**：加载带 4:3、16:9 图片的动态和封面，返回再进入、打开大图再返回。已有内容应先显示，刷新签名后同一媒体不重复下载。点赞／取消立即同步人数、名称和图标；退出重进保持成功结果。断网点赞失败后状态应回退，期间成功提交的评论仍保留。更换封面后应显示新图。
5. **推送与来电**：锁屏后从另一测试端发消息和发起语音呼叫，核对通知、铃声、系统来电页、接听与双向声音。继续核对前台来电和通话结束后的语音消息播放。

Android 应覆盖安装同签名 APK。iOS App Store 签名 IPA 应经 TestFlight 分发，或由签名方按现有企业分发身份重新签名后测试；本次构建不等于已更新官网。企业重签后的身份、推送能力和升级后的数据连续性须在实际重签包上验收。测试期间不要通过卸载旧应用来代替覆盖升级，否则无法验证升级保留历史这一条件。

记录设备型号、系统版本、安装包 SHA-256、实际签名渠道、失败步骤及时间；无需提供账号密码、语音内容或数据库密钥。
