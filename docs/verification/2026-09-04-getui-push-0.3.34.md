## 4. ✅ 凭据已打通（2026-09-04 二次排查解决，含事故复盘）

**结论**：用户提供的 `jYisy3SZ7K8BwSHKgbjNY6` **就是正确的
MasterSecret**——标准签名 `sha256(appkey+timestamp+mastersecret)` 实测
`code=0 success`，bridge 客户端取得 64 位 token。

**此前误判"密钥错误"的真实根因（部署事故复盘）**：更新服务器 .env 后
用了 `docker compose restart`——restart **不会重载环境变量**（容器仍持
有旧 AppSecret），而排查脚本从容器环境读密钥，导致"新密钥也被拒"的
假象；判别实验（AppID/AppKey 配对正确）结论有效，但"jYisy 不是
MasterSecret"的结论错误。修正操作：`docker compose up -d
--force-recreate` 重建容器后一次通过。

**运维教训（已写入 PUSH_SETUP）**：改服务器 .env 后必须 `up -d` 重建
容器，restart 无效。

**当前链路状态（生产实测）**：
- bridge 鉴权 ✓（真实 token，len=64）；
- 公网 `/notify` → 脱敏 → 个推 push/single/cid ✓（假 CID 返回个推业务
  码并收敛为 rejected，200 无 5xx；日志仅记 kind 与 code，无密钥/无
  业务内容）；
- **待真机**：0.3.34 APK 安装登录（同意隐私政策）→ CID 注册 pusher →
  杀进程收消息/来电通知（§6 清单）。
