# 0.3.31 发布验证（2026-09-03）：同步看门狗（后台停收根治尝试）

## 病理与推理

用户复测 0.3.30：电池白名单已开、`chatflow_sync` 常驻通知在（进程与
前台服务存活）——但后台收不到消息，**打开 App 立即弹出提示音+横幅**。
该现象证明：通知管线正常，但后台期间 Matrix 同步循环已停摆，回前台
（生命周期触发恢复路径）才追平消息。

SDK（matrix 0.34.0）同步循环为自链式 `_innerSync().whenComplete(_sync)`，
存在无自愈的悬挂路径：长轮询连接黑洞（`.timeout` 依赖的事件循环若被
ROM 干预）、续环断裂、`database.transaction` 卡死（abortSync 也会等它）。
我们的代码未触碰 backgroundSync/abortSync（已核）。

## 修复：`MatrixSyncWatchdog`（`matrix_sync_watchdog.dart`）

- 心跳 = `client.onSyncStatus` 的 waitingForResponse/processing/finished
  （健康长轮询每 ≤40s 一跳；error 不计心跳，持续报错同样触发自愈）；
- 停跳 >2.5min：`oneShotSync()`（45s 超时）踢活；
- 停跳 >5min：`abortSync()`（15s 超时兜底，事务卡死不阻断）→
  `backgroundSync = true` 强制重建循环 → 立即 `oneShotSync` 补拉；
- 阈值动作后重置计时，避免连环重启；AppHome 启动开启/退出销毁；
- 全部动作 debugPrint `chatflow/syncwatchdog` 标签（release logcat
  可见），真机复现时 `adb logcat -s flutter | grep syncwatchdog`
  即可定位悬挂形态（踢活即恢复=连接悬挂；重启才恢复=循环死亡）。
