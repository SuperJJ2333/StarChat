## 2. 发现的第二个生产缺陷（阻塞本次需求）

`GET /api/v1/app-updates/latest` 的**平台标记对 Android 缺失**：

- 客户端自 `4c199ae1`（0.3.81/2085 起）强制校验：
  `if (response['platform'] != platform) return {'configured': false};`
  而客户端永远显式请求 `?platform=android`（`business_api_client.dart:773`）。
- 线上 `/opt/business-api/app/api/app_update.py`（sha256 `65a806b3…`，来自 `8bec689e`）只对 iOS 打标记：
  `platform_fields = {"platform": "ios"} if platform == "ios" else {}`。
- 结果：**所有 0.3.81/2085 及以上的 Android 客户端都拿不到更新弹窗**（`configured:false`）。
  `releases/app-update-platform-20260910` 这次"平台修复"实际部署的就是上述 iOS-only 版本
  （其 payload `overlay/app_update.py` 与线上同 sha），仓库 HEAD 的对称标记版本从未上线。

证据（同镜像 + 生产导入路径的实测投影）：

```text
基线镜像 be11636c：android  → 无 platform 键     ← 客户端判定 configured=false
                  ios      → platform: "ios"
候选镜像          android  → platform: "android" + download_url
```

不改这一点，本次「更新弹窗」对任何现网 Android 用户都不可见，因此本任务包含这次最小 API 覆盖修复。
