## 2. 离线可重复反例

命令（PowerShell 7，已设置 UTF-8 及 Python UTF-8 环境）：

```powershell
py -3.12 docs/verification/artifacts/2026-09-09/media-dedup-preflight/deterministic_encryption_probe.py
```

退出码 0，4 项 unittest 通过。原始输出：[probe-result.txt](artifacts/2026-09-09/media-dedup-preflight/probe-result.txt)。脚本：[deterministic_encryption_probe.py](artifacts/2026-09-09/media-dedup-preflight/deterministic_encryption_probe.py)。

1. 同明文字节产生同密文。
2. 仅持有密文的观察者可从合成候选字典中匹配文件，再重算 key/iv 并解密；无需房间密钥或事件内容。
3. 独立密钥/IV 的对照信封不会匹配公开内容派生结果。
4. 内容哈希自洽的缓存命中仍可能对应错误事件 key，证明仅比较明文哈希不等于验证信封绑定。

所有数据为合成夹具。原计划未指定 HKDF info；脚本使用公开的演示标签，不将其指定为产品协议。这些是预审反例测试，**不是功能开发的 TDD red/green 证据**，不能替代 Tasks 2–9 的失败到通过记录。缓存演示只证明模型缺口，不声称新增缓存实现已经存在或已被利用。

## 3. Quality/Security 预审（后）

领域结论和修订 ADR 形成后，独立只读评审 `media_security_review` 结论为：**修订范围已可供用户审阅，受保护实现尚未批准。**

- ADR 准确保留已接受风险并纠正绝对保密/容量说法，明确共享引用和缓存验证要求。
- 协议版本、完整 HKDF/CTR 参数、缓存接受算法与热冷一致性尚需详细设计和对抗测试。
- 新逻辑引用仍需具体 schema、文件/数据库提交协议、删除/隔离/配额规则与回退兼容读路径。
- 归档原文中的不安全指令受顶部修订说明覆盖；批准修订后必须重写可执行 Tasks 2–8，不能让执行者按归档原文实施。
- 离线反例的证明范围仅为派生算法及哈希/信封区别，不代替真实 SDK 路径测试。
- 明文上传禁令的测试需限定加密聊天附件；管理头像属于另一种媒体用途，服务端去重不能把普通头像自动变成加密附件。

结果不要求再次接受字典攻击风险。下一步是确认 Task 6 生命周期重设计等范围修订，完成详细实施设计并复核，再进入受保护代码实现。
