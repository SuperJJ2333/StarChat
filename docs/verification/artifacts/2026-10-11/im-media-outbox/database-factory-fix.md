## Actual fault and minimal implementation

Root actualAndroid emulator5558 rebuilt/signed/installed candidate passed native directory policy then failed media_outbox_persistence_native_test at SqliteMediaOutboxStore._open: `/data/data/com.liuhetong.mobile.debug/lib/libsqlite3.so` missing. The immutable original evidence remains in root artifact `im-reliability-release/native-storage2214-r2/native-drive.log` (hash in manifest). This is not merely a fixture lacking startup initialization.

Resolved sqflite_common_ffi 2.3.6 database_factory_ffi_io.dart has one Dart-library `_isolate`; only its creation uses the caller's ffiInit. isolate.dart runs the callback once in that worker. Whichever factory invokes its first operation chooses the library. main.dart does not globally initialize that worker; MatrixClientFactory explicitly supplies SQfLiteEncryptionHelper.ffiInit, but six metadata defaults supplied no callback. Matrix-first happened to initialize SQLCipher, while metadata-first tried the absent Android libsqlite3 and a later Matrix factory could not repair the worker. A parent-isolate override or fixture-only warm-up would conceal this product dependency.

New core/local_database_factory.dart exposes a single metadata factory using the existing SDK's SQLCipher loader. Six metadata stores now select it unless a test/application factory is explicitly injected: durable media outbox, text outbox, moments page store, media reference index, media disk quota index, and profile repository. Matrix/retained-key/identity-preflight factories remain unchanged and already supply the same loader. Timeline migration workers directly initialize their own independent SQLCipher instances. No dependency/native library added, no PRAGMA key, key acquisition, schema, onConfigure, migration, encryption parameter, or file format changed. Existing metadata remains its prior SQLite format; Matrix retains its keyed encrypted format and wrong-key rejection. MediaIndex's obsolete startup-order comment is corrected.
