## Evidence and design

`red.log` (exit 1): actual 100 MiB cold load, six full plaintext digest calls on caller isolate. Only an observer wrapper was introduced at the existing digest call sites before this behavioral RED; it cannot supply a forged digest. `red-preview.log` (exit 1): actual 2 MiB synchronous seed performs a caller-isolate digest before returning.

`VerifiedMediaContent` is final with a private constructor. Only its verifier can register a proof for the exact immutable worker-owned byte snapshot in a private Expando. The scope contains account namespace, global clear generation, and account generation. A mutable source, immutable view created outside the verifier, equal digest in another account, or old epoch is not a proof. The factory validates expected digests and returns its worker snapshot, never the mutable producer source after await. No content/digest/account values are emitted by the digest observer. This is the existing Flutter compute/native isolate boundary, tested on Windows; Android/iOS profiles remain pending.

The cold load validates once in the worker and reuses that snapshot for store flight identity, object name, memory interning and joined references. Disk reads are still untrusted and verify actual bytes; stream verification/index corruption recovery is retained. Store/loader/preview paths recheck cancellation and epochs after asynchronous verification. The sender now caches the final transformed bytes via the preparation callback and passes those immutable bytes into envelope derivation: no second plaintext digest for that controlled chain. ADR-0060 raw-digest HKDF/AES-CTR and SDK ciphertext verification are unchanged; envelope flights are scoped to account epoch.

Local seed paths were inspected at baseline room_page.dart:1782 (vault original; GIF cap20MiB), 2141 (camera file; send cap100MiB), 2710 (gallery200px thumbnail), 2721 (GIF/original fallback; gallery cap20MiB), 2817 (post-send original). These sources cannot generally reuse a proof. Root approved keeping immediate local previews. For >64KiB, a copied immutable transient snapshot has a unique cache-local identity and consumes the existing byte/entry budget. It does not persist, intern by content, or join completed session memory until worker verification succeeds and entry, epoch, consumer and owner are current. Replacement, eviction, clear or dispose cannot be undone by the late proof. <=64KiB legacy seed/put compatibility remains synchronous and bounded in the production seed path; this is not a claim of zero synchronous hashing. Public synchronous compatibility put/verify APIs still validate untrusted callers; asynchronous production read/load/send paths use the worker. Large snapshot copying and existing streaming hash work are not claimed as removed; R8 memory limits are separate.
