# Android 2215 preparation and reviewed execution contract

Current status: code ready for independent review; actual final APK and its gate bundle are not available. Commands below are parameterized interfaces, not publication authorization. No placeholder release record exists.

## Local package inputs

Run `python package_release.py --help` from this artifact directory. Required arguments are `--apk`, `--artifact`, `--steps`, `--gates`, `--source-root`, `--source-manifest`, `--output`, and `--signing-confirmed-by`. Use an existing private output parent below this named verification task; the output itself must not exist. Source root is the real build checkout. The manifest is the exact `mobile-inputs.json` frozen by the builder, with `files` entries `{path, sha256}`; its bytes must match the receipt SHA, all source members are rehashed, and pubspec.yaml/lock must be present.

The builder receipt requires:

| Field | Required identity |
| --- | --- |
| version / build / mode | `0.4.46` / integer `2215` / `standard-arm64-release` |
| source_commit | Actual nonzero 40-character lowercase Git SHA from the builder |
| mobile_manifest_sha256 / pubspec_lock_sha256 | Actual nonzero SHA-256 values |
| final_apk_sha256 / final_apk_bytes | Actual final rebuilt/signed APK hash and positive integer length |
| signer_sha256 | `75b31c66476cd8e2c9319551b49405a1de1e5c23e9a0dbdcc9eb76b52ba61fff` |

Steps are the original builder TSV with `step` and `exit_code` as its first columns. Every row must succeed, names must be unique, and source build, conventional APK rebuild and signature verification phases must exist. Real builder names `flutter-build-release`, `apktool-rebuild`, `apksigner-verify` are supported, alongside explicit canonical receipt names `source-build`, `apk-rebuild`, `signature-gate`. Preserve all actual builder rows, including alignment/semantic/native checks; do not replace the real receipt with the three-row synthetic test fixture.

The gate JSON has these required fields (values must come from actual evidence):

- `source_commit`, `source_manifest_sha256`, `pubspec_lock_sha256`, `artifact_sha256`, all exactly matching the receipt.
- `final_identity`: exact `package: com.liuhetong.mobile`, `abi: arm64-v8a`, `version: 0.4.46`, integer `build: 2215`, fixed `signer_sha256`, integer `artifact_bytes`.
- `checks`: exactly `shared_flutter`, `native_android`, `final_apk`. Each has `status: pass`, `path` relative to the gate JSON directory, and the actual report file `sha256`. Files and ancestors cannot be symlinks; absolute/traversal paths are rejected. A combined final APK report must substantiate package/version/ABI, fixed signer, alignment, conventional rebuild semantics/assets and packaged native exports. A passed native gate is actual device/emulator evidence, never an offline double.

The package verifier checks artifact/evidence identity and successful receipts, not semantic truth of a handwritten report. Root review must read the bound reports. It refuses pending/missing gates instead of making up a successful status.

## Review binding and plan

After local packaging, root reviews `freeze-manifest.json`, its `runtime_files`, exact staged target payloads and source-backfill plan. A separate review JSON requires:

- `freeze_sha256`, `artifact_sha256`, `runtime_sha256`, `source_commit` copied from the actual reviewed package.
- `operation_id`: unique lowercase letters/digits/hyphens, 8–64 characters, beginning with a letter or digit. It determines private HK/SG stage paths, backup directory and transaction audit trace. Do not reuse an ID.
- `checks`: exactly `spec_domain` and `quality_security`, each `status: pass` plus actual relative report `path` and `sha256`. Conduct SPEC/domain first, then quality/security. Both reviews must cover the exact package and this executor source.
- `authorized_operations`: explicit subset of `preflight`, `runtime`, `upload`, `assemble`, `hk-install`, `cdn-install`, `cdn-check`, `hk-switch`, `publish`, `inspect`, `audit`.

`python execute_release.py OPERATION --package PACKAGE --operation-id ID` validates the complete local package and prints a plan without transport or execution receipts. Real execution also requires `--execute --review REVIEW_JSON`. No approved review JSON is generated by these scripts or this task.

## Explicit phase sequence

1. `preflight` is optional read-only inspection. `runtime` always repeats it immediately before the first remote write: Android must remain 2214 and iOS 2213/minimum3, static bytes/old immutable APK/aliases/schema/35 container identities and permanent guard/probe hashes exact, target absent, fixed AWS role/account/CF16/ETag/bucket policy exact and Deployed. Drift stops; never roll back containers or silently re-freeze a changed baseline.
2. `runtime` installs only the reviewed runtime into new private stages; `upload` sends bounded 16MiB chunks to HK, preserving immutable older objects. SG receives runtime only. `assemble` verifies every chunk and full APK. `hk-install` installs the exact new immutable APK while preserving the current alias.
3. `cdn-install` appends exactly one APK behavior, using ETag CAS. It may return InProgress; no busy wait. Use `cdn-check` later until Deployed and public HEAD/CORS pass. No full public APK download is added.
4. `hk-switch` obtains a fresh SG `cdn-check`, then performs alias CAS under the shared HK host lock. `publish` obtains another fresh check, then exact static/SettingService transaction publication and audited three-key readback with private backups. iOS five settings, both minima, install URLs, homepage, iOS manifest and selectors remain unchanged.
5. `audit` invokes the existing real public-route/trace verification script. Review its result, then parent applies the two-file source backfill with exact before hashes. The package script itself never edits source or appends a generic source-wide version replacement.

Every mutating phase is exclusive and single attempt. Any exception after entering its execution block writes `outcome-unknown.json`; even a timeout with no observed remote write is treated conservatively. Subsequent mutation is blocked. `inspect` reads current ten settings/static hashes/alias, and `audit` reads public routes and the unique trace. Neither clears the marker or repairs state. Inflight markers left by a killed local process also require inspection before manual recovery. Decide recovery with concrete server evidence and a separately reviewed action; never blindly delete markers and replay.

`scripts/verify.ps1` was preflighted: it renders environment configuration and runs the global server/client suite. This isolated artifact-only task does not alter those inputs and must not create environment files or rerun root's shared/native/build gates. Its dedicated 32-case preparation suite and unchanged six-case real PostgreSQL evidence are recorded separately; they do not replace root's final release gates.
