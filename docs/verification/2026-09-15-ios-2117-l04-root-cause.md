# 2026-09-15 iOS 2117 L04 复现根因与客户端修复

## 现象

iOS 0.3.91/2117（企业签名覆盖安装）重新登录时报“聊天登录未完成，请重试（L04）”；
Android 同期版本无此问题。9-10 的 L04 服务端修复（登录 flow 广告）依然有效。

## 根因（服务端审计 + 代码路径确证）

L04 是**阶段码**（matrix_login 阶段），不是唯一错误。本次是另一处失败：

`loginWithToken` 的“保留身份刷新”路径（本机仍有旧 userID/deviceID 时）：
1. 向 broker POST login token 时**带上旧的 device id**；
2. 响应校验要求 `user_id` 与 `device_id` 都与本地一致，不一致即抛
   `Matrix credential refresh identity mismatch` → 包装为 L04。

单设备策略下，本账号在其它设备（Mi 6/Android 测试登录）登录会**轮换服务端 device id**
并把旧设备顶掉。iOS 2117 覆盖安装保留了 2085 时代的旧 device id → 刷新时服务端返回
新 device → 本地拒绝 → L04。Android 无此问题是因为测试路径都是“先退出（清除本地身份）
再登录”，走的是全新登录分支，不存在旧 device id。9-10 修复的是同一阶段的另一原因
（服务端 flow 广告缺失），本次是余下的第二个原因——即当时记录的
“token-only 预检查/兼容”待办的延伸。

审计佐证：a1102 账号 16:47–16:52 多次 `login_token.issued` 而无 `consumed/completed`，
中间穿插一次成功——与“单设备约束下间歇性被拒”完全吻合；服务端 GET /login 两种 flow
广播正常（已排除 9-10 旧因复发）。

## 客户端修复（commit 38c589b0 + 98103bf0）

1. `loginWithToken` 刷新路径：`user_id` 仍严格匹配（安全边界不变）；
   `device_id` 改为**采纳服务端权威值**（token 登录已证明账号归属，单设备策略下
   服务端有权轮换设备），`active.init(newDeviceID: adopted)` 并继续密钥重注册。
2. 采纳后恢复 `LoginState.loggedIn`（此前 softLoggedOut 过渡标记未清除会让
   `credentialsInvalid` 恒为 true，登录后仍被判定凭据无效）。
3. `MatrixClientFactory` 声明 `supportedLoginTypes: {password, token}`——落实 9-10
   记录的待办：即使服务端将来移除遗留 password 广告，`checkHomeserver` 也不再抛
   `BadServerLoginTypesException`（L04 的第一个历史根因从客户端侧免疫）。
4. 回归测试：服务端轮换 device（NEW）时刷新必须采纳（`token refresh adopts a
   server-rotated device id instead of L04`）；既有 76 项 factory/continuity 测试全过。
