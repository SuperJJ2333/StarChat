# Cache/entry follow-up — 0.3.45+48

Base: `96ef29c`. User's five follow-up items implemented in `codex/cache-entry-optimization`.

## Changes and acceptance

1. **Favorites**: RoomPage no longer sequentially downloads all original favorites on entry. Visible cells request a static, aspect-preserving first-frame PNG (maximum 160px). GIF cells retain a GIF indicator; sending loads the original Matrix media, never the preview. Preview requests are serialized/coalesced, with 8MiB memory byte-LRU and 64MiB account-isolated AES-GCM disk LRU. Keys include account, vault room, item ID/hash and preview specification; secure storage holds the encryption key. Complete vault metadata is separately encrypted and restored before background paginated history replay, so recent-use events cannot push older favorites out of the restored set. Long press → Delete writes the encrypted removal event; failed authoritative deletion retains the item, successful deletion removes it even if disk cleanup fails. Originals above the existing 20MiB/4,194,304-pixel GIF safety budget are not forced through the animation codec; their panel preview uses an unavailable-image placeholder. Verify reopening the panel/offline app restart without repeated original downloads, normal GIF sending remains animated, and deletion persists after restart.
2. **Member search results**: fixed the empty-keyword branch that emitted an empty string. Rows show actual sender avatars and remark-priority names, including departed members. Text displays in full; media displays `[语音消息]`, `[图片消息]`, `[视频消息]`, `[文件消息]` etc. `displayText` is distinct from `visibleText`: existing body-only keyword matching and jump behavior remain intact.
3. **Startup**: removed the loading splash/spinner. Matching local business/Matrix identities may display the restored Messages list read-only while remote verification runs; missing/mismatched identities cannot expose that cache. Once existing business/identity checks pass, Messages is interactive while Matrix synchronization continues. Cached encrypted last events remain visible with safe placeholders. AppHome no longer gates the entire Messages tab on identity-cache initialization. Background identity hydration attaches to the existing list, without waiting for all network profiles/avatars. Preview mode cannot initiate member loads, presence writes or invitation operations. Generation guards protect logout/new-login races.
4. **Friend Message entry**: the previous route awaited canonical-directory lookup, contact/profile preload and all avatar predecoding before pushing RoomPage. Optional identity/avatar network warming no longer blocks navigation. A persisted per-account/peer cache reuses only server-issued canonical room IDs, refreshes in the background, and revalidates encryption, two-person membership and the requested peer on every open. Registration supersedes stale lookups without waiting for them. First-ever uncached room lookup/join/creation still requires the server; no universal millisecond SLA or measured real-device 5s→Nms claim is made.
5. **Moments count**: independent authenticated `/api/v1/moments/new-posts` metadata API applies the existing visibility/history-range rules, excludes own/deleted/unpublished posts, and pages without the old global 500-row truncation. First launch establishes server-time baseline (old history is not counted as new). Per-account pending/viewed IDs persist; startup/resume/Discovery entry refresh in the background. The red numeric badge caps visually at `99+`. Only posts actually displayed in the feed viewport consume reminders; failed loads and posts arriving during viewing are not blindly cleared. Feed has older-page loading so remaining reminders can be viewed. Likes/comments remain separate.
