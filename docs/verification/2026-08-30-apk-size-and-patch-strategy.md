# 安装包体积分析与瘦身 / 补丁更新策略（2026-08-30）

发布：**0.3.11+14**（arm64 64.5MB → **55.0MB**，-9.5MB）。

## 1. 为什么安装包变大（0.3.5 56MB → 0.3.10 64.5MB）

对 0.3.10 arm64 APK 的逐条目分析（压缩后 64.0MB）：

| 构成 | 体积 | 说明 |
| --- | --- | --- |
| 原生库 lib/ | **41.9MB** | Flutter 引擎 11.0MB + Dart 业务代码 11.1MB + WebRTC 音视频 10.9MB + SQLCipher 加密库 5.0MB + crypto/libc++ 3.7MB —— E2EE 聊天 + 音视频通话的技术底盘，固定成本 |
| 动效表情资产 | **16.5MB** | 0.3.6 表情高清化引入：56 枚 256×256 animated WebP（修复毛刺的产物） |
| 矢量表情 SVG | 0.6MB | 225 枚（APK deflate 后） |
| 其余 flutter 资产 | 2.8MB | 闪屏图/图标/字体等 |
| dex + res | ~2MB | |

结论：增长几乎全部来自 0.3.6 的动效表情高清化（原始资产 9.3MB GIF → 16.5MB WebP）。

## 2. 本轮瘦身（已发布）

动效 WebP 编码策略优化（`scripts/prepare_fluent_emojis.py`）：
- **长动画抽帧**：超过 32 帧的动画按等时间间隔抽帧并合并时长（总时长不变）；12fps→8fps 对卡通表情感知轻微，实测该档位体积 **-36%**（单枚 241KB→155KB）。
- 质量参数 60→55（平面卡通无可见伪影），编码器力度 method 4→6。
- 结果：动效资产 16.5MB → **7.5MB（-55%）**；56 枚全部保持 256×256 源分辨率与 8-bit 平滑 alpha——**毛刺修复效果不受影响**（分辨率未动，仅帧数/质量）。
- 回归：表情相关 21 项测试全过（含逐枚 256px 解码断言）；全量 `flutter test` 434 passed。

## 3. 补丁更新的可行路径（建议与说明）

- **系统级差量更新不可用**：应用商店（Play/华为等）的 delta 更新由商店基础设施完成；当前“官网直链下载 APK”的分发方式，Android 只能整包安装，系统不提供差量合成。
- **自建二进制差量（bsdiff/bspatch）**：需自建补丁生成流水线 + 应用内置合成器 + 失败回退整包，基础设施投入大；且 Dart AOT 的 libapp.so 每次发版都全量变化，差量收益通常 30-50%。可作为后续立项评估。
- **推荐中期方案：表情资源走热更通道（已具备基础设施）**：应用内已有资源更新机制（`downloads/resources/$build/resource-manifest.json` + `ResourceUpdateService`）。把 7.5MB 动效表情 + 0.6MB SVG 移出 APK、改为资源包按需下载后：
  - APK 底盘回落到 **~47MB**；
  - 表情/贴纸更新变为**百 KB 级资源补丁**，无需发 APK 版本；
  - 需要产品决策：首装是否内置精简表情包、下载时机（Wi-Fi 优先）与离线回退（未下载时收到的超级表情先以系统字形或占位显示）。
  - 确认后可按此立项实施。
