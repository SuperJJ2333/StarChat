# 四项修复与 Debug 真机交付

授权与设计见 `docs/superpowers/plans/2026-09-10-four-fixes-2083.md`。本次保留原有业务规则，在 main 上修复；工作区原有两项 iOS 中文本地化修改不属于本次提交。

## 1. 评论可见性

**线上根因已经核实**：生产容器的 Moments `dto` 对评论只按动态 ID 和未删除状态查询，未应用仓库中已有的评论者权限过滤。因此不是仅靠手机升级能够解决的问题。生产源码与 HEAD 的逐文件差异保存在本机受限验证目录的 `deployment/*.baseline.diff`。

本地还复现了两处漏洞：评论通知仅检查动态是否可见，可能泄露不可见评论者资料及未读数；只检查浏览者好友关系，不能处理评论者已被动态作者删除好友的情况。现在查询评论、投影头像/昵称/正文、计数、回复目标、幂等回复、评论通知和评论图片访问共同使用 `moment_comment_audience`。非作者浏览者取双方可见好友交集，保留自己和动态作者的既有例外；作者查看自己动态保持原有规则。点赞继续使用既有规则，未扩大本次策略范围。

改动：`services/business-api/app/modules/moments/{service,visibility,media_access}.py`；客户端 `lib/core/cache/cache_repository.dart` 将评论列表元数据缓存升级为 `cache.moments.feed.latest.audience-v2`，不清除图片磁盘缓存。

验证：A/B/C/D/E API 用例覆盖列表、详情、搜索、个人时间线、预览、游标分页、隐藏回复、通知计数、关系撤销、图片能力撤销、作者例外、原点赞行为；最终专项 14 项通过。候选镜像和已部署容器均运行同一独立内存 SQLite 服务验收脚本，通过以上权限检查。后者使用真实已部署代码和合成数据，不是向生产账号写入评论。

## 2. 更多菜单

根因是容器固定宽 176，配合过大的水平留白，内容不能决定菜单宽度。Flutter 现用实际字体、语言和系统字号测量最长文案，容器按文字、图标和设计间距组合；左右内边距为设计 token 8，点击行最小高度仍为 52。短选项组合居中，HTML 演示采用相同 token 和固有宽度。

改动：`lib/ui/components/top_more_menu.dart`、`frontend/src/styles/{tokens,components}.css`。当前默认文字/字号断言宽度不超过 132，即原 176 的 75%；长短文字测量、320 窄屏、2 倍字号、点击与分隔线专项通过。极长文本或极大字号超出物理屏幕时允许菜单内横向滚动，保持完整单行，不缩小系统字号、不换行或省略。宽度缩减指标针对同一默认文案与字号；极端字号不能同时满足固定百分比缩减和完整静态显示。

## 3. 普通群员群公告

复现根因：SDK `Room.getEventById` 的数据库命中路径直接返回缓存事件，而网络路径才解密；服务误以为缓存命中的加密公告已经解密。现在通过现有 SDK 在本地解密后验证事件来源与发布者。普通已加入成员可读，群主/管理员编辑权限保持不变；无公告保持空状态，正文与发布者、发布时间正常投影。现有文档没有独立标题字段，继续显示页面标题“群公告”，不新增文档格式。

改动：`lib/features/matrix/group_announcement_{service,page}.dart`。账号/服务替换及管理权限撤销使旧请求失效，覆盖读取、上传前文件选择/读取、保存成功/失败回调；旧账号结果不能写入或关闭新页面。仅网络传输错误、超时及可恢复服务端错误提供重试按钮；权限、格式、解密不可用及未知错误显示非重试状态，后续同步可重新加载恢复。

普通成员、空公告、网络失败后恢复、账号切换、权限撤销、旧异步结果及错误分类专项共 34 项通过，且各新增缺陷具有修复前失败证据。具体故障根因是在源代码及自动化夹具中复现；没有把这些结果称为用户所有群的真机验收。

## 4. 图片缓存与按需加载

现有磁盘缓存并非完全失效：真实本地 HTTP 用例证明稳定标识下首次加载和再次进入合计只有 1 次请求。实际补齐的问题是 URL 回退 key 未隔离账号、默认下载并发达到 10、失败/损坏图片没有完整重试恢复，以及缺少明确的临近视口预加载范围。

改动：`lib/ui/moments/{moment_media_cache,wechat_moment_image_grid,moment_image_viewer_page}.dart`、`lib/features/moments/moments_page.dart`。

- 缓存 key：可信 API 内容端点使用 API origin + 账号 + 服务端不可变摘要的 SHA256；无可信摘要时使用账号 + 完整 URL 的 SHA256，不删除签名参数。服务端已核实输出 `image_cache_keys`。摘要改变或回退完整 URL 改变会采用新 key；同内容签名轮换保留缓存。
- 内存：沿用 Flutter 有界解码图片缓存；磁盘：最多 200 条、7 天未使用清理，HTTP 有效期决定刷新时机。清理为缓存管理器定期执行，不宣称硬性磁盘字节配额。
- 下载最多 3 并发；SliverList.builder 按需构建，预取范围为视口相邻半屏，保留原有动态游标分页。
- 再次进入优先显示有效缓存；过期缓存先显示再刷新。弱网/离线刷新失败保留成功图片；无可用缓存时显示同尺寸占位及重试。显式重试移除该失败磁盘项和解码错误，损坏图片可重新下载恢复。

验证：34 项专项通过。真实 HTTP 计数：首次/再次读取 1，过期刷新累计 2，离线过期刷新累计 3 但仍返回旧文件；冷启动失败及重试恢复累计 5；批量新增请求总计 17、峰值并发不超过 3。网格和全屏的损坏图片重试各只下载一次并保持加载/失败/成功边界尺寸一致。未把本地 HTTP 结果写成 Redmi 抓包结果。
