## 0. 为什么必须递增版本号

发布前线上是 `0.3.95 / 2132`（`docs/verification/2026-09-17-android-0395-2132-release.md`），
而 main 的 `pubspec.yaml` 仍是 `0.3.95+2132`——新代码若用同一版本号出包，客户端不会收到弹窗，
且不可变文件名会与线上包冲突。故用 `scripts/bump_version.ps1 -Version 0.3.96+2134`（提交 `a4b53386`）
同时改写 `pubspec.yaml` 与 `lib/core/app_config.dart`，并立即通过版本契约门禁。

### 3.1 本次遇到并已脚本化的构建问题（dev-only 插件与 release classpath 冲突）

Flutter 3.44.9 下，`dev_dependencies` 里的 `integration_test`（带 Android 实现的开发期插件）会与
release 构建冲突：

1. `flutter build apk --release` 首先生成**已过滤 dev 依赖**的 `GeneratedPluginRegistrant.java`（正确）；
2. 随后 Gradle 调用的 `flutter assemble` **再次**生成同一文件，且未应用 release 过滤，
   把 `dev.flutter.plugins.integration_test.IntegrationTestPlugin` 写回；
3. Android Gradle 插件按设计**不把 dev 依赖放进 release 编译类路径**（`flutter_tools/gradle` 的
   `PluginHandler`：`flutterBuildMode == "release" && dev_dependency == true` 即跳过），
   于是 `javac` 报 `程序包 dev.flutter.plugins.integration_test 不存在`。

处理（脚本内固化，且**不改变生产插件集合**）：

- `strip_dev_plugin_registrant.py`：在生成文件中定位并移除**唯一**的 integration_test 注册块
  （断言“恰好一处”，移除后再断言文件中不再出现该名字）；若首个构建阶段本身成功（Gradle 任务已 up-to-date）
  则跳过该步骤；
- 第二阶段用 `flutter build apk --release --no-pub` 重建，使工具与 Gradle 都不再重写该文件；
- 构建脚本随后**断言** release APK 的反编译结果里不存在 `integration_test`——
  与已发布 2132 基线一致（其 `decoded/.../GeneratedPluginRegistrant.smali` 亦无该插件）。

脚本：`docs/verification/artifacts/2026-09-18/release-2134/build-android.ps1`（含 `BUILD_2134_OK` 终判）。
