# 2026-09-16 退出账号后 L07/L04 连锁根因修复 + 0.3.92/2121 双端交付

## 现象

iOS 0.3.92/2120：退出账号后，登录页提示“账号已退出：聊天会话暂停失败，请重新打开应用后重试”；
此时只能重登原账号，**登录任何未在该手机登录过的新账号均报“聊天登录未完成，请重试（L07）”**。

## 根因（代码路径确证，与此前 5 秒切换问题同族）

退出账号时 `matrix.suspend()` 负责安全关闭 Matrix 客户端。其中
`_waitForClientOperationsToDrain()` 等待未完成操作收尾，**超时（5 秒）即抛
`E2EE_LIFECYCLE_DRAIN_TIMEOUT`**，使整个 suspend 中途失败：

1. `_bestEffortMatrixSuspend()` 返回 false → 登录页出现“聊天会话暂停失败…”；
2. 更糟的是留下**半挂起态**（`_accessRevoked=true` 而 client 未关闭、卡死的操作仍在
   in-flight）。之后登录**新账号**必须走 `selectAccount`（account_storage 阶段），
   其内部再次 `suspend()` → 卡死操作仍未结束 → drain 再次超时 → 抛错 → **L07**；
   而重登**原账号**走的是保留身份刷新路径，不需要 selectAccount，所以“只能登录原账号”。

为什么“输入过内容/使用过后”更易触发：使用产生的未完成操作越多，drain 越容易超时。
这与此前“会话切换 5 秒等待”同族，都是 drain 超时引发的连锁。

## 修复（commit 81bac4e8）

**挂起是安全关闭，必须必达**：`suspend()` 中 drain 超时/失败改为记录安全日志
（新增 `lifecycleSuspendDrainTimeout` 事件码）后**继续关闭**——`_accessRevoked` 已置位、
全部资源已 revoke，未完成操作的后续访问一律 `E2EE_LIFECYCLE_ACCESS_REVOKED` 拒绝，
数据安全不受影响；`_suspendClient` 正常关闭并保留磁盘数据与密钥。
语义变更以测试锁定（改写 `suspend fails closed…` 用例：超时挂起也必须完成关闭、
数据库原样保留）。
