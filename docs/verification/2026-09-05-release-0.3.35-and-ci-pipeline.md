## 2. CI 服务器下行拉取发布管道（已端到端验证）

**动机**：本地→服务器上行受本地出口带宽限制；GitHub Actions 云端
构建 + 服务器数据中心下行拉取（公开仓库 Release 匿名下载，实测
~1.5MB/s，约为本地上行的 20 倍），签名密钥只留 GitHub Secrets。

**流程**（`docs/RUNBOOK_RELEASE.md` §5）：本地 `release_ci.ps1`
（干净工作树守卫 + 版本三方一致）→ tag `vX.Y.Z` 推送 →
android-release.yml（tag↔pubspec↔app_config 一致性校验 + 签名构建
含全部守卫 + `gh release create` 附 APK×3+SHA256SUMS）→ 服务器
`server_pull_release.sh` 下行拉取（`sha256sum -c` 强制校验后部署、
`ln -sfn` 别名、保留上一版）→ `publish_app_update.py`（幂等发布
更新弹窗）→ 本地公网回拉对照 **GitHub Release SHA256SUMS** + aapt。

**端到端验证证据（v0.3.35 试运行）**：

| 环节 | 结果 |
| --- | --- |
| tag v0.3.35 → android-release 运行 33898886175 | **success**（签名 Secrets 还原、构建守卫全过） |
| GitHub Release v0.3.35 | 4 资产 uploaded：arm64/arm32/x86_64 APK + SHA256SUMS |
| 服务器下行拉取（/tmp 验证，未部署） | 三包 `sha256sum -c` 全 OK，**SERVER_PULL_VERIFY_PASS** |
| 服务器→GitHub 实测下行 | ~1.5MB/s（175MB ≈ 2 分钟） |

⚠️ **0.3.35 双产物说明**：线上已发布的是**本地工作树构建**（含用户
未提交的红包等 WIP 改动，全部门禁在该树上跑过）；GitHub Release
v0.3.35 是 **CI 从提交树构建的验证产物，未部署**（哈希不同）。
下次发布（0.3.36+）一律走新路径——`release_ci.ps1` 的干净树守卫
保证"测过的=发出的"。
