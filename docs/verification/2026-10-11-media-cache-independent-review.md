## Stage 1 — specification and domain

1. **[P2] Last observer leaving during store preparation still publishes a cache object.** At `apps/mobile_flutter/lib/features/matrix/media_cache.dart:1616`, `hasConsumer()` is checked before `await MediaCache.store(...)` at line 1619. That store then yields at verification/root/filesystem boundaries (`631`, `642`, `681`, `711–713`). The new independent source scope at `1706–1714` correctly stays active until actual settlement, but therefore does not carry the changing observer set into those later publication boundaries. `_verifyAndStore` checks scope only at line 633; `_store`/`_atomicBytes` check generation/clearing but not current observers before object publication. Last-consumer cancellation while `_root` is waiting leaves zero scheduler consumers and no object yet; releasing the wait still writes the object. The final caller correctly receives `MediaLoadCanceled`, and byte accounting correctly returns to zero after settlement; disk publication is the failed assertion.

   Independent probe: `late-store-cancel_test.dart`. It uses the actual ConsumerScope, scheduler, byte budget, worker verification and store, and holds only the public path-provider dependency on its first lookup after real digest completion. It verifies the object is absent before cancellation, zero scheduler consumers after it, budget still held, and waits for the real store/scheduler/budget to finish before reading cache. The no-cancel control succeeds. Candidate final run: **1 PASS / 1 FAIL, exit 1**, `candidate-final.log`; observed `synthetic_cancel=true cache_published=true`. Baseline with the same probe and only its new-scheduler-slot assertion disabled: **1 PASS / 1 FAIL, exit 1**, `base-final.log`, same final publication. Therefore classify as an existing gap, not as 44dab's newly introduced root cause.

   Required correction: a private operation publication predicate that checks current consumers and the captured generation at actual store/publication awaits, including after preparation and before promoting temporary bytes. Keep the real source/budget alive until settlement, allow a later observer to rejoin while the source is still live, and remove only the current operation's temporary artifacts. Do not delete another consumer's existing shared object/reference. Add controls for no cancellation, last-observer cancellation during preparation, cancellation during temporary write, rejoin in that window, and generation clear. This is a local lifecycle correction; no encryption/protocol change is required.

2. **Priority root cause and remedy match.** At `1586–1592` the admitted work is defined without reserving bytes; scheduler admission occurs at `1706` before running that work. The source now owns the scheduler slot and byte scope through verification/storage instead of letting a queued prefetch reserve the whole budget in advance. Author's RED measured 201326592 active bytes for a merely queued prefetch; the strengthened priority test requires zero and then observes the later visible source start first. It remains bounded non-preemptive scheduling, not a claim that a later visible task can preempt already-running work.

3. **Observer cancellation and source settlement are correctly separated outside finding 1.** `media_load_scheduler.dart:69` exposes only read-only current-consumer presence; existing scheduler running-task retention and finalizer still control actual slot lifetime. `media_cache.dart:1706–1714` uses a fresh source scope in the captured reservation zone. Canceling the first observer removes its lease without releasing the actual source reservation. The unchanged task key includes generation, account root and media identity (`1528–1567`); a new live observer can join that same source, and the ordinary source-before-settle abandon test checks no publication when cancellation precedes verification.

4. **Full store preparation is now registered synchronously.** `media_cache.dart:578–610` inserts a unique preparation Future before control returns to the caller and removes it on completion. `_verifyAndStore` retains the pre-existing verified-digest deduplication (`638–665`), while account cleanup and playback enumerate matching flights (`216–223`, `747–751`). This closes the observed hash-before-registration playback/clear visibility race without introducing a persistent storage format change. Account and global epochs are still checked before delayed work becomes usable.

5. **E2EE/content authority is preserved.** Verified immutable snapshots and expected plaintext hash validation remain in the client; no key, plaintext, digest logging or API transmission is added. Account is part of cache/task identity (`1881–1890`). Native encrypted transport joining still requires the complete descriptor identity (`1910–1948`), and the revised prefetch test proves different descriptor B receives its distinct HTTP ciphertext while exact A receives its native ciphertext. Under approved ADR-0060, identical trusted plaintext content hashes may intentionally share account-local verified content even when envelopes differ; that is distinct from joining a wrong ciphertext transport and should not be misreported as a defect.
