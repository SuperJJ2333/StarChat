## 2. 逐 BUG 定位与修改

### BUG-01 错误邀请码出现重复提示
- 定位：`features/auth/registration_page.dart`（`_RegistrationPageState._inviteStatusRow` / `_fieldError`）+ `registration_controller.dart`（`register()`）。
- 根因：邀请码提示有**两个出口**。页面 600ms 防抖校验把结果显示在内联状态行（`_inviteStatusRow`）；提交/发送验证邮件时 `register()` 又通过 `fieldErrors['invitation_code']` 走 `_fieldError` 再显示一次 ⇒ 同一失败两条提示。
- 修改：内联状态行在 controller 已持有 `invitation_code` 字段错误时让位（`SizedBox.shrink`）；新增 `RegistrationController.clearInvitationCodeError()`，用户重新编辑邀请码时清除旧字段错误，恢复由状态行展示。一次失败 = 一次反馈。
- 文件：`lib/features/auth/registration_page.dart`、`lib/features/auth/registration_controller.dart`。

### BUG-02 用户协议、隐私政策无法打开
- 定位：`features/auth/login_page.dart`（`AuthAgreementRow(onUserAgreement/onPrivacyPolicy)`）+ `authentication_flow.dart`。
- 根因：两个回调是可选参数，**生产调用方（`AuthenticationFlow`）从未传入**，仓库与服务端也不存在可打开的协议页面 ⇒ 点击无任何反应；`AuthAgreementRow` 又按 `enabled` 渲染品牌绿，视觉上像可点。
- 修改：新增应用内置正文 `lib/features/auth/legal_documents.dart` 与原生渲染页 `lib/features/auth/legal_document_page.dart`（`openLegalDocument`）；登录页在调用方未注入回调时默认打开内置正文。不依赖外部 URL（不会 404）、无 WebView 初始化、iOS/Android 一致、离线可读。
- 文件：`lib/features/auth/legal_documents.dart`（新增）、`lib/features/auth/legal_document_page.dart`（新增）、`lib/features/auth/login_page.dart`。
- 说明：注册页当前设计没有协议入口（登录页勾选是前置条件），未新增 UI。

### BUG-03 通讯录右侧字母索引位置错误
- 定位：`features/contacts/contacts_page.dart`（`_ContactsPageState` Stack/`sectionOffsets`）+ `ui/components/wechat_contact_index.dart`。
- 根因：① 索引字母用 `Column` + `Expanded` 撑满整列高度，与设计契约（`.c-contact-index`：宽 20、字母高 18、`align-content:center`）不符，字母随屏幕被拉伸、贴住导航栏与底栏；② 字母跳转偏移量用魔法数字 `56.0 * 3` 与 `25 + n * 56`，与真实行高无强绑定。
- 修改：索引改为固定 18pt 字母 + 整块垂直居中（上下 12pt 呼吸间距，窗口极小时按可用高度等比压缩，永不溢出）；宽度改用 token；三个入口行用 `SizedBox(contactTileHeight)` 固定高度并让偏移量算式直接引用 `contactTileHeight` 与 `_ContactSectionHeader.height`，跳转偏移与实际布局逐项对应。
- 文件：`lib/ui/components/wechat_contact_index.dart`、`lib/features/contacts/contacts_page.dart`、`lib/ui/foundation/wechat_tokens.dart`。

### BUG-05 修改个人信息保存无成功提示
- 定位：`features/profile/profile_controller.dart`（`ProfileController.save`）+ `profile_page.dart`（`ProfileDetailsPage`）。

- 修改：新增结果事件 `ProfileSaveSuccess` / `ProfileSaveFailure`（`ProfileController.saveEvents`，`dispose` 关闭）；UI 监听后弹出一次性浮层（成功「保存成功」/失败「资料保存失败，请重试」）。失败文案不再同时写入 `state.message`，避免内联 + 浮层重复。新增公共浮层 `showWeChatToast`（根 Overlay，页面 pop 后仍完整显示，遵循「减少动态效果」）。
- 文件：`lib/features/profile/profile_controller.dart`、`lib/features/profile/profile_page.dart`、`lib/ui/components/wechat_toast.dart`。

### BUG-06 全部账单页面优化（仅展示层）
- 定位：`features/ledger/ledger_pages.dart`（`LedgerListPage`）+ `ledger_controller.dart`（新增筛选重置入口）。
- 根因/问题：① 日期筛选胶囊用 `_time()` 输出 `yyyy-MM-dd HH:mm:ss`，移动端不可读；② 空状态是无差别的一行「暂无点钻流水」，不区分「没有账单」与「筛选无结果」；③ 无筛选摘要/重置入口；④ 列表无日期分组。
- 修改：新增 `formatLedgerFilterDate`（只到日）与 `formatLedgerDayLabel`（今天/昨天/M月d日/跨年补年份），列表按自然日分组插入日期标题；空状态改用 `WeChatEmptyState` 并区分两种情形（筛选无结果时给「清除筛选」）；有筛选时显示摘要行 + 「重置」；`LedgerController.clearFilters()` 一次清空类型/时间/关键词只发一次请求。**未改**转账逻辑、钱包计算、数据模型与查询语义。
- 文件：`lib/features/ledger/ledger_pages.dart`、`lib/features/ledger/ledger_controller.dart`。

### BUG-08 减少动态效果无效
- 定位：`app_home.dart`（`_SettingsTile('减少动态效果', detail: '跟随系统', onTap: () {})`）+ `main.dart`（`LiuhetongApp`）。
- 根因：该行是**不可交互的占位**：没有开关、没有本地持久化、没有任何组件读取它。动效组件只读系统级 `MediaQuery.disableAnimations`；`CupertinoPageRoute` 转场时长是固定 500ms 常量，只有**系统**无障碍开关才会让 `AnimationController` 缩短时长。
- 修改：① `lib/ui/motion/motion_preferences.dart`（SharedPreferences 持久化 + 写失败回滚）、`lib/ui/motion/motion_page_route.dart`（`MotionPageRoute`，减少动态效果时转场压到 5%≈25ms，与框架处理系统开关的幅度一致）；② 设置页改为真实开关行（`settings-reduce-motion-switch`）；③ `main.dart` 启动即加载并把设置投影为根级 `MediaQuery.disableAnimations`，所有动效组件（菜单/点赞/按钮/图片帧）与路由立即跟随；④ 全应用页面跳转由 `CupertinoPageRoute` 机械替换为 `MotionPageRoute`（42 个文件，纯同义替换：仅转场时长不同）。
- 文件：`lib/ui/motion/motion_preferences.dart`（新增）、`lib/ui/motion/motion_page_route.dart`（新增）、`lib/app_home.dart`、`lib/main.dart`，以及 42 个路由调用文件。

### BUG-09 新增好友标签无法展示
- 定位：`features/contacts/request_friend_page.dart`（`_RequestFriendPageState._createTag`）+ `contact_models.dart`（`AddFriendGateway`）。
- 根因：申请好友页「新建标签」只把名字塞进**本地** `allTags` 并选中，**从未调用 `POST /contact-tags`**。标签表里没有这一行 ⇒ 通讯录「标签」页（`GET /contact-tags`）永远看不到新标签，也无法参与按标签的朋友圈可见范围（服务端 `_resolve_audience` 以 `ContactTag.id` 反查名称）。
- 修改：`AddFriendGateway` 增加 `createContactTag`；`_createTag` 改为先落库（含重复名/失败处理与「添加中」态），成功后以服务端标签列表刷新并自动选中；失败给出可读错误且不假装成功。
- 文件：`lib/features/contacts/request_friend_page.dart`、`lib/features/contacts/contact_models.dart`；测试替身同步（`add_friend_search_test.dart` 等）。

### BUG-10 黑名单设置无效
- 定位：`features/contacts/contacts_page.dart`（`_ContactMorePageState`）、`core/permissions/interaction_permission.dart` 的唯一生产调用点 `features/matrix/room_page.dart`（`isBlocked: false` 写死）。
- 根因：① 开关初值恒为 `false`，从不读取服务端 `GET /blocks` ⇒ 重开 App 状态丢失；② `_setBlocked` 只处理「开」，关掉时直接 return ⇒ 无法取消拉黑；③ 确认框确认按钮文案是「删除」；④ 聊天发送门的 `isBlocked` 是写死的 `false`，拉黑对互动没有任何影响。
- 修改：新增 `lib/core/permissions/blocked_contacts.dart`（进程内投影，账号级、登出清空）；`ContactsGateway` 增加 `blockList()` / `unblockContact()`，`BusinessApiClient` 实现 DELETE `/blocks/{id}` 并在拉黑/取消拉黑后更新投影；设置页从服务端读回真实状态（未读到前开关禁用，不用默认值冒充）、双向可操作、成功后立即更新投影、失败给可读错误；`AppHome` 启动同步一次；`RoomPage.canSendNow` 改用投影（去掉写死的 `false`）⇒ 拉黑立即生效，重开 App 仍生效。
- 文件：`lib/core/permissions/blocked_contacts.dart`（新增）、`lib/features/contacts/contacts_page.dart`、`lib/features/contacts/contact_models.dart`、`lib/core/business_api_client.dart`、`lib/core/session_bootstrap_controller.dart`、`lib/app_home.dart`、`lib/features/matrix/room_page.dart`。
