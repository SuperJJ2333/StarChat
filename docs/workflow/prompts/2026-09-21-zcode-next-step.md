## 不得改变的需求

- 中国大陆 +86 手机或邮箱二选一注册；手机号验证码登录。已绑手机换绑必须旧手机验证码→新手机验证码，只有未绑手机的邮箱账号才能邮箱验证码→新手机验证码。手机号搜索为完整号码精确搜索，支持隐私开关、限频和无手机号泄漏的公开资料卡。
- 点钻内部资产代码 CAIBI，1 点钻=1 CNY，旧余额数值与历史订单不重写。外部充值付款/提现出款仅 USDT，内部红包/转账仍点钻；不新增 USDT P2P/红包。
- 用户直接兑换和在线自动充值关闭；旧写接口明确拒绝，历史可查，既成资金事实不得删除或伪取消。
- 汇率由服务端指定 apihz USD/CNY 来源按需访问，持久共享缓存 60 分钟，无用户请求零调用。1 USDT≈1 USD 仅参考估算，明确最终以客服结算为准。供应商报价不是逐笔实时市场价。配置中的 API 凭据不进代码、日志、前端或文档。过期参考可展示，不可用于自动资金结算；full_backing 有点钻负债而无新鲜报价必须拒绝。
- 手工调整结算率无需用户二次确认、第二人复核或新增金额审批；保留其他既有支付密码、TOTP、审批、限额、余额、幂等、审计和 Outbox 约束。按现有 ADR-0077 的差额规则执行，不擅改财务公式。
- 手续费 0.5%，发送者在本金外承担；群主抽成 0.1% 本金，从已保留手续费中支付到个人点钻钱包，不设满 10 人门槛，不建群钱包。满 10 个实际 joined 成员时，仅群主在本群发红包免手续费，免手续费不发抽成。最低费、舍入、退款政策保持原样。抽成在 COMPLETED 同事务一次结算，退款 FORFEITED，创建时受益人快照不可随转让漂移。
- 满 10 人的群转让时检查当前群主自接任起是否任满 30×24 小时；人数达到 10 不重置任期。历史未知任期不能编造，少于 10 人不擅加永久限制。

## 第一批：后端上线阻断项

1. **完成群主转让协调流程。** 当前端点刻意返回 GROUP_TRANSFER_UNAVAILABLE，不能删掉此保护并恢复“数据库先改、客户端随后改 Matrix”的虚假成功。设计并实现持久转让操作（幂等键/请求摘要/预期旧群主与版本/阶段/失败原因），在服务端核验当前权限、joined 和任期后协调 Matrix 操作，读取权威事件确认结果，再推进财务群主/接任时间。对超时、不确定结果、进程重启、数据库提交失败、重复请求与并发转让提供可恢复路径。不要向服务端交 E2EE 密钥或明文。实际网关能力必须从现有代码/协议核实，不假定“Synapse 没有接口”，也不假定普通 HTTP 请求与 SQL 同一事务。测试旧客户端直接改 Matrix power levels 的路径；业务端点关闭只防止业务登记虚假成功，不能被当作所有 Matrix 客户端均受冷却约束的证据。安全审查和故障注入通过前保持端点不可用。
2. **补齐人工充值案件与财务执行绑定。** 当前 mark_credited 只消费已执行且匹配的真实调整凭证，不会入账；保留这些检查。建立一个案件只允许关联一个授权财务命令的持久绑定，经既有公开财务服务完成审批/执行，再幂等完成案件，支持执行后宕机自动恢复登记。不要直接写跨域余额/表，不要通过“重建调整”补失败登记。测试同凭证跨案件、错误用户/金额、撤销/冲正、重复回调、并发处理与取消竞争；确保无多次入账和虚假 CREDITED。
3. **接入真实 SmsSender 适配器与应用装配。** 提供可用的供应商配置验证、测试沙箱适配、超时/失败处理和监控；未配置继续 fail-closed。既有 app 路由测试的 RecordingSmsSender 不是生产实现。凭据外置，OTP 不入日志/Outbox 明文。验证多 worker 配额、5 次尝试、用途/目标/会话隔离、重放与两步换绑。真实通道凭据缺失只阻断真实发送验收，不编造通过，也不阻断无依赖代码测试。
4. 先做规格符合性审查，再做质量/安全审查。受保护的认证、财务状态机与接口变更要更新 ADR/计划并保留审查记录。不要擅自引入新的商业规则；遇到确实需要业务决定的分支，说明已完成内容和具体选项。

## 第二批：后台三页

- 人工充值案件：待处理列表、用户及资产单位、参考快照/是否过期、最终结算率与金额、实际凭证、审批/执行/登记状态与恢复入口。前端不能凭提交成功就展示已充值。
- 官方客服目录：列表、创建、修改、停用；使用按 ID 更新接口，鉴权、审计、地址网络标识与历史痕迹齐全，普通用户只看到启用条目。
- 汇率/钱包展示：点钻账面数量、参考 USDT 估值、实际 USDT 应付分开；显示更新时刻与过期状态。提现原报价、最终应付、调价记录与执行状态不能混用。
- 遵守仓库当前有效 UI 交付流程，功能实现与契约同步，不交静态假按钮。
