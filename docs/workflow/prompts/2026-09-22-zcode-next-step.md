## 不得回退的规则与修复

- 手机/邮箱二选一注册，大陆 +86 短信登录。已绑手机只能旧手机验证码→新手机验证码；未绑手机才允许已有邮箱验证码→新手机验证码。完整手机号精确搜索、隐私开关、限频和公开资料脱敏不变。
- 阿里云 Code=OK 不等于验证码正确；仅 VerifyResult=PASS 且 challenge 对应的 OutId 匹配可通过。保留用途/签发隔离、发送失败不可激活、五次尝试、单次消费及邮箱本地校验路径。
- SDK 及传递依赖已同步 requirements.lock。修改 pyproject 时必须更新 Docker 的锁文件并验证 pip check，不能仅靠本机已安装依赖通过测试。
- 1 点钻=1 CNY；旧数字与历史不重写。外部收付款仅 USDT，内部红包/转账仍点钻；关闭用户兑换和自动充值，历史保留。汇率服务端按需共享持久缓存 60 分钟，1 USDT≈1 USD 只作参考，不把每次展示变成上游请求，凭据不得出现在前端或日志。
- 手工结算率调整不新增用户确认、第二人复核或金额审批；保留其他既有支付密码、权限、TOTP、财务执行审批、幂等、审计及 Outbox。不能把“调整汇率免审批”扩大成全部财务写免审批。
- 手续费 0.5%，发送者在本金之外承担；群主 0.1% 从手续费中分到个人钱包，不设满 10 人门槛，不建群钱包。满 10 个 joined 成员时只豁免群主在本群发红包的手续费；免手续费不产生抽成。最低费、舍入和退款沿用现状。
- 满 10 人时，转让检查当前群主接任是否满 30×24 小时；不能编造旧群任期或擅加“曾满 10 人永久限制”。
- 充值 BOUND/NEEDS_REVIEW 保留有效绑定；已执行未冲正的登记失败不能释放绑定、取消案件或另建调整再次充值。登记和入账是两回事。保留 0081 迁移、终态历史、快照和账本锁顺序。
- 转让不确定发送不自动重发；保留整个 power_levels ACL，核对目标成员/身份及每房间唯一未决操作。端点与 worker 的启用开关默认关闭。不能把数据库事务说成与 Matrix 原子提交。

## 第一批：完成剩余流程，不急于开启生产

1. 先列实际缺口与验收表。充值 NEEDS_REVIEW、转让 NEEDS_REVIEW 的查询、审计时间线与人工处置流程必须明确。区分“只读核实”“依据既成事实完成登记”“已确证未执行后的重新发起”；不能把超时视为失败并重复资金或 Matrix 写入。任何会改变既成资金/权威群主的处置须按已批准 ADR 和公开领域接口执行，不直接改表；若现有规则不足，交付可审查方案并明确缺哪项业务决定。
2. 扩展管理端案件分页、历史查询、绑定/审批/执行/登记状态、失败原因和最终结算快照。现有单面板不等于完整工作台。目录必须能查看停用条目并恢复；沿用 PUT 与按 ID 更新。补实际 HTTP 契约测试、真实 DOM 交互与完整 admin 外壳下的界面验收，覆盖无权限、空数据、网络失败、重复点击和恢复刷新。
3. 在隔离 Synapse 测试真实转让：完整 ACL 不变、目标退出/封禁、旧客户端改权、并发请求、进程中断、发送已成功但返回丢失、观察失败和数据库提交失败。记录 Matrix 事件 ID 与业务意图对应关系；不接触 E2EE 密钥或消息明文。真实一致性和待核对流程未验收前保持开关关闭。
4. 核对真实阿里云账户是否接受按 challenge 派生的 SchemeName、OutId 回传，以及签名、模板、country/code_type 和中央 endpoint。优先 SDK/替身与离线测试；需要真实短信时先明确账号、测试号码与发送授权。不能拿替身 PASS 代替真实通道结果，也不能通过取消用途隔离兼容供应商。
5. 新代码涉及认证、财务状态机、账本或破坏性契约时先同步 ADR/计划，并依次完成规格符合性、质量/安全审查。保持 0081 历史迁移不可破坏回退。
