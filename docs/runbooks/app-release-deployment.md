# 安装包传输与发布职责

**Current · 2026-09-20**。本文只保留工件传输、备份与切换边界；页面、安装清单、弹窗设置及验证统一遵循[轻量发布门禁](release-metadata.md)，不再维护第二份发布命令。

1. 按[生产工作流](admin-production-workflow.md)读取当次实际文件、设置和运行基线，使用既有jumper；保留TLS和主机密钥验证。
2. 构建工件与签名交接已准备好后，上传到唯一任务暂存目录，再落为不可变版本文件。大文件可分块、顺序、可续传；未完成上传不清理分块。保留本地/服务器上传完整性控制，取消重复公网下载验包。
3. 不覆盖旧包；Android latest别名按本次实际提供的ABI管理。切换别名和发布设置不是数据库与文件系统的跨域事务，必须各自记录前后状态和回退路径。
4. 使用单一release JSON运行prepare/check/publish。HEAD证明可访问和大小，小文件解析证明安装清单与页面一致；均不能证明签名有效或设备安装成功。
5. 发布器保存0700备份，先验证页面再写单平台设置与审计；更新说明和最低支持版本默认保持。失败按[门禁恢复规则](release-metadata.md)处理，不盲目覆盖后续版本。
6. 后台/API/钱包/Matrix部署进入[生产工作流](admin-production-workflow.md)及相应专题，不能把移动包发布当作服务端变更授权。

[历史正文及当次部署链接](../archive/2026-09-20/runbooks/app-release-deployment.md)仅用于溯源。其中旧完整下载、短文本数据库限制及固定镜像不得当作现行约束。
