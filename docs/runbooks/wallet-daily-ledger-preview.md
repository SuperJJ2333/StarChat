# 钱包日流水预览与导出

本接口用于财务核对两个内部账本，不能代替真实托管对账或日终封账。

## 访问

已登录且具有 `FINANCE_REVIEW` 权限的财务账号或系统管理员可访问：

```text
GET /api/v1/admin/wallet/reports/daily?day=2026-09-06
GET /api/v1/admin/wallet/reports/daily?day=2026-09-06&format=csv
Authorization: Bearer <当前财务会话>
```

日期为香港自然日；2026-09-06 对应 UTC `[2026-09-05T16:00:00Z, 2026-09-06T16:00:00Z)`。将账号会话放入受保护的客户端会话管理，不写入命令日志或报告文件。未登录 401、普通账号 403、非法或未来日期 422。接口不依赖托管商，不会调用资金写入接口。

## 核对

`accounts` 按资产及账户展示期初、增加、减少、期末，必须满足 `opening + increase - decrease = closing`。平台对手账户、提现冻结账户和点钻托管账户均保留，不把平台对手分录算作用户收入。USDT 保留六位、点钻两位，返回金额都是字符串。

`entries` 提供对应分录 ID、账本来源、交易 ID、金额、时间、业务作用域及原因码。期初证据标为 `opening`，当日变动标为 `movement`。因此不仅包含充值提现，也覆盖已经通过这两个账本过账的兑换、调整、转账、红包以及冲正。未过账申请、外部归集和手续费若尚无账本分录，不会凭空出现在报表里。

`integrity` 检查每笔交易在每个资产内的平衡。两笔错误互相抵消时仍报告失衡。发现失衡应进入既有事故调查流程，不能删除或改写历史分录消差。此只读接口不自动解除或设置资金熔断。

`digest` 是所捕获 JSON 内容（不含 digest 字段）的规范化 SHA256，便于比对保留的导出证据；它不是外部数字签名或防数据库管理员篡改证明。接口读取同一数据库查询快照，`finalized=false` 表示未封账。随后提交的回溯日期分录可能让再次查询得到不同摘要，不得用日期相同推断内容必然相同。

## 导出与限制

CSV 使用相同报表内容及摘要；文本字段进行公式注入防护。摘要按原始 JSON 计算，需要复核时同时保存 JSON，不能直接对 CSV 文件字节求哈希后比较。下载与查看都会写入审计，记录操作者、日期、格式、摘要及请求追踪。成功和错误响应均禁止缓存；没有导出完整托管地址、认证材料或聊天内容。异常资产/精度证据返回 409 `WALLET_REPORT_DATA_INVALID`，不会误报为日期输入错误。

在线完整证据最多 100,000 条（含期初历史分录），超过返回 413 `WALLET_REPORT_TOO_LARGE`，不会静默截断或输出看似完整的期末。大账本需后续的持久化期初快照与异步封账导出方案，本版本不能通过提高客户端分页长度绕过限制。

持久化截止序号、独立不可变归档、正式日终封账、待处理充值/未知提现账龄视图、告警投递及案件闭环仍需后续实施。
