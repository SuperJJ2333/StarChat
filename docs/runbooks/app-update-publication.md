# App 更新配置发布与回退

更新配置的五个字段为版本名、构建号、最低支持构建号、更新文案和 APK URL。
管理 API 保持文案 1–2000 字符、URL 1–500 字符的契约；0038 将
`app_settings.value` 从 VARCHAR(255) 扩为 TEXT，避免合法请求在数据库层失败。

## 发布顺序

1. 先验证最终 APK 的版本、ABI、固定签名及 SHA256。正式发行构建号必须递增。
2. 上传到私有暂存目录，服务器核对 SHA256 后才放入下载目录的不可变版本文件名。
3. 从公网完整下载并核对 SHA256。此时还不更改更新提示和 latest 链接。
4. 通过管理 API 发布五个字段。`SettingService.set_many` 在一个事务内更新
   设置与审计；PostgreSQL 事务级锁序列化批量发布，包含首次发布。
   管理和客户端读取均使用 `get_many` 的单 SQL 快照。
5. 原子替换 latest 符号链接，复查 API 设置与下载响应。数据库和文件系统
   不是分布式事务；即使切换链接失败，API 的不可变 URL 仍指向完整的新包，
   旧链接仍指向完整的旧包。修复链接后复核，不删除旧包。

通过受控运维通道运行应用内发布脚本时，必须先通过 `AppUpdateSettingsBody`
校验，并使用一次 `set_many`，记录明确的 actor/trace。禁止循环调用 `set`
逐项发布。后者保留给既有单项设置业务。

## 0038 独立迁移与应用回退

2026-09-06 线上基线为 0036，0037 钱包迁移尚未部署。0038 直接从 0036
分支；仓库 0039 仅合并 0037/0038 的迁移图，不含 DDL。本次线上镜像只新增
0038，因此升级到其 head 不会带入钱包变更。未来全量部署前应独立审查尚未
上线的 0037，不能将 `upgrade head` 当成本次修复的授权范围。

扩容在事务中执行，线上使用 5 秒 lock_timeout 和 30 秒 statement_timeout；
获取不到锁时失败并保留原 schema。默认回退保留 TEXT，只恢复旧应用代码，
旧代码可读取 TEXT。回退镜像也必须携带 0038 的迁移定义，否则旧镜像的
Alembic 不认识已登记的 revision。

确需收窄时，0038 downgrade 先锁定表，再检查是否存在超过 255 字符的值。
存在则整笔迁移失败，不允许截断。此操作不是常规应用回退步骤。

## 验收

- API 接受 2000 字符文案、500 字符 URL，超出上限返回 422。
- PostgreSQL 验证 Unicode 长值往返不变；迁移前的短值保留。
- 任意设置或审计写入失败，整批设置和新增审计全部回滚。
- 竞争发布的结果和 audit before 值正确，读取不会拼接两个版本。
- 旧版本 APK 保留；新下载内容、版本、签名和发布设置一致。
