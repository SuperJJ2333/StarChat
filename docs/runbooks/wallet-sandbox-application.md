# 钱包应用 Sandbox 操作边界

2026-09-06：实现已接入 WalletService、Ledger 公共接口、业务 API、Worker 和 Flutter 钱包页。仅允许隔离测试。生产环境的托管工厂仍返回 unconfigured，不能通过打开兑换设置启用真实资金。

## 配置及启动

在独立测试环境使用 `environment=test`、`wallet_conversions_enabled=true`、`wallet_confirmation_threshold=20`。持久模拟托管可配置 `wallet_sandbox_store_path` 为仓库外受保护目录；未配置时仅为内存模拟器。业务数据库和模拟器数据库须隔离于生产。不要把测试 JWT、签名密钥或数据库加入 Git。

先用模拟托管生成充值证据并通过应用充值入口入账，再刷新独立资产证据。不能只调用 `credit_for_test` 后假定平台已有外部资产。所有可兑付点钻（含托管/冻结账户）都纳入储备；历史点钻储备不充分时保持兑换关闭。

API 兑换使用字符串金额与 `Idempotency-Key`；方向为 `USDT_TO_CAIBI` / `CAIBI_TO_USDT`。USDT 小于点钻精度的尾数留在原余额。提现头部幂等键必须等于 `client_order_id`。原请求未知时复用原键与金额地址，禁止重新生成意图。

## 处置原则

- 提现申请时冻结资金；经过两个不同且非申请人的审批后才可提交。Sandbox 单笔范围 10–100 USDT，滚动用户上限 200、平台上限 500。
- 只有提交意图之前允许取消。提交中或未知状态保留冻结，查询原外部订单。已确认链上付款不能撤回；账本差错通过关联冲正处理，不能删除历史。
- `WalletMaintenanceTask` 查询提交中、未知和外部已受理订单，并检测外部孤儿订单、执行对账。回调不能单独触发最终结算。
- `snapshot_report` 提供全量负债、合格资产、缺口、未知订单等汇总；风险限制通过公共账本接口保守冻结可兑付资产的所有出向操作。不得手工改表恢复。
- 旧提现缺少可证明冻结/请求摘要时必须人工核对重建，不能自动补付或退款。
