# 文本 Outbox 自动重试与升级

本页描述2026-09-23本地增量候选，不代表已发布。验收见[专项报告](../verification/2026-09-23-remaining-optimizations.md)。

## 重试语义

文本沿用既有账号隔离的本地 Outbox 和稳定 Matrix 事务 ID。`retryCount` 是累计认领尝试代次（包含发送前检查或租约失败后的认领，不等同于 SDK 网络请求次数）；新增 `serverRetryCount` 只记录可重试服务器失败消耗的预算，两者不可互相替代。首次发送之外最多自动重试三次，基础等待2/5/15秒，并且不缩短服务器 Retry-After；超过15分钟的服务器等待要求按既有策略停止自动重试，等待用户处理。

`nextServerRetryAt` 是持久化的最早派发时刻。定时器只负责唤醒，数据库条件认领负责判断能否发送。前台页面关闭、后台接管或进程重新启动均不能重置预算。永久拒绝不自动重发；断网和进程内的观察超时不能冒充服务器失败消耗预算。

进程内 SDK 请求尚未完成时，观察超时不能释放其认领。只有持有相应认领的操作结果能结算对应尝试；迟到或重复结算必须通过状态和派发代次条件检查，不能更改后来的尝试。账号切换不能让旧消息进入新账号。真正进程重启后按既有恢复流程处理未决记录，仍保留原事务 ID，不创建第二条消息。

手动重试只能针对允许重试、非 sending 的当前账号记录，重置本条服务器预算后继续使用同一事务 ID。不允许自动发送者认领 failed，也不允许离线状态处理将其他发送者拥有的 sending 改回等待。

## 本地 SQLite 升级与回退

保留文件名 `chatflow_outbox_v1.db`，schema升级至2，新增预算整数（默认0）和可空期限列。旧消息正文、账号、事务ID和状态保留；不从历史总派发次数猜测服务器重试次数。升级只加列，不清库或重建密钥库。

**不能把客户端源码回退等同于数据库回退。** 原版本按schema1打开时可能拒绝schema2；发生问题优先采用兼容schema2的前向修复。不得删除Outbox、强制降版本或恢复已过时数据库来绕过打开错误，否则可能丢失待发送记录或复活旧记录。若发布流程要求恢复完整备份，须先证明备份与已发送事务、当前账号状态一致；本次没有在生产执行恢复操作。

这项优化不提供附件字节续传。SDK附件修复仅复用同次请求中已上传成功的阶段，杀进程后附件恢复仍需独立方案。
