# 移动刷新恢复协议交付检查

适用[ADR-0080](../adr/0080-mobile-refresh-recovery.md)。这是交付约束，不是生产执行记录。先遵守[生产工作流](admin-production-workflow.md)及[移动工作流](mobile-delivery-workflow.md)。

## 顺序和兼容

1. 从最终审查提交构建候选，确认所有认证文件与OpenAPI匹配；读取当时真实运行镜像/配置/schema，不能把调查时的镜像当永久生产基线。保留JWT/issuer/数据库及已有运行配置，不旋转密钥作为部署步骤。
2. 核对迁移图。本任务0080接0071；主目录另有0072–0078未提交变化，集成时必须明确建立单一head，不能只按数字执行或覆盖另一任务迁移。先在隔离既有库快照证明保留旧refresh行和会话有效性。
3. 备份当前可回退镜像和配置；执行仅加可空operation_hash/result_key_version的扩展迁移。旧服务可读取额外列，不删除/清空令牌和设备表。
4. 发布兼容API，验证不带operation_id旧刷新仍可用、新协议同操作返回同一刷新结果、日志及错误响应不含凭证。验证只用专用测试账号，不挤掉用户正在使用的会话。
5. 客户端候选包含持久pending协议及本次错误分类。需同时合入仍独立的iOS重启/权限修复；不得用早期2145包声称已包含本次改动。Android遵守APK重建与固定签名流程，iOS按已授权TestFlight路径交付。
6. 不变更强更/最低版本或自动更新弹窗，除非任务另有明确授权。新包安装需保留原安全存储/数据库/签名身份，禁止卸载清数据来代替恢复验证。

## 回退边界

- 新客户端已投放后，回退服务必须保留新刷新协议处理。回到完全旧API会返回422并使新客户端暂时离线，不能声称可无感回退；禁止客户端删operation字段重试。
- schema降级保留新增列/数据；重复升级须能识别既有列，已做红绿验证。不要使用drop列/清理refresh行作为回退。
- 不向已使用pending协议的手机强制降级旧App；旧App不能安全继续新协议pending流程。
- 明确撤销/过期/真实重放仍要求用户认证；不恢复已撤销族，不用后台密码登录绕过安全策略。

## 双端现场验收

同账号在单台设备分别验证Android、iOS：后台返回；刷新请求发出后断网；返回结果时安全存储临时不可用；恢复联网；进程结束/系统重启后继续同一操作。不得同时登录第二台来混淆单设备替换行为。

确认聊天库与账号身份保留、无错误顶号提示、无重复弹窗；恢复后业务请求成功。另用独立测试账号验证真实新登录替换/主动退出/封禁不会被迟到响应复活。已有60天滑动期限和15分钟access期限不变。

诊断阶段闭集可观察网络/存储/恢复结果，无原始凭证、账号、聊天内容。退出后的客户端批次可能无法上传，服务端已提交撤销的固定日志与数据库原因作为终止事件证据；不将无日志推断为无异常。
