# 窗口外充值人工补录

本流程对应 [ADR0069](../adr/0069-manual-deposit-cases.md)。用于已确认到账、已记录待分配收据，但不存在正常或五分钟容差窗口内可用充值订单的情况。当前实现及发布状态以[任务记录](../workflow/tasks/2026-09-13-manual-deposit-cases.md)为准，源码完成不等于生产已上线。

## 操作

1. 由配置的钱包负责人完成现有钱包验证，打开“USDT提现与支付 → 官方钱包链上流水 → 充值补入账 → 超时/无匹配订单：人工补录”。
2. 核对系统展示的链上交易、日志索引、金额、历史地址绑定和归属用户。用户归属由交易区块对应的唯一历史绑定确定，不能任意输入受益人或修改金额。系统同时检查收据未入账、没有可用普通订单、链证据与资金门禁。
3. 填写核对依据并确认归属，创建补录单。此时没有入账。历史事实不改写，也不伪造或重复使用普通充值订单。
4. 负责人检查补录依据，填写批准或驳回的理由并明确确认。审批作为独立记录保存；批准仍不代表入账。驳回记录保留，必要时重新核对后建立新补录单。
5. 批准后执行预检，核对90秒有效期内的确认内容，再勾选并点击“确认入账”。服务端在提交前再次检查权限、链证据、归属、未重复入账和储备。
6. 以最终 `EXECUTED` 状态和账本交易编号判定入账成功。用户充值记录通过已关联的收据显示；旧订单状态和原始异常原因保留供审计。

## 异常与恢复

请求超时不代表失败。资金提交结果未知时，保留按账号、交易及日志索引保存的操作编号，只查询原操作结果。确认查询返回404后，可显式重新预检，仍沿用原操作编号；系统不会自动重新提交资金请求。创建补录单结果未知时，先查询历史记录，必要时显式使用原创建键和原内容重试。

`ORDINARY_INTENT_AVAILABLE` 表示存在可用普通订单，应返回普通补入账流程。没有唯一历史绑定、证据冲突、重复入账、账户限制、储备或权限过期时，先处理对应原因，不能通过更换用户、篡改时间或绕过审批解决。

同一链事件最多产生一次入账；新补录单、不同请求键或重复点击都不能增加第二笔余额。审批、命令、账本、义务变化、证据审计和事件写入必须在各自规定的事务中保持一致。

## 发布与回退

上线需先验证0066迁移及应用契约，并按管理后台发布工作流执行。停止新写可关闭人工修复开关；结果查询保留。应用回退保留新增表、收据列和全部财务历史；不能删除账本或破坏性降级来撤销已入账记录。资金纠错需使用批准的关联冲正流程。
