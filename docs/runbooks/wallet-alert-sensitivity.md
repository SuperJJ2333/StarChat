# 钱包数据源告警与邮件

2026-10-05 用户批准方案，见[计划](../superpowers/plans/2026-10-05-wallet-alert-sensitivity.md)和[发布证据](../verification/2026-10-05-wallet-alert-sensitivity.md)。

监控只记录事故及通知；钱包暂停和解除由管理员通过既有鉴权、近期验证、幂等和审计接口操作。诊断连续性表不授权资金操作；数据不足时资金证据检查仍拒绝相关动作。

已确认的网络传输错误、HTTP 429/5xx、数据过期、采样不稳定及对账等待连续 600 秒才通知。同次持续故障去重，重启沿用数据库计时；连续三次递增的不同有效观察确认恢复。MANUAL_SOURCE_UNHEALTHY 通知保持 P1；精确 SOURCE_READ_BUDGET_EXPIRED 沿用此前 T2。余额差额、身份/格式/时钟/基线异常及未知原因即时通知。诊断状态无法使用时走既有监控失败告警，不能永久静默。

邮件读取事件发生时保存的不可变诊断，说明中文问题、事件/事故 ID、北京时间、首次与当前原因、持续时长、脱敏采样证据、操作影响及建议。上下文只允许原因枚举和有界整数；不得保存异常原文、钱包地址、余额或凭据。历史事件无诊断时明确标为未记录，不能事后猜测网络原因。HTTP 鉴权/无效 JSON 不分类为临时网络错误。

上线顺序：按当次实际镜像增量构建；隔离恢复 PostgreSQL，验证最终镜像与兼容回退；先 expand 0095_wallet_source_alerts，再通过 refresh-release-guards 切换 API/worker，最后切换 watch 源码挂载。回退保留 0095 表与新邮件消费者，验证 cause_changed 排队事件及旧 SMTP 回执重放，再经同一镜像门禁恢复旧监控策略。敏感 Compose、数据库备份只留服务器 private 目录。
