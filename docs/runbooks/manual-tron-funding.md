# imToken 人工出款首版操作与验收

依据： [ADR-0013](../adr/0013-trongrid-single-source-manual-payout.md)。本文是待实现路径的操作契约，不代表功能已上线或资金已启用。实现进度见 [实施计划](../superpowers/plans/2026-09-07-manual-tron-funding.md)。

## 上线配置

仅通过既有受保护的部署配置渠道设置官方地址、网络、钱包配置版本、TronGrid 凭据、费用策略和限额；不要将真实配置写进 Git、截图或聊天。服务器不保存 imToken 助记词或私钥。

上线前需记录以下非秘密的验收结论：

- 官方钱包控制者与付款操作员角色；imToken 中核对网络和官方地址，确认具备支付网络费用的资源。不得以截图代替控制权验收。
- 官方钱包拥有者的管理员账户、角色和独立操作密码已配置；首版采用用户明确选择的 `OWNER_MANUAL_V1`，由该管理员确认和付款，不要求第二审批人员，不记录虚构的第二审批。
- 用户绑定消息签名已在所声明支持的钱包和设备上实测；官方 imToken 转账能力不等于用户绑定签名能力。
- 充值意图有效期、单笔及日限额、储备基线、告警接收者已明确设置。USDT 服务费显式配置为零；充值与提现本金最低均为 10 USDT；TRX 网络费由官方钱包承担。
- 观察起点、启用时间及配置版本已记录，历史观察记录不自动入账。数据库备份、恢复和暂停演练已完成。

2026-09-07 已确认的提现上限为：单笔 100,000 USDT、每用户滚动 24 小时 100,000 USDT、平台滚动 24 小时 10,000,000 USDT。统计须包括仍冻结或待核实的申请，不能通过重复申请或午夜换日绕过；实际余额和储备不足时仍拒绝。告警收件邮箱已由用户指定，上线时通过受保护配置接入并验证实际投递，不能以后台出现告警代替邮件送达。

新增配置使用 `BUSINESS_` 前缀：`WALLET_REAL_MODE=manual_tron` 选择真实适配器，`WALLET_REAL_FUNDS_ENABLED=false` 保留资金关闭。还必须设置 `WALLET_TOTP_ENCRYPTION_KEY`（Fernet 密钥）、`TOTP_ISSUER`、`WALLET_BINDING_DOMAIN`、`WALLET_OFFICIAL_ADDRESS`、`WALLET_OFFICIAL_CONFIG_VERSION`、`WALLET_MANUAL_OWNER_ADMIN_ID`、`WALLET_MANUAL_POLICY_VERSION`、`WALLET_FUNDING_BASELINE_AT`（带时区）和 `WALLET_FUNDING_BASELINE_HEIGHT`。TronGrid API 密钥通过 `WALLET_TRONGRID_API_KEY` 提供。密钥必须稳定保存并纳入受保护的恢复配置，不能在每次重启时生成。

三个限额配置 `WALLET_MANUAL_MAX_PER`、`WALLET_MANUAL_USER_24H`、`WALLET_MANUAL_GLOBAL_24H` 分别使用精确字符串 `100000.000000`、`100000.000000`、`10000000.000000`。服务端报价有效期默认 300 秒，充值意图默认 1200 秒，分别由 `WALLET_MANUAL_QUOTE_TTL_SECONDS` 与 `WALLET_DEPOSIT_INTENT_TTL_SECONDS` 配置；这些时间快照固定在已创建订单中。

MFA 注册接口位于 `/api/v1/security/mfa`：查询状态、`/enroll` 注册、`/enable` 启用与 `/abort-pending` 取消尚未启用的配置。注册和取消待启用配置需要当前密码及五分钟内的新登录会话；启用要求同一配置 ID 和真实动态验证码，并消耗当前时间步。已有启用配置不能经上述接口覆盖或删除。会话撤销在授权时检查，不承诺撤销会回滚已完成授权的并发操作。

服务端 MFA 加密密钥缺失时，状态仍返回真实的 enabled/pending 元数据。本人可以按同样的密码、近期登录与审计要求取消未启用的旧注册，此操作不解密旧密钥；创建和启用继续拒绝。不得由部署脚本自动删除注册或生成替代密钥覆盖仍需使用的凭证。已有启用凭证必须恢复原服务端密钥。

## 管理员固定操作密码（ADR-0014）

显式设置 `BUSINESS_WALLET_ADMIN_AUTH_MODE=operation_password`，并将 `BUSINESS_WALLET_MANUAL_OWNER_ADMIN_ID` 指向已核验的官方钱包拥有者账号 ID。默认 `totp` 保持旧版本兼容，禁止验证失败时回退。此配置只改变管理员人工出款、安全控制和交接认证；用户 MFA 与钱包绑定证明保持不变。固定操作密码是独立的可重复使用密码，不是动态 MFA。

在近期登录状态下进入“USDT 钱包 → 操作密码”。初次设置输入当前登录密码及新操作密码；更改还需要现有操作密码。新密码为 12–128 个字符，与登录密码不同，空格原样保留。不要把密码交给运维、聊天或部署脚本。服务端只保存慢哈希，浏览器不保存密码。连续五次失败进入十五分钟锁定；成功请求不清空同一失败统计窗口。

状态接口为 `GET /api/v1/admin/wallet/security`，设置接口为 `POST /api/v1/admin/wallet/security/operation-password`，要求幂等键。修改凭证提升版本并使旧的未提交授权失效。出现 `RECENT_LOGIN_REQUIRED` 时重新登录再刷新状态；设置请求结果不明时先刷新凭证状态，重试保留原参数和幂等键。忘记操作密码目前没有自助重置入口，不能删除数据库凭证绕过。

0054 采用扩展迁移保留旧 TOTP 数据。应用回退保留新增表和审计记录，禁止删除凭证表。密码事件消费者需与 API 协调发布，发布时仍保持资金关闭；后台显示密码已设置不代表资金已启用。储备、监控交接和告警验收仍独立执行。

## 充值

人工模式 Worker 必须挂载观察服务数据库并配置 `TRON_OBSERVER_DATABASE_PATH`，缺失路径配置将拒绝启动。0048 持久化发现游标与重试队列；关闭新资金时仅发现交易，已有提现仍持续核验。观察数据库的事件须保持追加，不得删除、改写 rowid 或执行 VACUUM；恢复历史时必须验证游标回退并重新验收，不能直接覆盖后继续入账。补扫 PROCESSED 表示已完成核验评估，实际到账须以收据 CREDITED 和账本关联为准。

1. 用户完成私人钱包控制权验证及有效绑定，再创建充值意图。页面展示该意图的官方收款地址、精确金额、到期时间和要求使用的已绑定来源。
2. 观察服务发现交易后获取固化收据；逐条校验 USDT 合约、成功状态、来源、目标、区块及时间范围。历史列表不是入账证据。
3. 只有唯一匹配的有效意图可原子入账；事件、归属、账本、审计和 Outbox 一起提交。重复补扫不能产生第二笔入账。
4. 小额、无意图、迟到、未知来源和归属冲突进入待处理义务，后台可追踪原因。不能删除以消除对账差异，也不能凭用户提供的哈希强制归属。
5. 改绑生效原子关闭旧充值意图；旧来源迟到款保留核查，不自动算给新绑定。

## 提现

1. 用户确认服务器生成的报价：绑定目标、本金、服务费、总冻结及报价到期时间。目标不能由客户端任意指定。
2. 申请时锁定绑定与报价快照，冻结本金（服务费为零）。官方钱包拥有者管理员以近期登录会话和独立操作密码确认同一付款摘要；修改金额或目标必须重新走申请和确认。
3. 领取付款任务先提交不可重复的本地付款意图，随后才展示可执行指令。操作员在 imToken 逐项核对网络、官方来源、完整目标和精确 USDT 本金，自行签名。
4. 操作员回填交易哈希。系统验证固化收据及唯一 Transfer 日志与订单完全一致，才结算冻结款和费用；输入哈希本身不改变订单为成功。
5. 签名后应用断线、哈希丢失或 TronGrid 不可用时，保留冻结并进入待核实状态。先补扫官方出账和核对原订单，禁止再次付款或自动解冻。
6. 地址、金额、来源、合约错误或重复付款必须告警并暂停相关新出款；保留链上事实和订单差异，不能修改原订单来掩盖错误。

## 对账与应急

人工模式使用专用储备监控，不能调用缺少托管接口的旧监控作为资金门禁。0049 保留逐日志覆盖证明；0050 保留不可变储备发布评估。Worker 依次核验已有提现、发现并登记待处理收款义务、完成覆盖和储备检查，最后才重试仍有唯一有效意图的入账。资金关闭或监控未通过时不重试入账。

储备发布须绑定同一观察截面的余额、流水游标、固化高度、观察编号及有效期；提交前重新锁定并检查储备版本、精确负债和人工在途计数。重复观察不能延长证据有效期，旧检查不能覆盖提现领取或结算造成的版本变化。只有已分配给实际结算订单的链上转出才算已核定出款，候选哈希不能替代结算。

健康来源的正常补扫积压返回 WAITING，使储备证据失效并停止新入账，继续补扫。积压达到五分钟、已知证据冲突、来源回退、对账不足或告警投递异常会触发事故暂停；正常人工在途付款在五分钟内也仅等待，超时或计数不符须核查。赶上正常补扫后可以重新发布储备，但不会自动解除已经设置的事故暂停。max rowid 是全部历史的发现水位，不等于启用后的有效流水数量；手工局部恢复或不匹配的数据库备份必须受控重验。

账本完整性核验使用单个数据库快照流式读取并按交易精确汇总，不受日流水预览的十万条展示上限影响。异常暂停、审计和告警 Outbox 在同一事务保存。网络及观察库读取不占用金融写事务。

人工监控每轮独立检查未确认 P0 的五分钟升级时间槽，源故障不跳过已有事故升级；同槽重试不重复创建升级事件。升级事务失败也不能继续发布储备。人工事故确认、复核及结案接口使用实际拥有者、近期登录和 MFA，复核事务重新检查完整储备与证据时效；结案继续保留暂停，不能以监控再次成功当作已经允许解除暂停。

0051 在共享监控心跳保存上一轮 Worker 的外部投递配置布尔值；旧数据与旧写入者默认 false。后台显示的“已配置”只表示 Worker 创建了非禁用的钱包告警发送处理器，不等于 SMTP 可达、邮件已接收或事故已处理。须同时核对心跳过期状态、最后错误和持久化告警投递回执。若 Worker 停止，旧配置值可能仍为 true，不能据此忽略 stale。

环境变量由 Settings 的 `BUSINESS_` 前缀读取，例如 `BUSINESS_WALLET_ALERT_RECIPIENT` 和 `BUSINESS_TRON_OBSERVER_DATABASE_PATH`；本文其余配置简称也需加此前缀。收件人通过部署环境配置，不写进仓库。人工模式启用资金时必须配置单一告警邮箱且启用 SMTP 投递；SMTP 使用验证证书的 TLS，拒收视为失败并由 Outbox 重试。邮件仅包含事件编号、事件码、等级及后台查看提示。SMTP 接受与数据库回执不是同一事务，崩溃可能重复发送；稳定 Message-ID 不等于恰好一次送达，也不证明收件人已读。

每日核对官方链上余额、逐条收支、用户负债、待处理充值义务、已冻结提现、已确认出款及手续费。后台明细须能从订单追溯到事件和账本，也能从每条官方流水查到订单或明确的未匹配原因。

断线恢复必须从持久化游标回溯补扫并去重；发现缺口、来源矛盾、证据过期或储备不足时阻止相关新资金操作。告警发送失败也须有持久化重试和可见状态。

紧急暂停阻止产生新的可执行付款资格；已在 imToken 签名广播的交易仍可能完成，必须继续只读观察和核对。链上已完成转账不能通过平台撤回。账本错误只能通过关联冲正纠正；退款属于单独经审批的资金操作，不能删除旧流水。

## 验收证据

0052 持久化人工限制来源、版本及幂等控制命令。后台通过 `/api/v1/admin/wallet/manual/operations/control` 获取当前摘要；暂停或恢复提交同一摘要与版本、稳定请求键、原因码和新的 MFA。恢复只能解除有证据归属于人工模式的限制，不能清除其他来源的限制。未知请求结果保留原键；明确的版本冲突需要重新查看状态后人工操作。

0053 提供首次无旧资金的历史监控交接。部署阶段设置 `BUSINESS_WALLET_HANDOVER_PREPARATION_MODE=true` 且真实资金关闭，Worker 只做发现与准备心跳，不继续升级被接替的旧托管监控事故。钱包告警此时只投递交接汇总；其他业务 Outbox 按原规则处理。受保护的服务器部署记录必须在实际核对旧 Worker 退出、新 Worker 模式与来源版本后生成，不可预填为已完成。

拥有者在后台生成限时清单、发送汇总邮件，收到邮件后用新的 MFA 确认清单及没有未登记付款。原失败告警和事故历史保持不变，追加处置记录关联实际发送回执。交接完成响应 `HANDOVER_COMPLETE_FUNDS_PAUSED`，仍不得付款；退出准备模式后，通过独立恢复核验以及小额真实验收再启用资金。清单变化或到期需重新生成，未知请求结果须沿用原键查询或重试。

发布预检只验证关闭资金版本的配置和 schema，不证明资金闭环或邮件送达。人工模式成功状态为 `RELEASE_READY_MANUAL_FUNDS_DISABLED`，监控验收标记 `MANUAL_ACCEPTANCE_PENDING`；真实资金已开启时该预检明确拒绝，避免误报关闭状态。

隔离验收覆盖 9.999999、10、10.000001 USDT 边界、同交易多日志、重复补扫、改绑迟到款、并发申请、管理员权限与 MFA、零费用快照、错误付款证据、断线与重启、暂停和备份恢复。记录测试命令、时间、版本、结果及失败原因，不保存真实密钥或完整钱包地址。

隔离验收通过且配置齐备后，由钱包控制者执行获准的小额真实充提。必须看到一次且仅一次入账、订单冻结、管理员确认、人工签名、精确链上结算及对账一致，再记录实际启用范围。尚未执行的环节必须写“待验收”，不得以 Sandbox 通过替代真实通过。
