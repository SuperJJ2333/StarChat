## 网络

默认`ssh -J jumper -p 23421 root@207.56.8.8`；SCP用`scp -J jumper -P 23421`。jump别名已有认证配置，不复制私钥/密码进仓库。使用`scripts/starchat-server.ps1`统一编码、超时及跳板参数。连接失败先区分跳板、目标SSH、命令返回码；不在同一代理链路反复重试。禁止自动关闭主机密钥或TLS证书验证。

公网检查在服务器与工作站分别执行。工作站普通TLS链路已多次EOF，默认用现有jumper临时loopback SOCKS进行发布验收，curl `--socks5-hostname`让域名在远端解析。保留HTTPS SNI/证书校验，完成后关闭自己创建的隧道；不改全局代理、不引入外部代理订阅。服务器API用liuhetong888.com，后台静态用admin.liuhetong888.com，www是下载网站，HTML200不能当API健康。

## 需求与实现

1. 将每条用户要求与后续澄清写入验收台账：ID、预期行为、代码、测试、生产证据、状态。需求设计不是功能完成；“推送”不可把未实现项从范围消除。
2. 声明文件所有权；并行任务用独立worktree。保留工作区已有变更，记录基线哈希。先检查迁移唯一head、API契约和导入，后启动完整回归，避免20分钟后才发现head冲突。
3. 使用现有设计规范；链上/事故详情使用可访问模态，关闭保留筛选分页滚动；所有时间统一北京时间。按钮必须连接真实接口，覆盖等待/空/错误/成功状态。金融方向不得混淆，历史未知信息不得猜造。
4. 专项测试先red/green；领域与规格评审通过后做质量安全评审。独立测试可并行但不得共享可写DB/临时容器。完整verify至少运行一次；失败记录根因和复测，不能用无依据的skip掩盖。无需重复已通过且未受后续修改影响的长测试。

## 生产

读docs/runbooks/app-release-deployment.md及对应发布runbook；确认当前镜像、Compose层、schema和源文件差异。基于当前镜像作最小覆盖，禁止从整个脏工作区重新构建并覆盖其他任务。

明确manifest及SHA256；服务器敏感快照留0700目录，数据库备份留服务器。先隔离恢复、候选与回退配置比对、需要的迁移及真实PG并发验证。开启功能前核对迁移真实head/表及候选digest，不仅依赖文件存在。仅重建清单内服务。

发布后检查资源hash、API JSON健康、未授权拒绝、实际配置、无新错误、其他容器不变；有验证账号时只做已授权操作，无账号则不得伪造生产会话。资金功能以隔离PG验证写入，生产实际补录需准确业务证据和管理员确认。

回退恢复已冻结旧镜像/配置和静态文件；扩展表与审计保留，不用破坏性downgrade。最终按验收ID报告范围和证据，保留明确缺口，不能写“全部完成”掩盖未上线项目。
