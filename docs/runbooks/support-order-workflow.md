# 客服充值提现订单运行说明

实现依据：[批准设计](../superpowers/specs/2026-09-23-support-order-workflow-design.md)、[ADR-0081](../adr/0081-support-order-settlement-and-staff-activation.md)。本文件不代表本批已经部署。

## 用户侧

充值第一步输入 USDT，优先展示参考点钻；第二步展示订单保存的官方 TRON 收款信息。用户付款、客服接单、到账核验、审批及点钻发放是不同事件。用户提交交易哈希不改变余额。只有服务端 CREDITED 才显示已到账。

提现输入点钻并展示预估 USDT；报价、冻结额度及用户验证沿用原服务。实际应付由客服结算，链上转出确认后才显示完成。充值和提现均以最终结算字段为准，参考汇率不承诺最终金额。

充值前需要已验证的钱包归属。交易所代付、来源不符或缺乏明确归属的付款进入核对；不能通过手填金额、截图或同金额匹配发放。不要删除此类订单或凭证。

## 客服首次登录

客服使用既有 APP 账号及其已验证手机号/邮箱开通后台；接收渠道由服务端决定。只有现有官方客服身份允许开通，开通不会授予新角色。处理资金的客服还须具有 FINANCE_SUPPORT。既有超级管理员登录保持兼容。

客服资金操作使用自己的操作密码或 TOTP，验证范围为 support-orders，有效期沿用既有策略。该验证不能用于钱包所有者的通用修复功能；APP 普通令牌不能访问后台订单。重新绑定联系方式、撤销/重授角色或替换管理会话后按服务端要求重新验证。

## 充值处理

1. 从公共队列或分页历史打开订单，认领后取得五分钟租约；可见工作台定期续租。
2. 核实用户交易凭证。服务端验证链上状态、官方地址快照、来源归属及实际 USDT 金额，并预留唯一凭证。
3. 填写最终结算率，提交订单专用待审批调整。金额由服务端使用实际到账 USDT 计算；客服不能在该入口指定任意收款用户或任意调账金额。
4. 独立管理员在工作台批准或拒绝；提交者不能自批。
5. 客服执行已批准结算。核验证据超过两分钟须重新核验，不能以旧按钮状态代替服务器检查。账本写入与凭证消费在一个事务完成；随后幂等登记，回包丢失由 worker 恢复。

两小时截止后进入待核对；复核认领需原因且清除旧的付款核验状态。已有资金执行或结果不明的订单不能任意接管。历史订单保留原绑定/登记入口，不虚构历史链上凭证。

## 提现处理

客服认领不等于已付款。开始付款前核对权威应付、地址与摘要；开始后处理人保持唯一，不自动接管、再次付款或解冻。不确定的交易由原处理人提交/修正候选交易并核对链上事实。

两小时后尚未开始付款且无候选交易的订单可填写原因进行复核认领，再核对应付及地址。已开始的超时订单只保留原处理人的证据核对路径。租约过期回到待核对，不隐式重新付款。

## 发布与恢复

- 先备份并演练恢复，再升级唯一迁移链 0083→0087，随后发布匹配版本 API、worker 和后台；最后发布客户端。新表不支持删除资金历史式降级。
- 现有 wallet_real_mode、官方地址/网络、资金开关及独立操作验证仍生效。人工充值服务遵守 runtime.deposits_enabled；自动充值和用户兑换仍保持关闭。开启人工流程不等于开启自动入账。
- 发布前检查每个拟处理订单的客服已经完成开通并具备所需角色；不要将所有客服提升为超级管理员。
- worker 负责充值登记恢复、充值/提现到期核对事件。后台通知使用事务 Outbox 和持久收件箱，重复投递按事件 ID 去重。
- 撤回发布时停止新业务入口并保留数据库证据。已执行但未登记的订单继续只读核对/幂等登记，不重新发币；出款不确定的冻结额不得自动释放。
- 本批验收证据为隔离环境；生产地址、凭据、短信和真实出入款不写入仓库。发布须重新核对线上版本与配置，不能用本地通过推断线上完成。
