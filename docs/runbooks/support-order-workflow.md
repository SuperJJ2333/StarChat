# 客服充值提现订单运行说明

实现依据：[批准设计](../superpowers/specs/2026-09-23-support-order-workflow-design.md)、[ADR-0081](../adr/0081-support-order-settlement-and-staff-activation.md)。本文件不代表本批已经部署。2026-09-30 修复依据：[客服资金订单规格](../superpowers/specs/2026-09-29-support-finance-order-recovery-design.md)与[受保护 ADR](../adr/2026-09-29-support-finance-order-recovery.md)。生产状态见任务台账。

## 用户侧

充值第一步输入 USDT，优先展示参考点钻；第二步展示订单保存的官方 TRON 收款信息。用户付款、客服接单、到账核验、审批及点钻发放是不同事件。用户提交交易哈希不改变余额。只有服务端 CREDITED 才显示已到账。

提现输入点钻并展示预估 USDT；报价、冻结额度及用户验证沿用原服务。实际应付由客服结算，链上转出确认后才显示完成。充值和提现均以最终结算字段为准，参考汇率不承诺最终金额。

充值前需要已验证的钱包归属。交易所代付、来源不符或缺乏明确归属的付款进入核对；不能通过手填金额、截图或同金额匹配发放。不要删除此类订单或凭证。

## 客服首次登录

客服使用既有 APP 账号开通后台，可选择邮箱或手机验证；服务端只向该账号已验证的绑定联系方式发码。只有现有官方客服身份允许开通，开通不会授予新角色。处理资金的客服还须具有 FINANCE_SUPPORT。首次开通后，客服入口使用 APP 账号与密码登录，不再要求验证码。具有超级管理员身份的账号（包括混合客服角色）须使用保留图形验证码的管理员入口。

依据 [ADR-0083](../adr/0083-staff-console-session-access.md)，客服充值和提现订单直接使用有效管理会话，不再要求独立操作密码、TOTP 或短期 grant。服务端每次操作及金融提交前继续检查账号、会话、开通身份及财务角色。APP 普通令牌不能访问后台订单；联系方式或角色变化使开通身份失效时须重新开通，管理会话被替换后须重新登录。管理员专用钱包的独立验证保持不变，客服侧边栏不显示该入口；旧 support-orders 验证端点仅为兼容保留，旧 grant 撤销不等于管理会话退出。

客服运营概览与管理员共用汇总指标和图表；这不授予管理员明细查询或写权限。

## 充值处理

1. 从公共队列或分页历史打开订单，认领后取得五分钟租约；可见工作台定期续租。
2. 核实用户交易凭证。服务端验证链上状态、官方地址快照、来源归属及实际 USDT 金额，并预留唯一凭证。
3. 填写最终结算率，提交订单专用待审批调整。金额由服务端使用实际到账 USDT 计算；客服不能在该入口指定任意收款用户或任意调账金额。
4. 独立管理员在工作台批准或拒绝；提交者不能自批。
5. 客服执行已批准结算。核验证据超过两分钟须重新核验，不能以旧按钮状态代替服务器检查。账本写入与凭证消费在一个事务完成；随后幂等登记，回包丢失由 worker 恢复。

两小时截止后进入待核对；复核认领需原因且清除旧的付款核验状态。已有资金执行或结果不明的订单不能任意接管。历史订单保留原绑定/登记入口，不虚构历史链上凭证。

## 提现处理

1. 当前租约由服务端决定。其他客服认领时显示“正被其他客服处理中”，普通客服不能操作。
2. 确认汇率只暂存准备率和版本；冻结金额保持原值，用户仍可取消，当前客服可按固定原因拒绝。可关闭弹窗返回列表、再调整汇率。
3. 客服明确点击“确认开始出款”时提交最新准备版本和摘要，服务端原子调整冻结并复核资金门槛。此前仅脱敏地址；此后通过单独审计且 no-store 的读取接口显示突出完整地址并复制。已开始订单不得以“未到账”直接退款或拒绝。
4. 无哈希时可只读发现 TronGrid 候选，限定官方付款方、该客户收款方、精确金额和出款时段。列表不证明付款；客服明确选择交易哈希/日志后，仍须固化收据、跨订单归属和唯一账本凭证才能完成。歧义、分页不完整或证据不足保持待核对。
5. 官方钱包所有者且具有实时 SUPER_ADMIN 的管理员可单独确认原因并提供本次选定模式新鲜操作密码/TOTP 接管。未开始单转移唯一租约；已开始单仅取得证据核对令牌，原付款人和指令不变，不能再次开始付款。
6. 旧版 Android 已开始取消失败保留稳定错误码，返回中文说明。按钮刷新与过期订单交互留后续 Android 版本；本轮不重建 APK。

## 充值认领接管

充值与提现共用占用提示和服务端能力判断。仅官方钱包所有者管理员经当次新鲜验证、预期认领版本和审计理由接管已证明尚未执行的安全订单。已有链上凭证和金额绑定不改变；缺失、已消费或归属不明凭证不得接管。旧但有效的凭证只用于接管归属证明，实际结算仍要求两分钟内重新核验。重放同一幂等键不重复转移或入账；旧客服令牌失效。

## 发布与恢复

- 本轮先冻结实时镜像/配置/静态并私有备份，隔离恢复验证唯一迁移 0092→0093，再发布最小覆盖 API 和清单内后台静态；Worker 保持当前镜像。候选及回退均通过双角色续期门禁。新表保留审计历史，禁止破坏性 downgrade；旧 API 回退须先证明新在途状态的安全写入口隔离或使用兼容前向镜像。
- 现有 wallet_real_mode、官方地址/网络、资金开关及管理员钱包独立验证仍生效。客服订单按上述管理会话授权，认领租约、到账凭证、审批、幂等、审计与 Outbox 不变。人工充值服务遵守 runtime.deposits_enabled；自动充值和用户兑换仍保持关闭。开启人工流程不等于开启自动入账。
- 发布前检查每个拟处理订单的客服已经完成开通并具备所需角色；不要将所有客服提升为超级管理员。
- worker 负责充值登记恢复、充值/提现到期核对事件。后台通知使用事务 Outbox 和持久收件箱，重复投递按事件 ID 去重。
- 撤回发布时停止新业务入口并保留数据库证据。已执行但未登记的订单继续只读核对/幂等登记，不重新发币；出款不确定的冻结额不得自动释放。
- 本批验收证据为隔离环境；生产地址、凭据、短信和真实出入款不写入仓库。发布须重新核对线上版本与配置，不能用本地通过推断线上完成。
