# 生产配置与漂移管理

**Current reference · 2026-09-20**。通用操作入口为[生产工作流](admin-production-workflow.md)。本页合并原根目录配置手册；不代表重新核验了生产状态。

## 权威输入

仓库模板定义预期配置，实际容器的Compose层、环境、挂载、启动命令、镜像和主机边缘代理定义运行基线。两者先比较再生成增量。不能用整个本地仓库或裸Compose覆盖生产特有配置。

- 相关模板：`infra/synapse/`、`infra/nginx/`、`infra/element/`、`infra/sygnal/`。
- 漂移检查：`python3 infra/render_config.py --check --require-production`；先确认所选目录/输入对应当次目标。该命令通过不代表全部服务可安全重建。
- 实际秘密保存在受保护运行环境；不得提交、打印或复制到文档。推送凭据不因模板同步被覆盖。

## 变更顺序

1. 保存当前镜像、配置、挂载及必要数据库备份到新的受限目录，不能覆盖旧发布证据。
2. 使用已审阅计划声明允许改变的服务和字段；保留未领取模块。
3. 验证模板渲染结果、占位符和格式；绑定单文件的配置注意inode和挂载关系。
4. 环境变化需要按精确运行配置重建对应服务，单纯restart不会重新读取容器环境；不得为了省事重建全部服务。
5. 网关变更先在实际网关容器执行配置校验；reload或重建采用当次评审方案。
6. 验证API JSON健康、未授权拒绝及其他容器/配置不变，失败恢复本次已冻结配置。迁移不做破坏性回退。

[历史模板映射与事故记录](../archive/2026-09-20/root/RUNBOOK_PRODUCTION_CONFIG.md)保留溯源；其中“总是重渲染”“整体up -d”和旧密钥状态不再作为通用操作步骤。
