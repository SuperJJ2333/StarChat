# BUG、新功能与 Android/iOS 交付工作流

生效：2026-09-10；来源：用户要求建立可跨聊天会话使用的工作流，减少两小时级交付中的重复等待和返工。本文规定执行顺序与证据复用，不自动授予未来生产发布权限。各任务以用户已授权范围为准。

## 1. 新会话恢复，先确定事实

按顺序读取：根 AGENTS.md → [当前状态](../workflow/current-state.md) → 对应任务记录及已批准计划。只读相关模块的产品规格、ADR和下级AGENTS；不要递归扫描历史构建目录或把全部日志灌入上下文。代码定位遵守CodeGraph规则。

开始记录：目标及验收ID、当前commit/工作树/未提交改动、文件所有权、双方设备和实际安装版本、授权范围、已有证据与下一步。新问题先挂到相应任务，不能把已发布包误当包含了后来提交的修复。不同任务使用独立记录；`current-state.md`只是索引，不让并行任务覆盖彼此进度。

有其他任务改代码时，使用独立且干净的工作树；可复用本任务已有干净工作树，避免重建。不要复制脏仓库到生产，不删除别人的分支/工作树。用户要求合并时逐项审查后集成main，仅清理本任务且已合并的临时分支。

## 2. BUG 修复与新增功能

| 阶段 | BUG | 新功能 | 退出条件 |
| --- | --- | --- | --- |
| 定义 | 现象、最短复现、预期、受影响版本/平台 | 用户目标、范围、边界、验收用例 | 任务台账可核对；已有授权不重复确认 |
| 定位/设计 | 先重现再沿客户端→API→Matrix/缓存追踪，区分错误码阶段与根因 | 对齐现有架构，说明数据流、权限、兼容、失败与回退 | 有证据支撑的根因或具体方案，受保护变更按ADR/审查规则 |
| 实现 | 一条失败用例证明原BUG，最小根因修复 | 先写关键行为失败用例，再分步实现 | 失败用例转绿，相关回归通过 |
| 验证 | 原复现+相邻路径+两端差异 | 正常/异常/权限/升级兼容 | 先规格符合性审查，再质量/安全审查 |

禁止仅隐藏错误、返回空数据、跳过测试、写死状态或降低鉴权来制造通过。沟通域仍属Matrix，财务状态仍由业务API权威管理。

## 3. 前置检查与测试选择

启动长测试/构建之前，用短检查确认：当前工作目录与源码SHA、Python实际导入路径、Flutter/SDK/Java/Xcode版本及锁文件、磁盘/设备可用性、迁移head与OpenAPI、所需.env是否存在。环境不足先解决；不得为了跑测试导入生产秘密或照搬整份生产配置。

| 改动 | 必做 | 不重复做 |
| --- | --- | --- |
| 纯文档、工作流 | 链接、路径、规则冲突、diff、审查 | APK/IPA、业务全量、生产部署 |
| 下载网页、更新设置 | 路由/平台隔离测试、旧客户端兼容、审计/回滚演练、公网检查；代码变动按根规则运行适用门禁 | 未变的移动端源码构建、语音全量 |
| Flutter共享逻辑 | 失败用例、受影响测试、analyze、最终候选的共享全量门禁及两端相关验证 | 每改一行就重跑全仓 |
| 原生音频/存储/登录/推送 | 上述检查+相关原生编译/集成测试+真实设备相关场景；服务端契约联测 | 用Android通过替代iOS，或用模拟器替代声学/企业签名验证 |
| 服务端契约/权限/同步 | 受影响API测试、鉴权与错误路径、契约/迁移检查、适用全量；POSIX权限问题必须有Linux证据 | 修改钱包安全策略只为CI通过 |
| 同一构建的企业重签回传 | 新文件SHA、身份/entitlements、资源/原生内容对比、签名与覆盖安装、分发验证 | 无源码变化就重新生成IPA、重跑全部Flutter用例 |

测试证据必须带命令、真实退出码、源码/相关输入hash、依赖锁、OS/工具版本、结果与日志位置。可复用的前提是相关输入与覆盖范围一致；有新修改、失败或未解决风险才扩大/重跑。同源同环境的CI完整结果已覆盖本地重复门禁时可停止本任务的重复运行，记录停止原因；不能把取消的本地测试说成通过。主分支合入改动后做影响比较，补跑被改变的覆盖范围。

已存在的无关失败须在基线复现并记录责任范围，不能声称全量通过；与当前交付相关的失败必须修复。若环境缺失，写“未执行/阻断”及影响，不用成功的最后一条日志覆盖失败退出码。

## 4. 构建一次，按来源交付

在构建前冻结候选源码和每个平台版本/build；先核对线上、CI和其他任务占用的版本，不能盲目沿用2085或只改文件名。平台可以独立发布，但必须记录每端实际包含的commit。统计助手等共享资源要核对源码与两端最终包内SHA。

Android：严格遵守 [APK重建与固定签名](android-apk-rebuild.md)。源码构建→Apktool→zipalign→固定签名→清单/ABI/DEX/资产/签名验证。Debug和正式包分开记录包名与证书；ADB先检查online、已安装包与版本，使用保留数据的覆盖安装，不自动卸载、清数据或降级。

iOS：按 [移动端构建入口](mobile-release.md) 和实际CI配置生成同源候选；保留音频/VoIP/APNs/SQLCipher与账号存储。候选写清“待企业重签”，收到输出后重新核验实际文件；不能相信文件名或把App Store候选当企业包。企业签名身份/Keychain关系改变必须单独处理，不能牺牲已有聊天数据。

Flutter测试可能改变生成的插件注册文件；构建前用正常构建工具恢复依赖/生成流程，不因`--no-pub`沿用测试产物。失败时定位首个有效错误再重试，不先盲目clean或重复整套构建。两端构建无共享输出且资源允许时可并行；同目录生成文件和上传分块不并行写。

## 5. 发布顺序与双端隔离

执行 [生产工作流](admin-production-workflow.md) 和 [分发手册](app-release-deployment.md)。默认使用已有jumper与scripts/starchat-server.ps1；不先反复尝试已知失效代理。临时SOCKS只绑定loopback，保留TLS/主机校验，等所有依赖它的下载/推送结束才关闭。

1. 读取当次运行镜像、schema、静态文件hash、两端设置及符号链接；不复用昨天的生产基线。与其他任务协调发布目标，不覆盖未领取文件。
2. 将设置/manifest/静态备份持久保存到宿主机本次发布目录（0700）。容器/tmp只能作工作副本，不能作唯一备份。发布脚本要识别前态/半完成态/完成态并支持安全重试；有未知漂移停止相关写入并重读。
3. 顺序、可恢复上传不可变版本文件，分块及合并SHA门禁；本地临时文件只放docs/verification/artifacts的任务目录。禁止上传中清理分块。
4. 先让包可下载，再切manifest/页面/相应平台链接；验证后再通过SettingService原子发布该平台设置和审计。文件与DB不是同一事务，要分别验证并有可恢复步骤。不擅自提高最低支持版本。
5. iOS配置使用app_ios_*及HTTPS安装页，Android使用其平台配置及APK路径。自动弹窗与“设置→关于畅聊→版本更新”必须走相同平台选择。浏览器阻止自动跳转时保留明确按钮。
6. 旧客户端没有platform参数时，不得在服务端根据普通Dart UA猜系统。记录覆盖范围与过渡限制；保留已批准的设备下载页桥接，直至有证据表明可退出过渡。UA仅用于网页下载选择，不能用于鉴权。新Android候选发布前还必须核验生产接口返回其所需的platform标记，不能只查iOS。
7. 两端分别验收：设置/审计读回、实际路由投影、未授权401、服务器和工作站HTTPS完整SHA、Range206、manifest MIME/缓存、旧包回退可用。声明服务端检查与真机反馈的不同层级。

发布仅一端时，另一端版本、包、强更规则保持原状；过渡必须修改共享链接时单独说明并审计，不能称“另一端配置完全未动”。一端等待签名/设备反馈不阻塞另一端已授权且可独立完成的工作。

## 6. 时间账本与跨会话交接

每个任务从 [模板](../workflow/task-template.md) 创建记录；启动、阶段切换、失败/重试、进入外部等待、结束时填写带时区的起止时间和命令/CI运行ID。分别记主动执行、工具执行、外部等待、返工；并行步骤墙钟按区间并集计算，不简单相加。

执行目标（提示检查，不是牺牲质量的硬截止）：开始后约5分钟给出范围/基线；约15分钟仍无定位证据时说明已排除项和下一检查；同一失败重试一次仍无新证据时先更换有依据的诊断方法。预计超过5分钟的命令先说明目的；活跃工作期间约60秒给出有内容的进展，避免机械重复状态。精确计时缺失必须写“未知”，不得根据文件修改时间编造工时。

会话结束或等待签名/真机时更新：已完成证据、未完成验收ID、实际产物路径/SHA/签名渠道、发布状态、授权与约束、仍在运行的任务/端口、下一条可执行操作。敏感信息不写入文档。只清理本任务且不再使用的进程与临时资源。

最终交付用短结论说明根因、改动、测试、实际发布版本/链接、尚需真机确认项及耗时分解。不得将“已提交”“已构建”“已上线”“用户验收通过”混为一个完成状态。
