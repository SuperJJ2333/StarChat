# ChatFlow 审计修复——真机手工验收清单

适用包：审计修复后的 debug 包（构建方式见文末）。每项写明操作、预期、失败时需记录的信息。
通用记录格式：`时间 / 设备与系统版本 / APP 版本 / 操作步骤 / 实际现象（截图或录屏）/ 日志（adb logcat -d > log.txt，注意脱敏）`。

## 1. 消息与来电（后台/锁屏）
| # | 操作 | 预期 | 失败时记录 |
|---|---|---|---|
| 1.1 | App 在前台，另一账号发消息 | 立即收到消息；无重复通知/重复响铃 | 通知截图、到达延迟 |
| 1.2 | App 退后台 → 发消息 | 系统通知到达（厂商 ROM 差异属预期）；点开 App 后消息完整 | 是否收到、延迟 |
| 1.3 | 锁屏 → 发消息 | 锁屏通知（有全屏权限时横幅/全屏）；厂商 ROM 限制导致的送达差异如实记录 | 锁屏截图 |
| 1.4 | 后台来电（语音）→ **不操作** | 来电提示出现但**绝不自动接听**；约 60 秒后自动结束并清理（通知/铃声/页面消失） | 是否自动接通（关键回归）、清理是否完整 |
| 1.5 | 后台来电 → 点通知**正文/全屏页** | 只展示来电页，**不等于接听**；需再点[接听]才接通 | 点正文是否直接接通（关键回归） |
| 1.6 | 后台来电 → 点[接听] → 回到 App | 通话页自动补开（"正在建立加密连接…"→接通计时）；不重复弹两个通话页 | 页面状态截图 |
| 1.7 | 通话中挂断 | 通话结束；通知/铃声/悬浮球全部收尾；**消息同步保活通知仍在**（不被误停） | 挂断后通知栏截图 |
| 1.8 | 重复推送（同一来电触发多次唤醒） | 只有一通电话、一个通知、一个页面 | 是否出现多通/多页 |
| 1.9 | 杀进程后来电（离线厂商通知，若已配置） | 仅通用文案通知可点 → 拉起 App → 同步恢复来电页；超过有效期的旧来电不再出现假来电 | 是否有"已结束"摘要、有无假来电 |
| 1.10 | 视频来电（真实类型） | 通知文案与通话页为**视频**类型（以同步结果为准） | 是否被当成语音 |

## 6. 生产门禁（部署验收时）
- 生产环境未配置真实托管时：充值地址/提现/回调接口返回 503 `WALLET_CUSTODY_NOT_CONFIGURED`；余额/历史/配置只读正常。
- 生产 + `BUSINESS_WALLET_CUSTODY_PROVIDER=production` + 占位 `BUSINESS_WALLET_WEBHOOK_SECRET` → **启动失败**（配置校验）。
- Outbox 死信监控：`SELECT topic, count(*) FROM outbox_events WHERE status='DEAD' GROUP BY topic;`——identity.* 之外的主题进入死信属预期，补齐消费者后重放。

## 构建与安装（Mi 6 / arm64）
```powershell
cd apps/mobile_flutter
$env:FLUTTER_STORAGE_BASE_URL='https://storage.flutter-io.cn'   # 注意：无引号包裹值本身
$env:PUB_HOSTED_URL='https://pub.flutter-io.cn'
flutter build apk --debug --flavor standard --target-platform android-arm64
adb devices                # 确认 Mi 6 已连接、已授权 USB 调试
adb install -r build\app\outputs\flutter-apk\app-standard-debug.apk
adb logcat -c              # 清空日志后再现问题，随后 adb logcat -d > log.txt
```
如需指定设备：`adb -s <serial> install -r <apk>`（`adb devices -l` 查看 serial）。
