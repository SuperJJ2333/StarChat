# 后台管理体验与会话改造

状态：用户于 2026-09-08 明确确认按本设计实施。

## 范围与选择

覆盖用户提出的七项管理后台改进。采用现有 HTML 管理台渐进改造、配套业务 API 和独立管理会话的方案，保持现有服务端权限及资金操作校验。仅改 CSS 无法解决会话和统计缺失；整体替换前端框架会扩大回归面，因此均不采用。

已确认：新设备登录成功，旧设备立即失效。刷新入口按已确认设计采用当前页面右上角一个刷新图标，刷新当前页可见数据区域。

## 现状证据

- `frontend/src/admin-api.js` 登录固定使用 `admin-browser` 设备标识；当前管理台没有续期调用。
- `modules/identity/tokens.py` 通用访问令牌默认 15 分钟、刷新令牌默认 60 天，不能直接用通用刷新周期作为管理员登录周期。
- `api/identity.py` 的管理员登录验证验证码后直接进入通用登录流程。
- `api/admin.py` 概览没有返回 `registration_trend`；前端已有柱形元素但没有按数据设置高度。
- `admin-manual-wallet-panel.js` 同时构造暂停与恢复操作，未按状态选择主要操作。
- 账本发行对应账户为 `PLATFORM_CLEARING`，手续费账户为 `PLATFORM_FEE`。复式分录直接全表求和为零，不能充当平台点钻总量。

## 1. 管理会话

- 登录成功起绝对有效 48 小时，关闭浏览器再打开仍可恢复；刷新不延长这 48 小时。
- 保持短期访问令牌，使用 Secure、HttpOnly、SameSite 的管理刷新 Cookie。刷新接口校验来源、防止跨站请求，所有认证响应禁止缓存；浏览器不持久化明文密码或刷新令牌。
- 管理会话独立于普通用户会话，服务器串行处理同一管理员的新登录，原子撤销旧管理会话。旧令牌即使尚未过期，也不能继续调用管理接口或续期。失败登录不影响旧会话。
- 服务端失效即时生效；在线旧页面通过会话检查及时显示“账号已在其他设备登录”，休眠页在恢复或请求时退出。不能仅依靠浏览器设备标识或前端计时保证单设备。
- 同浏览器多标签共享会话，协调续期避免刷新令牌重放误报；普通用户的移动端、Matrix 设备不受影响。
- 敏感资金操作的近期认证与操作密码保持独立。需要重新认证时保留表单，成功后由用户重新确认操作，不自动重放资金写请求，也不借此延长会话绝对寿命。
- 管理员会话专用边界覆盖所有后台入口，通用登录令牌不得绕过单设备策略；实施前核对现有移动端管理功能的调用路径与兼容性。
- 相关认证改动按 ADR-0059 执行，实施和发布前完成领域及质量/安全审查。

## 2. 钱包状态与刷新

- 运行中显示“暂停新资金操作”；暂停时显示“核验并恢复人工钱包”，同时展示暂停原因和恢复前置条件。
- 未结事故等已知阻断条件必须明确展示；状态未加载、失败或提交中不能执行资金启停。恢复仍使用服务端最新 epoch、证据摘要及全部现有检查。
- 当前页右上角采用醒目的蓝色刷新图标，提供“刷新”悬浮提示、键盘焦点和无障碍名称。若用户选择每面板一个入口，则同样样式放在各面板右上角。
- 监控与事故、人工出款队列、操作密码状态、资金启停的刷新均为只读请求；刷新中旋转、防止重复点击，显示更新时间。
- 局部刷新失败保留上次数据并标注过期及失败原因，其他面板继续更新。保留筛选、分页、正在编辑的内容与操作结果，不重建整个页面丢失草稿。
- 状态变化、过期异步响应及模块快速切换不允许覆盖更新的数据。

## 3. 布局与苹果风格

- 所有功能模块移入左侧固定侧边栏，按用户安全、运营、财务分组；主内容区取消“功能模块”卡片导航。
- 展开默认宽 240px，紧凑模式约 200px 且保留完整文字，另设隐藏/显示按钮；主内容滚动时侧边栏保持固定，长菜单自身滚动。窄屏使用可关闭抽屉，支持 Escape 与焦点恢复。
- 当前模块有清晰选中态，菜单权限与 API 权限一致，顶部显示页面标题、管理员身份与刷新入口。
- 使用浅灰背景、白色卡片、细边框、克制阴影和蓝色操作强调。通过字号、留白建立层次，减少无功能占位控件。
- 悬浮、按压、禁用、加载、成功、错误、空态统一；动效短且可打断，尊重 reduced-motion，资金提交结果以清晰文字反馈。
- 按 apple-design 和项目 UI 合约实施。远端 Figma 同步遵循项目规则；现有导出记录注明先前授权延期，须核实该授权范围，不将更新本地台账称作已修改远端 Figma。

## 4. 注册趋势

- 后端按 Asia/Hong_Kong 自然日汇总真实注册时间，默认最近 30 天，支持 7/30/90 天，包含今天并标记今天未结束。
- 无注册的日期补零；请求失败与真实零值区分；不能以最近 100 名用户列表代替全量统计。
- 图表显示日期轴、人数轴和每日数值提示，提供可读数据表。空数据库、全零、单峰和跨 UTC 日期边界均可正常展示。

## 5. 点钻总量与发行追踪

- 新增“平台点钻总量”：当前净发行量，以 CAIBI 的清算对手账户净额取反计算，包含仍在用户、冻结、托管及平台手续费账户中的点钻。
- 同时展示累计发行、累计回收/冲正扣减，以及用户与托管持有量、平台手续费持有量。明确总量与储备负债不是同一指标。
- 累计发行与回收按每笔交易清算账户净变化聚合，避免多分录重复计数；发行冲正单独标识并链接原交易。
- 点开总量查看可分页、筛选的发行与回收记录，包含交易 ID、时间、数量、操作人、原因代码及原交易/审计链接；无权限者不可访问。
- 以相同数据库读取快照验证“净发行 = 非清算账户净余额之和”。发现历史不平衡或缺失关联显示异常，禁止伪造补齐或修改旧账。
- 金额 API 使用两位小数字符串，后端 Decimal/NUMERIC，前端不使用浮点计算或转换大金额；不新增发行入口，不修改现有账本写入公式、储备规则或钱包状态机。
