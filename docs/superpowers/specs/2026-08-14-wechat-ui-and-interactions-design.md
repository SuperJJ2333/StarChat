# 微信风格移动端与交互补全设计

**状态：** 已批准  
**日期：** 2026-08-14  
**适用仓库：** StarChat / 六合通

## 1. 目标与范围

以根目录 `UI_DESIGN.md` 为唯一移动端视觉依据，建立 Flutter 自研微信风格设计系统，并按顺序交付：登录网络恢复、聊天时间线、语音录制、Matrix 加密附件、红包房间卡片、钱包交易历史、Docker 恢复与双模拟器回归。

不改变 Matrix 通信域、业务 API 权威性、E2EE、复式账本、资产精度、幂等、RBAC、TOTP、提现审批和托管状态机。

## 2. 设计系统架构

在 `apps/mobile_flutter/lib/ui/` 建立 tokens、theme、foundation、feedback、chat 和 finance 子模块。页面只组合公开组件，禁止复制样式。Flutter Cupertino 继续提供导航和平台行为，但视觉参数全部来自 `WeChatAppTheme`。

不引入 Web 版 Vant/WeUI，也不引入维护状态不明的 Flutter 仿制组件包。文件选择、图片选择和录音继续使用已锁定依赖，Matrix 加密使用现有 SDK。

## 3. 数据与安全边界

- 聊天文本、附件明文、语音和恢复密钥只在客户端/Matrix 加密域处理。
- 红包 Matrix 事件仅作为 E2EE 卡片载体；红包详情和领取状态查询业务 API。
- 钱包历史与提现状态来自业务 API；客户端不推导财务结果。
- 所有财务写继续携带幂等键、原因码和用户身份。
- 临时录音和待上传附件在成功、取消或超时后清理，不写日志。

## 4. 交互流程

### 4.1 登录恢复

客户端将连接失败、超时、5xx 和认证失败映射为可理解文案。网络类错误采用指数退避自动重试，最多 3 次；用户可立即点击“重试”。认证失败不自动重试。按钮在单次请求期间禁用，避免重复登录。

### 4.2 Matrix 时间线与附件

房间控制器拥有 Timeline 生命周期、分页、发送队列和重试。文本、图片、文件、语音统一映射为展示模型。附件先校验、读取、加密、上传，再发送加密事件；UI 展示本地待发送、上传进度、成功和失败重试状态。

### 4.3 语音录制

录音控制器实现 idle、recording、cancelArmed、preview、uploading、failed 状态。按住开始，上滑 60dp 取消，松手进入试听。1–60 秒有效；用户确认后才进行加密上传。波形来自本地音量采样，音频不上传业务 API。

### 4.4 红包卡片

创建红包成功后，在 Matrix 房间发送 E2EE 业务卡片事件。打开卡片时以 packet ID 查询业务 API，领取调用幂等接口；成功后刷新详情并发送非权威状态更新事件。并发领取结果以业务 API 为准。

### 4.5 钱包记录

业务 API 增加当前用户可分页查询的 USDT 交易与提现记录接口。客户端提供筛选、详情、复制地址、状态轮询。任何列表项金额都格式化为六位小数。

## 5. Docker 运维

只管理 Compose 项目 `starchat`。依赖启动顺序：PostgreSQL/Redis → migrations/API → Worker → Synapse。重建 business-api 使 `0.0.0.0:8082` 映射生效。检查 health、容器日志和宿主机端口；不操作同机其他 Compose 项目。

## 6. 测试策略

- Token 与组件 Widget 测试：颜色、尺寸、亮暗模式、语义。
- 控制器单元测试：登录重试、录音状态机、上传失败重试、钱包轮询终止。
- API 测试：用户隔离、分页、资产精度、红包状态、提现详情。
- 集成测试：Matrix 时间线、加密附件、红包领取、真实业务登录。
- 模拟器回归：正确登录、错误密码、网络断开/恢复、退出登录；验证码仅在服务端登录策略要求时覆盖，不制造客户端绕过。

## 7. 交付顺序

1. 设计系统与组件库。
2. Docker 重建与登录修复验证。
3. 登录错误和重试。
4. 时间线控制器与统一消息组件。
5. 语音状态机与控件。
6. 图片/文件 Matrix 加密发送。
7. 红包卡片、详情和领取同步。
8. 钱包历史、提现详情与轮询。
9. 双模拟器与 Release 回归、文档和证据。

## 8. 完成标准

所有新增行为具有红/绿测试证据；Flutter analyze/test、后端测试、Release 构建和模拟器关键路径通过；`UI_DESIGN.md` 与组件文档匹配实现；不存在硬编码主题、密钥、临时绕过、未解释警告或资金/E2EE 边界变化。

## 9. 好友与通讯录域

业务后端新增 `friendship` 模块作为权威好友图谱。功能包括用户名搜索、好友申请、接受/拒绝、删除、备注、标签、拉黑、解除拉黑、朋友圈权限和通讯录分页。Matrix 私聊房间不是好友事实来源；好友建立后客户端可以创建或复用 Matrix E2EE 私聊房间。

好友关系、申请和黑名单写操作必须有操作者、原因码、审计记录和幂等键。阻止关系必须同时作用于朋友圈读取、搜索、推荐、点赞、评论和好友申请。删除好友不会删除既有 Matrix 密文历史。

## 10. 朋友圈域

朋友圈属于业务后端公开社交域，不使用端到端加密。用户发布前明确提示内容可能被搜索、推荐和平台审核。私聊、群聊、通话与 Matrix 媒体仍保持 E2EE，朋友圈服务不得读取这些内容。

### 10.1 内容类型

首版支持纯文字、最多 9 张图片、链接卡片、位置和话题标签；不支持视频。支持点赞/取消、评论、回复、用户删除自己的评论、发布者删除评论、删除动态、新消息提醒、相册封面和个人朋友圈主页。

### 10.2 可见性

每条动态支持公开、仅好友、指定好友、排除指定好友和仅自己。用户全局朋友圈展示范围支持全部、最近半年、最近一个月和最近三天。权限必须在列表、详情、搜索、推荐、通知和媒体下载签名时分别校验，不能依赖客户端隐藏。

### 10.3 存储与媒体

正文、链接、位置和互动存 PostgreSQL；图片使用对象存储兼容接口和预签名上传。图片允许 JPEG/PNG/WebP，单张最大 20MiB。上传完成后进行 MIME/魔数验证、缩略图生成和安全扫描。删除采用软删除并保留审计，媒体由 Worker 按保留策略异步清理。

### 10.4 搜索

普通用户可按正文关键词、发布者用户名/昵称、话题、位置和发布时间搜索，但结果必须通过可见性、好友、黑名单、删除与下架过滤。管理员审计搜索使用独立权限和接口。首版使用 PostgreSQL 全文检索与结构化索引，不引入独立搜索集群。

### 10.5 推荐

公开推荐按好友关系、新鲜度、点赞、评论、已读衰减和举报风险进行可解释排序。用户可切换推荐/最新并关闭个性化推荐。彩币、红包、USDT、客服记录和 Matrix 聊天内容不得成为推荐特征。

### 10.6 内容治理

发布时执行敏感词、垃圾广告和图片安全检测。高风险公开内容进入审核中，审核通过后才公开。支持举报、隐藏、下架、封禁和申诉；管理操作必须记录标准原因码、操作者和审计日志。好友可见内容执行基础安全检测，但不进入公开推荐。

## 11. 朋友圈 API 与任务边界

业务 API 提供好友申请/关系/权限、动态发布/读取/搜索、点赞、评论、举报、通知和推荐流接口。所有写操作需要幂等键；列表使用稳定游标分页。Worker 负责图片处理、安全扫描、通知、推荐特征汇总、删除清理和 Outbox 投递。

朋友圈事件不能改变任何账本、红包或钱包状态。红包卡片仍由红包业务 API 决定领取结果，朋友圈不能发布或兑换 USDT。

## 12. 朋友圈测试要求

- 权限矩阵覆盖五种可见范围、四种时间范围、好友删除和双向黑名单。
- 搜索与推荐不得泄露无权动态或私有媒体地址。
- 并发点赞、评论删除、重复发布使用幂等断言。
- 图片上传覆盖类型伪造、超限、扫描失败和清理任务。
- 管理治理覆盖原因码、审计与申诉状态。
- Flutter 覆盖通讯录、时间线、九宫格、发布、评论、设置和亮暗主题组件。
