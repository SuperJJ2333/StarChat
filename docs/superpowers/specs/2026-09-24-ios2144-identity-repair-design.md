# iOS 旧账号身份故障与无损升级修复设计

日期：2026-09-24。状态：用户已确认“保留旧库后建立新设备，并接受部分旧消息可能无法解密”的恢复边界；受保护 ADR、实施与真机验收仍待完成。范围：iOS 0.3.102/2144 的旧账号 L07、后续源码修复包及企业回签后的覆盖升级。当前线上 iOS 为 0.3.102/2144；0.4.7/2172 iOS 更新入口已停用。本设计不把重新签署旧 2144 视为修复。

## 已证事实与目标

- 故障 iPhone 在 2144 点击旧账号登录后依次记录 `E2EE_ACCOUNT_SELECT_BEGIN`、`E2EE_CONTINUITY_FINGERPRINT_MISMATCH`、`E2EE_ACCOUNT_SELECT_CONTINUITY_MISMATCH`；同机新账号可登录。旧账号的 L07 早于 2172 的安装。保存的 `MatrixLocalBinding.ed25519Fingerprint` 与打开的客户端 Olm Ed25519 指纹不同，是这次 L07 的直接拒绝条件。最初分叉时间及原因未知。[脱敏证据](../../verification/2026-09-24-ios2144-old-account-l07.md)。
- SDK 初始化发生在现有连续性检查之前。对含有登录凭据但缺少 `box_client.olm_account` 的旧库，SDK 的 `OlmManager.init` 会新建 Olm 身份、上传设备公钥，再写回库；随后应用才发现旧绑定指纹不符。该源码时序可以造成不可逆的分叉，但目前没有故障前的库快照，不能断言它已在这台手机上发生。
- 用户要求保留旧应用数据并以同一企业签名覆盖升级。修复目标是阻止新的身份被静默生成，优先恢复可验证的原有本机身份；任何无法证明的状态保留原库和钥匙串，明确展示恢复条件。旧 Olm 私钥及房间密钥若物理上已经丢失，源码无法凭账号密码重新生成。
- 用户曾在故障手机选择“删除 App”。Apple 说明该操作会移除应用及其数据；无故障前整机备份时，后续安装包不能恢复当时已从应用容器删除的数据库。当前安装中仍存在的库和钥匙串则继续按本设计保护。[Apple 删除 App 说明](https://support.apple.com/en-mt/guide/iphone/iph248b543ca/ios)。

## 方案选择

1. **推荐：启动前只读核验与有证据的原身份恢复。** 打开 SDK 前检查已有库、绑定和 Olm 公钥；必要时只读检查同一账号的其他已登记或可从固定文件名发现的本机槽。仅将完整匹配的候选列为可恢复，不立即改写槽映射。若真机确有原身份，再设计带持久迁移日志的槽修复；若找不到，保留所有字节并进入恢复密钥/旧设备路径。这能防止再次把缺失的 Olm 账号替换为新身份，但不保证已经发生的 2144 L07 可被原地修复。
2. 仅重新签署 2144 或 2172：不改变已证实的 L07 路径；2172 的启动错误也未获独立事件码，不构成修复。
3. 直接改写保存的指纹或清除旧库后重新登录：可能让旧聊天密钥无法恢复，且违背现有 E2EE 连续性约束，不作为自动路径。

## 客户端设计

### 只读清点

新增本机身份清点组件，只使用已登记的账户槽、旧版无后缀槽及应用私有目录内符合固定命名的 SQLCipher 文件。读取现存数据库密钥与绑定时不得调用会“缺值即创建”的 `matrixDatabaseKey()`。SQLite 连接须以真正的只读模式开启、设置 SQLCipher key 并在设备内读取 `box_client` 的账号、设备和 Olm pickle；不得调用会建表或迁移文件的 `MatrixSdkDatabase.open`、`ensureDatabaseFileEncrypted`、`Client.init`。Olm pickle 只在设备内存中解开以取得公钥指纹，立即释放；日志只记录状态码及安装内加盐关联值，不记录密钥、pickle、完整指纹、账号或聊天内容。

清点结果至少区分：原指纹唯一匹配、多个候选、旧库缺少 Olm 账号、指纹不符、库/密钥缺失、数据库暂不可读。读取失败不能被解释为“全新安装”。真实 iOS/SQLCipher 只读打开及 WAL 行为须在原生测试和真机证实。

### 启动与登录

对已存在登录身份或绑定的库，`MatrixClientFactory.create()` 在 SDK 初始化前执行只读核验。缺少 Olm pickle、绑定指纹不符或读取不确定时，不初始化 SDK、不上传新公钥、不写入库。真正的新账号和空库继续走原首次登录流程。

旧账号选择先对目标槽做只读清点，**在 `selectMatrixAccount` 写 registry 和 active scope 之前**给出安全判定；`create()` 内的预检仍保留为第二道防线。遇到不匹配时，再清点本机同账号候选。只有唯一候选同时证明账号、homeserver、绑定、库密钥和 Olm 指纹一致，才可采纳原身份槽。`databaseGeneration` 当前只保存在 Keychain binding 中，不能独立证明数据库世代；单凭它不得选择候选。现有 registry 和 active scope 是两个 Keychain 写入，进程中断无法靠内存回滚，因此重指槽须使用持久迁移日志、启动重放/撤销规则和故障注入测试。经 Business grant 校验目标且旧客户端关闭后，可优先采纳唯一已验证的原身份候选；不得仅凭设备 ID 或文件名选库。

若无原身份候选，显示“本机聊天身份无法验证”，告知数据保持原状，并提供现有恢复密钥/已验证旧设备路径。恢复密钥或旧设备只能协助**新设备身份**取得有备份的 Megolm 房间密钥及对应历史，不能还原已经丢失的原 Olm 设备私钥，也不能自动消除当前指纹不符。用户已接受在此条件下保留旧库并显式建立新设备；执行时仍须在手机上明确确认，并证明旧库、旧数据库密钥与绑定未被覆盖。不得把新公钥写回旧绑定伪装成同一设备。没有原 Olm 私钥、可信旧设备或可用房间密钥备份时，旧加密历史可能无法解密，应如实提示；业务账号登录权可独立恢复。iOS 2172 的启动错误须单独采集事件码并做对应回归，不直接归入 2144 L07。

## 签名与分发

修复代码需用高于已安装 2172 的构建号制作新候选；按用户既有 v0.4.7 选择暂定 `0.4.7/2173`，确认构建号未被占用后锁定。CI 候选与企业回签包逐文件核对非签名代码和 Frameworks，不接受未经审查的新增动态库。

归档 2144 的 Team 为 `ZXB3TS7QD4`，生产 APNs 已有，但其已签 App ID 为 `ZXB3TS7QD4.cn.edu.buaa.wxwork.notifyext`，与 Bundle ID `com.liuhetong.liuhetongMobile` 不符。仅相同企业证书不能保证无损覆盖。签名方应保持 Team、Bundle ID、旧 Keychain 项目的实际可访问组及生产 APNs。Apple 的[安装故障说明](https://developer.apple.com/library/archive/technotes/tn2319/_index.html)指出 App ID 字符串变化可拒绝升级；文中迁移例子针对前缀变化，**不能推断它支持本项目同前缀、不同后缀的异常旧 App ID**。因此优先用与已安装 2144 完全相同的已签 App ID 和 Team 制作定向真机包，先实际验证旧数据覆盖、Keychain 可读与后台提醒；若拒绝，停发并向签名方和 Apple 确认获授权的迁移机制，不伪造权益。

用户要求在开发阶段沿用现有企业签名并保留旧数据。若上述精确旧 App ID 的**最终同一 SHA** 企业 IPA 在仍可登录且保有旧聊天的 2144 iPhone 上通过不卸载覆盖，同时通过 Team、旧 Keychain groups、生产 APNs、非签名包体及服务器本地 SHA 门禁，可使用显式的旧身份例外发布更新入口。该例外仅识别已取证的 `ZXB3TS7QD4.cn.edu.buaa.wxwork.notifyext`，发布证据必须如实保留其与 Bundle ID 的差异，不宣称已修正 App ID。默认新安装校验继续要求 `Team.Bundle`；任何其他 App ID 或不同 Team 不适用此例外。若无法取得真实无损覆盖结果，继续停发公开入口。

发布前分别完成两类真机验证：故障 iPhone 上验证旧账号恢复路径；另一台仍能以 2144 登录且持有旧聊天的 iPhone 上，用最终 SHA 对应 IPA **不卸载覆盖安装**并确认登录、旧聊天、Keychain 可读和后台提醒。故障手机曾删除 App 且旧账号已 L07，不能以它证明“原聊天数据覆盖保留”。签名、APNs、包体一致性、真机记录和服务端上传包 SHA 均通过后，才更新 iOS manifest、下载页及更新弹窗；Android 保持现值。若 Apple 不批准旧 App ID 迁移或真机覆盖失败，停止公开更新，不用改发布记录绕过门禁。

## 验证与评审

先写失败用例覆盖旧库缺 Olm pickle时零 SDK 初始化/零上传/零写库，唯一原身份候选可识别并经授权采纳，多候选、指纹不符、库/Keychain 读取失败全部保留原状态；再实现最小改动。槽迁移与新设备恢复另写失败用例验证持久迁移日志、崩溃重放/撤销和旧库留存。执行 Flutter 专项、全量受影响回归、`flutter analyze`、仓库 `verify.ps1` 的适用门禁，以及 iOS 原生编译/SQLCipher 只读测试与真机升级。按受保护 E2EE 变更要求完成 ADR、领域及质量/安全评审；测试和非 Git 证据存入 `docs/verification/`。

本设计不承诺原 Olm 私钥已经存在，也不把新账号可登录等同于旧加密聊天可恢复。
