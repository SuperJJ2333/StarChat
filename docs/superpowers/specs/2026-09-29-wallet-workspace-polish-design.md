# USDT 钱包工作台视觉与链上视图保持设计

状态：2026-09-29 用户已批准书面方向，并要求取消所有者转出申报的日志序号输入、把原因与用途合为单选；本修订须纳入受保护 ADR 与实施计划审批。

视觉示意：[钱包工作台静态稿](../../verification/artifacts/2026-09-29/wallet-ui-design/wallet-direction.html)。示意数据不连接生产，正式界面仅展示现有 API 可证实的字段与数量。

监视器 `PROTOCOL_PROBE_FAILED` 故障修复是独立认证与可用性任务。本规格调整后台展示、链上只读视图生命周期及所有者转出**预检**的兼容输入；不改监视器、钱包账本、出款状态机、执行接口的精确链上定位、审核门槛或事故等级。

## 页面结构与文案

沿用已选“墨夜银锋”视觉：深墨标题区、克制的银青色强调，工作区继续使用其他后台模块的浅色卡片、字体和间距；不把登录页的整屏特效搬到财务页面。顶部显示“USDT 钱包操作台”，状态摘要只使用现有 API 的权威字段。链上余额须明确写为“链上观察余额”，不可暗示为用户可用余额或账本负债。没有服务端汇总的人工出款数量不在顶部伪造总数；加载中和失败时不显示假 0。

页面顺序为官方钱包链上流水、人工出款队列、监控与事故、所有者转出申报、账户安全及现有资金控制/交接资料。顶部的分区导航是锚点，不是卸载内容的标签。各区有自己的数据时点、等待、空、失败和显式刷新反馈；恢复的链上视图须区分“本页缓存于”与服务端报告的“观察器最近成功扫描”，不可将前者冒充新链上扫描。主要操作、普通刷新、事故/资金危险操作使用不同视觉等级。USDT 保持六位小数和等宽数字；所有时间统一北京时间。窄屏卡片单列，表格只在自身容器横滚；键盘焦点、对比度及 `prefers-reduced-motion` 保留。

底部旧的 `GET /admin/modules/wallet` 表实际来自 `wallet_withdrawals`，标题定为“托管提现申请记录”，其 `Withdrawal.id` 列为“托管提现申请编号”。人工出款队列来自 `wallet_manual_payout_orders`，显示“人工出款订单编号”。简短帮助文案说明：编号是平台内申请/审计定位键，交易哈希与日志索引是链上事件定位键；二者在结算核对后建立关联。旧表不删除、合并或推断成当前人工出款事实。

## 链上流水与详情

列表保持现有按北京时间筛选、方向、完整 64 位哈希查询、快照与分页接口。哈希列显示前 8 位、`…`、末 6 位，日志索引以 `#<index>` 单独显示。复制按钮写入完整 `<64位txid> / <log_index>`；成功或失败以 `role=status` 明确反馈。完整值不进入 `title`、错误文案或分析日志；按钮仍由当前受控数据对象持有原始值。复制失败时不误报成功。搜索框继续接收完整哈希。

详情继续使用现有 `detailDialog`，桌面为宽模态、小屏接近全屏。顶部显示转入/转出、金额、链上证据与平台核定三种不同含义；下方分“链上证据”（哈希/日志、区块、时间、证据状态）、“资金路径”（来源、目标地址、金额）、“平台关联”（用户归属说明、关联收款/提现单、账本交易编号及原因）显示现有 API 已有字段。缺失字段显示“尚无可验证关联”或“暂无”，不猜测归属、不把 `REVIEW` 涂成成功。只读详情关闭后保留筛选、分页及滚动；修复/核对写按钮继续按钱包 grant、预检及原来的主动确认执行。

## 所有者转出申报的业务选择

申报表单展示交易哈希、用途单选及所有权确认，不再要求管理员填写技术性的日志序号、原因码或重复的用途说明。初始用途为“钱包测试转出”→ `OWNER_TEST_DRAW` 与固定说明“官方钱包持有人测试转出”、“对外付款”→ `OWNER_EXTERNAL_PAYMENT` 与固定说明“官方钱包持有人对外付款”；不提供含义不清的“其他”。菜单选择必须由管理员明确操作，不预选。后端仍保存和审计 `reason_code`、`reason_detail` 两个字段，且现有所有权、权限、grant、幂等、账本及不可变记录门槛不变。单选是后台 UI 约束；原 API 对旧调用者的原因格式兼容性保留。

`POST /wallet/manual/owner-transfers/preview` 的请求模型允许省略 `log_index`，这是唯一 API 兼容增量。预检先完成 owner/grant 授权与预算锁，再读取新鲜 TronGrid 证据：只有一笔从官方地址转出的 USDT Transfer 时，服务端自动解析并在响应中返回内部 `log_index`、链上金额与收款地址；零笔或多笔时拒绝自动选取，不能默认 0。多笔时页面引导管理员在上方官方链上流水查找该哈希，逐行打开详情，按真实金额、收款地址与时间选择具体转出；列表行的内部序号可传给同一预检，但不作为申报表单的可编辑输入显示。候选相同到无法区别、候选未进入只读观察记录、证据冲突或超出可安全展示范围时阻止提交并给出核查提示。预检再次核对 VERIFIED 覆盖事实、未被出款事件占用等既有条件。

预检成功只显示待确认的真实收款地址、精确 USDT 金额、缩略交易哈希和所选用途，不把技术性的日志序号放回申报表单；管理员主动确认后才调用原 `POST /wallet/manual/owner-transfers`，执行请求仍携带预检解析的精确 `log_index` 并在事务内重新获取证据、复核授权和状态，幂等键继续为 `owner-transfer:<txid>:<log_index>`。预检到执行之间数据改变时拒绝，绝不自动换链上事件、重放写命令或填写金额/地址。申报后按原流程刷新监控、处理事故，再单独核验资金恢复。OpenAPI、`wallet-incident-recovery.md` 与表单测试同步更新。

## 焦点、菜单与安全生命周期

现状有两处无条件重建：`admin-wallet-access.js` 在 `focus`/`visibilitychange` 时 `gate.lock()` 清内容，`admin-dashboard.js` 切模块时 `dispose()` 钱包面板。浏览器失焦不清空已确认的只读页面；重新可见时先遮蔽敏感字段、禁止写按钮并执行去重的会话/owner 检查，页面框架与筛选位置保持原样。核验成功去掉遮蔽，无须重新查询链上列表。有效 owner 下的 `ready -> verify`（60 分钟写授权到期）只锁写按钮，保留只读链上 DOM 和筛选。401、权限撤销、换账号、owner 改变、网络/权限状态不明仍清除敏感 DOM 与缓存，拒绝操作。现有 30 秒可见页轮询继续生效。

菜单切换只保存**链上只读视图的有限内存快照**：当前筛选草稿与已应用查询条件、offset、服务端 snapshot、最多一页 25 条列表与摘要、页面及表格横向滚动位置、单个已打开详情及其已取得的只读数据。导出须在关闭详情模态及 `dispose()` 之前完成；切走时关闭模态和资金修复对话框、清空密码/TOTP 输入及任何未提交写草稿，销毁钱包操作面板。已提交且仍在途的资金请求按现有 `operationJournal` 保留最小恢复元数据和原幂等键；返回后只查询原请求结果，不自动重放。本次不把新的链上快照、未提交写草稿或凭证写入 `localStorage`/`sessionStorage`/URL，也不删除既有 `operationJournal`。快照生命周期只属于当前 `createAdminShell` 实例及当前后台管理会话身份，不跨刷新、登出、会话替换或账号切换。返回菜单时先经服务端确认当前 owner 只读授权与管理会话身份；等待期间只显示非敏感页面框架，确认后从内存恢复链上视图，不自动请求链上列表，标出本页缓存时间与显式刷新。上次详情可在授权确认后恢复，旧修复/核对表单不恢复。权限检查失败、超时或网络未知时丢弃快照，继续沿用敏感页面关闭处理。异步旧请求须通过版本号阻止回填。

这项设计不增加钱包 grant 的期限或作用域，也不改变后台 48 小时会话。任何资金、事故、预检、所有者转出写请求仍由服务端在事务内做原有授权、RBAC、幂等、证据及审计检查；页面缓存或隐藏状态不得成为授权凭据。

## 验收与发布

先以现有 Node DOM 测试写失败用例：顶栏无提示/按钮且操作按钮仍触发验证、不自动重放；失焦/恢复和 grant 到期不重建链上列表；侧栏往返无链上列表二次请求并保留筛选/分页/滚动/详情；退出、换账号、owner 撤销、网络不明清敏感内容及快照；并发旧响应不可污染新页面；缩略哈希及完整复制、剪贴板失败；详情状态和字段分组；小屏与减少动效的样式契约。所有者转出补唯一非零日志、零/多笔歧义、候选选择、用途映射、授权先于证据读取、预检不落账、执行重验、旧请求兼容和幂等测试。随后实施和跑专项，再跑项目现行前端、领域与完整相关门禁。页面标题和操作核验以受控静态发布包真实内容检查，不凭 HTML 200 判定上线成功。

需新增精确 ADR 说明钱包视图短期内存保留与原 ADR-0064、2026-09-28 管理台入口 ADR 的关系，以及 ADR-0071 的预检兼容扩展；先通过领域审查，再进行独立质量/安全审查。实施计划须列出基线、文件所有权、红绿测试、OpenAPI、静态资源版本、隔离/生产验证及兼容回退。正式发布前重新冻结生产静态文件和 API 镜像，做最小清单发布，不整体覆盖脏工作树。
