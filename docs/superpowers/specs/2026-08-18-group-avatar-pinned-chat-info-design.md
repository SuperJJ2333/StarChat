# 畅聊群头像、置顶会话与聊天信息设计规格

日期：2026-08-18  
状态：已完成视觉评审，待实施计划

## 1. 目标与范围

本阶段严格扩展 Figma `20 Messages & Chat` 的原始节点，不另建平行风格。移动端仍以 iPhone 15、`393 × 852 px`、`1 CSS px = 1 Figma px` 为基准，并复用现有浅色 Token、导航栏、列表行、开关、头像和图标组件。

范围包括：

1. 群头像按当前群成员的入群顺序生成最多九宫格的本地组合头像。
2. 群聊和私聊导航栏只显示返回、标题和“更多”，不显示语音或视频图标。
3. 置顶群组按首次置顶顺序稳定排列，并使用导航栏背景色区分。
4. 群聊和私聊的“更多”统一进入聊天信息页面。
5. 群免打扰提供折叠会话、例外通知和最多四位关注成员。
6. 查找聊天记录进入独立面板，支持正文与分类检索。

不改变 Matrix E2EE、业务身份权威边界、资金业务或附件加密流程。

## 2. 已选方案

采用 **A：Matrix 账号数据保存个人会话设置，本地已解密索引负责搜索与通知判断**。

- 置顶、免打扰、折叠、保存到通讯录、例外通知和关注成员属于当前账号偏好，写入 Matrix room account data，并在同账号设备间同步。
- 群成员、成员资格和房间资料仍来自 Matrix 房间；群头像只在设备端合成，不上传新的明文成员资料。
- 搜索仅处理当前设备已经解密的时间线和附件元数据，不向业务 API、搜索服务或日志上传消息正文。
- 本地通知策略在设备端解密事件后判断；远端推送继续只携带通用提示和不透明标识。

未采用的方案：

- **B：仅本地保存设置。** 实现简单，但无法满足同账号多设备一致的置顶和免打扰状态。
- **C：业务 API 保存设置和搜索索引。** 可集中同步，但会破坏 Matrix 通信域与 E2EE 明文边界。

## 3. 群头像组合规则

### 3.1 成员来源和顺序

- 仅使用当前 `join` 状态的群成员，不显示已邀请但未加入、已退出或已封禁成员。
- 顺序以成员首次进入当前房间的入群顺序为准；群创建者是第一位，创建时邀请并加入的成员按加入事件顺序排列。
- 成员退出后从序列中移除，后续成员顺位前移；头像始终取当前序列前九位。
- 成员退出后重新加入视为新入群，排到当前序列末尾。
- 同一时间戳使用 Matrix user ID 升序作为确定性兜底，保证设备间结果一致。
- 顺序仓库从 Matrix membership timeline 重建并在本地加密缓存；缓存缺失时按已同步的成员加入事件重算，不使用联系人排序、昵称排序或最近发言顺序。

### 3.2 拼图布局

组合头像容器为圆角矩形，背景使用 `surface/avatar-group`。所有成员头像单元必须保持完全相同的正方形尺寸和圆角半径，不允许通过 margin、缩放或非等比裁切改变单元形状。

| 人数 | 行布局 |
| --- | --- |
| 1 | `1`，居中 |
| 2 | `2`，居中相邻 |
| 3 | `1 + 2` |
| 4 | `2 + 2` |
| 5 | `2 + 3` |
| 6 | `3 + 3` |
| 7 | `2 + 2 + 3` |
| 8 | `3 + 3 + 2` |
| 9+ | `3 + 3 + 3`，只取前九位 |

每行作为整体水平居中，相邻头像使用统一间距。头像加载失败时使用现有用户头像占位组件，不改变网格尺寸。

群头像用于消息列表、群聊页标题相关头像和其他群组入口；私聊继续使用单用户头像。

## 4. 消息列表与置顶顺序

### 4.1 稳定排序

- 账号首次将群组设为置顶时，保存 `pinnedAt`，取客户端时间并由 Matrix 同步顺序作冲突兜底。
- 所有置顶群组位于普通会话之前，并按 `pinnedAt` 从早到晚排列。
- 新消息、已读状态、草稿、成员变化和房间名称变化均不得改变置顶群组之间的顺序。
- 取消置顶后移出置顶区；再次置顶视为新的置顶动作，获得新的 `pinnedAt` 并排到现有置顶群组末尾。
- 普通会话继续按最后活动时间倒序排列。

### 4.2 视觉

- 置顶群组的完整会话矩形背景使用与导航栏相同的语义色 `surface/navigation`。
- 普通会话使用 `surface/list`。
- 分割线、头像尺寸、标题、摘要、时间和未读标记严格复用消息页原始节点，不通过额外边框或标签表达置顶。
- 深色模式使用对应 Token 自动切换，不写独立硬编码颜色。

## 5. 聊天页导航栏

群聊与私聊都使用同一导航结构：

```text
返回按钮 -> 居中标题 -> 更多按钮
```

- 删除导航栏语音和视频图标及其占位宽度。
- 群聊标题继续显示群名称；私聊标题显示对方备注或昵称。
- 右上角“更多”始终进入聊天信息页，不再打开私聊 action sheet。
- 语音消息、视频/语音通话等功能入口不从业务层删除；通话入口可继续存在于聊天输入区“更多”面板，本规格只移除导航栏快捷图标。

## 6. 群聊信息

导航栏标题为 `聊天信息(当前已加入人数)`。

页面顺序：

1. 自动折叠群成员头像；最后一位为添加图标。
2. 群聊名称。
3. 群公告。
4. 备注。
5. 查找聊天记录。
6. 消息免打扰。
7. 置顶聊天。
8. 保存到通讯录。
9. 本机清空聊天记录。
10. 退出群聊。

成员折叠、添加、名称限制和退出规则沿用已批准的群聊信息规格。清空记录仍只隐藏本设备本地聊天记录，不发送 Matrix redaction。

## 7. 私聊信息

导航栏标题为 `聊天信息`。

页面顺序：

1. 对方头像与添加图标。
2. 查找聊天记录。
3. 消息免打扰。
4. 置顶聊天。
5. 保存到通讯录。
6. 本机清空聊天记录。

私聊不显示群聊名称、群公告、群备注或退出群聊。点击添加图标进入好友多选页；默认包含当前用户和私聊对方，用户至少再选择一位好友后创建满足三人下限的新群聊。

## 8. 群免打扰与例外通知

### 8.1 一级设置

关闭消息免打扰时不显示子选项。开启后在同一分组下显示：

1. `折叠该聊天` 开关。
2. `以下消息仍通知`，摘要固定表达为 `@我、@所有人和群公告`，右侧使用进入箭头。

关闭消息免打扰时保留此前子设置值，但不执行折叠和例外通知策略；再次开启后恢复原值。

### 8.2 二级页面

点击 `以下消息仍通知` 进入同名页面，包含：

- `@我` 开关。
- `@所有人` 开关。
- `群公告` 开关。
- `关注群成员的消息` 入口及已选择数量 `n/4`。

关注成员选择页仅列出当前已加入且不是自己的群成员，最多选择四位。第五位选择被阻止并显示轻提示；成员退出群聊后自动从关注集合移除。

### 8.3 通知判断顺序

设备解密新事件后按以下顺序判断：

1. 非免打扰：按正常通知策略处理。
2. 免打扰且命中已开启的 `@我`、`@所有人`、群公告或关注成员：发送通用本地通知。
3. 免打扰且未命中例外：不通知。
4. 开启折叠时，会话进入折叠会话分组；命中例外通知不自动解除折叠。

通知正文不得包含消息明文、附件名或群公告正文。

## 9. 查找聊天记录

点击入口进入独立 `查找聊天记录` 页面：顶部为搜索栏，下方为分类入口。

群聊分类：

- 日期
- 图片与视频
- 文件
- 链接
- 群成员

私聊分类不显示群成员，其余一致。

行为：

- 输入关键字时搜索当前设备已解密的文字正文和可安全使用的本地展示元数据。
- 日期进入日期选择/时间分组结果。
- 图片与视频进入本地已解密媒体网格。
- 文件进入文件列表。
- 链接只匹配设备端从已解密正文识别出的 URL。
- 群成员进入成员选择，随后只显示该成员发送的本地已解密记录。
- 结果点击后定位到房间时间线中的对应事件；本地不存在或尚未同步的历史不伪造结果，并提供继续加载历史的入口。
- 搜索索引只保存在设备本地加密数据库，退出账号时按现有会话清理策略处理。

## 10. Figma 页面与组件

在现有 `20 Messages & Chat` 区域增加或更新以下独立 Frame：

1. 消息页：普通、多个置顶群组、深色代表状态。
2. 群头像组件：1–9 人、加载失败和成员退出替换状态。
3. 群聊页：仅更多按钮的导航栏。
4. 私聊页：仅更多按钮的导航栏。
5. 群聊信息：默认、成员展开、免打扰关闭、免打扰开启。
6. 以下消息仍通知。
7. 关注群成员：默认、四人上限。
8. 私聊信息。
9. 查找聊天记录：群聊、私聊、关键字结果。
10. 分类结果：日期、图片与视频、文件、链接、群成员。

每个状态均为独立 `393 × 852 px` Frame；超长结果页保持 393px 固定宽度并自然增高。真实图标、字体、间距、圆角、颜色和 DOM/组件嵌套沿用现有硬性规则。所有 Frame 必须通过 overflow、字体和尺寸审计。

## 11. Flutter 组件边界

- `GroupAvatarMosaic`：只负责布局算法与成员头像渲染。
- `ConversationOrdering`：根据置顶状态、`pinnedAt` 和最后活动时间生成稳定顺序。
- `ConversationPreferenceRepository`：统一读写群聊/私聊账号偏好并处理旧数据迁移。
- `GroupChatInfoController` / `DirectChatInfoController`：提供页面状态，不直接操作 Widget。
- `MuteExceptionPolicy`：纯函数判断解密事件是否触发通知。
- `LocalChatSearchIndex`：只接收设备端已解密事件，按房间与分类查询。
- `ChatHistorySearchPage`：呈现搜索和分类，不持有 Matrix 密钥或业务 API 客户端。

现有 `matrix_home_page.dart` 只负责路由与组合，不继续扩张为偏好、排序、头像和搜索算法的实现位置。

## 12. 迁移与异常状态

- 旧设置只有 `pinned=true` 而没有 `pinnedAt` 时，按房间列表首次加载的稳定顺序一次性补齐时间序列并写回账号数据。
- 账号数据读取失败时保持上次本地缓存，不静默覆盖远端设置。
- 群成员头像加载失败显示占位图；成员列表不因单张头像失败重新排序。
- 本地搜索索引尚未建立时显示加载状态；构建失败显示可重试错误，不上传明文诊断信息。
- 离线时允许查看缓存设置和搜索缓存；需同步的设置进入现有 Matrix 重试链路。

## 13. 测试与完成标准

### 13.1 测试先行

- 1–9 人布局行数、顺序、统一单元尺寸和圆角。
- 退出成员被下一位替换；重新加入排到末尾。
- 置顶群组按首次置顶顺序稳定；新消息不重排；重新置顶排末尾。
- 置顶群组背景绑定导航栏语义色，深色模式自动切换。
- 群聊/私聊导航栏不存在语音和视频按钮，仅有更多按钮。
- 私聊更多进入私聊信息，添加好友可创建至少三人的群聊。
- 免打扰子选项只在开启后出现；例外通知判断覆盖四类来源。
- 关注成员最多四位，退出后自动清理。
- 群聊/私聊搜索分类准确；搜索只使用本地已解密数据。
- 清空记录不发送 redaction；退出群聊才调用 leave。

### 13.2 完成证据

- Figma Frame 尺寸、字体、真实图标和 overflow 审计通过。
- Flutter focused tests、全量 `flutter test`、`flutter analyze` 和格式检查通过。
- 根级 `scripts/verify.ps1` 通过。
- Debug APK 构建成功并覆盖安装到 `emulator-5554`。
- 非 Git 视觉和运行证据写入 `docs/verification/`。
