# 管理后台流水、钱包交互与充值补入账改造规格

日期：2026-09-10。状态：需求与方案评审稿，含生产只读排查；不是已实施或已发布声明。

依据：用户本轮五项需求、现有代码与生产查询。用户已确认将原“转出拨款充值”修正为“转入流水做充值补入账；转出做提现核对”。本文提到的新增字段、枚举和接口均为拟定契约，除明确标为现有接口外尚未实现。

## 0. 边界与方案选择

采用“先补齐只读报表与交互，再分批上线会话策略和人工补入账”的方案。只改前端不能解决类型来源、归属原因或入账问题；一次性把会话、资金写操作与视觉改造同时上线则难以隔离风险。

会话口径已由用户明确：后台登录会话保持原有时长；仅USDT页面的验证缓存态有效60分钟，验证一次后在该期间不重复要求验证。使用独立服务端钱包验证凭证实现，不修改全后台登录期限，不缓存密码或验证码。属于钱包验证策略变更，需对应ADR和领域/安全审查。

所有资金金额使用Decimal/NUMERIC或十进制定点字符串：点钻2位，USDT6位。业务API为唯一金融事实来源；链上观察器只提供证据；不读取Matrix明文来推断交易分类，不修改历史交易、账本分录或审计事件。

认证策略、人工充值状态转换及资金写契约属于AGENTS.md保护范围，实施前需要对应ADR获批，以及领域、质量/安全两轮审查。此次规格和调查不执行生产补入账、绑定改写、订单改期或校时。

## 1. 点钻流水

### 1.1 改造需求与交互

列顺序：记账时间｜畅聊号｜用户名｜类型标签｜业务动作｜原因｜金额（点钻）｜交易号｜查看凭证。畅聊号来自User.username；用户名显示User.nickname。采用“用户账本分录”为列表行粒度，以entry_id作为唯一键；平台及托管账户单独标识，不能伪装成用户。一次转账可能产生不同用户的两行，一笔交易在用户分录上的正负金额不是两次发行。页面统计必须明确“分录数量”和“交易数量”，禁止对列表行重复累计交易总额。

筛选栏提供开始/结束日期时间、畅聊号、用户名、邮箱、类型多选、业务动作、原因、异常数据开关。不同字段AND组合，同一类型维度多选OR；时间为北京时间，转换为UTC请求。整日选择按[所选日00:00:00,次日00:00:00)；自定义截止时刻使用排他上界。验证起始小于结束，默认最近7天；超过90天提示缩小范围或走受权限控制的导出任务。

文本查询按字段匹配，不把畅聊号和昵称混为唯一身份；邮箱用于查询不默认显示。按查询按钮/Enter提交，重置恢复默认条件并回第一页。页大小25/50/100，默认50；上一页/下一页以及当前页位置。改变筛选成功后才提交新分页状态；失败保留旧列表、旧筛选快照和页码，并提供重试。详情关闭保留筛选、页码、焦点和滚动位置。账号内页面状态保留，切换账号清除；邮箱不放URL、日志或持久localStorage。

### 1.2 字段与枚举

| 字段 | 定义与约束 |
| --- | --- |
| entry_id / transaction_id | 稳定分录键/业务交易键；原有ID保留 |
| created_at | UTC ISO8601；展示北京时间yyyy-mm-dd hh:mm:ss |
| user_id / username / nickname | 内部用户键、畅聊号、展示名；非用户账户为null并给account_kind |
| account_kind | USER / PLATFORM / ESCROW / UNKNOWN；显示用户/平台/托管/待核实 |
| amount / asset | 带正负号的2位小数字符串；CAIBI显示点钻 |
| business_type | RED_PACKET红包 / TRANSFER转账 / ADJUSTMENT调整 / REVERSAL冲正 / OTHER其他 |
| red_packet_scene | GROUP群聊红包 / EXCLUSIVE专属红包 / DIRECT私聊红包 / UNKNOWN场景待核实 / NOT_APPLICABLE |
| distribution_mode | RANDOM手气红包 / EQUAL普通红包 / UNKNOWN方式待核实 / NOT_APPLICABLE |
| business_action | SEND发出 / RECEIVE领取或收款 / REFUND退回 / FEE手续费 / ISSUE发行 / RECOVER回收 / REVERSE冲正 / OTHER其他 |
| reason_code | 稳定机器码，保留原始值用于追溯；展示不直接泄露英文码 |
| reason_text / reason_detail | 中文原因和具体补充说明；OTHER的detail必填，建议1–500字 |
| data_quality / anomalies | COMPLETE / MISSING_REASON / UNKNOWN_CLASSIFICATION / MISSING_USER；异常原因数组 |

群聊/专属属于场景，手气/普通属于分配方式，不能设计为互斥单枚举。类型列可显示“群聊红包 · 手气红包”。筛选提供场景与方式分组，因此用户要求的群聊红包、专属红包、转账、手气红包、普通红包、其他均能展示和检索。

现有业务原因映射至少覆盖：RED_PACKET_CREATE→发出红包；RED_PACKET_CLAIM→领取红包；RED_PACKET_EXPIRED→红包到期退回；红包取消退回使用业务记录区分；TRANSFER→用户转账；TRANSFER_FEE→转账手续费；SUPPORT_CAIBI_GRANT→客服点钻发放；ADJUSTMENT_REVIEW→点钻调整审核；LEDGER_REVERSAL/REVERSAL→交易冲正。未识别历史码不能凭名称猜含义：保留raw_reason_code，若有经审计补充说明则显示“其他：说明”；没有说明显示“原因待补充”与异常标记，不能静默替换成统一“其他原因（待补充说明）”。新写入的未知码无说明则422。

当前红包表有mode、room_id、recipient_id。mode可提供分配方式；recipient_id可证明专属对象；room_id本身不能证明群聊类型。历史场景缺少可靠业务快照时标待核实，不向Matrix索取明文、群消息或客户端描述来强行回填。

### 1.3 接口与数据影响

新增GET /api/v1/admin/ledger/entries：start_at、end_at、username、nickname、email、business_type[]、scene[]、mode[]、action[]、reason_code[]、anomaly_only、limit、cursor、snapshot。返回items、next_cursor、snapshot、has_more、可选total_entries/total_transactions及统计时点。排序固定created_at DESC,entry_id DESC；游标绑定筛选摘要和snapshot，过期或跨条件游标返回422/409明确码。新增GET /api/v1/admin/ledger/entries/{entry_id}返回业务证据关联。

保留旧/admin/modules/ledger以兼容旧前端；不让旧接口突然改变行粒度。读模型由LedgerEntry/LedgerTransaction、用户安全投影及红包/转账业务关联提供；禁止用跨模块直接表写修正归属。对缺少明确transaction→business_id关联的历史数据采用可审计映射表或投影回填；无法唯一关联留异常。索引评估created_at+id、用户键、交易键；模糊昵称/邮箱搜索要EXPLAIN后确定索引，不在高频列表中执行N+1查询。

权限：沿用服务端audit.view/finance.review等现有查询边界，不以按钮是否可见代替授权。原因补充新增独立ledger.reason.annotate权限及审计；它只增加版本化说明，不改历史账本原因码。查询审计记录操作者、过滤字段名/摘要、时间、结果数、trace_id；不记录原始邮箱。

验收：两个昵称相同用户可通过畅聊号区分；组合筛选无跨条件结果；跨页无重复/漏读（同一快照）；未知原因显式异常；红包场景与方式不混淆；大额精度不变；分页失败恢复正确；未授权403；查询计划在具有实际容量代表性的数据集上验证，建议目标P95≤1秒、超时≤5秒，实测前不宣称达标。

风险与回滚：类型误归、分录重复计量、模糊搜索压力。读模型和新页面设独立开关，先灰度对比旧报表；回退关闭新读接口入口，保留兼容接口和新增投影，不回滚账本。

## 2. USDT提现与支付：标题、会话与隐私弹窗

页面、菜单、面包屑、读屏名称统一“USDT提现与支付”。现状有三层不同有效期：后台绝对会话48小时、访问令牌通常15分钟、钱包近期认证5分钟；一次资金证明另有短时有效校验。不能把三者混为一个“60分钟”。

目标：后台绝对登录期限保持原有48小时，访问令牌及refresh、单设备管理会话机制保持现状。新增独立钱包验证态：首次进入USDT页面且没有有效凭证时验证一次；成功后有效60分钟。离开再进入、页面刷新、同一后台会话的多个标签页均复用服务端验证态。倒计时从服务端验证成功时开始，普通访问和刷新不滚动续期。

钱包验证凭证绑定user_id、当前后台session_id/family_id、钱包作用域、权限/验证配置版本，字段包含grant_id、verified_at、expires_at、revoked_at与验证方式；expires_at=verified_at+60分钟。浏览器不保存密码、TOTP、操作密码或可跨账号复用的证明。建议凭证状态放服务端，通过已认证的后台会话读取和使用，前端只缓存显示状态；不能靠localStorage时间戳授权。

正常有效的60分钟内，页面访问及凭证作用域内的操作不重复弹出身份验证。钱包原有5分钟近期登录及逐次身份验证门槛，在该作用域内必须统一接入有效wallet grant，不能仍在下游5分钟后要求重验；作用域外功能保持原策略。资金操作仍逐次执行RBAC、账号状态、版本、额度/储备、证据新鲜度、幂等和审计检查，确认操作的弹窗也保留。二次确认是业务确认，不是再次输入密码/验证码。

60分钟到期后立即遮蔽敏感内容，下一次访问或操作需要验证；继续后台操作无需重新登录全后台。主动退出、切换账号/后台会话、会话被另一设备替换、账号禁用、权限撤销、钱包验证凭据变更时，旧grant立即失效。这些是身份或权限变化导致的撤销，不是将正常60分钟有效期缩短。若后台登录本身先到期，钱包grant不能越过后台登录边界；登录后不沿用旧session的grant。

弹窗分三类：

1. 后台401/AUTH_REQUIRED/ACCESS_TOKEN_INVALID/会话替换：显示“后台登录已失效，请重新登录”。“重新登录”进入同源登录流程，成功后按新会话进行钱包验证；不能把已失效后台会话当作仍有效的钱包缓存。
2. 后台仍有效，但钱包未验证/到期/凭证撤销：显示“请验证身份以访问USDT提现与支付。验证成功后60分钟内无需重复验证”。主按钮“验证并进入”，次按钮“返回其他后台页面”；不强制退出全后台。“刷新当前操作状态”仅在有效钱包验证后可用，明确说明未确认请求按账号保留且不自动重放。
3. 真正权限不足：显示无权访问，不反复要求登录或验证；提供返回其他后台页面。

隐私层：验证状态未知、失效或撤销时，先隐藏余额、地址等敏感DOM，再对背景应用全屏遮罩和8–12px blur；背景inert、禁止背景滚动/Tab/读屏访问。原生dialog位于应用最高模态层级。不能通过遮罩、Escape或右上角关闭回到未验证的敏感页面；Escape若提供退出行为，只能返回安全的后台概览。验证成功重新读取受权限控制的数据后恢复页面。接口响应设置no-store。

未确认请求保留actor_id、operation_id、幂等键、原参数摘要/最小恢复元数据；不保存密码、TOTP、JWT或未脱敏地址。同一账号可恢复，换号不得显示或重试前账号请求。验证成功或重登录成功只查询原命令状态，不提交原资金操作。网络未知结果与验证过期分别显示，不能因验证成功就把未知命令当失败并生成新幂等键。

拟新增GET /api/v1/wallet/manual/access验证状态（不返回可转移的秘密），POST /api/v1/wallet/manual/access/verify按既有选定验证方式验证并签发服务端grant，POST /api/v1/wallet/manual/access/revoke显式撤销。状态返回verified、verified_at、expires_at、server_time、scope和撤销原因；接口名称为提议，需实施时更新OpenAPI。重复状态查询不延期，验证失败限流和审计；不同管理员之间不可共用。401保留后台认证含义；WALLET_VERIFICATION_REQUIRED、WALLET_VERIFICATION_EXPIRED、WALLET_VERIFICATION_REVOKED独立区分钱包验证态。

资金事务提交前再次核验钱包grant、后台会话和权限；验证不能只发生在前端路由或请求入口。凭证在锁等待期间到期则拒绝尚未提交的操作并明确结果；已提交成功的命令仍可在重新验证后查询，不重复执行。原有CSRF、Cookie Secure/HttpOnly/SameSite与账号锁保留。

验收：验证后5:01、59:59及离开重进/刷新均不重验；60:00拒绝新的钱包敏感读取与提交并显示验证弹窗；状态查询不延长60分钟；后台48小时期限不变；同一后台会话多标签复用；跨账号/会话不能复用；退出/撤权立即失效；有效grant内操作只需业务二次确认，无重复密码/TOTP提示；锁等待跨期限拒绝且账本无写入；验证成功不重放未确认命令；数据库和浏览器均无明文验证秘密缓存。

风险为服务端快钟、过宽grant作用域、令牌泄漏、撤销传播延迟和旧的5分钟检查残留。采用可信时间健康监测、服务端绑定会话的grant、集中校验和逐接口集成测试。回滚关闭钱包grant功能并撤销已签发grant，恢复上一版钱包验证流程和文案；后台登录时长不变，不能复活已撤销后台会话或金融命令。按账号保留的未确认操作记录必须继续可查询。

## 3. 钱包页面布局、链上详情、监控与事故

### 3.1 结构和视觉

顺序：官方钱包链上流水 → USDT钱包摘要与操作 → 监控与事故列表 → 其他管理模块。顶部链上列表保留原有分页、筛选、快照；标题旁明确观察来源和最新数据时间。

钱包摘要按“可用/待处理/账本负债/链上余额/最近核对时间”分组展示，不能将链上余额等同用户可用余额。金额6位小数、数字等宽右对齐；地址先脱敏、权限允许时查看完整/复制并记录敏感详情访问。观察状态、归属状态、记账状态分列，不能用一个绿色“成功”覆盖三个含义。按钮按主要业务操作、只读刷新、危险操作分组；启停资金/人工处理用明确警示色和二次确认，不能把所有按钮都设计为同等主按钮。

遵循已有后台token、字体、16/24px间距及对齐规范；空状态说明“暂无记录”与可用下一步，错误状态保留旧数据并显示数据时点，加载骨架不显示假余额0。小屏单列卡片、表格容器内横向滚动；不把整页撑宽；键盘和减弱动态效果可用。

### 3.2 官方链上详情弹窗

现有GET /api/v1/wallet/chain/transactions及/{txid}/{log_index}保留；详情改原生模态卡片，桌面宽约800–960px，最大高度90dvh，小屏近全屏。展示网络、合约/币种、txid/log_index、区块号/时间/终局状态、来源与目标地址、方向、金额、观察时间、证据政策/来源、用户归属、关联充值/提现记录、记账状态、异常解释和审计入口。敏感字段按权限脱敏；不是向前端透传任意provider原始JSON。

新增attribution_status：VERIFIED已核实 / UNMATCHED未匹配 / AMBIGUOUS多个候选 / NOT_APPLICABLE不适用 / EVIDENCE_CONFLICT证据冲突；补充attribution_reason_code、reason_text、candidate_count、evaluated_at与关联用户安全字段。当前user_attribution二值字段保持兼容。无订单时显示明确原因；有REVIEW凭据却user_id为空不应只显示“尚未关联”。

关闭按钮、Escape、遮罩点击可以关闭只读详情；恢复触发按钮焦点和列表scrollTop，不重新查询列表；切换页面或账号销毁弹窗和未完成读请求，旧响应不得重开弹窗。

### 3.3 监控与事故列表

监控心跳摘要与事故业务记录分开：心跳刷新不能伪装为事故结案。列为严重性、事故编号、原因、首次发生/最近发生时间、状态、影响范围、关联数量、负责人、操作。现有事故状态OPEN/ACKNOWLEDGED/RESOLVED，condition_active单独显示；generation/version保留，不把“已确认”当“已恢复资金”。严重性沿用现有P0/P1。

现有GET /api/v1/wallet/incidents和/{id}扩展筛选：时间范围、status[]、severity[]、code[]、condition_active、subject_type、用户/交易定位，limit/cursor/snapshot；排序白名单opened_at、last_seen_at、severity，始终附id稳定排序。筛选切换清游标，失败保留已成功状态。现有接口已有cursor基础，本次是补排序、过滤和稳定快照，不能另外维护不一致的第二套事故列表。
