# 管理台入口、客服开通与管理员用户目录设计

状态：2026-09-28 用户确认总体方案；本文待书面审阅。视觉方向为“墨夜银锋”，视觉草图见 `../../verification/artifacts/2026-09-28/admin-entry-design/login-directions.html`，SHA256 `c073bab93c23f33788eb801cbccc0d6bce8f1f0a0573e73e351d2ea4d4458ed0`。

## 目标和已确认边界

1. 管理员和客服共用一个后台登录页面，保留“管理员 / 客服”切换。取消独立“首次开通”入口。未开通的客服第一次用正确密码登录时，页面直接弹出“首次开通验证方式”，可选择账号当前已验证的邮箱或手机。开通后的普通登录只用密码；已验证联系方式或客服角色变化时按 ADR-0081 重新验证。
2. 客服拥有“修改密码”入口，修改的是与畅聊 App 共用的登录密码；管理员、普通用户和混合管理员账号不能使用该入口或接口。
3. 登录页采用用户选定的“墨夜银锋”：深墨背景、银色剑光、青色星轨及四行诗。管理台启动加载态居中显示品牌图标、进度动画及可读状态。
4. “USDT提现与支付”的钱包负责人用有效后台会话即可进入并读取。实际出款、事故处理、预检及其他写操作继续依现有 60 分钟钱包授权和事务内校验执行。
5. 增加仅管理员可见的“用户管理”，可搜索并分页查看全部用户的畅聊号、邮箱、手机号、点钻余额和官方客服头衔。旧的统计与封禁用户列表不增加敏感字段。

## 登录与首次开通

页面保留现有管理员图形验证码和客服免图形验证码的两条服务端登录路径。只有客服登录在完成密码及角色检查后返回 `STAFF_ACTIVATION_REQUIRED`，才开启首次开通对话框；其他 401/403 不触发该流程。对话框展示“首次开通验证方式”和邮箱、手机选项，目标由服务端从当前已验证绑定中决定，响应只给脱敏目的地。发送、确认复用现有 staff activation 挑战、限频、有效期、审计和 Outbox，不新增账号、角色或钱包权限。

当前登录尝试中的密码仅保留在页面内存直到挑战确认或退出流程，不写浏览器存储、URL、日志或错误消息。确认成功后尝试用当前密码完成客服登录并清除内存；如密码或会话状态已变，清空输入并要求重新登录。取消、超时、换角色、离开页面都销毁挑战页面状态和临时密码。验证码错误允许按现有限制重试，不自动换通道或无限重发。

管理员入口只走管理员鉴权；混合管理员身份仍遵循 ADR-0083 的管理员入口策略。管理员验证码失败、客服非开通状态、发送失败等均给明确状态和可重试操作，且不向匿名用户披露绑定的完整联系方式。

## 客服修改共用密码

已登录客服的账号菜单显示“修改密码”；对话框输入当前密码、新密码及确认值，使用现有 12–256 位密码规则。新接口位于身份模块，要求有效后台管理会话、绑定的 HttpOnly Cookie、同源/CSRF 检查及限频。服务端在用户锁内重新核对 ACTIVE、当前管理会话、已开通客服角色、排除 SUPER_ADMIN、当前密码，再通过身份模块的公开改密事务更新哈希。普通 App Bearer、无 Cookie、权限变化、旧设备会话和并发替换均拒绝。

成功后沿用现有改密效果：撤销全部业务与后台 refresh family，设置 24 小时提现冷却，写审计及 Outbox。页面清空密码和会话并返回登录，不自动重放任何业务操作。改密审计不得包含明文密码、完整联系方式或恢复证明。现有 worker 的 `identity.password.reset` 事件契约必须保持兼容，若需新事件名则同步扩展消费者。

## 视觉与加载体验

登录页在桌面以诗句视觉区和清晰的登录卡片组成，窄屏纵向排列；精确呈现：

```text
赵客缦胡缨，吴钩霜雪明。
银鞍照白马，飒沓如流星。
十步杀一人，千里不留行。
事了拂衣去，深藏身与名。
```

使用本地 CSS 与轻量 Canvas 绘制剑光、星轨和层次，避免第三方资源阻断登录。动效不遮挡表单；弱设备和 `prefers-reduced-motion` 下显示静态画面。颜色对比、键盘焦点、表单标签、状态播报和对话框焦点管理应通过无障碍检查。后台启动时用占满可视区且居中的现有品牌图标、环形加载动效、“正在加载管理台”状态以及加载失败的重试入口，替换单行文字。

## 钱包读取与写入授权

钱包读操作继续限定配置的官方钱包负责人、ACTIVE 管理员、有效管理会话、设备和 family；仅免除钱包操作密码授予的 60 分钟 grant。统一边界及各路由的 GET/HEAD 调用只读授权；所有 POST 等写入，包括会落库的 preview、事故状态修改、资金处理、安全设置和 owner transfer，继续要求现有 grant、RBAC、幂等、审计、Outbox、事务提交前复核。直接 `/wallet/manual/payouts` 出款命令仍保留其原授权，不受页面入口改变影响。

页面无需验证即可装载只读钱包资料。写入按钮进入“验证以操作”流程，验证仅授予原有 grant；用户随后重新核对并主动提交原命令，不能自动重放。grant 到期后可继续只读，但写入恢复锁定。账号、会话或钱包负责人变化时清除旧资料。既有 60 分钟授权功能及管理员设置操作密码的要求不删除。新 ADR 精确替代 ADR-0064 关于读取必须有 grant 的一条规则，其他条款保留。

## 管理员用户目录

新建独立的后台只读搜索接口 `POST /api/v1/admin/users/search`，请求体为 `q`、`limit`、`cursor`。用 JSON 请求体承载邮箱或手机号搜索词，避免它出现在 URL 访问日志；响应 `Cache-Control: no-store`。接口要求真实管理会话、同源请求及 `SYSTEM_ADMIN`，不因 `AUDIT_VIEW`、`FINANCE_REVIEW` 或客服身份放行。查询审计只记录 actor、结果和搜索词摘要，不记录原始邮箱或手机号。

每页默认 50、最多 100，按稳定游标分页；搜索支持畅聊号、昵称、邮箱和手机号，过滤、排序与游标绑定，空结果和失效游标有明确状态。所有账号状态都在列表中，状态另列。响应为完整绑定邮箱和手机号及其验证状态、畅聊号、点钻余额字符串（精确两位小数）、官方客服头衔。余额通过账本模块公开批量只读接口按本页 ID 一次聚合 CAIBI 分录，缺少分录返回 `0.00`；前端不以浮点重算。头衔从官方客服资料及当前客服角色批量解析，不使用用户可编辑的个人后缀或 Matrix 昵称。客服撤权后不再标“客服”；禁用账号的角色状态须真实展示。

“用户管理”只在管理员侧边栏显示，进入后才调用专用接口。`/admin/context` 不预取这些联系方式和余额；原 `analytics` 与 `security` 响应保持现有脱敏列。页面提供搜索、上一页/下一页、刷新、空态、加载失败与保留当前筛选。浏览器仅用 textContent 渲染，不把个人信息写入本地持久存储或非必要遥测。

## 验收和发布

先写失败测试，再按登录开通、客服改密、钱包读写边界、管理员用户目录、视觉与加载态逐项实现。认证测试覆盖首次/后续/身份变化、管理员验证码和混合角色；改密覆盖 CSRF/Cookie/错密码/撤权/会话竞争、全部旧会话失效、提现冷却及审计 Outbox。钱包测试覆盖 owner 无 grant 的读取、非 owner 拒绝、所有写入仍拒绝、过期提交与不自动重放。目录测试覆盖非管理员拒绝、跨页与搜索、零余额与精度、客服撤权、无逐用户余额查询、旧接口不泄露敏感字段。

更新 OpenAPI、后台静态资源版本、运行说明和需求验收台账。先做规格及领域审查，再做质量安全审查；执行专项与受影响完整门禁并留真实退出码。生产发布需按后台工作流检查当前线上基线、备份与隔离恢复、精确清单及 SHA、服务和浏览器公开验收；不得从主工作区的其他未提交改动整树部署，也不得在生产触发真实资金操作。
