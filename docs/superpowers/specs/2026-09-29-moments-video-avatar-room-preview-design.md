# Android 2191 媒体发送、头像与会话预览修复设计

日期：2026-09-29。状态：用户已确认方案，待书面规格审阅。范围：朋友圈视频发送与首帧封面、业务头像缓存、会话图片与视频预览。用户确认：2026-09-29 对话中选择三模块完整修复，并批准本模块的数据流与缓存边界。

## 已核实的基线

- Android Debug 0.4.22（2191）中，`BusinessApiClient.putMomentTask` 复用普通业务请求的 8 秒单次超时。合法的 20 MiB 视频在慢网中可因此失败；任务目前把超时及转码异常折叠为“发送失败，内容已保留，请重试”。这是一条代码级可重现路径，不能单凭用户现有提示断定其当次失败就是超时。
- 运行中的 Business API 镜像 `sha256:0bdf751c05015454781c24b66a0c5066ca08ce23436c232ff8aecd1ba5042993` 已提供 0091 视频封面上传与 feed 封面字段；本工作树的业务 API 源码落后于运行镜像。任何服务器候选须先与线上不可变镜像逐文件对齐，保留 0091，再叠加本设计；不得直接用旧源码覆盖。
- `prepareMomentVideoPoster` 在抽帧、解码、压缩或输入超过 512 KiB 时静默返回 `null`。后台任务会发布没有封面 ID 的新视频；封面上传的非 404 错误则让整条动态失败。封面缺失且视频未在本地缓存时，列表只能显示播放占位。
- 新头像在服务器私有 S3 写入，旧迁移对象只在确定缺失时回退本地。手机经业务 API 的 300 秒签名 HTTPS 地址获取字节。每次重签使用不同的令牌路径；客户端把路径当成头像版本，前台资料刷新又按原始 URL 判变，于是同一头像反复失效。
- 会话图片首帧仅同步读房间实例内存，磁盘与 SDK 缓存在可见后异步读取；离房释放房间实例预览。空白不等于重复联网，须以来源计数和断网重复进房证明实际路径。

## 视频后台上传和失败处理

继续使用现有持久化朋友圈任务：用户点击“发送”后可离开编辑页，任务复制并保留源文件、上传进度和幂等 ID；账号切换、取消与任务成功的清理规则保持有效。

媒体 PUT 使用独立时限，普通业务请求仍为 8 秒。单次 PUT 时限按 `文件字节数 / 64 KiB 每秒 + 15 秒` 计算，限制在 30–360 秒；授权刷新与一次安全重试的总预算覆盖两次单次时限及 20 秒刷新余量。上传超时后的重试沿用既有 upload ID 和完成状态核验；服务器已接受的内容不能生成重复动态。新时限同时覆盖视频和不超过 512 KiB 的封面；控制面创建、完成和发动态请求维持短超时。发布前用慢速 20 MiB PUT 验证客户端、反向代理与服务器的有效时限一致。

任务记录有限枚举的阶段和原因，例如准备、视频上传会话创建、视频 PUT、视频完成、抽帧、封面上传会话创建、封面 PUT、封面完成、发布，以及超时、网络、大小、格式、服务端拒绝。上传会话创建与实际 PUT 分开计时，避免把创建请求的超时误报为传输超时。用户获得相应可重试提示；诊断仅发送阶段、类别、HTTP 状态、耗时、大小分桶和 App build，不记录文件名、媒体地址、内容或凭证。后台失败保留任务，用户可原任务重试。

## 首帧封面

新视频从已转码的 MP4 提取 0 毫秒首帧，失败时按 200、500、1000、2000 毫秒依次尝试。仅在来源可验证为该视频的预览帧时使用选择器预览作为回退。先缩到最长边不超过 480 像素，再压为 JPEG 不超过 512 KiB；输入超过 512 KiB 不应在压缩前直接拒绝，但需有解码像素和内存上限。

发布新视频前必须得到服务端确认的封面 ID，并与视频引用一起提交。抽帧或封面上传失败时保留后台任务、已上传的视频及原始源文件，显示明确的封面失败类别供重试；不再静默发布无封面的新视频。已有历史无封面的动态仍按现有本地可生成预览与中性占位逻辑显示。成功发布后，本机立即使用已验证封面，其他设备从 0091 feed 的封面 URL 获取同一首帧。

## 头像缓存契约

服务器仅对头像签名地址附加稳定的非敏感 `v=` 查询参数：取头像私有对象键的 SHA-256 前 32 个十六进制字符。对象键不发给客户端；每次上传新头像产生新对象键，故重签时版本不变、真正换图时版本变化。读取路由继续验证签名与 300 秒有效期，忽略 `v`；旧对象按既有换图与删除流程移除。读取路由本身不另查当前头像引用，因此旧对象删除失败或竞争窗口内的已签地址可能在有效期内继续读取；`v` 不参与鉴权。旧客户端可继续读取；无需数据库迁移或新增必填响应字段。此规则经个人资料、好友、搜索、朋友圈作者等头像投影保持一致，不用于 Matrix `mxc` 头像。

Flutter 使用稳定版本与头像主体身份建立缓存键，保留最新签名 URL 仅作缓存未命中时的下载地址。联系人快照比较与失效逻辑按版本判断是否真的换图，不能因令牌变化逐出磁盘项。账号切换须隔离可见的旧头像与签名 URL；真正换图和删除头像仍立即更新。服务端运行基线含 S3 主写/本地回退，合并候选时不得覆盖此行为。

## 会话媒体首屏

在现有加密媒体磁盘缓存之上，进入房间前预热可见窗口的图片缩略图与视频封面，并把同一账号、同一媒体版本已验证的小预览保留在有界内存 LRU 中供再次进房首帧使用。冷启动尚未解码时绘制明确的媒体占位框；缓存读出后替换，避免纯空白区域。预热不下载完整视频、不解密不可见的历史，也不把明文附件传到业务服务器。

阅后即焚/不可持久化媒体不进入跨房间预览 LRU；登出或切换账号清除对应明文内存。磁盘仍遵循现有加密和容量限制。预览来源计数区分内存、加密磁盘、Matrix 下载与封面 API；断网重复进房应显示已有预览且不增加网络请求，首次未缓存时允许占位与随后下载。

## 验收与交付边界

先写失败测试：8 秒以上合法 PUT、授权刷新后重试、已完成 PUT 的不确定回执、超大/不可解码封面回退、封面上传失败保留任务、重签头像命中同键与真正换图失效、不同账号隔离、断网重复进房以及阅后即焚不缓存。随后实现并运行定向 Flutter 与业务 API 测试、静态检查和适用的仓库验证门禁；记录请求阶段和缓存来源，不以网络良好时的单次人工体验替代慢网测试。

头像的服务器补丁须以当前生产镜像为基线构建候选，核对 0091、S3 双读、鉴权、内容类型和回退。按 `docs/runbooks/admin-production-workflow.md` 取得该候选的单独发布授权后才能部署。Android Debug 修复包按 `docs/runbooks/android-apk-rebuild.md` 的既有签名和重建流程交付模拟器测试；真实 Redmi K80 与实际失败视频的结论仍需设备时间线或脱敏阶段证据。
