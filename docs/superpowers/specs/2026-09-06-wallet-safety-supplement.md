# USDT—点钻钱包安全补充设计与 Sandbox 验证边界

日期：2026-09-06。状态：设计/Sandbox 授权范围内；生产实施与启用仍待领域、Quality/Security 和 ADR 书面批准。

本文细化同日完整钱包设计，冲突时以本文的安全约束为准。没有真实托管商参与，所有外部结果只能通过离线模拟注入。Sandbox 不证明真实链最终性、托管策略执行、持久化灾备、合规或 Android/iOS 可发布。

## 1. 方案选择与本轮边界

选择独立可执行模型加现有钱包回归：便于注入崩溃、超时和旧备份恢复，不需要外部服务。仅增加现有 Sandbox 的成功回调无法验证兑换与完整负债；直接修改生产钱包又涉及尚未批准的受保护规则。因此模型仅保存在验证目录，业务路由、现有资产权限、生产数据库与资金开关均不改变。

## 2. 资产、负债、流动性及发行

同一截止点 T，金额以 USDT 最小单位计算：

`required = user_USDT_available + user_USDT_held + redeemable_CAIBI_cents * 10000 + external_payables_not_already_counted + safety_reserve`

`solvency_surplus = eligible_controlled_USDT - required`

其中可兑付点钻包括用户可用、冻结、红包托管和其他仍归用户的待结算份额；转账和红包搬移不改变总兑付负债。平台发行对手账户的负值不是负债抵扣项。提现冻结已经计入 USDT 用户负债，不得再加一次提现本金。成功链上付款但尚未本地结算必须在同一对账截点解释为结算差异，不得通过删除负债消除差异。

受控资产按唯一地址和同一固化区块去重。托管余额与链上余额是同一批资产的不同证据，不能相加；归集来源和目标不得同时计入同一在途资产。受冻结、权属争议、控制权失效或无法验证的资产不计入 eligible；未固化充值不计入。

流动性另算：`spendable_payout_balance - reserved_unsigned_payouts - operational_buffer`，在实际出款钱包和资源条件下必须足够。锁定资产/额度后才能批准付款，不能以总偿付能力替代流动性。TRX/Energy 成本另设平台运营账和预算，不改变用户 USDT 计量。

发行/人工上分必须证明新增兑付负债有足额资产支持；冲正、赠送、手续费返还和补偿同样受此约束。所有储备消费和发行采用同一事务中的版本化全局额度记录及固定账户锁顺序，禁止并发读余额后分别批准。

历史点钻上线前完成全量快照、来源与归属核对、冻结/红包余额核对和一次性补足储备。无法证明覆盖时，保持全局兑换关闭，不静默削减历史余额或标成不可兑付。若产品选择区分赠送/可兑付点钻，须另行批准资产权利及跨用户传递规则，不能在同一无区分余额中实施。

## 3. 兑换原子性与风险传播

报价、输入及输出均用十进制字符串；拒绝 NaN、Infinity、负数、零、超限金额和精度超限。USDT 转点钻允许显式选择向下取至 0.01，确认页显示实际兑换额和原账户余量；点钻转 USDT 精确乘换单位。

来源扣减、目标增加、订单终态、两资产平衡分录、审计与 Outbox 在同一事务提交。若采用 FUNDS_HELD，则后续从冻结账户消费，不能再次扣可用账户。幂等键按用户和操作作用域绑定规范化载荷摘要；冲突返回原状态及稳定错误，不再过账。

承认“USDT → 点钻 → 转账/红包 → 他人兑换 → 提现”存在间接价值转移。USDT P2P 禁令仅限制直接接口，不能作为反洗钱或风险隔离证明。每条资金边保留业务订单、来源批次、受益账户、金额、风险策略版本与关联原事件，不读取聊天内容。

充值、发行、转账、红包领取、反向兑换及签名前重新检查账户限制。高风险资金进入单独冻结/调查状态，不能通过兑换改变限制；合并/拆分按可追溯批次保留来源，解除限制需要有权限的复核。上线前明确用户/关联账户/设备/目标地址/全平台滚动累计额度、风险名单版本、检测服务不可用时拒绝放行、申诉与误报处理。

离线默认限额：单笔提现 10—100 USDT、用户滚动 24 小时 200 USDT、全平台滚动 24 小时 500 USDT；全部人工审核，禁止自动审批。它们是 Sandbox 策略夹具，不是生产授权值。身份核验、地区准入及制裁筛查需求由适用地区评估转为生产配置，邮箱验证不等于完成身份核验。

## 4. 最终性与充值异常

必须同时满足固定网络/合约、有效 Transfer、正确归属、整数金额、执行成功、认可固化区块、两个独立来源的一致性和不少于 20 的业务确认阈值。确认数不能替代固化。两来源同上游不算独立。提现、归集也采用这一最终性契约。

低于最低充值进入 `MANUAL_REVIEW`，保留其对应资产和待处理负债，不记平台收入；不得未经规则把不同用户的充值拼接。无归属入账进入悬账账户，人工认领须证据、双审和唯一事件约束。错链/错币记录申诉及可找回性评估，不自动签名找回或承诺返还。

已入账事件失效：先限制受影响资金路径，再追加修正。余额不足进入 `REVERSAL_BLOCKED` 和差错案件，由批准的损失/应收会计政策承担缺口，不制造用户负余额。不能冲正一次就宣称追回后续转出资金。

## 5. 付款授权、撤销与紧急停止

每个出款意图保存不可变摘要：业务 ID、网络、合约、来源策略、收款地址、金额、费用上限、审批版本。第二审批人独立核对摘要；任何变更作废全部审批。MPC 分片与业务审批分别验收。

提现/归集共享出款控制域。数据库 CAS 将可提交状态转换为 SUBMITTING，转换前重验账户、资金冻结、审批和当前熔断 epoch。取消只有在 CAS 证明尚未提交且没有外部意图时成功；提交获得资格后禁止用户取消，未知结果继续占用冻结。

应用锁不能原子覆盖远程签名：托管契约必须支持签名策略独立校验及紧急禁签。暂停先阻止新的本地提交资格，再撤销外部签名授权；并发边界上的已受理订单一律作为在途继续调查。已签名/广播交易可能仍被传播，不承诺撤销。安全事故同时停止归集与金库补款，普通流动性暂停可只停止新提现/反向兑换。

托管“查不到”只表示未知，不证明未接收。只有提供方明确终结且不可再执行、独立链上结果符合预期，才能安全退款。幂等承诺必须覆盖整个订单生命周期，超出提供方保留期不得重发。未知订单超过 5 分钟进入调查，仍不能超时退款。

完整的撤销、审批和终态变更都保留 actor、reason、审计和 Outbox。同一业务冻结只能消费或释放一次。

## 6. 灾难恢复与外部意图

金融确认写目标为逻辑 RPO=0：向用户确认前，业务提交及其可恢复日志必须已跨故障域持久化；5 分钟仅可作为非金融数据备份目标。不能只用五分钟周期备份保证资金不丢失。

出款意图先进入独立耐久记录，再调用托管；记录包含业务关联、幂等键、摘要、审批证据引用，状态追加。若落意图后崩溃，恢复按相同键查询；意图不存在不能发出款。耐久系统不可用时拒绝新的出款。该过程需要明确 WAL/复制确认与外部日志耐久边界，不能把两个数据库的普通写入宣称为原子事务。

恢复模式默认禁止资金提交：恢复同一业务截点，导入后续可信提交日志，回扫安全区间，同时枚举托管方和独立意图记录中整个恢复窗口内的全部订单（包括成功、失败与未知），不能只查本地非终态。

外部存在、本地缺失的订单进入 `ORPHAN_EXTERNAL_ORDER`。不凭收款地址猜用户、不自动恢复余额、不再次付款；保留冻结/全局出款熔断，使用耐久意图和提交日志重建后再幂等补结算。若无法重建，保持案件打开及服务只读。

恢复验收需覆盖已成功出款但本地订单丢失、地址刚分配即丢记录、点钻转账已确认却回退、旧 Worker 复活（fencing epoch）、密钥/身份系统不可用。不能用链上余额匹配代替业务流水完整性证明。模型只验证“发现外部孤儿订单后保持关闭”，不模拟真实持久化设施。

## 7. 监控、报表与案件闭环

| 信号 | 检测目标 | 动作 |
|---|---|---|
| 未授权出款/策略变化/重复支付/账本失衡 | 事件到达后 60 秒内 | P0；全出款暂停；安全与值班通知 |
| 签名前储备不足/风险拒绝 | 每次资金操作同步检查 | 拒绝；保留原账；创建原因事件 |
| 扫描器、对账、签名监控心跳超过 120 秒 | 30 秒巡检 | P1；禁止新出款与反向兑换 |
| 外部未知订单超过 5 分钟 | 60 秒巡检 | 调查告警；不释放冻结 |
| 归集资源不足/地址滞留 | 5 分钟巡检 | 运营告警；停止补费循环 |
| 全量资产负债不平/外部孤儿订单 | 恢复前和日终；交易流持续检查 | P0；保持熔断直到解释并复核 |

时限是拟实施验收目标，离线虚拟时间测试不证明线上 SLA。告警包含唯一指纹、首次/最后发生时间、业务证据引用、负责人、ACK 时间、升级次数和关联案件；P0 5 分钟未 ACK 升级。通知链路须独立心跳和演练，不把“写了日志”当作通知成功。关闭案件与解除熔断分权，需复核、对账证据及新 epoch。

流水按固定时区 Asia/Hong_Kong 展示，存储 UTC，查询窗口采用左闭右开并锁定截止序号。报表包括期初、充值、提现、双向兑换、用户转账、红包托管/领取/退回、手续费、调整、冲正和期末；每资产 `期初 + 本期净变动 = 期末`。同时展示可用/冻结、待处理充值、未知提现账龄、总偿付与即时流动性。

按唯一业务 ID 与关联分录聚合，内部归集与金库补款不计用户收入或提现。支持用户/订单/交易哈希追踪、游标分页、筛选及 CSV 导出；导出防公式注入，完整地址仅授权查看并审计。追加账本不等于防 DBA 篡改，需要独立不可变审计副本和序号/摘要核验。

API 补充契约：`GET /wallet/transactions`、`GET /wallet/withdrawals`、`POST /wallet/withdrawals/{id}/cancel`、`GET /wallet/address-book`、`POST /wallet/address-book`、`GET /admin/wallet/reports/daily`、`GET /admin/wallet/incidents`、`POST /admin/wallet/incidents/{id}/ack`、`POST /admin/wallet/incidents/{id}/resolve`。均位于 `/api/v1`，用户接口强制所有权过滤，管理接口强制角色权限。列表携带 cursor/cutoff，金额为字符串；写操作有幂等键、版本和再认证。取消不能覆盖提交中/未知态。

## 8. 移动端验收与分阶段门槛

用户意图幂等键在请求前持久化，超时和进程重启保留；只有用户明确发起新意图才生成新键。服务端按当前用户查询原单，不依赖推送决定成功。报价过期重新确认；完整地址确认；复制与扫码输入防隐藏字符；MFA 失败不能提交。iOS Keychain/Android 系统安全存储保存认证材料，客户端不持有签名分片。

Android 按既有 APK runbook 稳定签名和覆盖升级；iOS TestFlight 构建有效期及审核单独验收。真机矩阵包括弱网/断网、杀进程、后台切换、多设备、旧客户端未知状态、登出恢复和可访问性。离线模型没有验证这些项目。

阶段 1—2 仅内部测试身份；“开放充值但提现关闭”阶段不能向普通真实用户开放无明确兑付出口的资金服务。生产上线仍需合法运营与分发评估、正式受保护变更批准及实现验证。有限自动审批从本版移除，未来另立 ADR。

## 9. 本轮可证明范围

模型验收：固定精度与余量、全负债储备、发行不足拒绝、双资产原子回滚、幂等冲突、固化与来源一致性门槛、冻结一次终结、提交前熔断、外部接收后超时保持冻结、查询补结算、旧快照孤儿识别和期初期末报表。

现有应用回归单独报告，不能把模型绿灯称为已修复现有应用。PostgreSQL 多进程锁、真实固化证明、MPC 门限签名、来源批次传播、滚动风控、独立耐久日志、SLA 告警投递、完整后台报表、真机和商店审核都不在模型已验证范围。
