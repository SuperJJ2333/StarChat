# 朋友圈媒体输入与全局用户展示统一规范

依据：用户在本任务中要求直接执行“统一封装、全局复用、一致展示”。

## 实现边界

1. 会话与朋友圈评论/回复使用同一个 ChatEmojiPanel 及其完整内置目录、分页、选择和自定义项删除交互。文字删除沿用会话现有系统键盘，不新增独立面板布局。不得保留评论专用的 Emoji 子集。内置 Unicode 表情插入当前光标位置并用同一 animated WebP 渲染目录展示；自选 GIF 作为媒体保留动画。
2. 评论图片入口调用会话相册页面组件。选取、取消、预览、原图选择及媒体预处理均复用公共实现；评论数量限制可作为显式参数传入。
3. 静态图片沿用聊天实际使用的格式、尺寸、质量及大小限制。GIF 保留原始动画字节，走统一安全校验，不能将首帧 JPEG 当作发送文件。超限、损坏或不支持的文件显示明确错误并保留文字草稿。
4. 共享的是组件、媒体策略和本地处理接口。聊天继续经 Matrix 加密发送；朋友圈通过其已有业务媒体授权接口发送。不得复用聊天上传结果泄露加密会话附件。
5. 用户展示由共享、按登录账号隔离的数据层解析：非空好友备注 > 最新昵称 > 稳定兜底名称。头像采用最新已知自定义头像 > 默认头像；缺失字段不代表清除，显式清除操作须按权威版本处理。
6. 页面不各自拼接上述优先级；备注及头像修改后所有订阅页面同步更新，冷启动恢复与后台刷新不得先将已知自定义头像降级为默认头像。
7. 覆盖信息流、评论/回复、好友搜索结果、聊天发送者/历史记录、分享好友选择器、好友及用户资料页。朋友圈权限、账号隔离与媒体访问控制保持有效。

## 已确认的共享参数与数据边界

- 静态相册压缩继续使用 DeviceGallerySource 的 1280 像素目标与质量 80；原图保留原始格式。共同的 prepareGalleryMedia 根据实际文件签名确定 MIME/扩展名，图片上限 20MiB。
- GIF 原始字节不经静态压缩；最大 20MiB、逻辑画布 4×1024² 像素、累计合成帧 128×1024² 像素。校验帧矩形、数据块、结束标记；业务服务端另外逐帧解码验证。
- 评论最多 9 张；数量作为共用相册组件的参数。缩略图按设备 DPR 有界解码（48–192 像素），上传仍使用原始准备结果。
- 内置 Emoji 字符集完全复用。自定义区可选取本次从相册导入的图片/GIF；现有 Matrix 加密收藏不上传到业务接口，不宣称两个域的私密收藏同步。
- 朋友圈发布动态及封面原有裁剪/处理入口未改为评论相册入口；此次统一媒体入口范围为用户指定的评论和回复。后续若统一发布动态策略，应另核对其原有封面裁剪和发布尺寸要求。
