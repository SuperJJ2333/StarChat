# 输入响应优化设计

用户已批准调查报告中的方案并要求执行（2026-09-23）。本设计落实客户端热路径减负，不变更服务端、E2EE、财务、鉴权或视觉设计。

采用：有预算的本机索引维护 + 有序增量索引 + 时间线复用。相比仅延长去抖，避免工作堆积与丢批；相比直接把整个 SDK 搬到 isolate，保持现有状态所有权与兼容性。

索引更新不得在 RoomPage 的消息通知内扫描全部历史。当前窗口作为优先队列；历史使用惰性迭代分片，单片最多64项/目标2ms，片间让出事件循环。通知合并但不取消未提交任务，持续消息到来不能无限重置等待时间。当前窗口优先变更屏蔽本轮旧快照同ID，撤回/闪照/本地echo不得入索引。队列仅在内存，账号epoch变化/页面退出停止；失败不提前确认。索引已加载历史由已有加密本机库可重建，不新增明文落盘。

GlobalSearchIndex 按ID更新记录，以有序树维护最近记录和容量，不在每次增量写入对全部历史排序。同ID内容更新和时间变化必须生效；旧历史保留、分页/撤回/账号隔离不变。逻辑时间线使用已有不可变消息对象复用，仅排序新增/替换行，再线性合并；多源同ID优先级和时间/ID顺序稳定。底层 capability 未承诺单源列表不可变或按timestamp排序，因此不冒险直接返回它；单源仍保留O(N)遍历，记录为剩余采样热点。

验证：连续批次、持续洪峰、分片工作量、失败重试、撤回覆盖、延迟解密、账号切换/销毁；排序与容量；输入 composing 和焦点回归。既有帧诊断保留，实测手机型号未提供，桌面测试不冒充真机性能。未证实的成员/解密热点不盲目改动，留真机采样决定。

审查补充：待处理优先项最多2048、失败批次最多64、旧快照覆盖ID最多2112、已提交版本缓存最多60000。过载丢弃的是可从权威已加载 source 重放的优先调度副本，触发新一轮扫描，不是持久消息；这不是任意不可重放事件流的持久队列。已卸载历史仍由现有加密库回填，不能声称任意过载也有持久队列保证。源读取失败重开迭代器，账号有效性在两次索引回调之间再次校验。
