# 通讯录滚动、聊天发送态与群聊信息严格映射规格

**状态：** 已批准  
**日期：** 2026-08-18  
**设计源：** Figma `zpzwTbnj1hqx80tyRygX78`  
**映射方式：** A．原始节点严格映射

## 1. 通讯录根页面

- `通讯录` 与消息、发现、我共享根 Tab 页面滚动模型；用户在列表顶部继续下拉时，导航与内容板块必须作为同一滚动表面产生一致的下拉位移和回弹。
- 底部主导航保持固定，不参与内容滚动。
- 通讯录原有 `★ / A-Z / #` 索引、分组顺序、白色内容表面与 `#EDEDED` 页面背景保持不变。
- 右侧索引跟随通讯录内容表面移动，不得独立悬浮在回弹区域之外。

## 2. Chat 输入发送态

- 输入框只要存在非空内容（包括单个或多个 Emoji），右侧“更多”立即切换为“发送”；不再以输入框是否持有焦点为前置条件。
- 发送按钮保持 44 × 44px 可点击区域，内部使用品牌按压色 `brand/pressed` 作为背景，并用高对比前景色显示发送图标。
- 清空输入内容后恢复“更多”图标和普通透明背景。
- DOM / Widget 顺序固定为：语音、输入框、Emoji、更多或发送。

## 3. 群聊创建与默认名称

- 群聊总人数至少三人，即当前用户加至少两位受邀好友；少于两位受邀好友时创建按钮不可用，服务层也必须拒绝。
- 未填写群聊名称时，按成员稳定顺序取前三位显示名，以 `、` 连接；默认名称最多 20 个 Unicode 字符。
- 用户输入的群聊名称也限制为最多 20 个 Unicode 字符，输入控件与服务调用前双重约束。
- 群聊继续创建为非 direct、私有且强制 E2EE 的 Matrix 房间。

## 4. 群聊 Chat 与聊天信息

- 群聊 Chat 的右上角只显示真实“更多”图标；点击进入独立 `group-chat-info-default` 页面。
- 页面导航标题固定为 `聊天信息(n)`，`n` 为当前已加入和受邀的群成员总数。
- 首屏成员区以头像网格呈现。成员较多时自动折叠，只显示当前可容纳的成员；最后一格始终为添加图标，点击进入联系人选择并调用 Matrix invite 添加成员。
- 成员区下方按微信式分组列表依次展示：`群聊名称`、`群公告`、`备注`、`查找聊天记录`、`消息免打扰`、`置顶聊天`、`保存到通讯录`、`清空聊天记录`、`退出群聊`。
- `群聊名称` 写入 Matrix `m.room.name`；`群公告` 写入 `m.room.topic`；`备注`、免打扰、置顶、保存到通讯录属于当前账号的房间级设置；查找聊天记录进入可搜索当前本地解密时间线的页面；清空聊天记录只隐藏当前设备本地记录；退出群聊调用 Matrix leave。
- 所有编辑操作具有加载、失败提示和成功后的即时刷新；权限不足时显示 Matrix 返回的失败状态，不伪造成功。
