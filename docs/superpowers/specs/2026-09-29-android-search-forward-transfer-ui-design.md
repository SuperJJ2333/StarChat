# Android 2191 搜索、转发头像与群主转让界面设计

日期：2026-09-29。状态：用户已确认方案，待书面规格审阅。范围：聊天记录搜索提示、全局搜索结果头像、转发“发送给”头像、群主转让完成后的页面流与成员选择。用户于 2026-09-29 确认三模块完整修复和本模块设计，并在本地视觉方案中选择“采用此布局”。

## 现状与边界

- 聊天记录搜索页在结果和空结果分支显示“部分本地消息尚未解密，无法完整检索”。本次只去掉可见文案；`LocalRoomHistorySearch.coverageIncomplete` 和检索性能/覆盖度统计仍保留，不把未解密消息计成已完整搜索。
- 全局搜索把 Matrix 房间快照转成搜索行时丢弃房间头像、私聊对端身份和头像引用；结果行又没有使用 `matrixAvatarUri`，且默认 28dp 的列表前导区域会压小头像。历史消息命中应显示所属群或好友头像，发送者继续在文字副信息中可辨。
- 群头像九宫格使用未显式清零内边距的 `GridView`；在转发弹层非零顶部安全区中会继承顶部留白，造成头像整体下移。应在共享组件修复这一布局来源，同时核对单人头像与群头像的几何对齐。
- 群主转让成员页没有搜索与头像；已完成状态显示常驻“刷新状态”卡片并停留在转让流程。服务端还可能返回待核对状态，必须继续区别于完成。

## 聊天记录搜索

删除上述两处可见警告。搜索有命中时直接展示命中；没有命中时使用中性的“暂无匹配记录”。内部覆盖状态及诊断照旧；网络或解密尚未完成时不能展示“全部历史已搜索完”之类的错误保证。此改动不重置搜索索引，也不引入新的网络请求。

## 全局搜索和转发头像

全局搜索结果行从当前 Matrix 房间快照及身份缓存解析头像：私聊用当前对端头像，群聊优先群头像，缺失时使用现有群成员九宫格或稳定占位；聊天记录命中使用所属会话的同一头像。结果索引只保存稳定的房间/用户标识，渲染时取当前身份资料，避免旧签名 URL 或空值覆盖现有头像。前导头像尺寸与主会话列表一致为 40dp，文字对齐不随头像加载跳动。

“发送给”页的 `GroupAvatarMosaic` 显式设零内边距并禁止成为主滚动视图，父级统一控制 44dp 头像框；单人头像与群头像使用一致的框尺寸、对齐和加载占位。修复放在共享组件和实际调用点，避免只在一个弹层中加偏移量。图片加载失败时显示现有首字占位，不出现上半部纯空白或整排下移。

## 群主转让

成员选择页常驻搜索框，支持昵称与畅聊号匹配，并复用已有联系人搜索/拼音规则。每行显示 40dp 头像、名称和明确的选择状态；缺图时用稳定姓名首字占位。筛选不清除已选成员，确认按钮只对合法的单一目标可用，原权限、冷却期及二次确认规则不变。

只有服务端权威结果为 `COMPLETED` 才显示一次“群主转让已完成”Toast，刷新群资料并从选择页、管理页返回“群聊信息”。不再展示常驻“群主转让已完成 / 刷新状态”卡片。`NEEDS_REVIEW`、超时或失败保留当前操作上下文与可核对入口，不弹成功 Toast，也不擅自更改本地群主身份。

## 设计一致性与验收

钱包另按已选的 A 版白色余额卡实施。本模块同步更新 ChatFlow HTML demo 和组件登记表中对应的搜索、转发、群主转让页面，使 Flutter、HTML 的头像尺寸、搜索框、成功跳转和占位状态一致；Figma 同步不在当前 demo 工作流范围。复用现有颜色、圆角、间距和无障碍触摸区规范，不增加一次性视觉 token。

测试先红后绿：未解密覆盖状态仍为真但页面不含旧提示；群聊/私聊/历史命中各有正确头像与 40dp 前导区域；非零 `MediaQuery.padding.top` 下转发群九宫格和单人头像顶边对齐；成员搜索后选择保持；`COMPLETED` 恰好一次 Toast 并回群信息，`NEEDS_REVIEW` 不跳转。完成后运行聚焦 widget 测试、静态检查、HTML demo 页面视觉核对与适用仓库门禁，并在模拟器以新 Debug build 验证实际导航。
