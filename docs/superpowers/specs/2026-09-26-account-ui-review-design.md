## 2. 总览与信息架构

初始总览并排展示“个人信息”“设置”“登录”三台手机。窄屏可顺序浏览，页面内容及操作不应被裁切。审阅控制可切换浅色/深色、已绑定/未绑定以及相关失败状态；这些控制属于 demo，不作为客户端产品操作。

```text
个人信息
  ├─ 昵称：固定左标签 + 输入值
  └─ 个性签名：固定左标签 + 输入值

设置
  ├─ 账号
  │   └─ 账号安全
  │       ├─ 绑定或更换手机号
  │       ├─ 绑定或更换邮箱
  │       └─ 更换密码 ─┐
  └─ 通用            │
      └─ 聊天        │
          └─ 是否自动允许加入群聊
                    │
登录 → 忘记密码 ────┘
  共用：已绑定渠道验证码 → 新密码与确认 → 成功
```

每个二级页有一致的返回导航和标题。设置入口使用微信列表风格：分组标题、清晰行标签、必要的简短摘要和进入箭头；聊天偏好使用开关。

## 3. 四项要求

### 3.1 个人信息

- 不展示昵称和签名的 `3/12`、`0/20` 等数字计数；demo 输入限制对齐当前真实昵称 64、签名 140，不修改正式契约。12/20 是用户安装 UI 反馈，不是当前源码约束。
- “昵称”“个性签名”使用固定左侧标签。标签与输入值是分开的元素；有值、空值、编辑时及保存后都显示标签。placeholder 只作为空值提示，不承担字段名称。
- 保存成功在 demo 内立即更新展示，并仅将演示昵称和签名写入专用 localStorage 键；刷新后继续显示固定标签。保存失败显示明确错误并保留草稿，可重试。此处没有真实 API 写入或客户端跨重启持久化证明。

### 3.2 设置层级

- “账号”分组仅通过“账号安全”进入手机号、邮箱和密码操作。
- 账号安全中提供“绑定或更换手机号”“绑定或更换邮箱”“更换密码”。手机号与邮箱二级页均可操作审阅，用模拟绑定状态决定显示“绑定”或“更换”。
- 复用既有手机号两步证明的界面顺序：已有手机先验证原手机号，再验证新手机号；尚未绑定手机则先验证既有邮箱，再验证新手机号。仅验证新输入的手机号不足以证明现有账号的所有权。缺少可用既有渠道时不能直接继续。
- 用户邮箱当前没有 bind API；邮箱绑定/更换页面是审阅候选，后续需要明确新契约和安全评审，不能把模拟操作称为现有正式功能。
- “通用”分组通过“聊天”进入“是否自动允许加入群聊”。说明保留既有“好友邀请”范围；开关展示当前模拟值、切换及失败反馈，不声称偏好已同步服务端。

### 3.3 登录忘记密码与更换密码共用流程

- 登录页加入“忘记密码”；与账号安全“更换密码”调用同一个 demo 流程，步骤、表单和验证提示一致。
- 验证渠道限定为已经绑定的邮箱或中国大陆手机号。流程为：渠道/账号验证信息 → 验证码 → 新密码和确认密码 → 成功。
- 只有验证码模拟验证成功才进入新密码步骤；两次密码不一致不能提交。正式密码策略沿用现行服务端契约，本设计不发明或放宽策略。
- 成功页提供明确完成操作；demo 只显示模拟状态，输入密码不写入 URL、日志、浏览器持久存储或 API。

当前密码 reset 后端仅支持邮箱链接；`docs/adr/0075-mainland-phone-registration.md:26` 明确手机号不参与旧密码找回。上述邮箱/手机验证码共用流程是本轮审阅目标，后续须补独立 ADR 后才能改变正式契约。正式实现保留既有密码回收后的全部业务刷新会话失效和 24 小时提现冷却，不涉及 E2EE 密钥恢复。

### 3.4 未绑定与通用反馈

- 已登录的审阅场景可展示“未绑定”的本地状态。未绑定验证渠道时阻止继续，提供通用帮助文案。
- 匿名找回入口采用通用反馈，例如“如账号已绑定该验证方式，验证信息将发送至相应渠道”。不显示“该账号不存在”“该邮箱未绑定某账号”等可用于账号枚举的细节。
- 验证码错误或过期使用同类文案；网络失败明确提示重试，保留无敏感信息的表单草稿。此 UI 文案只是防枚举设计的一部分，不能替代正式服务端响应、限流和时序审查。

## 4. 视觉与交互复用

审阅页工具栏复用 `frontend/src/styles/tokens.css` 的全局灰蓝主题，手机预览复用其 `.ui-screen` 移动覆盖：品牌 `#07c160`、按下 `#06ad56`，浅色背景 `#ededed`、导航 `#f7f7f7`，深色背景 `#111111`、导航 `#191919`。字级、间距、行高、按钮与触控尺寸沿用现有 token。demo 内联选用值及来源，文件保持自包含。

按 UI_DESIGN 使用白底中性边框、轻阴影、绿色图标和深字的操作按钮；列表/表单横线沿用共享渐隐分割线（色源 divider，中段 alpha 0.5，stops 0/18/82/100%）。登录保留现有 `landing-changliao.png` 背景、登录方式切换、协议提示及注册入口，背景以内联 data URL 嵌入。未修改 token 源文件。现有注册表 drift 门禁通过，但本审阅稿是独立 proposal，不是已经注册或实施的 Flutter/catalog 页面。

表单采用固定标签、明确输入区、适度留白和统一导航。按钮具有正常、按下、禁用、加载、失败状态；可用键盘访问，错误提示与关联字段对应；深色模式保持文本与操作清晰可辨。用户可重复体验失败后重试与返回，无需重载整个总览。

## 5. Demo 状态与数据边界

| 页面/流程 | 必须可审阅的状态 | 模拟边界 |
| --- | --- | --- |
| 个人信息 | 有值、空值、最长值、保存成功、保存失败 | 保留长度限制和草稿，成功只更新当前 demo |
| 设置/聊天 | 默认分组、二级导航、开关开/关、失败反馈 | 仅本地临时模拟，不保存服务端偏好 |
| 账号安全/绑定 | 已绑定、未绑定、原手机号证明或既有邮箱证明→新手机、绑定/更换入口、返回 | 使用虚构/脱敏样例，不发真实验证码；邮箱 bind 是待批准新契约 |
| 更换密码/忘记密码 | 邮箱、大陆手机号、未绑定阻断、验证码错误、网络失败、密码不一致、成功 | 共用模拟状态机，无 API、无真实密码存储 |
| 全局 | 浅色、深色、三机总览、窄屏与键盘导航 | 审阅控制可改变模拟情境，无真实账号连接 |

样例不得使用真实账号、完整手机号、令牌或生产凭据。验证码标为演示用途，密码仅在当前输入与校验过程使用，完成或退出敏感步骤后清空；不得进入日志、localStorage、sessionStorage、IndexedDB、URL 或网络请求。
