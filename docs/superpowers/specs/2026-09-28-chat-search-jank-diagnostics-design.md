# 聊天搜索、收消息卡顿与可定位诊断设计

日期：2026-09-28。用户授权：修复当前 Android 正式版聊天记录搜索持续加载、消息收发前后输入法与会话切换卡顿，并使网络及性能诊断可按畅聊号定位测试账号。用户报告设备为 Redmi K80；尚无该真机的进程时间线。

## 基线与事实边界

- 当前正式 Android 为 0.4.21（2190）。搜索页、房间租约、诊断客户端等关键文件已与 2190 冻结清单核对；Matrix SDK 整文件在工作目录有后续未提交差异，本设计只将双方共有的片段写入热路径视为 2190 已发布行为。
- 房内搜索在同房间事件到达时清空结果、取消在途查询并从头检索。连续消息可能使查询始终无法完成。检索从本机 SQLCipher 以 512 条为页扫描；稀疏词和很旧的记录需要多页，不走服务器搜索。全局搜索在本机历史仓库每次变化时也重算全部匹配结果。
- 退出房间后，路由未取消 Matrix 房间租约；租约持有页面和导航回调，可使旧页面被保留。Matrix SDK 接收单条消息时复制并重写整份房间事件 ID 数组；同批多条会重复编码和写入。桌面 FFI 既有测试证实写放大，尚未证明它是 K80 每次输入法卡顿的唯一原因。
- 2026-09-28 21:36 +08 服务器内只读滚动聚合：2190 组有 historySearch/slow、消息页慢帧、API request_timeout、Matrix sync 失败及诊断丢失。扫描到日志尾部上限，存在 ID 冲突和覆盖不完整；采样数不是用户数或总体故障率。现有记录既无认证畅聊号关联，也无输入法阶段或搜索取消次数。conversation_open 的远端等待可发生在房间已显示后，不能据其总时长推断可见页面卡住。

实施基线硬门槛：本规格分支从远端主线建立，而该主线缺少部分已发布 2190 搜索文件。写第一个 RED 测试前，须按 2190 冻结清单在隔离工作树复原完整相关源码和依赖，逐项核对哈希、版本及与正式包一致的行为；任何无法复原的文件先查清来源，不得针对旧搜索实现写“通过”的测试。之后把本任务补丁作为相对 2190 的最小差异复核。

## 目标与边界

1. 搜索提交后保持同一查询的结果和分页游标稳定；普通新消息不让已显示历史消失，也不让搜索无限重启。旧记录、稀疏关键词和连续收消息时仍可完成本地检索。
2. 房间关闭后释放归该路由所有的租约；一批消息对同一历史片段至多写入一次最终 ID 列表，保持事件顺序、去重、发送确认和撤回语义。
3. 认证客户端诊断可通过畅聊号查到受限服务器记录；捕获搜索扫描、取消、输入法开合与同步处理的无内容阶段数据，供 Redmi K80 与服务器时间线关联。
4. 保持 Matrix 端到端加密、本机搜索、账号隔离、现有恢复与金融边界。查询词、消息正文、媒体、房间 ID、密钥、凭证及原始异常均不进入诊断。匿名启动诊断继续匿名。

不在本轮增加服务端明文搜索、扩展云端聊天保存、切换 Matrix 身份、修改加密密钥存储，或仅凭聚合数据宣称弱网是输入法卡顿的确定根因。生产发布和真机性能结论分别按既有发布及设备验收流程处理。

## 方案选择

采用本机稳定查询、事务内批量写入及受限诊断三条并行边界。简单地跳过刷新会让动态 offset 分页在新消息插入后重复或遗漏；仅延长网络超时无法修复本机反复扫描与写入；服务端全文检索会改变 E2EE 明文边界。先复用现有加密库与内存投影，不直接提升 Matrix SDK 数据库版本：现有升级默认可能清空事件缓存。若同设备 1 万/10 万记录基准仍无法满足首批可见和完整覆盖的时间目标，本任务须继续设计 SQLCipher 内可重建索引并完成 E2EE 领域及安全审查，不能把慢检索留作无期限后续。

## 搜索数据流

### 房内检索

- 用户停止输入约 250 毫秒或提交搜索后，建立查询代次。该代次固定可检索房间及按新到旧排列的本地事件 ID 顺序。给 SDK 增加有界批量按 ID 读取接口：一页 ID 对应一页事件，缺失行用不可展示占位保持位置；不得拿冻结 ID 配合仍会移动的 offset 取正文，也不得退化为 512 次单条 SQL 查询。
- 每个房内搜索页面同时只持有一代查询快照；通过新增 SDK 只读快照接口保留一次解码 ID 列表，不再每页复制，按 ID 字符数及列表开销设 32 MiB 会话预算。超过预算时改用首尾边界及上次 ID 的低内存锚点翻页，不把超额当作无记录；若现有片段格式无法在大历史下完成有界读取，则须先实现可重建的加密本机分页索引。关闭搜索、切号、撤权时释放快照；1 万与 10 万 ID 场景检查峰值内存及 GC。
- 每次扫描最多处理两个 512 条页或约 100 毫秒匹配工作便发布当前已验证命中，即使不足 50 条；若尚无命中也返回“仍在扫描”而非空结果。后台继续扫描，下滑继续补页，空态只在当前本机范围全部覆盖后显示。匹配循环分段让出 UI，但需单独测量 SDK 解码整份片段的峰值；失败可重试且不清掉已验证的可见结果。
- 普通追加消息不改变当前代次。页面可显示“有新消息，点击更新”，用户主动更新或修改查询词时建立新代次；当前页结果和滚动位置不被消息洪峰清空。新代次使用新的本机快照。
- 撤回、删除、本地清除、房间可见性变化、租约撤销和账号切换属于安全失效：立即隐藏不再可见的内容并终止受影响代次，不能等用户刷新。未解密内容和闪照不进入正文匹配。中断或旧代次晚到的结果不可覆盖新结果。
- 索引缓存仅复用本账号已解密的本机投影，不增加新的明文落盘。冷查询仍需扫描未缓存历史；在目标设备按首次扫描时间验证，不能把“首屏已响应”冒充“全历史已完成”。

### 全局检索

- 仓库变更区分普通追加与安全删除/切号。普通追加只标记现有结果待更新，避免每条消息重跑全量内存索引和结果排序；查询词改变、用户刷新或空闲合并刷新再重算。安全删除立即从当前结果移除，账号切换立即清空。
- 查询代次检查必须覆盖所有异步阶段，包括房间归组和联系人返回。旧代次不得覆盖新查询、改变 loading，或把已有结果清空。联系人网络加载失败不阻塞本地房间及消息命中。

## 房间和 Matrix 写入

- AppHome 管理的房间路由在所有退出路径取消对应房间租约：正常返回、替换路由、导航失败及页面异常都覆盖。等待归租约所有的操作按现有取消语义终止；不取消其他仍在使用同房间的独立租约。
- 在 vendored Matrix SDK 的事务与片段持久化边界，按房间及 fragment 聚合同一批事件 ID 更新，事务内读取必须看到尚未落盘的最终列表，提交时每个受影响片段至多一次写入。现有 BoxCollection 异常路径可能遗留活动 batch 与已更新的内存 cache；先用失败测试覆盖并仅在事务边界修复清理/恢复，确认 SQL 与缓存均回滚后才承诺事务失败整体回滚。事务外原行为保持。发送中转已同步、历史尾插、实时头插、重复 sync、撤回与删除保留原有顺序和去重语义。
- 不做通用 Box 各表 put 语义重构、放宽 E2EE、增加线程任意并发或直接提升数据库版本来获得指标。网络请求和远端同步不能成为已缓存房间打开与本地输入法动画的同步前置条件。

## 诊断协议与隐私

- 现有认证诊断接收入口继续验证 access token 的用户、设备和会话。满足“按畅聊号定位”的方式是受限查询工具按完整当前畅聊号精确查到稳定用户 ID；客户端不自报畅聊号，接收端也不为每批重复读取用户名。接收时用独立服务器诊断密钥对已认证用户 ID、经验证的 device_id 分别做域隔离 HMAC，原始诊断行只加入不可逆主体/设备引用，不写明文畅聊号、用户 ID 或设备 ID。改号后用当前新号仍可找到同一稳定主体的可留存记录；旧号是否可查仅取决于已授权的账号改号审计，不从日志还原。匿名启动入口仍匿名。
- 诊断密钥由服务器私有配置提供，不进代码、容器日志或客户端；轮换时在日志保留窗内保留前一密钥的只读查询能力。仅授权运维可按完整畅聊号精确查询本人所需的 7 天内记录，不开放公共查询、模糊搜索或批量账号枚举。Docker 日志物理留存仍是现有 20 MiB×10 的字节轮转，不能宣称固定 7 天；受限工具最多查询 7 天并报告日志覆盖起止。通用 triage/网络导出剔除主体和设备引用，既有批次大小、限流及脱敏限制继续有效；更新严格协议解析器、私有生产 triage 工具与隐私手册。
- 新增严格枚举和有界数值：搜索代次重启/取消原因、扫描页数与行数、首批命中和完整覆盖耗时；输入法请求到首个稳定布局帧、房间本地首帧、同步处理/片段写入耗时及同期消息数量。新操作记录可选的客户端 UTC 起止与单调时长，服务器校验顺序、持续时间和可信范围，旧客户端批次保持兼容。无关键词、正文、房间 ID、URL、IP、键盘输入、账号凭证。采样和有界缓冲不能因测量本身阻塞 UI；上报丢失继续显式计数。
- 离线积压与手机时钟漂移可使上传时间晚于发生时间。时间锚点取现有认证请求/诊断响应的服务器 Date 与往返时长并有限期保存在内存，不为键盘动画额外发请求。受限时间线以已验证的设备伪名分组；仅在锚点距操作不超过 5 分钟且往返误差可界定时，才把输入法窗口与同设备网络请求或服务端时段作时间关联，否则标记“时间不确定”。同一请求 UUID 仍优先作直接链路关联；同期出现不自动推断因果。生产聚合须保留版本、平台、覆盖缺口和采样含义。

## 错误处理、验收与交付

- 测试先红后绿。房内：1 万条本地历史、稀疏词与连续 50 条追加，第一命中在首个相关页处理后即可发布、不等凑满 50 条或扫完整库；可见结果不闪空，跨页无重复遗漏，内存超额不显示假空态；撤回与撤权立即隐藏，切号和迟到扫描不能泄漏。全局：消息洪峰不触发逐条全量重算，旧异步结果不发布，联系人网络失败不阻塞本地结果。
- 同一 Android 设备/模拟器以 2190 正式源码和候选、相同 1 万/10 万条本地已解密文本、近处命中/稀疏命中/无命中分别重复测首个结果、完整覆盖、UI 帧和峰值内存。目标为 K80 近处命中首显 P95 ≤500 毫秒、1 万稀疏记录完整覆盖 P95 ≤3 秒、10 万 P95 ≤10 秒，连续 50 条到达不重启查询；不达标须继续本机索引/扫描优化。没有实体 K80 时只报告模拟器对照和 K80 待验，不以主机毫秒数冒充真机结论。
- 房间：真实路由退出后租约数回基线，反复进入/退出不累积页面引用；保留发送/媒体/导航取消测试。SDK：1 万 ID 加 50 条同事务更新，从 50 次片段写降到每片段至多 1 次；重开数据库核对顺序、去重、ACK、撤回、异常回滚及事务内外读一致。
- 诊断：客户端额外畅聊号字段被拒绝；改号后当前号仍能解析历史伪名，不同账号/设备、无效 token、匿名入口、限流、密钥轮换、7 天查询边界、日志轮转和通用导出均有断言。输入法/搜索阶段测试验证固定枚举、UTC/单调时间边界、离线积压时的“不确定”分类和无敏感文本。
- 在 Android 测试设备和模拟器做弱网、恢复后消息洪峰、键盘开合、房间切换与历史搜索对照，记录 UI/raster 帧、Dart CPU/GC、SQLite 写次数和本机阶段时间。模拟器不冒充 Redmi K80；真机缺席时只报告候选及未验收项。聚焦测试、静态分析、仓库 verify 环境门禁、规格复核后再做质量/安全复核。
- 先形成独立 Android 候选和服务端候选。服务端发布依仓库规则单独取得本候选授权，随后核查认证、健康状态及其他容器身份；Android 正式更新另按当前版本、固定签名和分发手册验收。任何未完成真机阶段不写成“已解决 K80 全部卡顿”。
