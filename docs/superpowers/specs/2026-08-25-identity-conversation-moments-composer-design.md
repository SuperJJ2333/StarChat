# 身份实时同步、会话展示与朋友圈发表页重构设计

**状态：** 已批准

**日期：** 2026-08-25

**适用范围：** Flutter 朋友圈、好友设置、通讯录、消息列表、群聊页面及群聊信息页面；Business API 契约保持兼容。

## 1. 目标

本设计一次性解决以下问题：

1. 朋友圈封面区使用当前登录账号的头像和 nickname，不再显示固定“畅聊朋友圈”。
2. 好友备注保存成功后，消息页、通讯录及已打开的相关页面立即使用新备注，无需重启 APP。
3. 群聊会话标题、最新消息摘要、聊天页标题和聊天信息页名称使用各自明确的展示规则，不再泄漏 Matrix SDK 的 `Group with` 回退文案。
4. 私聊会话标题严格使用 `remark → nickname`。
5. 新建无名称群聊保持真正的无名称 Matrix 房间，同时在不同页面按产品规则显示。
6. 朋友圈发表页和“谁可以看”流程重构为已确认的微信式 UI。

## 2. 权威数据与边界

- Business API 是 username、nickname、remark 和头像的权威来源。
- `users.nickname` 是用户本人设置的昵称；`contact_profiles.remark` 是当前查看者为好友设置的备注。
- Matrix 仅提供房间、成员、事件、密文及设备端解密后的消息内容，不作为好友备注的权威来源。
- 客户端不得向 Business API 上传 Matrix 明文消息、解密附件或房间密钥。
- 联系人展示名称统一为 `remark → nickname`；只有数据异常导致 nickname 为空时才使用 username 防御性兜底。

## 3. 共享可观察身份缓存

`ChatIdentityCache` 从一次性预加载对象升级为会话级可观察状态源：

- 继承 `ChangeNotifier`，集中持有当前 Profile、联系人列表和 `contactsByMatrixId`。
- `preload()` 保留首次并发去重；新增 `refresh()` 强制重新请求 Profile 和联系人，不复用已完成的旧 Future。
- 新增 `applyUpdatedContact(ContactDetails)`，使用服务端返回的完整联系人对象替换内存列表、重建 Matrix ID 映射、写入磁盘快照并通知监听者。
- 磁盘写失败不回滚已成功的服务端更新和内存状态；记录不含备注正文、Token 或 Matrix 明文的诊断日志，下次 refresh 校正。
- API refresh 失败保留最后一次成功快照，不用 Matrix 房间显示名覆盖联系人身份。

好友备注保存闭环为：API 成功 → 应用服务端返回值到共享缓存 → 持久化快照 → `notifyListeners()` → 返回上一页。保存失败时不修改缓存、不退出页面、保留用户输入并显示错误。

通讯录和消息页使用同一 `ChatIdentityCache`。联系人资料页返回更新后的 `ContactDetails`，而不是只返回模糊的 changed 布尔值；当前页面和共享缓存都使用同一服务端结果。

## 4. 朋友圈封面身份

朋友圈页面并行加载 feed、preferences 和当前 Profile。封面右下角显示：

- 当前用户头像，使用 Profile.avatarUrl 和稳定默认头像回退；
- 当前用户 `Profile.nickname`；
- 白色文字及适当阴影，保证不同封面上的可读性。

不得显示固定“畅聊朋友圈”，不得使用好友 remark 或 Matrix 昵称。Profile 网络请求失败时优先使用共享缓存中的 Profile；没有缓存时显示默认头像和可重试错误状态，不恢复固定文案。点击封面仍执行放大/换封面，头像本身不改变封面点击语义。

## 5. 消息列表展示规则

### 5.1 群聊标题

消息页的群聊标题始终按已加入成员生成，不使用自定义群名或 `room.getLocalizedDisplayname()`：

- 包含当前登录用户；
- 当前用户使用自己的 nickname；
- 好友成员使用 `remark → nickname`；
- 使用中文顿号 `、` 连接；
- UI 单行溢出省略，不截断或重写源名称。

Matrix 成员资料暂未与 Business API 联系人匹配时，防御性回退为 Matrix 成员显示名，再回退到 Matrix ID localpart。该回退只用于暂态展示，不写入 Business API 缓存。

### 5.2 群聊副标题

普通已解密消息：

```text
[3条]项目小李：消息内容
```

- 未读数大于 0 时添加 `[xxx条]`；为 0 时省略前缀。
- 发送者有 remark 时只显示 remark；否则只显示 nickname。
- 保留列表右侧现有红色未读角标。

撤回事件：

```text
[3条]项目小李撤回了一条消息
```

撤回操作者按 `remark → nickname → Matrix 成员显示名 → Matrix ID localpart` 解析。真正的成员加入、退出、改名等状态事件使用对应本地摘要。尚未解密的事件使用安全占位文案，不将密文或异常正文发送给 Business API。

### 5.3 私聊

- 私聊标题使用 `remark → nickname`，异常时才回退 username。
- 私聊副标题保持最新消息内容，不添加发送者名称。
- 私聊标题不得再直接使用 Matrix 房间 localized display name。

## 6. 群聊页面与命名

- 新建群聊继续保留“群聊名称（可选）”输入框。
- 未填写时传入空名称，创建真正的无名称 Matrix 房间；不得用成员名字生成持久化群名。
- 消息页标题始终显示包含自己的成员名称拼接，与是否设置自定义群名无关。
- 群聊聊天页导航栏始终显示 `群聊(人数)`，与自定义群名无关。
- 聊天信息页在房间名称为空时显示 `未命名`；主动设置后显示自定义名称。
- 群二维码等依赖群名称的附属页面也以 `未命名` 作为空值回退。

## 7. 朋友圈发表页 UI

视觉方向采用用户在浏览器流程稿中确认的“严格微信式”：

- 白色背景和微信式导航栏；左侧“取消”，中间“发表”，右侧绿色“发表”按钮。
- 大面积正文输入区。
- 九宫格图片区，最多 9 张，保留删除和图片选择能力。
- 主页面底部只显示“谁可以看”和“添加链接”。
- 取消、草稿保存、发布 loading/success/error 行为保持可见且可恢复。

现有 `moments_page.dart` 中的 Composer 拆为独立页面组件，避免 feed、互动、封面、草稿和可见范围继续堆叠在同一文件。

## 8. “谁可以看”流程

父页面采用两个分组：

1. 第一组为“公开 / 私密”单选。
2. 间隔一行后显示“只给谁看 / 不给谁看”两个二级入口。它们不是单选项，均显示“选择标签或朋友”和右箭头。

点击定向入口进入对应二级页。二级页包含：

- “标签 / 朋友”两列切换；
- 搜索框，同时支持当前列过滤；
- 标签多选；
- 好友多选，好友名称使用 `remark → nickname`；
- 已选计数和完成按钮；
- 切换列不丢失已选内容。

二级页返回键放弃本轮未完成修改；点“完成”将标签和好友选择回填到父页面摘要。父页面点“完成”后才将最终 visibility 和选择集合回填发表页。加载标签或联系人失败时保留原选择，显示重试，不用空结果覆盖已确认状态。

## 9. 错误与恢复

- 备注 API 失败：保留输入、停留编辑页、显示错误，不修改共享缓存。
- 身份 refresh 失败：保留最后成功数据，显示非阻断错误，不退回 `Group with`。
- Profile 加载失败：使用共享缓存；无缓存时默认头像、明确错误和重试。
- 可见范围数据失败：保留已选值、显示错误和重试。
- 发表失败：保留正文、图片、链接和可见范围，恢复发表按钮，不删除草稿。
- 所有诊断日志不得包含 Token、备注正文、消息正文、Matrix 明文或签名 URL 查询参数。

## 10. 测试策略

### 10.1 单元测试

- `ChatIdentityCache` 更新、删除备注、通知、磁盘写入和强制 refresh。
- 群聊标题包含当前用户和所有成员，严格使用 remark/nickname，不出现 `Group with`。
- 群聊普通消息、零/非零未读、撤回、系统事件和未解密摘要。
- 私聊标题 remark/nickname 回退。
- 群聊导航始终为 `群聊(人数)`；空群名详情为 `未命名`。

### 10.2 Widget 测试

- 好友设置 API 成功后，通讯录和消息页无需重启立即显示新备注。
- 保存失败保留输入和错误。
- 朋友圈封面显示本人头像和 nickname，不存在“畅聊朋友圈”。
- 微信式 Composer 结构、九宫格和独立“谁可以看”入口。
- 可见范围分组、二级入口、标签/朋友双列、搜索、多选、取消和完成回填。

## 12. 验收标准

- 六项用户需求均有失败测试、最小实现和绿测证据。
- 备注保存后消息页和通讯录立即更新，重启后保持一致。
- 会话列表、群聊页和信息页均无 `Group with`。
- 群聊标题、副标题、撤回、私聊标题和未读格式与本设计逐字一致。
- 朋友圈封面身份与发表/可见范围 UI 符合已批准流程。
- 不改变 Matrix E2EE、业务身份权威边界和现有幂等/审计规则。
- 公网健康、APK 安装和模拟器运行证据齐全；Git 推送若受外部权限阻断必须如实记录。
