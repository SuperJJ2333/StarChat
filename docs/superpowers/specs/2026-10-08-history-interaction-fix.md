# 大历史会话交互与弱网消息顺序修复规格

状态：用户2026-10-08明确授权修复，沿用已批准的历史连续性、分页窗口与消息权威顺序；实现细节由任务负责人在该范围内裁定。

## 目标与验收

1. 同一待发送消息重试保留原本地插入时间与稳定事务标识；发送尝试计时独立记录。HTTP ACK 不充当服务端时间线确认，首次 Matrix sync 确认后采用权威事件顺序，重复刷新不再次换位。
2. 历史总量属于持久存储，普通进入房间、发送/接收、键盘变化和切换房间不得在 UI isolate 解码、复制、扫描整房间历史 ID 或正文。数据库分页/定位使用有索引的顺序元数据；活跃 UI 与 SDK 源均有明确上限。1千/1万/10万及更大合成历史用真实公共路径检验返回大小与操作次数。
3. 连续快滑、窗口交换和不等高气泡布局变化必须保持可见消息锚点与惯性模拟一致；修正后的下一帧不得回到旧模拟坐标。新手势、页面退出与异步分页竞争不执行过期恢复。
4. 键盘显示/隐藏、房间来回切换和分页/同步重叠有交互回归；长历史不能造成与总量成正比的同步 UI 工作。桌面测试计时不得宣称手机帧率，最终证据明确实际设备与未测平台。
5. 保留全部已保存历史正文、连续性/缺口、上下文跳转、日期与搜索、待发送、消息更新/删除/已读语义。新增本地顺序表采用可恢复的加法迁移；旧大 JSON 的一次性迁移在后台执行，取消/切房间不阻塞 UI，不假称旧二进制可无条件回退。

## 安全与交付

保持 Matrix 端到端加密、现有 SQLCipher 与密钥恢复边界，不改变财务、身份或业务 API。只处理设备端事件/顺序，不记录正文、密钥或账户库。测试数据均为合成数据。候选包含现有未发布语音修复71355adb；正式Android仍0.4.35+2204，不覆盖不可变成品。
