# 统一媒体出入口与 GIF 原图身份

状态：用户2026-10-01明确要求实施，并继承本会话自主计划/ADR、移动交付授权。架构改造；无需重复批准。基线main 7d8b8d6a，Android2195已发布、iOS2195候选待回签。本任务修改不包含在2195包内。

## 目标与验收

用户链路：C发送5MB GIF → 我收藏 → 发送群A → A转发群B → B保存相册 → B发布朋友圈。未编辑原图的每一步保持相同GIF字节与内容摘要，自动压缩不能生成各用户不同的GIF。所有媒体出入口由共享客户端策略识别格式、保留原图、验证读取、生成导出元数据；协议适配器继续负责账号、授权、上传和本地解密。

- UMA-1：GIF按内容头识别，即使文件名.jpg或声明image/jpeg；校验完整结构/20MiB/400万像素/累计128Mi像素既有限制。原图处理跳过压缩；缩略图独立派生，不改变原图。损坏GIF不得降级为JPEG。
- UMA-2：收藏使用ADR-0060既有确定性信封，与聊天发送相同字节得到相同密文。服务器既有摘要去重返回共享mxc；上传者引用保持独立。已收藏的同内容不再上传；存量随机收藏仍可读取，重新发送会进入新统一出口，不批量迁移或删除旧媒体。
- UMA-3：聊天图片/文件/语音/视频、群公告附件、表情收藏使用共享媒体出口；业务头像、朋友圈动态/评论/封面/视频封面上传使用共享验证入口及现有授权传输。统一识别在begin前完成，已有upload session的MIME/长度不允许暗改。
- UMA-4：聊天原图、朋友圈及头像读取保持现有账号隔离、内容校验、取消和缓存预算；共享原图读取/导出接口不得绕过这些适配器。相册保存采用真实格式的扩展名和原图字节，GIF不可写成.jpg。编辑后的导出属于新内容，摘要重新计算。
- UMA-5：端到端链路测试验证相同GIF经收藏/聊天/转发/保存/朋友圈预处理仍字节一致、压缩器调用0次；独立静态图片/视频、格式伪装、损坏GIF、错误摘要、账号撤销与旧收藏兼容测试通过。
- UMA-6：功能覆盖清单明确每个入口、出口、共享策略调用及权限域；全量共享门禁、原生/两端构建、固定Android重建签名与发布、iOS候选回签交接按移动工作流执行。不得声称真机/RSS或实际物理对象数已经实测。

## 统一边界

选用共享客户端MediaAssetGateway + 已有Matrix/业务协议适配器。另一方案是把Matrix密文字节迁入业务媒体平台，违反冻结的域归属；完全重写所有协议、缓存和渲染也会放大近期内存修复风险。共享层必须实际承担格式、保真、导出与原图校验，不能只增加未接入的包装类。

相同原始内容使用一致的本机摘要；存储身份仍按域区分。聊天/收藏/转发共享一份加密原图；用户主动发布朋友圈产生该权限域的业务媒体对象。不承诺两域同一个公开URL或同一物理对象，不开启跨用户明文去重，不将聊天明文/密钥交给业务API。已有Moments capability、头像授权、Matrix mxc、S3 key布局及GC保持兼容。

共享层不得持有全局字节缓存、已完成Future或密钥缓存；校验与内容摘要的大工作沿用后台isolate。20MiB GIF完整结构校验沿用既有限额；不能以只读文件头代替完整发送校验。原图保真不取消恶意/损坏媒体限制。

自动静态图/视频处理产生派生内容；用派生字节计算身份。显式编辑、裁切和格式转换也产生新内容，不能冒用旧摘要。GIF普通发送/收藏/保存/朋友圈发布始终使用原图；仅缩略图及用户主动编辑允许派生静态帧。

## 兼容与风险

收藏随机→确定性使用已批准的ADR-0060参数与风险，不修改算法、Megolm轮换或密钥存储；提供领域及质量/安全复核。旧事件和旧收藏信封不改写。业务上传保持原合同，失败可重试但不能更改已创建session的声明。GIF保存到系统相册的最终动画保留需要两端真机反馈；本轮至少保证传给原生API的字节和格式元数据正确。

本任务不修复上一任务已记录的iOS完全挂起后新媒体发现链；该缺口仍单独保留，统一媒体层不能声称已解决系统唤醒。
