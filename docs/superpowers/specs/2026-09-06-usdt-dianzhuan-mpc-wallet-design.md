# 畅聊 ChatFlow USDT—点钻 MPC 钱包完整技术设计

**状态：** 待书面审阅批准  
**日期：** 2026-09-06  
**适用仓库：** `StarChat`  
**依赖决策：** `docs/adr/0010-usdt-dianzhuan-convertible-custody-wallet.md`  
**设计基线：** 专业托管/MPC 钱包 + APP 自有复式账本；初始日资金总额低于 1,000 USDT  
**范围限制：** 本文只解决技术架构与工程控制，不构成美国或其他地区的法律、牌照、税务或合规结论

## 1. 目标与非目标

### 1.1 目标

1. 为每个用户分配唯一且永不重分配的 TRON 充值地址。
2. 只识别 TRON 主网官方 USDT-TRC20 合约的有效 `Transfer` 事件。
3. 达到确认阈值后，以幂等、原子、可审计的方式给用户 USDT 账本入账。
4. 将充值地址中的 USDT 通过 MPC 托管系统自动归集至受保护配置指定的官方资金地址。
5. 支持 USDT 与点钻按 `1:1` 显示单位双向兑换。
6. 支持用户向合法 TRON 地址提现 USDT，并确保任意重试、超时和恢复路径最多支付一次。
7. 通过链上、托管平台和内部复式账本三方对账，发现差异时自动熔断。
8. 在节点、Webhook、托管平台、Worker 或数据库故障后恢复确定状态并保留完整证据链。

### 1.2 非目标

- 不支持 Ethereum、BSC 或其他网络上的 USDT。
- 不支持 TRX、其他 TRC20 代币或用户自定义合约。
- 不支持 USDT 用户间转账或 USDT 红包。
- 不支持动态汇率、做市或资产价格交易。
- 不在 APP 或自有服务器保存完整私钥，不自建签名钱包。
- 不使用 Matrix 消息、Bot 回调、推送或客户端展示状态决定资金事实。
- 不把法律可行性视为本文已经解决；真实开放前需另行审查。

## 2. 核心不变量

1. CAIBI/点钻保留两位小数，USDT 保留六位小数；应用使用 `Decimal` 或最小单位整数，数据库使用 `NUMERIC`，禁止二进制浮点。
2. USDT 与 CAIBI 分属独立账本。每笔账本交易只能包含一个资产，且分录总和必须为零。
3. 账本交易和分录追加写；已过账记录禁止更新或删除，纠错只允许关联原交易的反向冲正。
4. 用户账面余额等于可用余额与冻结余额之和；可用与冻结余额均不得为负。
5. 每次金融写入必须携带用户作用域或业务作用域幂等键、稳定原因码、操作者、审计记录和 Transactional Outbox 事件。
6. 每个链上事件最多入账一次；每个兑换订单最多过账一次；每个提现订单最多发生一次链上成功支付。
7. 未知托管结果不释放冻结、不换键重试、不创建第二笔出款，只查询原订单并独立查链。
8. 官方 USDT 合约、归集目的地址和出款钱包策略只能来自受保护的服务端配置。
9. 自动归集不阻塞用户到账；归集失败不能撤销已确认且合法的充值入账。
10. 平台受控 USDT 资产必须覆盖用户 USDT 负债、已承诺兑付、待结算提现和配置的安全准备金。

## 3. 系统架构与信任边界

```text
用户外部钱包
    │ USDT-TRC20
    ▼
用户专属 TRON 充值地址
    │ 链上监听 + 托管 Webhook
    ▼
Wallet 应用服务 ───────────────→ USDT 复式账本
    │                                  │
    │ MPC 自动归集                     │ 兑换订单
    ▼                                  ▼
官方归集/金库钱包                  CAIBI 复式账本
    │ 按出款需求补充                    │
    ▼                                  │
MPC 出款钱包 ← 提现冻结/审批/签名 ─────┘
    │
    ▼
用户 TRON 提现地址
```

组件边界：

- **Flutter 客户端：** 展示地址、余额、流水、报价和订单状态；发起业务意图，不构造链上交易。
- **Wallet API：** 地址分配、充值、归集、兑换、提现和状态查询的应用边界。
- **Ledger 公共接口：** USDT 与 CAIBI 的追加写复式过账、冻结、释放、消费及冲正；Wallet 模块不得直接写 Ledger 表。
- **CustodyProvider：** 分配地址、创建/查询 MPC 订单、验证 Webhook、读取托管余额。生产实现与 Sandbox 通过同一契约测试。
- **TRON Observer：** 扫描区块、解析固定 USDT 合约事件、持久化游标、确认和回放。
- **Wallet Worker：** 归集、提现状态查询、Outbox、增量和全量对账。
- **管理后台：** 只通过受 RBAC、TOTP、再认证和审计保护的 API 审批及调查，不能直接修改余额。

事实源层级：业务复式账本是用户余额事实源；TRON 链是链上转移事实源；MPC 平台是其托管订单和签名参与事实源。Webhook 只负责发现，不是结算依据。两家链上数据提供方结果不一致时不得完成新的资金结算。

## 4. 受保护配置

生产配置至少包含：

```text
network = TRON_MAINNET
usdt_contract_ref
treasury_address_ref
collection_wallet_policy_ref
payout_wallet_policy_ref
confirmation_threshold = 20
minimum_deposit = 1.000000 USDT
minimum_withdrawal = 10.000000 USDT
sweep_threshold
sweep_interval
withdrawal_fee_policy
auto_approval_limits
reserve_requirement
feature_flags
```

真实合约地址、官方归集地址、钱包标识、MPC 凭证和 Webhook 密钥不得写入仓库、客户端或普通日志。服务启动时校验配置引用并记录脱敏指纹。地址、合约、确认阈值、审批限额或 MPC 策略变更须双人批准、产生差异审计、实时告警并触发资金功能熔断，完成对账后才能恢复。

## 5. 数据模型

### 5.1 链上与地址

- `wallet_deposit_addresses`：用户、资产、地址、托管引用、分配时间、停用时间、版本和状态；地址全局唯一，停用后永不重分配。
- `wallet_chain_blocks`：网络、区块高度、区块标识、时间和最终确认状态。
- `wallet_chain_events`：网络、合约、交易哈希、日志索引、区块、来源/目标内部地址引用、原始整数金额、执行结果、确认时间、来源提供方和原始载荷哈希。
- `wallet_scanner_cursors`：扫描器、最后扫描高度和区块标识、最后终结高度、租约持有者和租约到期时间。

链上事件唯一键为：

```text
(network, contract_address, transaction_hash, event_log_index)
```

### 5.2 充值与归集

- `wallet_deposits`：链上事件引用、用户、地址历史引用、金额、确认数、状态、入账账本交易和时间。
- `wallet_sweeps`：来源地址、序列、金额、目的配置版本、托管幂等键、托管订单、交易哈希、状态和失败原因。
- 同一来源地址同一时间最多存在一笔未终结归集。

### 5.3 兑换

- `wallet_conversions`：用户、方向、来源/目标资产与金额、固定汇率及版本、幂等键、状态、两笔账本交易、冲正引用、原因码和操作者。
- `(user_id, idempotency_key)` 唯一；一个兑换订单最多关联一组正式过账，一个原订单最多成功冲正一次。

### 5.4 提现与费用

- `wallet_withdrawals`：用户、规范化目标地址、申请金额、到账金额、网络费、服务费、总扣款、报价和到期时间、状态、审批、托管订单、交易哈希和原因。
- `wallet_fund_holds`：业务订单、资产、冻结金额、状态、创建、释放或消费时间。每笔冻结只能释放或消费一次。
- `wallet_fee_quotes`：费用策略版本、报价金额、到期时间和用户确认时间。

### 5.5 对账、审计和事件

- `wallet_reconciliation_runs` 与 `wallet_reconciliation_items` 保存三方快照、差异分类、调查和修复结果。
- 所有人工决定进入现有追加审计域；完整地址只保存在受权限保护的业务表，普通日志使用内部 `address_id` 或掩码。
- 业务状态、账本交易、审计引用和 Outbox 必须在同一数据库事务内提交。

所有迁移采用 expand-migrate-contract，先新增兼容结构和索引，再迁移/验证，最后切换读取；禁止破坏性改写历史金融记录。

## 6. 充值确认状态机

```text
DETECTED -> VALIDATED -> CONFIRMING -> CONFIRMED -> CREDITED
    ├──── 非支持网络/合约/无效金额 ────> REJECTED
    ├──── 系统地址但无法归属用户 ──────> UNASSIGNED
    ├──── 交易失败或确认期内失效 ──────> INVALIDATED
    └──── 长时间未确认 ────────────────> CONFIRMATION_DELAYED
```

校验必须同时证明：TRON 主网、受保护配置指定的 USDT 合约、`Transfer` 事件、目标地址属于系统、金额大于零、交易执行成功且区块属于认可链。达到 20 个确认后才能进入 `CONFIRMED`；阈值可通过受保护配置提高，降低需走受保护变更流程。

从 `CONFIRMED` 到 `CREDITED` 在单个数据库事务内：锁定充值、检查唯一链上事件、解析地址历史归属、创建平衡 USDT 分录、更新状态、追加审计并写 Outbox。幂等键由完整链上事件身份派生。同一事件任意回放只能产生一次入账。

低于 `1.000000 USDT` 的有效充值保存为人工处理记录，不自动增加可用余额。非支持代币不入账，也不承诺找回。

## 7. 自动归集状态机

```text
CREDITED -> SWEEP_PENDING -> SWEEP_READY -> SWEEP_SUBMITTED
         -> SWEEP_CONFIRMING -> SWEEP_COMPLETED

SWEEP_PENDING -> RESOURCE_REQUIRED | DEFERRED | SWEEP_REVIEW
SWEEP_SUBMITTED -> SWEEP_UNKNOWN | SWEEP_DELAYED | SWEEP_FAILED
```

归集在充值入账后异步执行。MPC 托管订单使用稳定键 `SWEEP:{deposit_address_id}:{sweep_sequence}`；超时或未知结果只能查询原订单。广播前重新读取链上余额；链上确认时重新验证固定 USDT 合约、官方目的地址和金额。

TRC20 转出需要 TRON Energy/Bandwidth 或 TRX。优先使用托管商代付、Energy 委托或托管归集能力；如必须由平台补充资源，则仅在已确认 USDT 余额存在时执行，并限制每地址补费次数、每日额度和失败重试。未达到归集阈值的金额按配置延后，避免粉尘攻击消耗手续费。

## 8. USDT 与点钻兑换

### 8.1 精度与比例

```text
1.00 USDT = 1.00 点钻
USDT 最小单位 = 0.000001
点钻最小单位 = 0.01
兑换最小金额及步长 = 0.01
```

`10.123456 USDT` 最多兑换 `10.12 点钻`，余下 `0.003456 USDT` 保留。禁止向上取整。点钻转回 USDT 时，`8.25 点钻`产生`8.250000 USDT`。兑换免手续费，汇率和计算结果完全由服务端决定。

### 8.2 状态机

```text
CREATED -> VALIDATED -> FUNDS_HELD -> POSTED -> COMPLETED
    ├──── 参数、余额、账户或精度不合法 ─> REJECTED
    ├──── 风险或储备不足 ──────────────> REVIEW_REQUIRED
    ├──── 冻结后、过账前失败 ──────────> FAILED/CANCELLED（释放冻结）
    └──── 结果不明确 ──────────────────> RECONCILING
```

USDT 转点钻在一个数据库事务内创建：

```text
USDT：用户可用账户 -X；平台兑换储备账户 +X
CAIBI：平台发行/储备账户 -X；用户可用账户 +X
```

点钻转 USDT 创建完全相反的两笔资产内平衡交易。两笔交易共享 `conversion_id`，任意一步失败时整个事务回滚。点钻转 USDT 前锁定并验证可兑付储备；储备不足进入审核且不得制造无资产支持的 USDT 余额。

### 8.3 冻结与冲正

冻结通过同资产账户间的平衡分录实现：可用转冻结；取消时冻结转可用；成功时冻结转平台结算账户。冻结只能被释放或消费一次。

正式过账后不得改状态伪装失败。冲正创建相反的两笔资产交易，引用原 `conversion_id`，默认只允许全额且一次。若用户已消费目标资产，进入 `REVERSAL_BLOCKED`，暂停相关兑换和提现并人工处理；不得自动制造负余额。管理员只能提交 `ADJUSTMENT_CREDIT`、`ADJUSTMENT_DEBIT`、`REVERSAL`、`FEE` 或 `REFUND` 等平衡业务交易，不能直接填写余额。

## 9. USDT 提现

### 9.1 创建、报价和地址验证

服务端仅接受目标地址、申请金额、幂等键及必要的二次验证凭证。地址必须通过 TRON 主网 Base58Check 校验、规范化和隐藏字符检查；用户不能传入网络、代币合约、来源钱包、汇率、合约方法或原始交易。

初期使用外加手续费：

```text
recipient_amount = requested_amount
total_debit = requested_amount + network_fee + service_fee
```

兑换手续费为零；提现网络费单列。费用报价包含策略版本和到期时间，用户确认后固定。报价过期需重新确认，不得静默加价。实际资源成本与报价的差异按平台费用规则进入平台账户，TRX/Energy 不混入用户 USDT 账本。

### 9.2 状态机

```text
CREATED -> VALIDATED -> FUNDS_HELD -> APPROVED -> SIGNING -> SIGNED
        -> BROADCAST -> CONFIRMING -> COMPLETED

CREATED/VALIDATED -> REJECTED
FUNDS_HELD -> REVIEW_REQUIRED | CANCELLED | FAILED_SAFE
APPROVED/SIGNING -> PROVIDER_UNKNOWN
BROADCAST/CONFIRMING -> CONFIRMATION_DELAYED | RECONCILING | ONCHAIN_FAILED
```

创建订单、冻结总扣款、审计和 Outbox 在一个事务内完成。所有提现至少经过财务审核；单笔达到 `1,000 USDT`、风险命中或超过配置累计阈值时要求第二审批人和 TOTP。发起人与审批人、两名审批人不得相同。

### 9.3 MPC 签名和唯一支付

业务服务只提交结构化出款意图：内部提现 ID、固定 TRON 网络、固定 USDT 合约、目标地址、金额、钱包策略和稳定键 `WITHDRAWAL:{withdrawal_id}:SUBMIT`。任何单台业务服务器或单个员工不能独立完成签名。审批后地址、金额和网络不可修改；变更必须取消未提交原订单并创建新订单。

托管超时或结果未知进入 `PROVIDER_UNKNOWN`，保留冻结，只查询原订单和链上来源钱包。已取得交易哈希后持续验证交易存在、合约执行、目标地址、金额和确认数；不得因延迟创建另一笔交易。只有托管明确未创建订单，或链上明确失败且证明资金未转出，才可依据状态机安全释放冻结或创建新的用户请求。

链上成功后将冻结本金转入提现结算账户、费用转入对应费用账户并完成订单。链上成功但本地宕机时，对账任务使用原业务引用幂等补结算。链上明确失败时按已公布费用规则释放本金和费用；原交易哈希及原因永久保留。

## 10. 链上监听、回滚和溯源

采用托管 Webhook 与 TRON 节点轮询双通道发现、独立链上确认。扫描器按区块保存事件后才推进持久化游标；崩溃后从安全重叠区间回扫。多实例通过数据库租约协调，但正确性依赖唯一约束而不是锁本身。

保存区块高度与区块标识。若同高度标识变化，则回退到共同安全高度重新扫描：未入账事件标记失效；已入账事件只能创建关联冲正，并暂停相关用户兑换和提现直至调查完成。

充值证据链必须可从链上区块追踪到 Transfer 事件、地址历史归属、充值、USDT 账本交易、归集订单及官方地址收款。提现证据链必须可从用户请求追踪到冻结、风险结果、审批、MPC 订单、签名策略、链上事件和结算分录。

## 11. 三方对账与熔断

三方为：TRON 链上实际资产及交易、MPC 托管订单及余额、APP 内部复式账本。每小时执行交易级增量对账，每日执行全量资产负债对账；提现状态分钟级检查，充值地址及归集每 5—15 分钟检查。

必须检测：链上充值未入账、无链上依据的入账、重复入账、链上出款无本地订单、单提现多个成功交易、链上成功却释放冻结、托管成功而链上不存在、归集流向非官方地址、地址残留及总资产不足。

可自动修复的操作仅限使用原幂等键补记已确定结果、推进本地状态、重投 Outbox 或补做已确认充值。不得自动修改金额、删除记录、重发不明确提现或伪造链上事实。

出现未授权链上出款、重复支付、账本失衡、MPC 策略异常、资产低于负债或数据库疑似篡改时，触发 P0：立即暂停新提现和反向兑换，保留现有订单、冻结和证据，并通知值班及安全负责人。已广播交易继续监控。

## 12. 威胁控制

- **假币：** 固定网络和合约，不信任代币名称或客户端声明。
- **Webhook 重放：** 验签、时间戳、请求 ID、正文哈希和链上复核。
- **并发双花：** 数据库事务、账户锁、冻结分录和唯一业务引用。
- **精度套利：** 最小单位整数/Decimal、0.01 步长、禁止向上取整及往返属性测试。
- **粉尘补费：** 归集阈值、补费次数与额度上限、仅对已确认 USDT 地址补资源。
- **账户接管：** 敏感操作再认证、MFA、新地址和安全设置变更冷静期、设备风险检测。
- **地址替换：** 规范化、校验和、完整确认页、签名前重比对，审批后不可修改。
- **拆单绕限额：** 按用户、设备、网络、目标地址、时间窗口和全平台累计聚合风控。
- **托管或节点欺骗：** 独立查链、备用提供方、状态分歧熔断和三方对账。
- **内部人员作恶：** 职责分离、双人审批、临时高权限、追加审计和策略变更告警。
- **供应链攻击：** 固定依赖和镜像版本、SBOM、依赖扫描、可复现/签名构建及生产秘密隔离。
- **拒绝服务：** API 限流、队列隔离、按主体配额、背压和不影响既有资金状态的熔断。

## 13. 权限模型

- 客服只看掩码订单，不看密钥、完整地址或审批提现。
- 财务审核员审核订单与对账差异，不修改 MPC 策略或直接写账。
- 安全审核员管理风险策略和事故，不能单独出款。
- 钱包运维查看节点、余额和资源健康，不访问用户认证秘密或账本写接口。
- MPC 审批人只批准不可变的指定订单，不能修改地址和金额。
- 审计员只读账本与审计。
- 服务账户按组件拆分并使用最小权限，禁止交互式通配访问。

高危操作包括修改合约、官方地址、出款钱包、确认数、审批限额、MPC 策略、手续费、人工冲正、补记充值和解除熔断。所有高危操作要求近期再认证、MFA、工单、双人审批、前后差异、追加审计和实时告警。

## 14. 日志、隐私和秘密

普通日志只记录关联 ID、业务订单 ID、脱敏交易哈希、内部地址 ID、状态和原因码。禁止记录完整钱包地址、MPC 令牌、私钥/密钥分片、授权头、完整 Webhook 正文或用户验证凭证。完整地址只允许在受 RBAC 保护的业务表中读取，读取本身产生审计事件。

生产、测试使用完全不同的钱包、托管账户和凭证。Secret Manager 中的凭证由专用服务身份读取；CI/CD 和数据库管理员均不能单独调用生产签名。

## 15. 灾难恢复

初始目标为数据库 `RPO <= 5 分钟`、服务 `RTO <= 4 小时`。业务数据库启用加密备份和时间点恢复；地址归属、账本、订单和审计必须处于一致恢复点。审计副本与生产数据库隔离保存。

恢复流程：停止新资金写入，恢复数据库，从最后可信扫描游标向前回退安全区间并回放，查询所有非终态 MPC 订单，执行三方全量对账，经人工确认后逐项解除功能熔断。切换托管商前必须证明旧平台无未知或在途出款；不能通过迁移重发不确定订单。

链上可重建充值和提现事件，但不能重建用户身份、地址归属、点钻账本和审批，因此这些记录及托管订单标识必须独立备份并定期执行真实恢复演练。

## 16. API 与兼容性

OpenAPI 至少覆盖：

```text
GET  /api/v1/wallet/config
GET  /api/v1/wallet/deposit-address
GET  /api/v1/wallet/deposits
GET  /api/v1/wallet/balances
POST /api/v1/wallet/conversions
GET  /api/v1/wallet/conversions/{id}
POST /api/v1/wallet/withdrawals/quotes
POST /api/v1/wallet/withdrawals
GET  /api/v1/wallet/withdrawals/{id}
POST /api/v1/webhooks/custody/{provider}
GET  /api/v1/admin/wallet/reconciliation
POST /api/v1/admin/wallet/withdrawals/{id}/approve
POST /api/v1/admin/wallet/controls/pause
POST /api/v1/admin/wallet/controls/resume
```

金额序列化为十进制字符串，客户端不得提交 JSON 浮点。资金写接口强制 `Idempotency-Key`；相同键相同规范化载荷返回原结果，不同载荷返回稳定的 `IDEMPOTENCY_CONFLICT`。旧客户端继续读取原余额和提现接口时保持兼容；新增兑换字段和状态采用向后兼容扩展，破坏性变更需独立审批。

## 17. 测试策略

### 17.1 单元和属性测试

- 地址 Base58Check、隐藏字符和规范化校验。
- 金额精度、最小金额、费用报价和固定 1:1 计算。
- 任意合法金额往返兑换不凭空增值，六位余量不被向上取整。
- 每资产分录总和为零，可用/冻结余额不为负。
- 状态机拒绝非法回退和重复终结。
- 冲正只能关联原交易且默认一次全额执行。

### 17.2 并发和故障注入

- 重复/乱序 Webhook 与重复区块扫描最多入账一次。
- 并发兑换和提现不能重复消费余额。
- 在充值入账事务的每个中断点恢复后不丢账、不重账。
- MPC 提交超时、响应丢失和回调丢失不会产生第二笔支付。
- 链上成功、本地宕机后使用原业务引用完成一次结算。
- 节点分歧、链回滚、资源不足和 Outbox 重投触发预期状态。

### 17.3 安全、集成和恢复

- 假 USDT、伪造/重放 Webhook、地址污染、拆单、微额补费和越权审批攻击测试。
- Sandbox 与生产 `CustodyProvider` 契约测试一致。
- PostgreSQL 真实事务、锁、唯一约束和迁移回滚演练。
- 链上、MPC 与账本三方增量/全量对账。
- 未授权出款触发 P0 熔断。
- 从加密备份恢复并回放安全区间后，全部差异可解释。

## 18. 分阶段上线

1. **只读观察：** 扫描和记录真实链上事件，不改变用户余额。
2. **受控充值：** 内部账户验证专属地址、确认、入账和归集。
3. **开放充值：** 使用低单笔和每日限额，保持提现关闭。
4. **单向兑换：** 开放 USDT 转点钻，验证账本和储备。
5. **反向兑换：** 开放点钻转 USDT，提现仍关闭。
6. **邀请制提现：** 白名单、小额且全部人工审批。
7. **有限自动审批：** 只对低风险小额订单开放，异常继续人工处理。

每阶段至少完成一次日终对账和相关故障演练。出现未解释资金差异时回到上一安全阶段；关闭入口不影响已广播交易的持续监控和结算。

## 19. 上线验收门槛

### 19.1 充值与归集

- 地址唯一、历史可追溯且停用后不可重分配。
- 只有固定 USDT 合约事件能入账；20 确认前不可用。
- 重复扫描和回调不会重复入账，入账与账本事务原子。
- 归集只能流向受保护配置地址，未知状态不重复发起。

### 19.2 兑换

- ADR-0010 已获领域与 Quality/Security 书面批准。
- 两套账本各自严格平衡，往返属性测试和并发测试通过。
- 储备覆盖受保障负债，冲正和储备不足流程完成演练。

### 19.3 提现

- 完整私钥不存在于客户端、业务服务、数据库、日志或构建产物。
- 冻结、审批、MPC、广播、确认和补结算全链路通过。
- 未知结果恢复证明最多支付一次；地址冷静期及 MFA 有效。
- 三方对账、P0 熔断、备份恢复和未授权出款检测完成演练。

### 19.4 工程门禁

- 格式、lint、类型检查、单元、属性、集成、E2E 和安全测试通过。
- OpenAPI、生成客户端、迁移、配置、告警和运行手册与实现一致。
- 非 Git 验证证据保存于规定的 `docs/verification/` 子目录。
- 没有硬编码真实钱包地址、托管凭证、占位符、临时绕过或忽略警告。

## 20. 交付拆分与审查顺序

本规格规模较大，实施计划必须拆成可独立验证的阶段：

1. ADR、领域接口和兼容迁移基础。
2. 链上观察、专属地址、充值确认和归集。
3. 通用冻结与 USDT—CAIBI 兑换。
4. 提现报价、审批、MPC 出款和未知结果恢复。
5. 三方对账、熔断、告警和灾难恢复。
6. Flutter 与管理后台交互、OpenAPI 生成客户端及分阶段发布。

每阶段先执行规格符合性审查，再执行代码质量和安全审查。任何阶段都不得通过直接跨模块写表绕开公共 Ledger 接口。
