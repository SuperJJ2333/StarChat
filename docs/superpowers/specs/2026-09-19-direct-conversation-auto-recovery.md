# Automatic direct-conversation recovery

Accepted under the user's explicit authorization for implementation, production correction and ADR decisions, extended by the request to repair the system for all friends after confirming the incident pair now sends successfully. Stable logical conversation identity and encrypted history remain invariant; physical sending destinations may recover under server authority. No promise of delivery without connectivity, membership/permission, or available device keys.

## Evidence and decision

Fresh production metadata audit:65 canonical pairs,59 exact joined/encrypted,2 invitation states,2 fully exited,2 partially exited. Both fully exited pairs remain active unblocked friends; one has an eligible registered alternative, the other does not. One partial exit remains friends; the other friendship was removed. The multiple-alternative pair has a healthy canonical and must remain unchanged. Raw identifiers remain protected on the server.

Manual correction cannot solve this. Blind failover on network error can duplicate sends/rooms. Adopt a shared authoritative lifecycle resolver, compatibility maintenance for old directory readers, and a new client preparation path.

## Server lifecycle

An additive durable recovery record serializes each pair and records recovery generation, expected old canonical, fixed alias/reservation marker and publication state. Existing canonical and old history are retained while a replacement is pending. First creation reuses V2; later generations never replace the original reservation or return a false absence to old clients.

New authenticated POST resolve requires current friendship and absence of bilateral block, and verifies profiles. A healthy canonical remains preferred regardless of other rooms. JOIN/invite pairs keep the current room for normal client membership convergence. One departed participant retains normal invitation repair when safe; no admin forced join. A strictly retired old room (successful details with zero joined plus strict state without invite/knock/ban) may switch to a metadata-verified registered source. Selection is server-owned and deterministic among equally valid sources; all remain history. If no safe source exists, reserve one durable generation with a fixed alias; every retry/concurrent device receives the same alias. Unknown/timeout/permission/ban evidence never authorizes a new room.

Generation publication verifies current generation, expected old destination, alias and marker, exact expected joined/invited pair, Megolm, and server-known source metadata. Under the pair lock it preserves logical ID, adds old/new history, switches destination, and writes actor/reason/before/after audit plus transactional Outbox. Late generation publication cannot overwrite a newer destination. Initial creation stays compatible with V2. No message plaintext, keys or attachment contents reach the business service.

Partial-exit amendment: a departed requester cannot join an invitation-only room without the absent peer inviting them. Explicit new-client POST may recover when strict state proves requester leave and peer JOIN, retaining exact pair, encryption, send-power and relationship guards. Prefer a verified both-JOIN registered source; if none exists use a durable generation recording reason and original departed user. Revalidate that original user on every pending resolution/publication: still leave, while peer JOIN or subsequent leave can continue the same generation. A return/invitation/ban/unknown blocks switching. The joined peer cannot initially invoke this exception for someone else. Compatibility GET behavior is unchanged.

When both have subsequently departed and Synapse returns successful empty state, an existing partial-exit generation may instead use the same strict fully-retired proof accepted for normal retirement (including matching successful details with joined_members=0). Initial partial authorization cannot use absent membership as leave. This prevents a real empty-state transition from stranding the fixed pending alias while retaining all target and relationship checks.

Both old GET directory endpoints use the same bounded compatibility maintenance policy for strictly retired destinations with a verified existing source. They never expose null for an existing canonical or authorize a new generation. Normal readers avoid repeated Matrix probes using bounded per-pair throttling; concurrent correction is fenced by the existing DB pair lock and stable operation key. Unavailable evidence preserves the old mapping. Cache controls probe frequency only, never substitutes for fresh mutation evidence. Document any per-process vs cross-process throttling limitations, keep a global probe limit and finite candidate bound.

## Client lifecycle

New-client coordinator invokes resolve and uses its fixed generation alias for creation/publication. It remains local-first for opening history. Online preparation of new sends resolves a current target and refreshes a stale active room page/lease before dispatch; group rooms never enter this protocol. New attachments/forwards resolve before creating/uploading/encrypting their operation. Existing in-flight attachments and already-bound outbox rows never move across rooms.

Only null-room outbox rows are proven undispatched by the current storage contract. Preserve local/transaction IDs when binding those rows to the new target. Do not infer unsent from failed/queued/retryCount. Final SDK membership/encryption/account-generation and send-permission guards remain. An unavailable resolver yields bounded recoverable failure, not a new room or a silent send to an old source. Per-peer unbound retries after 2/5/15 seconds avoid permanent online waiting; exhaustion retains a manually retryable failed row and original transaction ID. Bound sends retain existing retry semantics. New protocol404 does not silently fall back to an older mutation protocol.

## Acceptance and publication

Test first: stale registered-source recovery, healthy primary stability, no-source generation replay, lost-response/concurrent creation, alias/marker/late-publish fencing, friendship/block/malformed/unavailable rejection, both directory endpoints, active-page convergence, null vs bound outbox, attachments/groups separation. Spec review precedes independent quality/security review; isolated PostgreSQL proves concurrency and upgrade/rollback. Production overlay preserves unrelated fixes, expands schema without destructive rollback, and repairs only eligible relationships. New mobile artifacts must be built/tested before claiming client recovery shipped; old2136 compatibility limits remain explicit. Device feedback is separate from service metadata proof.
