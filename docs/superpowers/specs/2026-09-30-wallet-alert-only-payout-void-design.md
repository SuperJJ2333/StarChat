# 钱包监控仅邮件告警与未广播出款撤销设计

日期：2026-09-30。用户已确认：该笔付款从未签名、从未广播；所有钱包监控事故只发邮件，不自动暂停钱包；已批准本设计的管理员再次声明、最新链上扫描、精确冲回与独立恢复流程。决策见 [ADR](../../adr/2026-09-30-wallet-alert-only-and-unbroadcast-void.md)。

## 用户可见结果

- 事故继续显示级别、原因、时间线与邮件告警状态。新监控事故不会改变资金启停状态；页面同时如实显示现有暂停或单笔操作因证据不足被拒绝。
- 当前订单只有在管理员执行“确认未广播并撤销”且服务端复核通过后，才显示“已撤销（确认未广播）”。提交失败时保持 `UNKNOWN` 和原资金状态，并给出可操作的失败原因。
- 事故处置与现有资金暂停的解除仍是两个独立操作。撤销订单不会自行恢复资金。

## 服务边界与流程

1. 人工储备监控、旧钱包监控及定时维护中的对账与孤儿订单扫描只记录信号并调用事故服务；事故服务继续生成审计、Outbox、邮件提醒及未确认 P0 的升级提醒。移除这些路径自动调用全局暂停的分支。明确的人工暂停、账户级安全限制和已有暂停的恢复接口不改。
2. 新 `void_unbroadcast` 应用命令与管理后台入口要求官方钱包管理员权限、近期登录、独立钱包写入验证、订单 ID、预期版本、明确声明、原因码和幂等键。命令保存声明摘要与观察证据身份，不保存私钥、助记词、明文地址或敏感日志。旧用户取消接口仍只适用于 `REQUESTED`。
3. 金融事务外取得新鲜观察快照，核对扫描游标越过订单领取时间且接近当前时间；检查官方地址对原锁定目标的转出及疑似转出。若证据不完整、观察源错误、快照过期或疑似付款，拒绝。提交前在预算和订单锁下重新核对证据期限、订单版本、候选及已分配事件，并重新验证管理员权限。
4. 原子补偿依次核对原 HOLD、汇率调整与兑换记录：释放最终应付 HOLD，再精确冲回原兑换的全部 USDT 和 CAIBI。无足额可用 USDT、任何分录不平衡或并发漂移则全部回滚。`VOIDED` 保留领取与处理历史，扣减待处理计数，审计和 Outbox 在同一事务提交。命令重放只返回既有结果，载荷变化拒绝。
5. 管理员再执行当前事故的复核与结案、资金启停中的独立恢复；服务端执行现有新鲜证据和未结订单检查。生产操作使用真实管理会话与操作验证，不通过 SSH 直接改库。

## 验收重点

先运行红测证明现行代码会自动暂停且拒绝 `UNKNOWN` 撤销，再最小实现并转绿。测试覆盖两条监控路径、所有事故级别、邮件失败、既有暂停保留、单笔证据门槛、订单终态、关联兑换、汇率调整、余额不足、重复请求、并发、权限与审计。代码完成后按仓库要求先做规格符合性审查，再做领域和质量/安全审查；生产部署以现行镜像、schema 与源码哈希为基线，隔离数据库演练并保留回退。
