# Wallet Monitor Temporary Source Unavailability T2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record the known source read-budget expiry as literal T2 without an automatic global wallet pause, and align reserve publication with its verified source window while preserving independent financial gates.

**Architecture:** Classify the precise `SOURCE_READ_BUDGET_EXPIRED` exception before the generic fail-closed branch; preserve incident bookkeeping through the existing service. Use the validated source window in reserve publication while leaving payout's independent 120-second rule. Extend the incident type through persistence validation, API, reports, alerts and admin UI. Reclassify the identified historical generation through an idempotent application command, never by rewriting audit or Outbox history.

**Tech Stack:** Python 3.12, SQLAlchemy 2, FastAPI/Pydantic, PostgreSQL, React/JavaScript admin panel, pytest and Node test runner.

**Decision:** [Wallet monitor T2 ADR](../../adr/2026-09-28-wallet-monitor-t2.md). This plan owns only the identified budget-expiry subtype of `MANUAL_SOURCE_UNAVAILABLE` plus the verified 120/360-second publication mismatch. The first observed pause was due to separate `MANUAL_MONITOR_UNAVAILABLE`; changing T2 classification cannot clear it.
