# 计划：添加朋友 — 畅聊号/邮箱前缀搜索精确规格（2026-08-30）

## 精确需求规格

### 1. 搜索方式与匹配规则
- 用户在「添加朋友」页搜索框输入文本，可按 **畅聊号**（username）或 **邮箱**（email）查找。
- 匹配方式为**前缀匹配**：输入文本（去首尾空格、大小写不敏感）与畅聊号或邮箱**开头连续字符**一致即命中；中缀/尾部命中不算。
- 命中即去重排除：自己、与本人存在拉黑关系的用户（双向）不会出现在候选中。

### 2. 最小匹配长度
- 输入**至少 2 个字符**（去空格后计数，中文按 1 字计）才开始返回候选结果。
- 少于 2 个字符时客户端不发请求，展示引导文案「输入至少 2 个字符，可通过畅聊号或邮箱搜索」；服务端同时以参数校验（`min_length=2`）拒绝，双端兜底。

### 3. 候选排序逻辑（三级）
1. **匹配度**：畅聊号前缀命中的用户排在邮箱前缀命中之前（畅聊号是主要找人标识）；
2. **最近活跃时间**倒序：同级内按该用户全部未吊销设备的 `last_seen_at` 最大值降序（登录与心跳都会刷新该字段；无活跃记录的排最后）；
3. **畅聊号字典序**：保证同分稳定排序。

### 4. 结果展示与容量
- 每条候选展示：**头像**（无头像用昵称首字占位）+ **昵称**（主标题）+ **畅聊号**（副标题，"畅聊号：xxx"）。
- **不展示邮箱**：他人邮箱属 PII，仅作为匹配字段，不在任何出参中出现。
- 单次最多返回 **20** 条；与该用户的好友关系由操作按钮体现（添加 / 申请已发送 / 已添加 / 重新申请）。

### 5. 交互与安全
- 客户端输入防抖 300ms；提交（回车）立即搜索。
- 端点 `GET /api/v1/users/search?q=`（登录用户），参数长度 2–64；限流每用户 30 次/60 秒。

## 实现落点
- 后端：`modules/identity/profile.py::search_public_profiles`（前缀双字段 + 排序）、`api/friendship.py`（min_length=2、限流）、`main.py`（注入 rate_limiter）。
- 客户端：`features/contacts/contacts_page.dart::AddFriendPage`（防抖搜索 + 头像/昵称/畅聊号列表）、`contact_models.dart::AddFriendGateway`、`core/business_api_client.dart` 实现声明。
- 测试：`tests/business_api/test_user_search.py`（6 项）、`test/features/contacts/add_friend_search_test.dart`（4 项）。
