# iOS 16.7.16 重启会话恢复与错误提示修复计划

状态：用户已批准并要求执行（2026-09-20）；2026-09-20。用户报告 0.3.96，整机重启解锁后首次打开退出且任意账号 L07；杀 App 重开正常。

## 事实与证据边界

基线83c2f196，隔离分支codex/ios-reboot-session-20260920。
- 安装检查读取SharedPreferences和数据库目录；都报告缺失时执行clearInstallation删除钥匙串。未检查iOS受保护数据状态；Directory.exists把不可访问与不存在混为false，旧测试甚至要求“路径是文件也判为新安装”。这是待修复的保守性缺陷，与此次重启触发因的关联仍需设备验证。
- 有效业务会话加本地Matrix未登录时，bootstrap主动清除并远端撤销业务会话。
- 业务登录早于本地账号库选择，因此L07之前可能已经踢掉另一设备。
- LoginStageException仅显示阶段码，无法识别具体异常。
- 未取得受影响设备日志，不能声称已证明聊天库物理删除或唯一根因。

## 修复设计

1. 安装世代检查前明确检查iOS保护数据可用性；不可访问只延后与重试。重新可访问后重新加载Preferences，不能使用锁定期间缓存的空值。未知目录/错误不能证明全新安装，绝不据此删密钥。保留既有AfterFirstUnlock安全策略，评估锁屏来电影响，不弱化E2EE。
2. 业务会话有效、聊天本地状态暂不可用时保留会话和库，关闭聊天访问并给出恢复操作。权威凭据失效、主动退出继续遵循现有策略。
3. 业务登录前只读检查可确定的本地存储故障，失败不发登录请求。目标账号仍须认证后才能选择；这不保证避免后续网络故障引发的所有顶号，不改服务器单设备策略。
4. 根据真实异常类型/安全错误码区分钥匙串锁定/权限、存储元数据、数据库、身份校验、网络、Matrix服务拒绝和未知阶段。文案说明位置与下一步，不显示L04/L07，不直接显示原始异常或秘密。
