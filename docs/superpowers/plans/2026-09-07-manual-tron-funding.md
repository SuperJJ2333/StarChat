# 单源 TRON 与人工出款实施计划

> 使用 subagent-driven-development 逐任务实现，测试先行，领域审阅后安全审阅。用户已批准 ADR-0013 的单源和人工签名模式，不需要再次确认同一架构决策。

**Goal:** 补齐可审计的绑定、充值入账、imToken 人工提现与兑换闭环，完成隔离和实际资金启用条件核验。
**Architecture:** TronGrid 证据适配与钱包业务事务分离；正式资金路径新增，不放开 Sandbox 入口。复用公共账本、储备和审计 Outbox 接口。人工钱包签名由用户操作。
**Tech Stack:** Python 3.12、SQLAlchemy/PostgreSQL16、Flutter、现有管理前端、TronGrid HTTP。

## 1. 充值意图与事件

- [x] 新建 `wallet/funding_models.py`、`wallet/funding.py` 和 `tests/business_api/wallet/test_funding.py`：有效绑定与官方配置版本快照、每用户一个有效意图、服务端时间和区块边界、幂等与并发互斥。
- [ ] 新事件逐日志唯一；错误合约、未知来源、无意图、迟到、小额、重复冲突和旧 txid 重叠不自动入账。测试 9.999999/10/10.000001、多日志和跨绑定边界。
- [x] 通过公共 WalletLedger 在同一事务记录事件归属、余额、审计和 Outbox。待处理义务须接入公共储备接口；独立审阅后才接生产路径。
- [x] 改绑激活在同一事务关闭旧充值意图；不可变快照不得被改绑覆盖。

## 2. 身份与单源证据

- [x] 新单源策略适配器显式记录 ADR-0013 策略版本；固化收据和日志验证、源不可用失败关闭，不能仅把来源数量检查改成 1。
- [x] 复用真实 TOTP 防重放公共接口及会话身份，加入限流；TRON 账户权限首版只支持经核验的普通单密钥账户。
- [ ] 用户消息签名入口和控制权证明接通；不推断 imToken 支持未核验的消息签名 API。未具备设备支持时明确列出支持范围。

## 3. 人工提现

- [x] 新不可变提现快照：绑定版本、目标、本金、服务费、总冻结、规则/官方配置/熔断版本及报价到期。请求不接受任意目标。
- [x] 使用与改绑一致的锁顺序；按用户确认的 `OWNER_MANUAL_V1` 由官方钱包拥有者管理员以近期 MFA 确认同一摘要，USDT 服务费显式为零，不伪造第二审批。付款领取后保持冻结，禁止自动重付，改绑被阻断。
- [ ] 后台提供付款指令、复制地址和精确金额；用户在 imToken 签名，回填哈希仅用于定位，必须匹配真实固化日志和未使用事件再结算。
- [ ] 测试错地址/金额/来源/合约、重复哈希、同一日志结算两单、付款后断线、服务重启、未知结果及订单取消边界。
- [x] 追加式候选哈希更正保留首次和后续证据、实际操作者与原因；更正不授予付款或解冻资格。测试错误定位符后补交正确证据、并发更正与结算、多笔真实匹配出款异常。

## 4. 接线、储备和验收

- [ ] 2026-09-08 生产只读核验发现既有 CAIBI 历史；按 `docs/verification/artifacts/2026-09-07/manual-tron-completion/readiness/caibi-history-handover-design.md` 补齐版本化历史摘要交接，保留全部负债、历史和原储备公式，新增领域/安全及 PG 并发验收。当前官方观测储备不足，不得启用。

实施细化（沿用 ADR-0013，不改变用户资金路径）：

- [x] 收据两阶段处理：先记录完整证据及待处理义务，再由公共接口在真实储备可用后重试符合条件的入账。重复操作不改写已入账历史，不重开已改绑关闭的意图，不将其他 REVIEW 原因强制归属。
- [x] 从同一只读 SQLite 截面取得余额、固化高度、发现最大 rowid、观察编号及到期时间；持久化事件覆盖与不可变储备评估。仅游标追平不足以声明核验完成。
- [x] 提交储备时重锁并重算精确负债、核对版本、覆盖和人工在途计数；HOLD 不重复计算，网络/跨库读取在金融事务外，旧截面不能覆盖新领取/结算导致的失效。
- [x] 独立人工模式监控替换旧托管监控；基线后未分配转出、晚到重复出款、缺口/过期/不足产生可审计限制和告警。不得自动解除既有暂停或清除其他监控范围事件。
- [x] 恢复人工监控的 P0 五分钟未确认升级；与储备事务分开，源故障不跳过升级，升级失败不发布储备。
- [ ] 客户端接线细化：Flutter 强类型接口和后台人工付款/MFA API 封装完成后，独立审阅并接入实际操作页面、稳定请求恢复和真机消息签名。
- [x] 后台监控状态读取实际 Worker 投递配置，并提供范围限定、保留审计与暂停保护的人工事故复核/结案流程；不得调用无托管商的旧监控作为恢复证据。
- [x] 补齐独立受控启用/恢复操作：持久化 ledger restriction 来源与版本、旧限制来源未知拒绝释放；owner/MFA/会话事务内复验，所有事故结案后取得新鲜完整储备复核，原子释放仅人工来源限制并记录幂等命令、审计与 Outbox。暂停保留所有来源，不靠手工改表启用；需要领域及独立安全审阅。
- [ ] 对无旧资金记录的生产初次模式切换，按 `docs/verification/artifacts/2026-09-07/manual-tron-completion/readiness/legacy-handover-design.md` 实施精确清单交接：只接管有审计证明的旧无托管监控停止，逐条保留事故与历史失败告警，单条汇总通知实际送达后才能处置历史积压；交接结果继续暂停，再由独立受控恢复核验。任何其他风险、在途支付、未知来源或清单变化均拒绝。用户需确认无后台外未核清付款，不能从数据库空记录推断。

- [x] 扩展迁移由 root 独占分配下一版本，注册模型；API/Worker/管理端/Flutter/OpenAPI 同步，最低10和30天同源，老任意地址客户端拒绝。
- [ ] 储备核对加入待处理款义务、人工在途支付及手续费预算；对账差异暂停新操作。兑换保留真实储备覆盖门禁。
