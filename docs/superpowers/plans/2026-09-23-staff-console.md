# 客服后台五项反馈实施计划

> 执行：按独立领域并行，专项先红后绿，规格复核后做质量/安全复核。用户已明确批准本计划对应的五项行为；沿用同一后台生产修复交付授权，不重复请求确认。

**Goal:** 首次联系方式验证后，客服以账号密码进入同款概览并直接处理订单。
**Architecture:** 独立客服密码登录入口复用现有48小时管理会话；首次开通明确选择已绑定且已验证的邮箱/手机。客服订单以有效管理会话、当前角色、开通身份为授权基础，每次写入/提交前重查；不使用操作密码/TOTP/钱包grant。管理员专用USDT钱包原策略保持。客服可读取同款汇总概览，不扩展用户明细或管理员写权限。
**Tech Stack:** FastAPI/SQLAlchemy、既有HTML/JS后台组件。

## 所有权和验收

- [ ] A1 root：frontend/src/admin-login.js、相关CSS/API/session和测试。三入口选中颜色+aria-pressed，键盘可用；客服普通登录不请求图形/短信/邮箱码。首次开通选择邮箱或手机，固定服务端绑定目的地。
- [ ] A2 auth agent：identity/staff_activation.py、api/staff_activation.py、api/identity.py及认证测试。新增/auth/staff-login，不绕过未开通/停用/角色撤销；管理员仍需原验证码。兼容旧开通记录，选择邮箱不会因已绑手机而被错误判定失效；实际联系方式改变仍使相关开通失效。
- [ ] A3 root：api/admin.py及概览测试、admin-dashboard.js/home.js及测试。客服概览复用同一汇总数据和展示；侧栏不显示USDT提现与支付，不发起对应模块请求。
- [ ] A4 orders agent：支持订单鉴权服务、充值/提现调用点、兼容security状态路由及订单边界测试。登录即订单可用；真实角色/撤销会话/来源域/提交重查、认领冲突、幂等审计和链上证据必须保持。禁止将客服会话用作管理员钱包grant。
- [ ] root集成：后台全量、身份/订单/概览相关组合、OpenAPI、UI契约、迁移和verify门禁，按已有证据影响范围复用未变输入，不重复Flutter构建。先规格再独立安全复审。
- [ ] root交付：只整合本批文件到main；当前生产源码/配置基线→精确候选/备份→API与必要worker及静态增量→双侧HTTPS与资源SHA/权限拒绝。后台可浏览器联测，不发送真实验证码、不操作真实资金。

遗留金融账本、结算审批、链上来源证据及管理员钱包不在本次简化范围。本轮无需APK。
