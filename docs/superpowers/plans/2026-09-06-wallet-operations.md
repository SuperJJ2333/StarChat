# Wallet durable close and incident operations plan

> Use subagent-driven-development, test-first implementation, domain review followed by quality/security review. Continuation is authorized by the user's request to complete the remaining work and the previously approved wallet safety supplement §7.

**Goal:** Persist reproducible internal daily closes and implement incident detection, ACK/escalation/review records and Sandbox alert delivery receipts. Production funding remains disabled; no real third-party messages are sent.

**Architecture:** Additive operational tables only, migration 0041. Existing financial journals/posting formulas are untouched. Capture exact entry-set snapshots using the prior single-query reporter, save immutable payload/digest and day revision links. Closed days must be in the past in Hong Kong; each later corrected close is a new immutable revision, never overwrites prior evidence. This pins the captured entry set, not a fictitious global commit sequence or an external immutable archive.

## Ownership

- Close agent: `wallet/closing.py`, `wallet/closing_models.py`, tests `wallet/test_wallet_closing.py`. Own immutable report command idempotency/revisions and GET integrity verification. No API/migration edits.
- Incident agent: `wallet/incidents.py`, `wallet/incident_models.py`, tests `wallet/test_wallet_incidents.py`. Own state/version/idempotency, fingerprints, evidence clearance, escalation and Sandbox receipt handler. No API/worker/migration edits.
- Root: `api/wallet_operations.py`, router mount, recent-login public helper/tests, `wallet/monitoring.py`, worker integration/tests, migration0041/env/head test, docs/OpenAPI. No edits to agent-owned files while active.

## Contracts and acceptance

- [x] `WalletClosingService(factory, now_factory=None).close(day, actor_id, reason_code, idempotency_key)` creates or replays `{id, day, revision, previous_id, digest, created_by, created_at, cutoff_kind:'CAPTURED_ENTRY_SET', report}`. Report is persisted verbatim with its digest and finalized=false (the wrapper is sealed internal evidence, not an immutable global accounting period). Reject current/future day and any report integrity failure. GET `get(id)` verifies digest before returning; same key binds day/actor/reason; revisions serialized; restart/late post/replay/concurrency tests. All commands transactionally audit+Outbox; immutable snapshot rows never updated/deleted.
- [x] `WalletIncidentService(factory, now_factory=None).observe(signals, actor_id='wallet-monitor')` takes a complete scan of `{fingerprint, code, severity:P0|P1, subject_id}` with safe deterministic identifiers, opens/deduplicates incidents and records last-seen. Absence on successful complete scan marks condition inactive and supplies `clearance_digest`; failed scan must not clear conditions. Returned digest is derived from server scan, not caller assertions.
- [x] Incident `list_incidents(limit=50,cursor=None)`, `get(id)`, `ack(id,actor_id,reason_code,idempotency_key,expected_version)`, `resolve(id,actor_id,reason_code,idempotency_key,expected_version,clearance_digest)`; stale version409, replay same original result, payload collision409. ACK assigns owner; resolve requires ACK, different reviewer, currently inactive condition and matching server clearance digest. Close never unpauses wallet or releases funds. Recurrence reopens with new epoch/version and fresh alert.
- [x] P0 unacknowledged for >=5 minutes creates durable escalation at most once per5-minute interval, including across restarts. `escalate()` uses injected server time. Append audit/outbox for state-changing commands; sanitized alert payload only IDs/codes/severity. Separate `wallet.alert` topic and Sandbox handler `SandboxWalletAlertHandler(factory)(event)` stores unique event-ID receipt with transport='SANDBOX' (not a real delivery claim). Outbox provides retry/backoff/dead-letter; receipt deduplicates consumer replay.
- [x] Root monitor checks immutable-journal integrity, unknown/SUBMITTING withdrawals older5m, global pause/reserve mismatch, provider orphan order result and reconciliation task health. Critical signals invoke existing public pause method before incident handling. Failed source reads generate MONITOR_UNAVAILABLE; never auto-clear signals on failed/partial scan. Heartbeat persisted only after a successful scan; admin status computes staleness (>120s) even if worker stopped. No claim the same process can independently page about its own complete outage.
- [x] Read API financial role/admin. New command API requires real session claims and server-side refresh-family creation within5m (fresh login, refresh alone cannot satisfy); production commands remain503 until real operational MFA/delivery controls are integrated. This is a Sandbox operational gate, not a TOTP substitute. Commands require Idempotency-Key, strict reason and expected version; no-store errors/success. Endpoints `/admin/wallet/reports/close`, `/reports/closed/{id}`, `/incidents`, `/incidents/{id}`, `/incidents/{id}/ack`, `/incidents/{id}/resolve`, `/monitor/status`.
- [x] Worker wiring uses callable consistently (fix existing `.run_once` on bound function), adds independent monitoring maintenance callable, registers Sandbox alert consumer only outside production. No silent real delivery fallback. Production heartbeat/status may report unavailable but never substitute custody simulation.
- [x] Add migration0041 operational tables and indexes; verify preservation on isolated PostgreSQL and refuse destructive downgrade. Test-first known startup bug, recent-session gate, endpoint auth/permissions/errors, report restart/immutable revision, escalation/retry/duplicate delivery, active-condition resolution refusal. Update OpenAPI; run focused PostgreSQL checks then scripts/verify.ps1.
- [x] Domain review, then security review; resolve findings. Record evidence and exact remaining infrastructure gaps under docs/verification/artifacts/2026-09-06/wallet-operations/. No APK rebuild needed for backend-only changes. No deployment or production migration in this task.

**Limits:** Local DB persistence plus hash is not independent WORM, true cross-fault-domain RPO=0, real MPC, real notification SLA, full risk provenance, or iOS acceptance.
