# 移动聊天可靠性实施计划

授权：用户已明确要求四项双端排查、修复与验收。其最新要求取代原来“切换 Matrix 账号清除前账号数据”的产品规则；不删除旧账号聊天数据库或密钥，不降低 E2EE。继续在 main 工作，保留现有 iOS 本地化修改。

设计与顺序：

1. 语音：沿下载解密、缓存、文件格式、播放器与平台会话追踪；通过真实插件代码与失败测试区分根因和实机假设，修复资源/路由及异步状态。负责 voice_2084，仅语音组件及测试。
2. 账号本地数据：root 负责登录协调器、Matrix客户端实例/数据库选择、安全存储。账号以准确 homeserver+MXID 隔离，登出只停止同步和移除当前业务授权，明确清理功能仍需显式操作。旧数据库非破坏性迁入账号命名空间，复用本地设备/加密状态及同步游标；不把A凭证放入B库。登录新账号自动切换，不清库、不强制确认删除。
3. 单设备：server_sessions_2084 负责服务端身份会话、Matrix撤销及兼容接口。先制定移动单设备与非破坏性账号保留ADR并经Domain/Quality评审。新认证按事务序列替换旧移动会话，旧设备明确SESSION_REPLACED；Matrix独立令牌也须失效，不能只在UI退出。管理会话独立，不误撤销新会话，不在无法联网时宣称旧离线设备已经收到通知。
4. 视频：video_2084 负责统一视频压缩模块和调用者。拍摄/相册一致，取消压缩确认，先普通后激进质量策略，实际输出上限20MB；合理估算提前拒绝明显超限，最终仍量实文件。所有临时产物由创建者回收，保留用户相册原件。
5. 测试先行，定向测试/原生插件契约检查后全量Flutter、前端及仓库验证。每个模块先规格符合性、后质量/安全审查；认证/密钥存储遵守受保护审查要求。
6. 报告逐条采用“问题现象—复现步骤—根因排查—修改要求—验收标准”，附实际实现结果、接口/前后端分工与异常语义。设备原始描述 iPhone 15、iOS 26.6 保留；自动化/模拟器/实机证据分开，不虚称Windows已执行Xcode或iPhone验收。
