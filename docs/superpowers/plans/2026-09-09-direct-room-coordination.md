Goal: a pair of business accounts gets one creation authorization before any Matrix create request; unknown directory/creation outcomes never authorize another room. Preserve existing rooms and history. No server receives Matrix credentials, encryption keys or chat plaintext.

Architecture: an additive durable pair reservation (sorted account IDs, database unique constraint) serializes both directions. Only the transaction inserting an empty reservation returns `may_create=true`. Replays and other devices wait for its published room. Authorization never automatically expires after a possible Matrix creation. The owner persists its attempt ID before requesting authorization and persists the resulting room ID before publication. On retry it may recover a safe existing Matrix room, but never repeat an uncertain create. Legacy registration becomes first-writer-wins and cannot bypass an active reservation. Existing canonical rooms are adopted without replacement. Unknown identity, directory errors and room validation failures fail closed.

This favors history/uniqueness over availability when a creator crashes at an ambiguous point. Recovery uses the owner's existing joined/invited room or persisted result; otherwise explicit reconciliation is required. Old clients can still call Matrix independently and must be upgraded; this cannot prevent arbitrary obsolete clients from creating Matrix rooms.
